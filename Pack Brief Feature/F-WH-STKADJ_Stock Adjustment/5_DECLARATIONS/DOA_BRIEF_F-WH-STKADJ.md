> ใบประกาศ — feature **ประกาศ** ว่ามีการอนุมัติแบบไหน · **ห้าม hardcode สายอนุมัติใน feature**

> ตอน submit **UI ต้องให้เลือกคนจริงต่อ slot** (avatar + ตำแหน่ง + ชื่อ) · **ห้ามแสดง role ID บนหน้าจอ**

**เหตุผลที่ StockAdj ต้องมี DOA:** การปรับยอดคือการ **เปลี่ยนตัวเลขทรัพย์สินโดยไม่มีเอกสารการค้ารองรับ** — เป็นจุดเสี่ยงทุจริตอันดับต้นของคลัง ERP มาตรฐานทุกเจ้าจึงบังคับสายอนุมัติตามนัยสำคัญของมูลค่า (BASELINE M-07) · ต่างจาก GRN (บันทึกข้อเท็จจริงว่าของมาถึง = ไม่ต้องอนุมัติ)

★ **ทำไมฐานต้องเป็นค่าสัมบูรณ์:** ใบผสมที่ปรับ `+1,000,000` และ `−1,000,000` มียอดสุทธิ = 0 — ถ้าใช้ยอดสุทธิเป็นฐาน ใบนี้จะ **หลุดการอนุมัติทั้งที่ขยับทรัพย์สินสองล้าน** (ดู mock `ADJ-2026-0003` ใน PREBRIEF §8 ที่ Σ\|มูลค่า\| = 23,575 แต่สุทธิ = −10,175)

## 2. Approval Actions

| Action | Trigger | สถานะก่อน | ผลเมื่ออนุมัติครบ | ผลเมื่อตีกลับ | ผลเมื่อยกเลิก |

> **ไม่มี** DOA แยกสำหรับ `กลับรายการ` — จำกัดด้วยสิทธิ์ (หัวหน้าคลัง) + เหตุผลบังคับแทน → ดู DOA-Q3

## 3. Matrix ที่จะไปตั้งค่าที่หน้า DOA กลาง

**ฐานวงเงิน = `Σ |มูลค่าที่ปรับต่อบรรทัด|` หน่วย = บาท · `amount_to: null` = ไม่จำกัด · ช่วงต่อเนื่องไม่ทับ ไม่มีรู**

| set | amount_from | amount_to | departments | chainMode | steps (ลำดับ slot) |
|---|---|---|---|---|---|
| 1 | 0 | 20,000 | merged | sequential | slot 1: หัวหน้าคลัง |
| 2 | 20,001 | 200,000 | merged | sequential | slot 1: หัวหน้าคลัง → slot 2: ผู้จัดการคลังสินค้า |
| 3 | 200,001 | 1,000,000 | merged | sequential | slot 1: หัวหน้าคลัง → slot 2: ผู้จัดการคลังสินค้า → slot 3: ผู้จัดการฝ่ายบัญชี |
| 4 | 1,000,001 | *null (ไม่จำกัด)* | merged | sequential | slot 1: หัวหน้าคลัง → slot 2: ผู้จัดการคลังสินค้า → slot 3: ผู้จัดการฝ่ายบัญชี → slot 4: ผู้อำนวยการสายงาน |

`[DEFAULT — รอยืนยัน]` ทั้ง 4 set — จุดตัดวงเงินและจำนวนชั้นยังไม่ผ่านการเคาะจากเจ้าของกระบวนการ (owner: **Strike** · pin `OQ-STK-01` / `OQ-ADJ-01`)

> **จุดตัดตั้งต่ำกว่า RTV และ PO โดยเจตนา** (20,000/200,000/1,000,000 เทียบ RTV 50,000/500,000 และ PO 100,000/1,000,000) — การปรับยอดไม่มีคู่ค้าภายนอกมาถ่วงดุล ความเสี่ยงทุจริตสูงสุดในสามตัว จึงคุมเข้มกว่า `[DEFAULT — รอยืนยัน]`
> **ชั้นบัญชีเข้ามาที่ set 3** เพราะมูลค่าระดับนี้กระทบงบการเงินอย่างมีนัยสำคัญ `[AI-DRAFT]`

**Gate check**
- G2 ทุก set มี `amount_from` + `amount_to` ครบ ✅
- G3 ช่วงต่อเนื่อง 0→20,000 · 20,001→200,000 · 200,001→1,000,000 · 1,000,001→null — ไม่ทับ ไม่มีรู ✅
- G4 set สุดท้าย `amount_to: null` ✅
- G5 `approval_scope = document_sign` ✅
- G6 ค่าที่ยังไม่ยืนยันติด `[DEFAULT — รอยืนยัน]` ครบ ✅
- G7 ไม่มีสายอนุมัติ hardcode ใน HTML/เอกสาร feature — HTML ใช้ mock ที่ resolve จากรูป DOA entry + marker `FWD-WIRE: DOA engine` ✅
- G1 role master (`references/doa-contract.md`) **ไม่มีในเลนนี้** → slot เขียนเป็น "นิยามตำแหน่งที่ทะเบียน DOA ใช้ดึงคน" แทน role id · ผู้ตั้งค่าต้อง map เป็น `role-*` จริงตอนกรอกที่หน้า DOA กลาง — **ข้อจำกัดของรอบนี้ ไม่ใช่การแต่ง role เอง** (เหมือน F-PUR-PO / F-PUR-RTV)
