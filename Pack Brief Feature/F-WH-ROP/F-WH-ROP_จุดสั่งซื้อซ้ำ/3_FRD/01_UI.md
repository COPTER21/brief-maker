# 01_UI · F-WH-ROP

## 1.0 Layout decision log and HTML alignment
Frozen v9 console/master shell is the layout source. All three routes use one page-head with action group at upper right, tab row immediately below it, then data-derived stats and a canonical `.toolbar>.search-box` filter block copied without custom class. Drawer follows v9 standard. No Pattern Q, no hint/banner. UI uses existing Item/Warehouse searchable master picker; a free-text identifier not selected from menu fails reference validation. Palette/type/spacing are inherited from v9 and are not hardcoded here.

| Route | HTML selectors/functions | User action and state |
|---|---|---|
| `#/records` policy list | `#mainPanel`, `#thead/#tbody`, `render`, `ropRows`, `ropOpenPolicy`, `ropSaveFromDrawer` | filter/search/sort, create/edit version, field errors, future/effective status |
| `#/history` suggestion list | `#mainPanel`, `ropSuggestions`, `ropOpenCheck`, `openView` | computed availability/min/qty and mock PR/NC action; missing pair check |
| `#/settings` events | `#mainPanel`, `ropEvents`, `openView` | read-only event/version/mock reference, no delete/edit |

Canonical toolbar retains search, type and status selectors; `fillFilters` derives actual options from rows, `renderTableOnly` recomputes visible rows/counts and empty state. Stats are counts/sum from policy/suggestions/events, not invented readiness percentages. `ropPicker` menu filters master options, `ropChoosePicker` binds a valid code. `ropValidate` and `ropSaveFromDrawer` show input errors; cancel leaves policies/events unchanged. External PR/NC mock outcomes show ack/candidate text; never “PR created” or “notification sent”. Action buttons are in page-head or drawer; tab row is below page-head. No persona switcher is present. The topbar sample user is a DEMO label; it carries no permission effect.

## Interaction limits
Local HTML stores seeded data only in memory. It demonstrates formula and idempotency in isolated VM tests, but no browser screenshot or actual keyboard/pointer interaction was captured. Production APIs/role guards in 02_API are specifications, not witnessed UI behavior. Screens at <=767px may collapse shell, but desktop visual result is NOT-CHECKED due renderer gap.

## Observed pattern and text anchors
`#/records`, `#/history`, `#/settings` all use v9 console list/detail (Pattern A observed); drawers serve edit/view, not transactions. Exact visible anchors in authored frozen source: `เพิ่มนโยบาย`, `แก้นโยบาย`, `คำนวณใหม่`, `ตรวจคู่สินค้า×คลัง`, `แนะนำเปิด PR`, `ส่งตัวเลือกให้กฎ NC`, `ยังไม่มีนโยบาย`, `ปลายทาง PR ยังไม่พร้อม`, `บันทึกนโยบายแล้ว`, `รายการนี้ส่งแล้ว`.
