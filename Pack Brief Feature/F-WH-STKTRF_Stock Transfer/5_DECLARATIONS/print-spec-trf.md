## 1. Identity

| ช่อง | ค่า |
|---|---|
| doc type | `TRF` — ใบย้ายสินค้า |
| ขนาด | **A4 แนวตั้งเสมอ** (ห้าม override) |
| ฟอนต์ | Sarabun (ฝัง base64 ในไฟล์) |
| body | 9pt / น้ำหนัก 400 · เน้น 600 เฉพาะจุด |
| ที่มาข้อมูล | TRF entity ตาม PREBRIEF §3.1 / §3.2 |
| เมื่อไหร่ถูกสร้าง | ★ **พิมพ์ได้ตั้งแต่ `รออนุมัติ`** (คนขับต้องถือไป) · **เก็บสำเนา `approved_final` ตอนใบเข้าสถานะปิด** — ดู DOCCFG_BRIEF §3 · **ไม่มี `sent_external`** (ใบภายในล้วน) |
| ใครถือใบนี้ | ★ **3 ชุด**: คลังต้นทาง (ต้นฉบับ) · **คนขับ/ผู้ขนส่ง (ถือไปกับของ)** · **คลังปลายทาง (เซ็นรับแล้วเก็บ)** `[AI-DRAFT]` |
| ★ ไม่มีคู่ค้าภายนอก | ต่างจาก PO/RTV — ใบนี้เป็นเอกสารภายในองค์กร จึง **ไม่มีบล็อก VAT · ไม่มีช่องเซ็นฝั่งผู้ขาย · ไม่มีเงื่อนไขการชำระเงิน** |
| ★ ไม่ใช่เอกสารภาษี | มูลค่าที่แสดงเป็น **ต้นทุนอ้างอิงเพื่อการอนุมัติและควบคุม** ไม่ใช่ราคาขาย — ต้องมีข้อความกำกับ (§6) |

## 2. โครงหน้า (ตาม pattern เอกสารตาราง)

```
.doc-page
├── .doc-content
│   ├── HEADER   โลโก้ + ชื่อบริษัท + ที่อยู่ + เลขผู้เสียภาษี + สำนักงานใหญ่/สาขา
│   │            + หัวเรื่อง "ใบย้ายสินค้า / STOCK TRANSFER"
│   ├── META     เลขที่ TRF · วันที่ใบย้าย (ค.ศ.) · ★ ชิปโหมด · วันที่คาดว่าถึง · สถานะ · หน้า x/y
│   ├── ROUTE    ★ แถบเส้นทาง (บล็อกเฉพาะของเอกสารนี้ — §3)
│   ├── PARTIES  ซ้าย = คลังต้นทาง (รหัส + ชื่อ + ที่อยู่คลัง) + ผู้จัดทำ
│   │            ขวา = คลังปลายทาง (รหัส + ชื่อ + ที่อยู่คลัง) + ศูนย์ต้นทุน + เหตุผลการย้าย
│   ├── ITEMS    ตารางรายการที่ย้าย (§4) — ★ มีคอลัมน์ "จำนวนที่รับจริง" เว้นว่างให้เขียนมือ
│   └── NOTES + TOTALS   ซ้าย = หมายเหตุ + จำนวนเงินเป็นตัวอักษร + ★ ข้อความกำกับว่าไม่ใช่เอกสารภาษี
│                        ขวา = บล็อกยอดรวมมูลค่าที่ย้าย (§5)
└── .doc-bottom
    ├── SIGNATURES  ★ ช่องลายเซ็น 4 ช่อง (§6) — รวมช่องผู้รับปลายทาง
    └── FOOTER      เลขที่ใบ + วันที่พิมพ์ (ค.ศ.) + หน้า + ลายน้ำสถานะ (§8)
```

## 3. ★ แถบเส้นทาง (ROUTE) — บล็อกเฉพาะของเอกสารนี้

**โหมด A (ภายในคลัง)** — 1 บรรทัด
```
เส้นทาง:  WH-BKK-01 คลังกลางบางนา  ──▶  WH-BKK-01 คลังกลางบางนา          [ ย้ายภายในคลัง ]
```

**โหมด B (ข้ามคลัง/สาขา)** — 1 บรรทัด · ★ **ต้องแสดง in-transit ให้เห็น**
```
เส้นทาง:  WH-BKK-01 คลังกลางบางนา  ──▶  ระหว่างทาง (TR-BKK-CNX)  ──▶  WH-CNX-01 คลังเชียงใหม่   [ ย้ายข้ามคลัง/สาขา ]
```

| กติกา | รายละเอียด |
|---|---|
| ชิปโหมด | ข้อความ `ย้ายภายในคลัง` / `ย้ายข้ามคลัง/สาขา` — **derive จากคลัง ไม่ใช่ input** (PREBRIEF BR-03) |
| ★ กล่อง in-transit | **แสดงเฉพาะโหมด B** · ต้องมีรหัส `TR-*` จริง — ห้ามเขียนคำว่า "ระหว่างทาง" ลอย ๆ โดยไม่มีรหัส |
| ★ ข้อความเตือนใต้แถบ (โหมด B เท่านั้น) | **"เอกสารนี้ยังไม่ถือเป็นการส่งมอบสมบูรณ์ จนกว่าคลังปลายทางจะลงชื่อรับในช่องที่ 4"** — เป็นข้อความบังคับ กันความเข้าใจผิดว่าใบนี้ = ของถึงแล้ว (PREBRIEF BR-15) |
| โหมด A ซ่อนอะไรบ้าง | ซ่อนกล่อง in-transit · ซ่อนข้อความเตือน · ซ่อนช่องลายเซ็นที่ 4 (§6) · ซ่อนคอลัมน์ "จำนวนที่รับจริง" (§4) |

## 4. ตารางรายการ (ITEMS) — 1 row = 1 บรรทัด (ตารางผอม)

| # | คอลัมน์ | ชิด | ที่มา (PREBRIEF §3.2) | หมายเหตุ |
|---|---|---|---|---|
| 1 | ลำดับ | กลาง | ลำดับบรรทัด | — |
| 2 | **สินค้า** | ซ้าย | สินค้า (soft-ref) | รหัสสินค้าเป็น `<span class="sub">` ใต้ชื่อ |
| 3 | **จาก (bin ต้นทาง)** | ซ้าย | bin ต้นทาง | รหัส bin · ชื่อโซนเป็น `sub` |
| 4 | **ไป (bin ปลายทาง)** | ซ้าย | bin ปลายทาง | รหัส bin · ชื่อโซนเป็น `sub` |
| 5 | **จำนวนที่ย้าย** | ขวา | จำนวนที่ย้าย | `#,##0.00` (ตัดทศนิยมถ้าเป็นจำนวนเต็มหน่วยนับชิ้น) |
| 6 | หน่วย | กลาง | UOM (soft-ref) | — |
| 7 | ต้นทุน/หน่วย | ขวา | ต้นทุนอ้างอิง (**mock** `[ASSUMED contract]`) | `#,##0.00` · class `num` |
| 8 | **มูลค่าที่ย้าย** | ขวา | `จำนวนที่ย้าย × ต้นทุนอ้างอิง` | `#,##0.00` · class `num` |
| 9 | ★ **จำนวนที่รับจริง** | ขวา | **เว้นว่างไว้ให้เขียนมือตอนรับ** | ★ **โหมด B เท่านั้น** · ถ้าพิมพ์หลังปิดใบแล้วให้เติมค่าจริงจาก `รับแล้วสะสม` |

**กติกาตาราง**
- ★ **ไม่มีคอลัมน์ VAT · ไม่มีส่วนลด · ไม่มีราคาขาย** — ย้ายภายในกิจการไม่ใช่รายการภาษี/การค้า (PREBRIEF §3.6)
- ★ **ไม่มีคอลัมน์ Lot/Serial** — ไม่มี Lot master ในเลนนี้
- หัวตาราง = แถบ navy เข้ม ตัวอักษรขาว · เนื้อตาราง minimal (ไม่มีเส้นแนวตั้ง/zebra) — Design Rule R4
- บรรทัดยาวเกิน 1 หน้า → ตัดหน้าใหม่ พร้อมซ้ำหัวตาราง + META ย่อ + `หน้า x/y`
- ★ **ใบที่ปิดพร้อมส่วนต่าง**: เพิ่ม **แถวสรุปใต้ตาราง** (ไม่ใช่คอลัมน์) — `ส่วนต่างที่ตัดออกจากระหว่างทาง: {qty} {uom} · มูลค่า {amount} บาท · เหตุผล: {reason}` พร้อม **สีแดง CI** (PREBRIEF S-07)

## 5. บล็อกยอดรวม (TOTALS — ขวาล่าง)

| บรรทัด | สูตร | แสดงเมื่อ |
|---|---|---|
| จำนวนรายการ | นับบรรทัด | เสมอ |
| จำนวนรวมที่ย้าย | `Σ จำนวนที่ย้าย` (แยกตามหน่วยถ้าหลายหน่วย) | เสมอ |
| ★ **มูลค่ารวมที่ย้าย** | `Σ (จำนวนที่ย้าย × ต้นทุนอ้างอิง)` — **บวกเสมอ** | เสมอ · **แถบ navy เข้ม ตัวอักษรขาว** (Design Rule R4) |
| ★ จำนวนที่รับแล้ว | `Σ รับแล้วสะสม` | โหมด B + สถานะ ≥ `รับบางส่วน` |
| ★ **คงค้างระหว่างทาง** | `Σ คงค้างระหว่างทาง` | โหมด B + สถานะ ≥ `ส่งออกแล้ว` · ★ **ถ้า > 0 ให้ใช้สีส้ม CI** |
| ★ ส่วนต่างที่ตัดทิ้ง (มูลค่า) | `Σ (จำนวนส่วนต่างที่ตัด × ต้นทุนอ้างอิง)` | เฉพาะใบ `ปิดใบพร้อมส่วนต่าง` · **สีแดง CI** |

**จำนวนเงินเป็นตัวอักษร** (ซ้ายล่าง): ใช้ `python scripts/baht_text.py <มูลค่ารวมที่ย้าย>` — ★ อิงจาก **มูลค่ารวมที่ย้าย** ไม่ใช่ยอดที่รับจริง

## 6. ★ ช่องลายเซ็น (SIGNATURES) — 4 ช่อง

| # | ช่อง | ใคร | มีเมื่อ | ที่มา |
|---|---|---|---|---|
| 1 | **ผู้จัดทำ** | ผู้สร้างใบ (คลังต้นทาง) | เสมอ | §3.1 ผู้จัดทำ (คนจริง) |
| 2 | **ผู้อนุมัติ** | สาย DOA จุดตัดสินใจที่ 1 (A1/A2) | เสมอ · **หลายชั้น = หลายช่องย่อยเรียงตามลำดับ** | DOA_BRIEF §3.1/§3.2 |
| 3 | **ผู้ส่งของ / ผู้ขนส่ง** | คนที่นำของออกจากคลังต้นทาง | เสมอ | §3.1 ผู้ส่งออก (คนจริง) |
| 4 | ★ **ผู้รับปลายทาง** | เจ้าหน้าที่คลังปลายทาง | ★ **โหมด B เท่านั้น** | §3.1 ผู้รับปลายทาง (คนจริง) |

**กติกาลายเซ็น**
- ★ ทุกช่องต้องมี **ชื่อ-นามสกุล + ตำแหน่ง + วันที่ (ค.ศ.)** — **ห้ามพิมพ์ role ID** (DOA-UI-LOCK 2026-08-17)
- ★ **ช่องที่ 4 พิมพ์ออกมาเป็นช่องว่างเสมอตอนพิมพ์ก่อนส่งของ** — คนขับถือไปให้ปลายทางเซ็นจริง · ถ้าพิมพ์ซ้ำหลังปิดใบแล้วให้เติมชื่อผู้รับจริง + วันที่รับ
- ★ **ใบที่ปิดพร้อมส่วนต่าง** → เพิ่ม **ช่องที่ 5 "ผู้อนุมัติการตัดส่วนต่าง"** (สาย DOA จุดตัดสินใจที่ 2 · B1) — ต่อท้ายแถวลายเซ็น หรือขึ้นแถวใหม่ถ้าไม่พอ
- ★ **ใบกลับรายการ** → เพิ่มข้อความเหนือช่องลายเซ็น: `กลับรายการของใบเลขที่ {original_trf_no} เมื่อ {date} (เหตุผล: {reason})`
- ลายเซ็น + footer ห่อใน `.doc-bottom` ชิดล่างหน้า — Design Rule R5

| ยอดรวม | §3.3 | — |
| สถานะ (ลายน้ำ) | §3.1 `สถานะเอกสาร` | §8 |
| หมายเหตุ | §3.1 | — |

## 8. ลายน้ำสถานะ + กติกาพิมพ์

| สถานะใบ | ลายน้ำ | พิมพ์ได้ไหม |
|---|---|---|
| `ร่าง` | — | ★ **พิมพ์ไม่ได้** (ยังไม่มีเลขที่ · PREBRIEF BR-09) |
| `รออนุมัติ` | **"รออนุมัติ"** เทาอ่อน | ✅ พิมพ์ได้ (แต่ห้ามใช้เบิกของ) |
| `อนุมัติแล้ว` | — | ✅ **ฉบับที่คนขับถือไป** |
| `ส่งออกแล้ว — อยู่ระหว่างทาง` | **"อยู่ระหว่างทาง"** สีส้มอ่อน | ✅ |
| `รับบางส่วน` | **"รับบางส่วน"** สีส้มอ่อน | ✅ |
| `ปิดใบ (รับครบ)` | — | ✅ ฉบับสมบูรณ์ |
| `ปิดใบพร้อมส่วนต่าง` | **"มีส่วนต่าง"** สีแดงอ่อน | ✅ |
| `ตีกลับคืนต้นทางแล้ว` | **"ตีกลับคืนต้นทาง"** สีแดงอ่อน | ✅ |
| `ยกเลิก` | **"ยกเลิก"** สีแดงอ่อน ทับกลางหน้า | ✅ (เก็บเป็นหลักฐาน) |
| `กลับรายการแล้ว` | **"กลับรายการแล้ว"** สีแดงอ่อน | ✅ · ต้องมีข้อความอ้างใบคู่ (§6) |

**กติกาอื่น**
- ★ **ปี ค.ศ. ล้วนทุกจุด** รวมวันที่พิมพ์ใน footer (GOLDEN_RULES §1 · PREBRIEF BR-29)
- ตัวเลขเงินทุกช่อง `#,##0.00` + class `num` ชิดขวา
- ห้ามเขียน hex สีเองใน body — ใช้ class จาก `base.css` เท่านั้น
- ★ ข้อความกำกับบังคับใต้ NOTES: **"เอกสารนี้เป็นเอกสารภายในเพื่อการควบคุมสินค้าคงคลัง ไม่ใช่เอกสารทางภาษี มูลค่าที่แสดงเป็นต้นทุนอ้างอิง"**
