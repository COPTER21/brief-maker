## 1. doc_type ที่ประกาศ

| Code | ชื่อ | Module | Preset default | Reset | Scope | No-gap | Snap: ส่งออก | Snap: อนุมัติ+เซ็น |
|---|---|---|---|---|---|---|---|---|
| **TRF** | ใบย้ายสินค้า | WH | `{PREFIX}-{YYYY}-{run:4}` → **`TRF-YYYY-NNNN`** | **รายปี** | `global` | ✗ | ✗ | ✅ |

**เหตุผลของแต่ละค่า default**

| ช่อง | ค่า | เหตุผล |
|---|---|---|
| **Code `TRF`** | 2–5 ตัวอักษร unique | ไม่ชนกับ registry ในเลนนี้: `PO` · `GRN` · `RTV` · `ADJ` · **`TRF`** — Putaway **ไม่มี doc_type** (ไม่ใช่เอกสาร) |
| **Preset** | `{PREFIX}-{YYYY}-{run:4}` | ตรงตาม CONTEXT_PACK §2.3 · **`YYYY` = ปี ค.ศ. ล้วน** (GOLDEN_RULES §1 · BR-29) — ห้ามใช้ พ.ศ. |
| **Reset** | รายปี | เลขรันเริ่มใหม่ทุกปีปฏิทิน (ค.ศ.) — ชุดเดียวกับ ADJ/GRN/RTV ในเลน |
| **Scope** | `global` | 1 ชุดเลขทั้งบริษัท `[DEFAULT — รอยืนยัน]` · ★ **ประเด็นเฉพาะของ feature นี้**: ใบย้ายมี **2 คลังเกี่ยวข้อง** ถ้าใช้ `branch` จะไม่ชัดว่าเลขเป็นของสาขาไหน → `global` ตัดปัญหา (ดู DOCCFG-Q1) |
| **No-gap** | ✗ | ใบย้ายสินค้า **ไม่ใช่เอกสารภาษี** — ไม่ต้องบังคับเลขต่อเนื่องไม่ขาดตอน (ต่างจาก INV/RV/CN/DN/JE) |
| **Snap ส่งออก** (`sent_external`) | ✗ | ★ **เอกสารภายในล้วน ไม่ส่งให้บุคคลภายนอก** — ต่างจาก PO/RTV ที่ส่งให้ผู้ขาย |
| **Snap อนุมัติ+เซ็น** (`approved_final`) | ✅ | ★ **ต้องเก็บสำเนา** — ใบย้ายมีลายเซ็นสายอนุมัติ + **ช่องลงชื่อผู้รับปลายทาง** ที่คนขับรถถือไป · เป็นหลักฐานการส่งมอบระหว่างคลัง ต้องย้อนดูได้ (สำคัญกว่าปกติเพราะมีช่วง in-transit ที่ของอยู่นอกคลัง) |

## 2. จุดออกเลข (ENG-DOC-NUM)

| เมื่อไหร่ | อ้าง PREBRIEF | หมายเหตุ |
|---|---|---|
| **`ร่าง → รออนุมัติ`** (กด "ส่งอนุมัติ" ที่ wizard step 5) | §5.1 transition แรก · §4 **BR-09** · S-04 | ★ **ไม่ออกเลขตอน draft** — กันเลขกระโดดจากร่างที่ถูกทิ้ง · ร่างแสดง **`(ร่าง — ยังไม่ออกเลขที่)`** |
| **ส่งอนุมัติซ้ำหลังถูกตีกลับ** | §5.1 `รออนุมัติ → ร่าง → รออนุมัติ` · S-05 · BR-13 | ★ **ใช้เลขเดิม ไม่ออกเลขใหม่** — เลขเอกสาร **immutable** (Iron #3) |
| ★ **ใบกลับรายการ (reversal)** | §5.1 `ปิดใบ → กลับรายการแล้ว` · S-15 · BR-26 | ★ **ออกเลข `TRF-YYYY-NNNN` ใบใหม่** (mock `TRF-2026-0011` คู่กับ `TRF-2026-0010`) — ใช้ **doc_type เดียวกัน ไม่สร้าง type ใหม่** · ผูก soft link 2 ทางกับใบเดิม |

**จุดที่ไม่ออกเลข (เขียนไว้กันเข้าใจผิด)**

| ไม่ออกเลข | เหตุผล |
|---|---|
| ตอนสร้าง/บันทึกร่าง | BR-09 · S-03 |
| ตอนกด "ส่งออก" / "ย้าย" | ใบมีเลขแล้วตั้งแต่ส่งอนุมัติ |
| ★ **ตอนปลายทางยืนยันรับ (ทุกรอบ)** | ★ **การรับไม่ใช่เอกสารใหม่** — เป็นการเดินสถานะของใบเดิม · **ห้ามออก "ใบรับ" แยก** (ต่างจาก Odoo ที่ใช้ 2 ใบ — CUBE รอบนี้ใช้ **1 ใบ 2 จังหวะ** แบบ D365 Transfer Order) |
| ★ ตอนตัดส่วนต่างระหว่างทาง | เป็น movement ในใบเดิม ไม่ใช่เอกสารใหม่ (S-07) |
| ★ ตอนตีกลับคืนต้นทาง | เป็นการปิดใบเดิม ไม่ใช่เอกสารใหม่ (S-08) |

## 3. จุดเก็บสำเนา (ENG-DOC-STORE)

| Event | เมื่อไหร่ | อ้าง PREBRIEF |
|---|---|---|
| `approved_final` | ★ **เมื่อใบเข้าสถานะปิด**: `ย้ายสำเร็จ` (โหมด A) / `ปิดใบ (รับครบ)` / `ปิดใบพร้อมส่วนต่าง` / `ตีกลับคืนต้นทางแล้ว` | §5.1 · §6.3 tab PDF |

**เหตุผล:** สำเนาต้องเก็บ **ตอนใบจบจริง** ไม่ใช่ตอนอนุมัติ — เพราะเนื้อหาที่ต้องเก็บรวม **ผลขารับ** (จำนวนที่รับจริง · bin ที่ลงจริง · ส่วนต่างที่ตัด · ลายเซ็นผู้รับปลายทาง) ซึ่งยังไม่มีตอนอนุมัติ `[AI-DRAFT]`

> ⚠️ **ไม่เก็บ `sent_external`** — ใบย้ายเป็นเอกสารภายใน ไม่ส่งออกนอกองค์กร (ถ้าอนาคตมีผู้ให้บริการขนส่งภายนอกต้องรับเอกสาร → **เปลี่ยน flag ที่จอ F-DOCCFG ได้ ไม่ต้องแก้ feature** · BASELINE N-02 อยู่ backlog)

## 4. Dev wiring note

- `trf.number = ENG-DOC-NUM.next('TRF', company_ctx)` **ที่ transition `ร่าง → รออนุมัติ` เท่านั้น** — ห้าม format เอง ห้าม `+1` เอง ห้ามเก็บ counter ในตาราง TRF
- ส่งอนุมัติซ้ำหลังตีกลับ → **ตรวจว่ามีเลขแล้วหรือยัง** ถ้ามีแล้วให้ข้าม `next()` (เลข immutable)
- render PDF แล้วเรียก `ENG-DOC-STORE.store(pdf, 'TRF', trf_id, 'approved_final')` ตอนใบเข้าสถานะปิด — **engine เช็ค flag เองว่าเก็บหรือไม่**
- ห้ามอ่าน/เขียนตาราง config ตรง — ผ่าน engine API เท่านั้น
- ในรอบ Phase A (HTML prototype) เลขในหน้าจอเป็น **mock ตามรูปแบบ `TRF-2026-NNNN`** + marker **`FWD-WIRE: ENG-DOC-NUM`** — **ห้ามมีฟังก์ชัน format/increment เลขในไฟล์ feature**
