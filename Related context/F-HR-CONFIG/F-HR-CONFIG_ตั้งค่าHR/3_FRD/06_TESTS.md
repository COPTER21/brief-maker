## §6.1 Acceptance Criteria (AC) — AT-01…AT-38

> ทุก AT map 1:1 กับ Story ใน BRD §7 (ST-01…ST-37) + AT-38 สำหรับ BR-03

### AT-01 — ตั้งวันมีผลทุกครั้งที่บันทึก (ST-01 · FN-01/FN-02 · BR-01)
**Given** อยู่ขั้น "ตรวจสอบและยืนยัน" ของ drawer สร้างค่า
**When** เว้นช่อง "วันมีผล" ว่างแล้วกด "บันทึกและตั้งวันมีผล"
**Then** ระบบบล็อก · error ใต้ field = `ต้องกรอกวันมีผลก่อนบันทึก (บันทึกร่างไว้ก่อนได้)` · toast = `ยังตั้งวันมีผลไม่ได้ ตรวจข้อความสีแดง`
**And** API ตอบ 422 `BR_EFFECTIVE_DATE_REQUIRED`
**And** เมื่อกรอกวันในอนาคตแล้วบันทึก → เวอร์ชันสถานะ `รอมีผล` + toast `บันทึกแล้ว — จะมีผล <วันที่>`

### AT-02 — Draft/Scheduled ไม่รั่วไปปลายทาง (ST-02 · FN-03/FN-06 · BR-19)
**Given** ค่าหนึ่งมีเวอร์ชัน Draft และเวอร์ชัน Scheduled ที่ยังไม่ถึงวัน
**When** เรียก `GET /hr-config/resolve?date=<วันนี้>&company_id=…`
**Then** response คืนเฉพาะเวอร์ชัน `status='active'` — ไม่มี Draft/Scheduled
**And** ใน view drawer tab "ใครใช้ค่านี้" ส่วน "เวอร์ชันที่ปลายทางอ่านอยู่ตอนนี้" แสดงเวอร์ชัน Active เท่านั้น

### AT-03 — แก้ค่า Active = สร้างเวอร์ชันใหม่ (ST-03 · FN-04/FN-05 · BR-02)
**Given** ค่าหนึ่งมีเวอร์ชันสถานะ Active
**When** กดปุ่ม "แก้ไข"
**Then** ระบบเปิดฟอร์ม **สร้างเวอร์ชันใหม่** ที่ copy payload เดิม (ไม่ใช่ฟอร์มแก้ทับ)
**And** เมื่อกรอกเหตุผล < 10 ตัวอักษรแล้วบันทึก → บล็อก · `กรอกเหตุผลการเปลี่ยนอย่างน้อย 10 ตัวอักษร` · 422 `BR_CHANGE_REASON_REQUIRED`
**And** เรียก `PUT /hr-config/versions/<id ของเวอร์ชัน active>` โดยตรง → 422 `BR_VERSION_NOT_EDITABLE`

### AT-04 — ยกเลิกเวอร์ชันที่รอมีผล (ST-04 · FN-07 · BR-20)
**Given** เวอร์ชันสถานะ "รอมีผล"
**When** กดยกเลิก + กรอกเหตุผล ≥10 ตัวอักษร
**Then** เวอร์ชันเป็น `cancelled` · toast `ยกเลิกเวอร์ชันที่รอมีผลแล้ว` · ค่าที่ Active เดิมยังใช้ต่อ
**And** เมื่อเวอร์ชันเป็น Active แล้ว ปุ่มยกเลิก **ไม่ปรากฏ** และเรียก API ตรง → 422 `BR_CANCEL_ONLY_BEFORE_EFFECTIVE`

### AT-05 — ย้อนดูค่า ณ วันที่ + ประวัติ (ST-05 · FN-27/FN-28)
**Given** ค่าหนึ่งมี 3 เวอร์ชัน (superseded / active / scheduled)
**When** เลือกตัวกรอง "มีผล ณ วันที่" เป็นวันในอดีต
**Then** list เปลี่ยนเป็นค่าที่ Active ณ วันนั้น + แถบ `กำลังดูค่าที่มีผล ณ <วันที่>` + ปุ่ม `กลับมาวันนี้`
**And** เปิด tab "ประวัติเวอร์ชัน" เห็น timeline ค่าเก่า→ใหม่ · ผู้แก้ไข · เวลา · `เหตุผล: …` **โดยไม่มีปุ่มแก้/ลบ**

### AT-06 — milestone ต้องต่อเนื่อง (ST-06 · FN-08 · BR-16)
**Given** กรอกขั้น 0–2 ปี แล้วขั้นถัดไปเริ่มที่ 4 ปี
**When** กดบันทึก
**Then** บล็อก · `ช่วงอายุงานมีช่องว่างระหว่างขั้นที่ …` · 422 `BR_MILESTONE_GAP_OR_OVERLAP`
**And** ถ้าขั้นถัดไปเป็น 2–5 ปี (ทับซ้อน) → `ช่วงอายุงานทับซ้อนกันที่ขั้นที่ …`

### AT-07 — ยกยอดต้องมีวันหมดอายุ (ST-07 · FN-09 · BR-12)
**Given** กรอกยกยอดสูงสุด 5 วันโดยเว้นวันหมดอายุ · **When** บันทึก
**Then** บล็อก · `ยกยอดมากกว่า 0 ต้องระบุวันหมดอายุยกยอด` · 422 `BR_CARRY_EXPIRY_REQUIRED`
**And** ใส่วันหมดอายุ 31 มี.ค. ปีถัดไป → บันทึกสำเร็จ

### AT-08 — prorate + ปัดเศษ (ST-08 · FN-10)
**Given** เลือก prorate "ตามเดือน" และปัดเศษ "ครึ่งวันใกล้สุด" · **When** บันทึกแล้วเปิดดู
**Then** ค่าถูกเก็บตามที่เลือก **And** `resolve()` คืน `prorate` และ `rounding` ตรงกัน

### AT-09 — กติกาการนับวันลา (ST-09 · FN-29)
**Given** เปิด "นับวันหยุดในช่วงลา" และปิด "อนุญาตครึ่งวัน" · **When** บันทึก + resolve
**Then** payload ที่ปลายทางได้มี `count_holiday=true` และ `half_day=false`

### AT-10 — จ่ายบางส่วน + เงื่อนไขเอกสาร (ST-10 · FN-31)
**Given** เลือก "จ่ายบางส่วน" โดยไม่กรอกเปอร์เซ็นต์ · **When** บันทึก
**Then** บล็อก · `เปอร์เซ็นต์ที่จ่ายต้องอยู่ระหว่าง 1–99`
**And** เปิด "ต้องแนบเอกสาร" โดยไม่ระบุเงื่อนไข → `ระบุเอกสารที่ต้องแนบ`

### AT-11 — เตือนโควตาต่ำกว่ากฎหมาย (ST-11 · FN-32 · BR-06)
**Given** กรอกโควตาลาพักร้อน 4 วัน/ปี · **When** บันทึก
**Then** modal `โควตาต่ำกว่าขั้นต่ำตามกฎหมาย` แสดงพร้อมข้อความ `โควตาลาพักร้อน 4 วันต่อปี ต่ำกว่าขั้นต่ำ 6`
**And** กดยืนยัน → **บันทึกสำเร็จ** (เตือน ไม่บล็อก) · API ตอบ 200 พร้อม `warnings[BR_LEAVE_QUOTA_BELOW_LEGAL_MIN]`
**And** มี audit entry ระบุว่าผู้ใช้ยืนยันต่อทั้งที่ถูกเตือน

### AT-12 — อัตรา OT + เพดาน (ST-12 · FN-11)
**Given** เลือก "OT วันทำงาน" ตัวคูณ 1.5 ฐานรายชั่วโมง เพดาน 36 · **When** บันทึก → สำเร็จ
**And** เว้นเพดานว่าง → บล็อก `เพดานชั่วโมงต้องมากกว่า 0`

### AT-13 — `payroll_code` เป็นช่องอ้างอิง (ST-13 · FN-12 · BR-18)
**Given** กรอก `payroll_code` = `OT01` · **When** บันทึก
**Then** เก็บค่าโดย**ไม่มีการคำนวณเงินใด ๆ** ในหน้านี้ (ตรวจว่าไม่มี field จำนวนเงินใน response)
**And** เว้นว่างในประเภทที่จ่ายค่าจ้าง → **เตือนเบา บันทึกได้** (200 + `warnings[BR_PAYROLL_CODE_MISSING]`)

### AT-14 — บล็อกอัตรา OT ต่ำกว่ากฎหมาย (ST-14 · FN-13 · BR-05) 🔴 P0
**Given** อยู่ขั้น 2 ของ wizard tab อัตรา OT
**When** กรอกตัวคูณ 1.2 สำหรับ "OT วันทำงาน" แล้วกดถัดไป
**Then** **บล็อก** · ข้อความขึ้นต้นด้วย `ตัวคูณต่ำกว่าขั้นต่ำตามกฎหมายแรงงาน — ` และระบุขั้นต่ำ `1.5`
**And** wizard **ค้างอยู่ขั้นเดิม ไม่ข้ามไปขั้น 3**
**And** API ตอบ 422 `BR_OT_BELOW_LEGAL_MIN` พร้อม `min_value: 1.5`
**And** ค่า 1.5 ต้องมาจาก `T_hr_legal_minimum` (แก้ค่าในตารางแล้วข้อความต้องเปลี่ยนตาม — **พิสูจน์ว่าไม่ hardcode**)

### AT-15 — กะข้ามวัน (ST-15 · FN-14 · BR-17)
**Given** กรอกเวลาเข้า 22:00 ออก 06:00 โดยไม่ติ๊กข้ามวัน · **When** บันทึก
**Then** บล็อก · `เวลาออกต้องมากกว่าเวลาเข้า หรือติ๊ก “กะข้ามวัน”`
**And** กรอก 08:00–17:00 พัก 12:00–13:00 → `ชั่วโมงทำงาน/วัน` แสดง **8 ชม.** อัตโนมัติ

### AT-16 — ปฏิทินวันหยุดรายปี (ST-16 · FN-15)
**Given** เลือกปี 2570 เพิ่มวันหยุด 16 รายการ · **When** บันทึก
**Then** ชุดปฏิทินแสดงจำนวนครบ **And** เปิดชุดของอีกปี → เห็นเฉพาะวันหยุดของปีนั้น

### AT-17 — วันหยุดชดเชยอ้างวันต้นทาง (ST-17 · FN-16)
**Given** เลือกประเภท "วันหยุดชดเชย" โดยไม่ระบุวันต้นทาง · **When** บันทึก → บล็อก
**And** ระบุวันต้นทางที่มีอยู่จริง → บันทึกสำเร็จพร้อมแสดงการอ้างอิง

### AT-18 — ชุดปฏิทินตามสถานที่ (ST-18 · FN-49 · `[AI-DRAFT]`)
**Given** สร้างชุดปฏิทินใหม่ระบุสถานที่ "โรงงานระยอง" · **When** บันทึก
**Then** ชุดนั้นแยกจากชุดสำนักงาน **And** เว้นช่องสถานที่ว่าง → บันทึกได้ (ชุดกลาง)

### AT-19 — บล็อกวันหยุดซ้ำ (ST-19 · FN-17 · BR-09)
**Given** มีวันหยุด 13 เม.ย. 2570 อยู่แล้วในบริษัทเดียวกัน
**When** เพิ่มวันเดิมอีกครั้ง **ในชุดเดียวกัน** → บล็อก · 422 `BR_HOLIDAY_DUPLICATE`
**And** เพิ่มวันเดิม **ในชุดปฏิทินคนละชุดแต่บริษัท+ปีเดียวกัน** → **ยังบล็อก** (ตรวจข้ามชุด)

### AT-20 — รอบตัดเวลา + รอบจ่าย (ST-20 · FN-18 · BR-11)
**Given** กรอกวันตัด 28 วันจ่าย 25 · **When** บันทึก → บล็อก `วันตัดเวลาต้องไม่เกินวันจ่ายในงวดเดียวกัน`
**And** กรอกวันตัด 25 วันจ่าย 30 ความถี่รายเดือน → บันทึกสำเร็จ

### AT-21 — สร้างงวดทั้งปี + ปิด/เปิดงวด (ST-21 · FN-48 · BR-21) 🔴 P0
**Given** กติกาตัด 25 จ่าย 30 รายเดือน active อยู่
**When** กด "สร้างงวดทั้งปี" ปี 2569
**Then** สร้าง **12 งวด** ครบ พร้อมวันเริ่ม–จบ–วันจ่าย · toast `สร้างงวดปี 2569 ครบ 12 งวดแล้ว`
**And** ปิดงวดหนึ่ง → สถานะ `ปิดแล้ว` + บันทึก `closed_by`/`closed_at` + toast `ปิดงวด <งวด> แล้ว`
**And** เปิดงวดกลับโดยไม่กรอกเหตุผล → บล็อก 422 `BR_REOPEN_REASON_REQUIRED` · กรอกแล้ว → toast `เปิดงวด <งวด> กลับแล้ว` + audit ยังเก็บร่องรอยการปิดครั้งก่อน
**And** กด "สร้างงวดทั้งปี" ซ้ำในปีที่มีงวดปิดแล้ว → 422 `BR_PERIOD_CLOSED_CANNOT_REGENERATE`

### AT-22 — ความถี่รอบบันทึกเวลาแยกจากรอบจ่าย (ST-22 · FN-50 · `[AI-DRAFT]`)
**Given** เปิดฟอร์มรอบเวลาครั้งแรก · **Then** ค่าเริ่มต้นของ "ความถี่รอบบันทึกเวลา" = **"ใช้รอบเดียวกับรอบจ่าย"**
**And** เลือก "รายสัปดาห์" แล้วบันทึก → เก็บแยกจากความถี่รอบจ่าย

### AT-23 — รอบประเมิน (ST-23 · FN-20)
**Given** กรอกรอบ 1 ม.ค.–30 มิ.ย. ช่วงเปิดกรอก 1–15 ก.ค. · **When** บันทึก → สำเร็จ
**And** กรอกช่วงเปิดกรอกก่อนช่วงประเมินเริ่ม → บล็อก `ช่วงเปิดกรอกต้องอยู่หลังหรือคร่อมช่วงประเมิน`

### AT-24 — บล็อกรอบประเมินทับซ้อน (ST-24 · FN-21 · BR-10)
**Given** มีรอบ 1 ม.ค.–30 มิ.ย. 2570 · **When** สร้างรอบ 1 พ.ค.–31 ต.ค. 2570
**Then** บล็อก · `ช่วงวันทับซ้อนกับรอบ “<ชื่อรอบ>”` · 422 `BR_APPRAISAL_OVERLAP`
**And** สร้างรอบเดียวกันแต่คนละปี → สำเร็จ

### AT-25 — ค่ากลาง vs เฉพาะบริษัท (ST-25 · FN-22)
**Given** เลือก "เฉพาะบริษัท" โดยไม่เลือกบริษัทใด · **When** บันทึก → บล็อก `เลือกบริษัทอย่างน้อย 1 บริษัท`
**And** เลือกบริษัทลูก 1 ราย → คอลัมน์ "ขอบเขต" แสดงชื่อบริษัทนั้น

### AT-26 — บริษัทลูกทับค่ากลาง (ST-26 · FN-23 · BR-13) 🔴 P0
**Given** `code` เดียวกันมีทั้งค่ากลาง (shared) และค่าเฉพาะของบริษัท A
**When** `GET /hr-config/resolve?date=…&company_id=<A>`
**Then** คืนค่าของบริษัท A · `resolved_from = "company:<A>"`
**And** `company_id=<B>` (ไม่มีค่าเฉพาะ) → คืนค่ากลาง · `resolved_from = "shared"`

### AT-27 — `applies_to` เป็น hook (ST-27 · FN-30)
**Given** เปิด drawer สร้างค่า · **Then** ช่อง "ขอบเขตการใช้" แสดง "ทั้งบริษัท" **อ่านอย่างเดียว** + มี ⓘ อธิบาย
**And** เรียก API แก้ `applies_to` โดยตรง → 403 `ERR_FIELD_READ_ONLY`

### AT-28 — ปิดใช้โดยไม่ลบถาวร (ST-28 · FN-24/FN-25 · BR-07) 🔴 P0
**Given** อยู่หน้า list ของทุก tab · **Then** **ไม่มีปุ่มลบถาวรที่ใดในหน้า** (ตรวจทุก tab + drawer + modal)
**And** ยิง `DELETE` ไปที่ทุก path ของ feature → **404/405 ทุกเส้น** (ไม่มี DELETE endpoint)
**And** กดปิดใช้แล้วยืนยัน → สถานะ "ปิดใช้" + โน้ต `ปิดใช้แล้ว — เลือกใหม่ไม่ได้` + toast `ปิดใช้แล้ว — ข้อมูลเดิมที่อ้างค่านี้ยังอ่านได้`

### AT-29 — เห็นผลกระทบก่อนปิดใช้ (ST-29 · FN-26 · BR-08) 🔴 P0
**Given** ค่าหนึ่งมี consumer อ้างอยู่ 2 ราย · **When** กดปิดใช้
**Then** modal `ปิดใช้ “<ชื่อค่า>”` แสดง **รายการ feature ที่อ้างอยู่** ก่อนให้ยืนยัน
**And** กรอกเหตุผล < 10 ตัวอักษร → บล็อก `กรอกเหตุผลอย่างน้อย 10 ตัวอักษร`
**And** เรียก `POST …/deactivate` โดยไม่ส่ง `acknowledged_usage=true` → 422 `BR_WHERE_USED_NOT_ACKNOWLEDGED`

### AT-30 — ดูว่าใครใช้ค่านี้ (ST-30 · FN-33)
**Given** เปิด view drawer · **When** เข้า tab "ใครใช้ค่านี้"
**Then** เห็นรายชื่อ consumer พร้อม pill `พร้อมใช้` / `ยังไม่ทำ` และลิงก์
**And** ค่าที่ไม่มีใครอ้าง → `ยังไม่มี feature ใดอ้างค่านี้`
**And** response ของ `API-11` **ไม่มีข้อมูลภายในของ consumer** (มีแค่ชื่อ feature/สถานะ/ลิงก์)

### AT-31 — บล็อกวันมีผลย้อนเข้างวดที่ปิด (ST-31 · FN-19 · BR-04) 🔴 P0
