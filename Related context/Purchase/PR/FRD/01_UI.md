**ERP Context:**

- Header 52px + Page Header (title + ปุ่ม "สร้างคำร้องขอซื้อใหม่")

**Components (canonical):**
- Data Table (`.tbl-compact`, single-line rows) — 9 data cols + 1 action

**States:** Loading (skeleton) · Empty ("ยังไม่มีใบขอซื้อ" + CTA) · Error (retry) · Loaded

### P-02: สร้างใบขอซื้อ (PR Create)

**Purpose:** ฟอร์มสร้าง/แก้ใบขอซื้อ
**Layout Template:** create-drawer (document drawer — slide-in **1290px**, ดู LD-01) — **no breadcrumb (drawer)**
**Steps (3):** ① ข้อมูลทั่วไป · ② รายการสินค้า · ③ แนบไฟล์

**Components:**
- **Step ① ข้อมูลทั่วไป (form-grp 2-col):**
  - วันที่ขอซื้อ (date, default today) · วันที่ต้องการ (date, default today+7)
  - แผนกที่ขอ (select) · **สาขาปลายทาง (รับสินค้า)** (select จาก Branch — บังคับ)
  - ผู้ขอ (employee combobox — แสดง avatar/ชื่อ/ตำแหน่ง, เก็บชื่อ)
  - ผู้ขาย (vendor combobox — optional)
  - section "อ้างอิงงบปลดอายัด" — **แสดงเมื่อ Purchase Config.require_unlock_ref=true** (combobox: code · ชื่อ · งบคงเหลือ + hint tooltip)
- **Step ② รายการสินค้า:** ตาราง line items
  - product picker (combobox — รหัสสั้น—ชื่อ) → autofill ราคา + vat_group
  - หน่วย (select จาก product.units[] — เปลี่ยน→ราคาอัปเดต) · จำนวน · ราคา/หน่วย (แก้ได้) · ส่วนลด% · VAT (mode/อัตรา) · จำนวนเงิน
  - การ์ดสรุป: subtotal · ส่วนลดท้ายบิล (doc) · VAT · WHT card · ยอดรวม
  - แถบเตือน over-budget (เมื่อ Σ PR > งบคงเหลือ)
- **Step ③ แนบไฟล์:** upload list

**Actions:**
| Action | Triggers | Calls (API) |
|---|---|---|
| บันทึกร่าง | save draft | F-PR-API-02 POST (ใหม่) / F-PR-API-04 PUT (แก้) |
| ส่งอนุมัติ | validate + submit | F-PR-API-05 POST /:id/submit |
| เลือกสินค้า | autofill ราคา/หน่วย/VAT | (lookup Product master) |
| เลือกใบปลดอายัด | แสดงงบคงเหลือ + ตรวจ | (lookup Budget Release) |

**States:** validating · over-budget (block submit) · saving · error

**Permissions:** เฉพาะผู้ขอซื้อ (Maker)

### P-03: ดูใบขอซื้อ (PR View)

**Purpose:** ดูรายละเอียด + เอกสาร PDF + สายอนุมัติ
**Layout Template:** view-drawer-tabbed (Doc/Transaction = Pattern G+H+I) — **no breadcrumb (drawer)**
**Tabs (3):** ① รายละเอียด · ② PDF Preview · ③ ลายเซ็น/สายอนุมัติ

**Components:**
- **Tab ① รายละเอียด:** grid ข้อมูลคำร้อง (เลขที่/สถานะ/ปีงบ/ประเภท/ผู้ขอ/แผนก/**สาขาปลายทาง+ที่อยู่**/วันที่/สายเบิก progress) + ตารางรายการ + การ์ดสรุปยอด + route badge (ถ้า approved)
- **Tab ② PDF Preview:** iframe เอกสาร A4 + ปุ่มดาวน์โหลด + เต็มจอ
- **Tab ③ ลายเซ็น:** signature cards = N ชั้นจาก DOA chain (Pattern I) — ชื่อผู้อนุมัติ/ตำแหน่ง/สถานะ/เวลา

**Actions:**
| Action | Triggers | Calls (API) |
|---|---|---|
| อนุมัติ (Approver) | advance DOA | F-PR-API-06 POST /:id/approve |
| ตีกลับ | reject + reason | F-PR-API-07 POST /:id/reject |
| ยกเลิก | cancel | F-PR-API-08 POST /:id/cancel |
| เลือกเส้นทาง (Buyer) | set route | F-PR-API-09 POST /:id/route |
| ดาวน์โหลด PDF | render | F-PR-API-10 GET /:id/pdf |

**Permissions:** ดู = ทุก role · อนุมัติ/ตีกลับ = Approver · route = Buyer · ยกเลิก = Maker (ก่อนอนุมัติ) / Approver (หลังอนุมัติ)

## §1.3 User Journey (Happy Path)

```
ผู้ขอซื้อ เริ่มที่ P-01 → คลิก "สร้างคำร้องขอซื้อใหม่"
  ↓ เปิด P-02 (drawer)
Step① กรอก ผู้ขอ/แผนก/สาขาปลายทาง (+ ใบปลดอายัดถ้า config บังคับ)
  ↓
Step② เพิ่มสินค้า (autofill ราคา/หน่วย/VAT) → ระบบคำนวณยอด + ตรวจเพดานงบ
  ↓ (F-PR-API-02 บันทึกร่าง)
กด "ส่งอนุมัติ" → F-PR-API-05 (validate + Hard Control + DOA resolve)
  ↓ status: draft → pending
ผู้อนุมัติเปิด P-03 → Tab ลายเซ็น → อนุมัติ (F-PR-API-06)
  ↓ DOA chain ครบ → status approved + emit procurement.pr_linked
Buyer เปิด P-03 → เลือกเส้นทาง (F-PR-API-09): cp หรือ po_direct
  ↓
[outcome: PR approved + route set → ส่งต่อ CP/PO]
```

### Branch: Reject
```
pending → ผู้อนุมัติ "ตีกลับ" (F-PR-API-07, require reason) → rejected
  → ผู้ขอแก้ → rejected → draft → ส่งใหม่
```
### Branch: Over-budget
```
Step② Σ PR + ใบนี้ > งบคงเหลือ → แถบเตือน + block "ส่งอนุมัติ"
  → ลดยอด / เปลี่ยนใบปลดอายัด → ปลดล็อก
```

## §1.6 Empty States & Errors (UI)

| State | UI behavior |
|---|---|
| No data | "ยังไม่มีใบขอซื้อ" + CTA สร้าง |
| over-budget | แถบแดง "ยอดรวม PR เกินงบคงเหลือ" + block submit |
| API 403 | "ไม่มีสิทธิ์ดำเนินการ" |
| API 409 (stale) | "ข้อมูลถูกแก้โดยผู้อื่น — โหลดใหม่" |
| API 500 | "เกิดข้อผิดพลาด — ลองใหม่" + retry |
