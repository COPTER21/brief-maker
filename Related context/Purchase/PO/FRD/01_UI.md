## §1.2 P-01 PO List

**Table columns (1 บรรทัด/แถว):** เลขที่ PO · วันที่ · ผู้ขาย (ชื่อ+id inline) · อ้างอิง (PR·CP inline) · สถานะเอกสาร · รับสินค้า · การจ่าย · ลายเซ็น (progress x/3 + bar) · ยอดรวม · ⋮

## §1.3 P-02 PO Create (Wizard 5 ขั้น)
Drawer 920px (document) · footer ตาม Drawer Button Contract (Rule #31): step 1 = "ยกเลิก" ghost ซ้าย · step>1 = "ย้อนกลับ" · spacer · "บันทึกร่าง" · primary "ถัดไป/สร้าง PO" ขวา

| Step | Title | Components | Notes |
|---|---|---|---|
| 1 | เลือกแหล่งที่มา | source combobox (PR/CP) + hint icon `i` (tooltip 3 โหมด Purchase Config, Rule #33) | ไม่ required (ตาม config); CP → ตารางผู้ชนะ; PR/ไม่เลือก → note "เลือกผู้ขายขั้นต่อไป" |
| 1 | ตารางผู้ชนะ (CP เท่านั้น) | table: ผู้ขาย · สถานะ PO · จำนวนรายการ · มูลค่าชนะ · ปุ่ม "เลือก" | ปุ่ม disable ถ้า po_status=CREATED (E01) |
| 2 | ข้อมูลหลัก PO | วันที่ PO · วันที่คาดว่าจะได้รับ · **ผู้ขาย** (CP=ล็อก / PR-direct=combobox) · ผู้จัดซื้อ (combobox) · payment term (select) · หมายเหตุ | vendor required ก่อนพ้น step (VR01) |
| 3 | รายการสินค้า | line table: # · สินค้า(ชื่อ) · จำนวน · หน่วย · ราคา/หน่วย · **ส่วนลด (input + toggle ฿/% ขวา)** · ภาษี (badge none/add/included) · จำนวนเงิน · ⋮ ; + ปุ่มเพิ่มรายการ ; ส่วนลดท้ายบิล ; WHT toggle | สรุปยอด real-time; ≥1 รายการ (VR04) |
| 4 | เอกสารแนบ | upload list (optional) | — |
| 5 | ตรวจสอบและยืนยัน | สรุป header + รายการ + ยอด + ผู้ขาย/ผู้จัดซื้อ | ปุ่ม "สร้าง PO" → submit |

**Vendor field logic (key):**
- `source_cp_no` set → ช่องผู้ขาย = display ล็อก (lock icon) จากผู้ชนะ
- PR-only / ไม่มี source → ช่องผู้ขาย = combobox เลือกจาก Vendor Master (active); เลือกแล้ว set payment_term default + (PR) build lines จาก PR

## §1.4 P-03 PO View (Tabbed)
Drawer 920px · footer: "ปิด" secondary only · header actions: secondary→primary→danger→divider→X
| Tab | Content |
|---|---|
| รายละเอียด (detail) | ข้อมูลเอกสาร → สถานะ 3 แกน (+progress) → เอกสารอ้างอิง → ผู้ขาย/ผู้จัดซื้อ → เงื่อนไขการชำระเงิน (code·name·summary·due) → หมายเหตุ → สรุปยอด → รายการสินค้า |
| เอกสาร (PDF) | preview PO PDF (รูปแบบภาษีตาม PO) — 1 ตัวอย่าง (Pattern G) |
| ลายเซ็น (signature) | สาย Maker/Checker/Approver + สถานะลงนาม (Pattern I) |

**Header actions ตาม status_doc:** draft → แก้ไข/ส่งอนุมัติ · pending → อนุมัติ/ตีกลับ/ปฏิเสธ (Approver) · approved → พิมพ์ PDF/ยกเลิก

## §1.5 Journey (สรุป)
สร้าง: เปิด drawer → (เลือก source) → เลือกผู้ขาย → กรอกข้อมูล+รายการ → ตรวจสอบ → submit (pending)
อนุมัติ: เปิด View → tab รายละเอียด → อนุมัติ (DoA tier) → approved + ออกเลข + PDF
> รายละเอียด COSO ต่อ step → BRD §5 / 03_LOGIC applyStatusTransition
