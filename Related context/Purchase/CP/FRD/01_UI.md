## §1.2 Per-Page Detail

### P-01: รายการ CP (List)

**Purpose:** จุดเข้าหลัก — ดู/ค้นหา/กรอง CP ทั้งหมด + เข้าสร้างใหม่
**Layout Template:** Pattern A (List + Drawer)

**ERP Context:**
- Sidebar menu active: "เปรียบเทียบราคา (CP)" (กลุ่มการจัดซื้อ)
- Breadcrumb: การจัดซื้อ > เปรียบเทียบราคา (CP)
- Header 52px · Sidebar 232px

**Components (canonical):**
- Page Header (title + subtitle) + Action Toolbar (ปุ่ม ส่งออก CSV + สร้าง)
- Filter Bar: search input (เลขที่ CP / ผู้จัดทำ / อ้างอิง PR) + status select + ปุ่มรีเซ็ต
- Data Table (`tbl tbl-compact`): sortable headers, `tbl-name` / `tbl-mono` (เลขที่) / `tbl-num` (ยอด) + status pill
- Pagination (info + prev/next)
- Row menu (more-vertical): ดู / ส่งออก

**Table columns:** เลขที่ CP · วันที่ · อ้างอิง PR · ผู้จัดทำ · จำนวนรายการ · จำนวนผู้ขาย · จำนวน PO · มูลค่าผู้ชนะ · สถานะ

**Actions:**
| Action | Triggers | Calls (API) |
|---|---|---|
| Click row / ดู | เปิด View drawer | navigate #/view/:id → F-CP-001-API-02 |
| Click "สร้าง" | เปิด Wizard | navigate #/create |
| Click "ส่งออก CSV" | ดาวน์โหลด CSV | F-CP-001-API-09 (client-side Blob ใน prototype) |
| เปลี่ยน filter/search/sort | refresh table | F-CP-001-API-01 |
| เปลี่ยนหน้า (pagination) | refresh table | F-CP-001-API-01 |

**States:** Loading (skeleton) · Empty (CTA สร้างใบแรก) · Error (retry) · Loaded

**Permissions:** buyer (สร้าง/ดู/ส่งออก) · proc_manager/approver/finance (ดู/ส่งออก)

### P-02: สร้าง CP (Wizard — 4 ขั้น)

**Purpose:** สร้างใบเปรียบเทียบราคาใหม่ตั้งแต่อ้าง PR จนแยก PO
**Layout Template:** Pattern B (Wizard Drawer 1290px) — stepper 4 ขั้น + footer contract (Iron Rule #31)

**Stepper:** (1) ข้อมูลทั่วไป · (2) ผู้ขายที่เทียบ · (3) เปรียบเทียบราคา · (4) สรุป + แยก PO

**Step 1 — ข้อมูลทั่วไป (stepGeneral):**
- วันที่ CP (date)
- ผู้จัดทำ — searchable combobox (employee master): พิมพ์ค้นหา, avatar initials, ↑↓ Enter เลือก, Esc ปิด
- อ้างอิง PR — รายการ PR แบบ 2 บรรทัด single-select (`.pr-row`): บรรทัด 1 = เลขที่ PR · วันที่ · pill approved · ผู้ขอ · แผนก · สาขา + ยอดเงินขวา; บรรทัด 2 = N รายการ + ชื่อสินค้า
- เลือก PR → ดึงรายการสินค้า (pullLines) เข้า step 3

**Step 2 — ผู้ขายที่เทียบ (stepVendors):**
- กล่อง "เลือกแล้ว" (chips ผู้ขายที่เลือก + ลบได้)
- Toolbar: search ชื่อผู้ขาย + filter dropdown (ทั้งหมด / เงินสด / เครดิต)
- Grid การ์ดผู้ขาย (vcard): เลือกได้สูงสุด 3 (PURCHASE_CONFIG.cp_max_vendors), ต้อง ≥ 2
- เพิ่มผู้ขาย → ดึงราคา preset จาก price list มาเติม column ใหม่ (applyPriceList)

**Step 3 — เปรียบเทียบราคา (stepMatrix):**
- ตาราง matrix (`table.cmp`): แถว = สินค้า (ชื่อ+รหัส+PR ต้นทาง / จำนวน+หน่วยขวา), คอลัมน์ = ผู้ขาย
- เซลล์ = ช่องราคา (`.cmp-price-inp`, ฿ prefix) **pre-filled จาก price list แก้ไขได้** + ป้าย "ต่ำสุด" (ราคาต่ำสุดของ line) + ปุ่ม **เลือกผู้ชนะ** (toggle teal)
- tfoot: ผลรวมต่อผู้ขาย
- ปุ่ม: "เติมราคา price list" (เติมเฉพาะช่องว่าง) + "เลือกอัตโนมัติ (ราคาต่ำสุด)" + pill นับ "เลือกผู้ชนะแล้ว N/total"

**Step 4 — สรุป + แยก PO (stepSplit):**
- po-summary 3 stat + po-card ต่อผู้ขายที่ชนะ พร้อมตารางรายการ + subtotal

**Footer (Iron Rule #31):** ยกเลิก (ghost ซ้าย) → ย้อนกลับ (secondary) → spacer → บันทึกร่าง (secondary) → ถัดไป/สร้าง (primary ขวา)

**Actions:**
| Action | Triggers | Calls (API) |
|---|---|---|
| ถัดไป (step1→2) | validate pr_refs ≥ 1 + pullLines | — (client) / F-CP-001-API-01 (PR lookup upstream) |
| ถัดไป (step2→3) | validate vendors ≥ 2 + applyPriceList | — (price list = F-CP-001-API ref vendor-price-list) |
| ถัดไป (step3→4) | autoWinners (เติม winner ที่ว่าง) | — (client) |
| บันทึกร่าง | save draft | F-CP-001-API-03 (create) / F-CP-001-API-04 (update) |
| สร้าง (step4) | save pending/draft | F-CP-001-API-03 |

**States:** validation toast (ขาด PR / ผู้ขาย < 2) · re-open repaint (preserve scroll+focus)

**Permissions:** buyer only

### P-03: ดู CP (View Drawer — 4 แท็บ)

**Purpose:** ดูรายละเอียด CP + แยก PO + เอกสาร PDF + ลายเซ็น + ดำเนินการตามสถานะ
**Layout Template:** Pattern C (Tabbed Drawer 1290px) — `.tabs/.tab` (เหมือน F-PR-001 เป๊ะ)

**Tab bar:** รายละเอียด (file-text) · แยก PO (receipt) · PDF Preview (file) · ลายเซ็น (pen-tool) — landing = รายละเอียด

**Tab 1 — รายละเอียด (viewDetail):** info grid — เลขที่ CP / สถานะ / วันที่ / ผู้จัดทำ / อ้างอิง PR / จำนวนรายการ-ผู้ขาย-PO / มูลค่าผู้ชนะ

**Tab 2 — แยก PO (viewPoSplit):**
- po-summary 3 stat: จำนวน PO ที่ต้องแยก · รายการรวม · **สร้าง PO แล้ว N/total** (accent)
- po-card ต่อผู้ขาย: หัว (index avatar — เทาถ้ายังไม่สร้าง / ชื่อผู้ขาย / N รายการ · รวม ฿sub) + badge ขวา **สร้างแล้ว · po_id (teal)** หรือ **ยังไม่สร้าง (warning)**
- **ตารางรายการในแต่ละ PO:** สินค้า (+รหัส) · จำนวน+หน่วย · ราคา/หน่วย · รวม + แถวรวมใบนี้
- empty state สำหรับ draft

**Tab 3 — PDF Preview (viewDocument):**
- toolbar: ป้ายชื่อ "ใบเปรียบเทียบราคา {cp_no} · A4 · 1/1" + hint-i + ปุ่ม **ดาวน์โหลด** (`<a download>`) + **เต็มจอ** (เปิดหน้าต่างใหม่)
- iframe แสดง PDF จริง (`src=...#view=FitH`, สูง 1000px) — เอกสารฝัง base64 (build-time), runtime bind จาก F-CP-001-API-10

**Tab 4 — ลายเซ็น (viewApprove):**
- การ์ดเต็มแถว 3 ช่อง (เหมือน F-PR-001): ผู้จัดทำ / ผู้ตรวจสอบ / ผู้อนุมัติ
- แต่ละช่อง: ไอคอนวงกลม (check เขียว / clock เทา), role uppercase + pill (ลงนามแล้ว/รอลงนาม), ชื่อ, ตำแหน่ง, "ลงนามเมื่อ {date}" หรือปุ่ม ลงนาม
- สถานะผูกกับ record: draft = เซ็นแค่ผู้จัดทำ · pending = +ผู้ตรวจสอบ · approved/awarded = ครบ 3
- ผู้ตรวจสอบ/ผู้อนุมัติ = resolved จาก DOA (mock placeholder)

**Footer per status:**
| Status | Footer action | Calls |
|---|---|---|
| draft | ส่งเซ็น (สายอนุมัติ DOA) | F-CP-001-API-05 submit → pending |
| pending | ตีกลับ (danger) + อนุมัติ (primary) | F-CP-001-API-07 reject / F-CP-001-API-06 approve |
| approved | ออกใบสั่งซื้อ (N ใบ) | F-CP-001-API-08 award → awarded + po_id |
| awarded | (อ่านอย่างเดียว) | — |

**Permissions:** buyer (submit) · approver (approve/reject) · proc_manager (award) · ทุก role ดูได้

## §1.3 User Journey (Happy Path)

```
Buyer เริ่มที่ P-01 (รายการ CP)
  ↓ คลิก "สร้าง" → P-02 Wizard
Step 1: เลือกวันที่ + ผู้จัดทำ + อ้าง PR (approved, route=cp)  → pullLines
  ↓
Step 2: เลือกผู้ขายที่เทียบ ≥ 2 ราย  → applyPriceList (เติมราคา preset)
  ↓
Step 3: ตรวจ/แก้ราคาแต่ละผู้ขาย + เลือกผู้ชนะรายรายการ (default ต่ำสุด)
  ↓
Step 4: ดูสรุป + การแยก PO  → "สร้าง" (F-CP-001-API-03) → status=draft/pending
  ↓
P-03 View → tab ลายเซ็น → "ส่งเซ็น" (API-05) → status=pending
  ↓ (DOA chain)
Approver: tab ลายเซ็น → "อนุมัติ" (API-06) → status=approved
  ↓
Proc Manager: tab แยก PO → "ออกใบสั่งซื้อ (N ใบ)" (API-08 award)
  → F-PO-001 สร้าง PO + ส่ง po_id กลับ → status=awarded, po_split.po_id เติมครบ
```

### Branch: ตีกลับ (reject)
```
pending → Approver "ตีกลับ" (API-07) → status=draft + reject_reason → Buyer แก้แล้วส่งใหม่
```

## §1.6 Empty States & Errors (UI)

| State | UI behavior |
|---|---|
| ไม่มี CP | "ยังไม่มีใบเปรียบเทียบราคา — สร้างใบแรก" CTA |
| ไม่มี PR ให้อ้าง (step 1) | "ไม่มีใบขอซื้อที่พร้อมเปรียบเทียบ (approved + route=cp)" |
| ผู้ขาย < 2 (step 2) | toast warning "ต้องเลือกผู้ขายอย่างน้อย 2 ราย" |
| ยังไม่เลือกผู้ชนะครบ | pill เตือน "เลือกผู้ชนะแล้ว N/total" (warning) |
| API 403 | "ไม่มีสิทธิ์ดำเนินการ" |
| API 409 (stale) | "ข้อมูลถูกแก้โดยผู้อื่น — โหลดใหม่" |
