## §1.2 Per-Page Detail

### P-01: GL Posting Group — main (dual-tab list)

**Purpose:** Single entry point for both registries; Finance Lead searches/filters/bulk-acts/imports/exports either tab.
**Pattern:** A — list-view (×2 via tab switch)

**ERP Context:**
- Sidebar menu active: "GL Posting Group" (under โมดูล "การเงิน")
- Breadcrumb: (none rendered on this screen — page title only, `.ph-title` = "GL Posting Group")
- Shell-bar: 52px white (per v7 CI tokens)

**Components used (as-built, canonical names):**
- Tab bar (`.tabbar`/`.tab-btn`) — "Posting Groups" / "General Posting Setup", each with a count badge
- Stat cards (`.stats`, 4 cards) acting as **quick status filters**: ทั้งหมด / ใช้งาน / ไม่ใช้งาน / ร่าง — clicking toggles `state.filters.status`
- Bulk action bar (`.bulkbar`, dark, appears only when ≥1 row selected): ใช้งาน / ไม่ใช้งาน / ร่าง (bulk status) + ลบ (bulk delete) + ยกเลิก
- Card toolbar: title + "ส่งออก CSV" / "นำเข้า CSV" (btn-secondary) / "เพิ่ม Posting Group"|"เพิ่ม Setup" (btn-primary)
- Filter bar: search input (`.input-search`), `kind` search-dropdown filter (tab1 only, master-combobox pattern #94), status `<select>`, "ล้าง" reset button (shown only when a filter is active)
- Data table with sticky thead (Iron Rule #96), checkbox column, row-click opens view drawer, inline row action (pencil = edit)
- Table footer: descriptive caption + "แสดง N จาก M [กลุ่ม|setup]"
- Empty state (`.empty`) when filtered rows = 0: "ไม่พบรายการที่ตรงกับเงื่อนไข"

**Table columns:**
- Tab 1 (Posting Groups): checkbox · รหัส · ชื่อกลุ่ม (TH+EN) · ประเภท (pill) · บัญชีที่ผูก (COA, chip row) · สถานะ (pill) · จัดการ (edit icon)
- Tab 2 (General Posting Setup): checkbox · กลุ่มธุรกิจ (badge) · กลุ่มสินค้า (badge) · บัญชีรายได้ · บัญชีซื้อ · บัญชีต้นทุน · สถานะ (pill) · จัดการ (edit icon)

**Actions on this page:**

### P-02: Specific Posting Group — create/edit drawer

**Purpose:** Create a new `kind`→account mapping, or edit an existing one (subject to R05/IR-PG-01 locks).
**Pattern:** B — drawer 920px, single-step form (conditional field sections, no Stepper)

**Components used:**
- Drawer header: avatar icon (kind icon when editing, `plus` when creating) + title "เพิ่ม Posting Group" / "แก้ไข Posting Group" + subtitle (code when editing) + close (X)
- Section "ประเภทกลุ่ม": `kind` master-combobox (create mode, 4 options) — **on edit, rendered as a static disabled-looking box, never a dropdown** (R05 — see §1.4 below)
- Section "ข้อมูลกลุ่ม": `code` (text input, uppercase-on-type; **replaced by a static locked `<div>` + `.lock-tag` "ล็อก — มีการบันทึกบัญชีแล้ว" when editing a record with `used>0`** — IR-PG-01), `name_th` (text, required), `name_en` (text, optional)
- Section "บัญชีที่ผูก (จากผังบัญชี)": conditional account field(s) by `kind` — 1 field for bank, 2 fields for vendor/inventory/customer — each a COA master-combobox filtered by account type (see 02_API §2.5)
- Info note: "บัญชีทั้งหมดอ้างอิงจาก ผังบัญชี (F-COA-001) — เลือกได้เฉพาะบัญชีลงรายการได้ (leaf)"
- Status `<select>`: ร่าง / ใช้งาน / ไม่ใช้งาน — always editable, no lock, defaults to "ใช้งาน" on create (as-built default; BRD §6.2 says "no forced default" — see 05_RULES note on this nuance)
- Drawer footer: "ยกเลิก" (ghost) ··· "ยืนยันสร้าง" / "บันทึกการแก้ไข" (primary, shows `loader-2` spin + "กำลังบันทึก…" while busy — Iron Rule #44 submitting state)

**Conditional account fields by kind (observed in HTML):**
| kind | Field 1 (required) | Field 2 (optional/conditional) |
|---|---|---|
| vendor (เจ้าหนี้) | บัญชีเจ้าหนี้ (AP control) — COA type filter `liability` | บัญชีภาษีซื้อ (Input VAT) — COA type filter `asset` |
| inventory (สินค้าคงคลัง) | บัญชีสินค้าคงคลัง — COA type filter `asset` | บัญชี Interim (GR/IR) — COA type filter `asset, liability` |
| bank (ธนาคาร) | บัญชีเงินฝาก (GL) — COA type filter `asset` | (none) |
| customer (ลูกหนี้) | บัญชีลูกหนี้ (AR control) — COA type filter `asset` | บัญชีภาษีขาย (Output VAT) — COA type filter `liability` |

**onKindChange behavior (R07):** selecting a different `kind` (create mode only — locked in edit) clears **all** account fields already entered, keeping only `code`/`name`/`name_en`. Confirmed in HTML `onKindChange()`.

**Actions:**
| Action | Triggers | Calls (API) |
|---|---|---|
| Change kind (create only) | Re-render account fields for new kind, clear old account values | F-PG-API-02 (deferred to submit) |
| Submit | Client validates (required, dup code, required primary account) → server validates (R01-R07) → save | F-PG-API-02 (create) / F-PG-API-04 (edit) |
| Cancel/X | Close drawer, discard form state | — |

**States:** default form / field-invalid (red border + inline error) / busy-submitting (disabled button + spinner)

## §1.3 User Journey (Happy Path — Create Specific Posting Group)

```
Finance Lead lands on P-01 (tab='groups' default)
  ↓ click "เพิ่ม Posting Group"
P-02 opens — kind picker empty
  ↓ select kind (e.g. vendor) → account fields render for vendor
  ↓ fill code/name/accounts/status
  ↓ click "ยืนยันสร้าง"
  ↓ (F-PG-API-02 POST /gl/posting-groups)
Record created — used=0, DOA placeholder×4 null, toast "สร้าง Posting Group แล้ว"
  ↓ drawer closes, P-01 list refreshes
```

### Branch: Edit a `used>0` record (IR-PG-01)
```
Click row on P-01 → P-04 view drawer → click "แก้ไข" → P-02 edit drawer
  ├─ code field shown as static locked div + lock-tag (IR-PG-01)
  ├─ kind field shown as static locked div (R05 — always, independent of used)
  ├─ name/account/status fields fully editable
  ├─ attempt to type a different code anyway → client can't (field is not an input)
  └─ Submit with name/account/status changed → F-PG-API-04 → save succeeds, code unchanged
```

### Branch: Status change (no approval, BR-06)
```
From P-04/P-05 "เปลี่ยนสถานะ" menu OR P-01 bulk bar
  → pick new status → immediate save, no confirmation step, no approver
  → toast "เปลี่ยนสถานะเป็น [label] แล้ว"
```

## §1.6 Empty States & Errors (UI)

| State | UI behavior (as-built) |
|---|---|
| No rows after filter | "ไม่พบรายการที่ตรงกับเงื่อนไข" / "ลองปรับคำค้นหรือล้างตัวกรอง" (`.empty`) |
| Validation error on submit | Field gets `.is-invalid` (red border) + inline `.field-error` text; toast on blocking errors (dup code, dup combination, IR-PG-01 lock violation) |
| Import row invalid | Row highlighted `.pill.is-inactive` with first error shown, full list on hover `title` |
| API error (backend, not yet in HTML mock) | **Must be added at implementation** — HTML mock never fails network calls; backend team must add generic error toast "เกิดข้อผิดพลาด กรุณาลองใหม่" (per microcopy) for 500s, and a permission-denied state for Auditor role hitting mutation endpoints |
