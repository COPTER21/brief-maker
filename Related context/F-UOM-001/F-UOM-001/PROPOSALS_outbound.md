## E · ข้อเสนอปรับตัว skill — 3 ข้อ

### E-1 · `microcopy.md §5` — ชุดสีของสถานะ 3 ค่าไม่มีในตารางกลาง

| | |
|---|---|
| **ตารางกลางกำหนด** | *ใช้งาน* → ฟ้า · *ปิดใช้งาน* → เทา · *ร่าง* → เทา |
| **กลุ่มงานข้อมูลหลักใช้จริง** | *ใช้งาน* → **เขียว** · *ไม่ใช้งาน* → **เหลือง/ส้ม** · *ร่าง* → เทา |
| **ใครใช้ชุดนี้แล้วบ้าง** | `F-PDM-001` · `F-CAT-001` · **`F-UOM-001`** — ทั้ง 3 ตัวใช้ชุดสถานะ 3 ค่าเดียวกัน |
| **ทำไมไม่ตามตารางกลาง** | เป้าหมายของกฎคือ *"สถานะเดียว = สีเดียวทุกไฟล์"* — การตามพี่น้องในกลุ่มงานเดียวกันรักษาเป้าหมายนั้นไว้ได้ดีกว่าการตามตารางแล้วกลายเป็นไฟล์เดียวที่ต่าง |
| **ที่เสนอ** | เพิ่มแถวชุด **3 สถานะของข้อมูลหลัก** เข้าตารางกลางเป็นชุดที่ 2 อย่างเป็นทางการ |

### E-2 · Rule #32.5 — บังคับให้การนำเข้ามีโหมดล้างของเดิม ซึ่งขัดกติกากลาง

| | |
|---|---|
| **กฎว่า** | การนำเข้าต้องมี 2 โหมดเสมอ: ล้างของเดิมแล้วโหลดใหม่ + รวมข้อมูลด้วยรหัส |
| **ทำไมทำไม่ได้** | โหมดล้างของเดิม **ขัด Global Contract #7 โดยตรง** · และเนื้อธุรกิจสั่งว่ารหัสซ้ำ = **บล็อก** ไม่ใช่ทับ |
| **ใครทำแบบเดียวกันแล้ว** | `F-PDM-001` ตัดสินเหมือนกัน |
| **ที่เสนอ** | เพิ่มข้อยกเว้น: *"ข้อมูลหลักที่ผูกกับ Global Contract #7 ใช้โหมดเพิ่มทีละแถวพร้อมการตรวจได้ โดยไม่ต้องมีโหมดล้างของเดิม"* |

### E-3 · Rule #62.2 ชนกับ Rule #95 — ทำให้เมนู portal จมได้

Rule #62.2 บังคับให้เมนูลอยทุกตัวประกาศ `z-index` ของตัวเอง (ไม่งั้นตัวตรวจตก)
แต่การประกาศนั้น**ทับค่าที่ Rule #95 ให้มา** เพราะ specificity เท่ากันและ page CSS อยู่หลัง → **เมนูจมใต้ลิ้นชัก**

**ที่เสนอ:** ให้ `.menu-fixed` ของชุดพื้นฐานทนต่อการทับ (ใช้ `!important` หรือยกระดับ specificity)
→ **ลงทะเบียนไว้ที่ `_SHARED/DESIGN_SYSTEM_PENDING.md` แล้ว** (ดูกลุ่ม F)
