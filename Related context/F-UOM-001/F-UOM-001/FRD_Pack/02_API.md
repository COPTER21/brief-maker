# 02_API — F-UOM-001 ทะเบียนหน่วยวัด

> ต้นแบบใช้ข้อมูลจำลองในหน่วยความจำ — เอกสารนี้คือ **สัญญาที่ระบบจริงต้องทำให้ได้**
> ทุก endpoint ต้องกันสิทธิ์ที่ฝั่ง server ด้วย **ไม่ใช่พึ่งการซ่อนปุ่มบนจอ**

## §2.2 โครงข้อมูลหน่วยวัด

```jsonc
{
  "id":         "U-001",           // ระบบกำหนด
  "code":       "PCS",             // ห้ามซ้ำ (ไม่สนตัวพิมพ์)
  "name_th":    "ชิ้น",             // บังคับ
  "name_en":    "Piece",
  "symbol":     "pcs",             // เว้นว่าง = ใช้รหัสตัวพิมพ์เล็ก
  "category":   "count",           // 1 ใน 6 ค่า
  "status":     "active",          // draft | active | inactive
  "used":       128,               // อ่านอย่างเดียว — มาจากทะเบียนสินค้า

  "created_by": "wipa",  "created_at": "2025-01-04T09:00:00+07:00",
  "updated_by": "wipa",  "updated_at": "2025-06-12T14:30:00+07:00",

  // ที่ว่างรอเชื่อมระบบสายอนุมัติในอนาคต — ต้องมีอยู่จริงและเป็น null เสมอ
  "approver_role": null, "approved_by": null,
  "approved_at":   null, "approval_chain": null
}
```

**ข้อบังคับ**

| # | ข้อ |
|:--:|---|
| 1 | `used` เป็น **อ่านอย่างเดียว** — ถ้ามีใครส่งค่านี้มาใน `POST`/`PATCH` ให้เพิกเฉย ไม่ต้องคืนข้อผิดพลาด |
| 2 | ที่ว่างรอสายอนุมัติ 4 ตัว **ต้องมีอยู่จริงในผลลัพธ์และเป็น `null`** — ห้ามตัดออกเพราะยังไม่ได้ใช้ |
| 3 | **ห้ามมี field ใดที่เกี่ยวกับตัวคูณแปลง/ความละเอียด/หน่วยฐาน** ในโครงนี้เด็ดขาด |

## §2.3 `GET /uom` — อ่านรายการ

**พารามิเตอร์**

| ชื่อ | ชนิด | ค่าตั้งต้น | ความหมาย |
|---|---|---|---|
| `q` | ข้อความ | — | ค้นหาใน **รหัส · ชื่อไทย · ชื่ออังกฤษ · สัญลักษณ์** (ไม่สนตัวพิมพ์) |
| `category` | ข้อความ | `all` | กรองตามหมวด |
| `status` | ข้อความ | `all` | กรองตามสถานะ |
| `sort` | ข้อความ | `code` | `code` · `name_th` · `category` · `used` · `status` |
| `dir` | ข้อความ | `asc` | `asc` · `desc` |
| `page` | จำนวนเต็ม | `1` | หน้าที่ต้องการ |
| `page_size` | จำนวนเต็ม | **`25`** | **ค่าตั้งต้นอ่านจาก config — ห้ามฝังเลข 25 ในโค้ด** |
| `active_only` | จริง/เท็จ | `false` | **`true` = คืนเฉพาะสถานะ *ใช้งาน*** — ปลายทางใช้ค่านี้ (ดู §2.9) |

**ผลลัพธ์**

```jsonc
{
  "records": [ /* โครงตาม §2.2 */ ],
  "total": 35, "page": 1, "page_size": 25, "total_pages": 2,
  "summary": { "all": 35, "active": 29, "inactive": 4, "draft": 2 }
}
```

> `summary` ต้องนับจาก **ทะเบียนทั้งหมด ไม่ใช่หน้าปัจจุบัน** — การ์ดสรุปบนจอต้องแสดงตัวเลขทั้งระบบเสมอ

## §2.4 `POST /uom` — สร้าง

**คำขอ:** `code`(ไม่บังคับ) · `name_th`(**บังคับ**) · `name_en` · `symbol` · `category`(**บังคับ**) · `status`(ตั้งต้น `active`)

**ลำดับการทำงาน**

1. ตรวจ `name_th` ไม่ว่าง → ไม่ผ่านคืน `VALIDATION_ERROR`
2. ถ้า `code` ว่าง → **ออกรหัสอัตโนมัติ** (ดู `03_LOGIC §3.1`)
3. ตรวจรหัสซ้ำแบบไม่สนตัวพิมพ์ → ซ้ำคืน `CODE_DUPLICATE`
4. ถ้า `symbol` ว่าง → ใช้รหัสตัวพิมพ์เล็ก
5. เขียนพร้อม `created_*` / `updated_*` และที่ว่างรอสายอนุมัติเป็น `null`

**สำเร็จ:** `201` + โครงตาม §2.2

## §2.5 `PATCH /uom/{id}` — แก้ไข

แก้ได้ทุก field ใน §2.2 ยกเว้น `id` · `used` · ที่ว่างรอสายอนุมัติ

| ข้อควรระวัง | รายละเอียด |
|---|---|
| **ตรวจรหัสซ้ำต้องยกเว้นตัวเอง** | เงื่อนไขต้องมี `id ≠ ตัวที่กำลังแก้` ไม่งั้นกดบันทึกโดยไม่เปลี่ยนรหัสจะถูกตีว่าซ้ำ |
| แก้ได้ทุกสถานะ | ไม่มีสถานะไหนที่ล็อกการแก้ |
| อัปเดตผู้แก้/เวลา | ทุกครั้ง |

> ⚠️ **ขึ้นกับ `OQ-02`** — ถ้าตัดสินให้ล็อกรหัสเมื่อมีสินค้าใช้อยู่ ต้องเพิ่มการตรวจ:
> `used > 0` และ `code` เปลี่ยน → คืน `CODE_LOCKED`

## §2.6 `PATCH /uom/status` · `POST /uom/delete` — ทำหลายรายการ

### เปลี่ยนสถานะ

```jsonc
// คำขอ
{ "ids": ["U-001","U-002"], "status": "inactive" }
// ผลลัพธ์
{ "changed": 2, "unchanged": 0 }   // unchanged = ตัวที่สถานะเดิมตรงกับที่สั่งอยู่แล้ว
```

### ลบหลายรายการ

```jsonc
// คำขอ
{ "ids": ["U-001","U-005","U-011"] }
// ผลลัพธ์
{
  "deleted": 2, "skipped": 1,
  "skipped_items": [ { "id":"U-001", "code":"PCS", "reason":"IN_USE", "used":128 } ]
}
```

> 🔴 **ต้องสำเร็จบางส่วนได้** — ตัวที่ `used > 0` ถูกข้าม แต่ตัวอื่นลบสำเร็จ
> **ห้ามคืนข้อผิดพลาดทั้งก้อนเพราะมีตัวเดียวลบไม่ได้**
> ถ้าไม่มีตัวไหนลบได้เลย → คืน `200` พร้อม `deleted: 0` (ไม่ใช่ error) ให้จอไปปิดปุ่มเอง

## §2.7 `POST /uom/import` — นำเข้า

**2 โหมด — บังคับ**

| โหมด | ทำอะไร | เขียนข้อมูลมั้ย |
|---|---|:--:|
| `validate` | ตรวจทุกแถวแล้วคืนผล | ❌ |
| `apply` | เขียนเฉพาะแถวที่ผ่าน | ✅ |

```jsonc
// ผลของโหมด validate
{
  "total": 5, "valid": 3, "invalid": 2,
  "rows": [
    { "row":1, "code":"TON", "name_th":"ตัน", "category":"ชั่งน้ำหนัก", "status":"ใช้งาน", "error":null },
    { "row":2, "code":"SET", "name_th":"ชุด", "category":"นับจำนวน",   "status":"",       "error":null,
      "resolved_status":"draft" },
    { "row":4, "code":"PCS", "name_th":"ชิ้น (ซ้ำ)", "category":"นับจำนวน", "status":"ใช้งาน",
      "error":"CODE_DUPLICATE" },
    { "row":5, "code":"BAG", "name_th":"ถุง", "category":"นับจำนวน", "status":"พร้อมใช้",
      "error":"BAD_STATUS" }
  ]
}
```

**กติกาของไฟล์**

| # | ข้อ |
|:--:|---|
| 1 | คอลัมน์: `code` · `name_th` · `name_en` · `symbol` · `category` · `status` |
| 2 | **อ่านตามชื่อหัวคอลัมน์ ไม่ใช่ตำแหน่ง** — สลับลำดับได้ |
| 3 | `category` กรอกเป็น **ชื่อไทย** แล้วระบบแปลงเป็นค่าในระบบ |
| 4 | `status` เว้นว่าง = **ร่าง** |
| 5 | ตรวจรายแถว — แถวผิดข้าม **ไม่ล้มทั้งไฟล์** |
| 6 | ไฟล์ต้องอ่านแบบ UTF-8 · ไฟล์ที่ระบบสร้างต้องมีเครื่องหมายนำหน้าเพื่อให้ Excel เปิดภาษาไทยได้ |

**รหัสข้อผิดพลาดรายแถว:** `REQUIRED` · `BAD_CATEGORY` · `BAD_STATUS` · `CODE_DUPLICATE`

## §2.8 สิทธิ์ + รหัสข้อผิดพลาด

| Endpoint | ต้องมีสิทธิ์ | ไม่มีสิทธิ์ |
|---|---|---|
| A-01 · A-02 · A-08 · A-09 · A-10 | `uom.read` | `403 FORBIDDEN` |
| A-03 · A-04 · A-05 · A-06 · A-07 | `uom.manage` | `403 FORBIDDEN` |

| รหัส | HTTP | เมื่อไหร่ | ข้อความบนจอ |
|---|:--:|---|---|
| `VALIDATION_ERROR` | 400 | ข้อมูลบังคับไม่ครบ | ตามช่องที่ผิด |
| `CODE_DUPLICATE` | 409 | รหัสซ้ำ (ไม่สนตัวพิมพ์) | `รหัส {X} ถูกใช้แล้ว` |
| `BAD_CATEGORY` | 400 | หมวดไม่อยู่ใน 6 ค่า | (ใช้ในการนำเข้า) |
| `BAD_STATUS` | 400 | สถานะไม่อยู่ใน 3 ค่า | (ใช้ในการนำเข้า) |
| `NOT_FOUND` | 404 | ไม่พบรายการ | ตกกลับหน้ารายการ |
| `FORBIDDEN` | 403 | ไม่มีสิทธิ์ | ข้อความมาตรฐาน |
| `CODE_LOCKED` | 409 | *(รอ `OQ-02`)* แก้รหัสของหน่วยที่มีสินค้าใช้อยู่ | ยังไม่กำหนด |

## §2.9 สัญญาข้ามเอกสาร ⭐

> **ส่วนนี้คือสิ่งที่ feature อื่นต้องอ่าน** — เปลี่ยนอะไรตรงนี้ = เปลี่ยนสัญญากับปลายทาง
> ต้องแจ้งทีมที่เกี่ยวข้องก่อนเสมอ

### §2.9.1 ทะเบียนหน่วยวัด → ทะเบียนสินค้า

| หัวข้อ | ค่า |
|---|---|
| **ทิศทาง** | ทะเบียนหน่วยวัด (ต้นทาง) → ทะเบียนสินค้า (ปลายทาง) |
| **รูปแบบ** | ปลายทาง **ดึงตอนใช้งาน** ผ่าน `GET /uom?active_only=true` |
| **ส่งอะไร** | **`code` · `name_th` · `symbol` · `category` · `status` เท่านั้น** |
| **ไม่ส่งอะไร** | 🔒 ตัวคูณแปลง · ความละเอียด · หน่วยฐานต่อสินค้า — **ไม่มีในทะเบียนนี้ตั้งแต่ต้น** |
| **ปลายทางเก็บอะไร** | **`code` อย่างเดียว** — ห้ามผูก foreign key ห้าม cascade (Global Contract #6) |
| **ปลายทางเห็นอะไร** | **เฉพาะสถานะ *ใช้งาน*** — ร่าง/ไม่ใช้งาน ต้องไม่โผล่ในตัวเลือก |
| **ค่าที่เคยเลือกไว้แล้ว** | ต้องแสดงต่อได้แม้หน่วยนั้นเปลี่ยนเป็น *ไม่ใช้งาน* ภายหลัง (การอ้างอิงแบบหลวม) |

### §2.9.2 นิยามหมวดหน่วยวัด — **ทะเบียนนี้เป็นเจ้าของ** 🔒

ปลายทางต้องใช้ชุดนี้ **ห้ามนิยามเอง**

| รหัสหมวด | ชื่อไทย |
|---|---|
| `count` | นับจำนวน |
| `weight` | **ชั่งน้ำหนัก** |
| `volume` | **ตวงปริมาตร** |
| `length` | ความยาว |
| `time` | เวลา |
| `service` | บริการ |

**ทำไมถึงสำคัญ:** ปลายทางใช้หมวดเป็นการ์ดกันการตั้งสูตรแปลงข้ามชนิดของ —
หน่วยแปลงต้องอยู่หมวดเดียวกับหน่วยฐาน ถ้าหมวดไม่ตรงกัน 2 ระบบ การ์ดนี้จะทำงานผิด
เช่น หน่วย *งาน* ถ้าถูกจัดเป็น *นับจำนวน* ที่ปลายทาง ระบบจะยอมให้ตั้ง *"1 งาน = 12 กล่อง"*

> ⚠️ **สถานะปัจจุบัน: ทะเบียนสินค้ายังใช้ 3 หมวด และชื่อไทยต่างกัน** → ต้องปรับตาม (`OQ-04`)
> รายการที่ต้องแก้อยู่ที่ `BRD §11.2` (`RG-01`…`RG-06`)

### §2.9.3 `จำนวนสินค้าที่ใช้` — ไหลกลับจากปลายทาง

| หัวข้อ | ค่า |
|---|---|
| **ทิศทาง** | ทะเบียนสินค้า → ทะเบียนหน่วยวัด |
| **นับอะไร** | จำนวนสินค้าที่อ้างหน่วยนี้ **ทั้งเป็นหน่วยฐานและหน่วยแปลง** |
| **ใช้ทำอะไร** | ตัดสินว่าหน่วยนี้ลบได้มั้ย (`used > 0` = ลบไม่ได้) |
| **จังหวะ sync** | ⚠️ **ยังไม่กำหนด — `OQ-03`** |
| **ถ้าค่าไม่สด** | 🔴 เสี่ยงลบหน่วยที่เพิ่งถูกเอาไปใช้ → **ระบบจริงต้องตรวจซ้ำที่ฝั่ง server ตอนกดลบ ไม่ใช่เชื่อค่าที่จอถืออยู่** |

### §2.9.4 สิ่งที่ทะเบียนนี้ **ไม่** ส่งให้ใคร

| ปลายทาง | ส่งมั้ย | เหตุผล |
|---|:--:|---|
| ศูนย์แจ้งเตือน | ❌ | ไม่ส่งสัญญาณเอง — กระดิ่งบนจอเป็นที่ว่างรอเชื่อมภายหลัง |
| ระบบสายอนุมัติ | ❌ | ไม่มีสายอนุมัติ · มีแต่ที่ว่างรอในโมเดล |
| บัญชี / สต๊อก / งบประมาณ | ❌ | ไม่มีมูลค่า ไม่มีจำนวน ไม่แตะยอดใด ๆ |
