## §3.0 Logic Placement Matrix

> **หลัก:** ตรรกะที่มีผลต่อความถูกต้องของข้อมูล **ต้องอยู่ฝั่ง server เสมอ**
> ฝั่งจอทำได้แค่ให้ผู้ใช้รู้เร็วขึ้น — ไม่ใช่ที่กันของผิด

| ตรรกะ | ฝั่งจอ | ฝั่ง server | ฐานข้อมูล | เหตุผล |
|---|:--:|:--:|:--:|---|
| ชื่อไทยห้ามว่าง | ✅ (บอกเร็ว) | ✅ **ตัวจริง** | `NOT NULL` | กันคนยิง API ตรง |
| รหัสห้ามซ้ำ ไม่สนตัวพิมพ์ | ✅ (บอกเร็ว) | ✅ **ตัวจริง** | `UNIQUE` บนคอลัมน์ตัวพิมพ์เล็ก | 2 คนสร้างพร้อมกันได้ — ต้องมีตัวกันชั้นสุดท้าย |
| ออกรหัสอัตโนมัติ | ❌ | ✅ | — | ต้องเห็นข้อมูลทั้งตารางถึงกันชนได้ |
| หมวดต้องอยู่ใน 6 ค่า | ✅ (ตัวเลือกปิด) | ✅ | `FOREIGN KEY` | |
| สถานะต้องอยู่ใน 3 ค่า | ✅ (ตัวเลือกปิด) | ✅ | `CHECK` | |
| ลบไม่ได้ถ้ามีสินค้าใช้ | ✅ (ปิดปุ่ม) | ✅ **ตัวจริง** | — | ค่าที่จอถืออาจไม่สด (`OQ-03`) |
| กันกดซ้ำ | ✅ | ✅ | — | จอกันได้แค่คลิกรัว ไม่กันการยิงซ้ำ |
| ตรวจไฟล์นำเข้ารายแถว | ❌ | ✅ | — | ไฟล์อาจใหญ่ · ต้องตรวจซ้ำกับข้อมูลจริง |
| กรองเฉพาะสถานะใช้งานให้ปลายทาง | ❌ | ✅ **ตัวจริง** | — | ถ้าให้ปลายทางกรองเอง จะมีคนลืม |
| ค้นหา · กรอง · เรียง · แบ่งหน้า | ❌ | ✅ | index | ข้อมูลอยู่ที่ server |

## §3.1 การออกรหัสอัตโนมัติ

**เมื่อ:** ผู้ใช้เว้นช่องรหัสว่างตอนสร้าง

**ขั้นตอน**

1. เอา **ตัวอักษร 3 ตัวแรกของรหัสหมวด** แปลงเป็นตัวพิมพ์ใหญ่ → `count` = `COU` · `weight` = `WEI` · `volume` = `VOL` · `length` = `LEN` · `time` = `TIM` · `service` = `SER`
2. ต่อท้ายด้วย **เลขรัน 2 หลัก** เริ่มที่ `01`
3. ถ้ารหัสที่ได้ชนของเดิม (ไม่สนตัวพิมพ์) → เพิ่มเลขรันแล้ววนใหม่
4. ได้รหัสที่ไม่ชน → ใช้อันนั้น

**ตัวอย่าง:** หมวด *ตวงปริมาตร* และยังไม่มีรหัสขึ้นต้น `VOL` → ได้ `VOL01`

| ข้อควรระวัง | รายละเอียด |
|---|---|
| **ห้ามฝังสูตรในโค้ด** | ทั้งตัวย่อและจำนวนหลักต้องอ่านจาก config (`04_DB §4.4`) |
| **แข่งกันสร้างพร้อมกัน** | 2 คนสร้างหมวดเดียวกันพร้อมกันอาจได้รหัสเดียวกัน → ต้องพึ่งตัวกันซ้ำที่ฐานข้อมูล แล้ว **ลองใหม่อัตโนมัติ 1 ครั้ง** ก่อนคืนข้อผิดพลาด |
| เลขรัน 2 หลักพอมั้ย | 99 หน่วยต่อหมวด — เกินเพดานที่คาดไว้ (`BRD T-01` เตือนที่ 200 หน่วยรวมทุกหมวด) · ถ้าเต็มให้ขยายเป็น 3 หลักผ่าน config |

## §3.2 ลำดับการทำงาน — สร้าง / แก้ไข

```
รับคำขอ
  │
  ├─ ตรวจสิทธิ์ (uom.manage)              ─── ไม่ผ่าน → FORBIDDEN
  ├─ ตรวจชื่อไทยไม่ว่าง                    ─── ไม่ผ่าน → VALIDATION_ERROR
  ├─ [สร้าง] รหัสว่าง? → ออกรหัสอัตโนมัติ (§3.1)
  ├─ ตรวจรหัสซ้ำ (ตัวพิมพ์เล็กเทียบกัน)
  │     [สร้าง]  ชนกับใครก็ตาม           ─── ชน → CODE_DUPLICATE
  │     [แก้ไข]  ชนกับคนอื่นที่ไม่ใช่ตัวเอง  ─── ชน → CODE_DUPLICATE
  ├─ สัญลักษณ์ว่าง? → ใช้รหัสตัวพิมพ์เล็ก
  ├─ เขียนข้อมูล + ผู้ทำ + เวลา
  └─ คืนผล
```

> 🔴 **จุดที่พลาดบ่อย:** ตอนแก้ไขต้องมีเงื่อนไข *"ไม่ใช่ตัวเอง"* ในการตรวจรหัสซ้ำ
> ไม่งั้นผู้ใช้กดบันทึกโดยไม่เปลี่ยนรหัสเลยก็จะโดนบล็อก

## §3.3 ลำดับการทำงาน — ลบหลายรายการ

```
รับรายการ id ที่จะลบ
  │
  ├─ ตรวจสิทธิ์
  ├─ ดึงข้อมูลจริงจากฐานข้อมูล   ← ห้ามเชื่อค่าที่จอส่งมา
  ├─ แยกเป็น 2 กอง
  │     used > 0  → กอง "ข้าม"
  │     used = 0  → กอง "ลบ"
  ├─ ลบเฉพาะกอง "ลบ"
  └─ คืน { ลบไปกี่รายการ, ข้ามกี่รายการ, รายการที่ข้ามพร้อมเหตุผล }
```

| ข้อบังคับ | รายละเอียด |
|---|---|
| **สำเร็จบางส่วนได้** | มีตัวลบไม่ได้ **ห้ามล้มทั้งคำสั่ง** |
| ลบไม่ได้เลย | คืนสำเร็จพร้อมจำนวนลบ = 0 (ไม่ใช่ข้อผิดพลาด) |
| **ตรวจ `used` ที่ server เสมอ** | ค่าที่จอถืออาจเก่า (`OQ-03`) |
| บันทึกประวัติ | ต้องเก็บว่าใครลบอะไรเมื่อไหร่ **ก่อน**ลบจริง |

> ⚠️ **ขึ้นกับ `OQ-05`** — ถ้าเจ้าของกติกากลางตัดสินว่าห้ามลบจริง ให้เปลี่ยนเป็น
> ทำเครื่องหมายซ่อนแทน แล้วกรองออกจากทุก endpoint · โครงตรรกะข้างบนไม่เปลี่ยน เปลี่ยนแค่คำสั่งสุดท้าย

## §3.4 การเปลี่ยนสถานะ

**ไม่มีตารางเงื่อนไขว่าเปลี่ยนจากอะไรไปอะไรได้** — ทั้ง 6 เส้นทางระหว่าง 3 สถานะเปิดหมด

```
รับ { รายการ id, สถานะใหม่ }
  ├─ ตรวจสิทธิ์
  ├─ ตรวจว่าสถานะใหม่อยู่ใน 3 ค่า
  ├─ ข้ามตัวที่สถานะเดิมตรงกับที่สั่งอยู่แล้ว   ← ไม่นับเป็น "เปลี่ยน"
  ├─ เขียนสถานะใหม่ + ผู้แก้ + เวลา
  └─ คืน { เปลี่ยนกี่รายการ, ไม่ต้องเปลี่ยนกี่รายการ }
```

| ข้อบังคับ | รายละเอียด |
|---|---|
| **ไม่มีขั้นตรวจ/อนุมัติคั่น** | เปลี่ยนแล้วมีผลทันที |
| **ไม่ต้องเช็ค `used`** | หน่วยที่ถูกใช้อยู่เปลี่ยนสถานะได้ (แค่ลบไม่ได้) |
| ผลต่อปลายทาง | เปลี่ยนออกจาก *ใช้งาน* → หายจากตัวเลือกทันที **แต่สินค้าที่ผูกไว้แล้วยังใช้ค่าเดิมได้** |
| นับเฉพาะที่เปลี่ยนจริง | ข้อความแจ้งผลต้องบอกจำนวนที่เปลี่ยนจริง ไม่ใช่จำนวนที่เลือก |

## §3.5 `จำนวนสินค้าที่ใช้` — การคำนวณ

| หัวข้อ | รายละเอียด |
|---|---|
| **เจ้าของข้อมูล** | ทะเบียนสินค้า ไม่ใช่ทะเบียนนี้ |
| **นับอะไร** | สินค้าที่อ้างหน่วยนี้เป็น **หน่วยฐาน** + สินค้าที่อ้างเป็น **หน่วยแปลง** (นับสินค้าเดียวกันครั้งเดียว) |
| **ทะเบียนนี้ทำอะไร** | อ่านมาแสดง + ใช้ตัดสินการลบ — **ไม่มีทางแก้ค่านี้จากที่นี่** |
| **จังหวะ sync** | ⚠️ **ยังไม่กำหนด — `OQ-03`** |

**ทางเลือกที่เสนอ (รอเคาะ)**

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| นับสดตอนขอข้อมูล | ค่าตรงเสมอ | ช้าลงเมื่อสินค้าเยอะ |
| เก็บค่าไว้แล้วอัปเดตตอนสินค้าเปลี่ยน | เร็ว | ต้องดักทุกจุดที่สินค้าเปลี่ยนหน่วย |
| คำนวณรอบกลางคืน | ง่ายสุด | 🔴 **ค่าไม่สด — เสี่ยงลบหน่วยที่เพิ่งถูกใช้** |

> 🔴 **ไม่ว่าเลือกทางไหน ตอนกดลบต้องนับสดที่ server เสมอ** — ห้ามเชื่อค่าที่แสดงบนจอ
