# 07_LOCKED_DECISIONS — F-UOM-001 ทะเบียนหน่วยวัด

## §7.2 LOCK-01 · ไม่มีข้อมูลการแปลงหน่วย 🔒

| | |
|---|---|
| **เนื้อมติ** | ทะเบียนหน่วยวัดเก็บแค่ **นิยามของหน่วย** — รหัส · ชื่อ · สัญลักษณ์ · หมวด · สถานะ · จำนวนสินค้าที่ใช้ |
| **ห้ามมีเด็ดขาด** | ตัวคูณแปลง · ความละเอียดทศนิยม · หน่วยฐานต่อสินค้า · ความสัมพันธ์ *"1 กล่อง = N ชิ้น"* |
| **ทำไม** | ความสัมพันธ์ระหว่างหน่วยเป็นเรื่อง **ต่อสินค้า** ไม่ใช่เรื่องสากล — 1 กล่องของสินค้า A ไม่เท่ากับ 1 กล่องของสินค้า B |
| **แล้วของพวกนั้นอยู่ที่ไหน** | **ทะเบียนสินค้า** — ตั้งค่าตัวคูณต่อสินค้าที่นั่น |
| **ที่มา** | `_SCOPE_LOCK` (ศักดิ์ใบเซ็น) · `GR-UOM-01/02` · `LD-01/02` ของเอกสารชุดเดิม |
| **ตรวจยังไง** | เดินทุกสถานะของจอแล้วต้องไม่เจอคำเหล่านี้ + โมเดลข้อมูลต้องไม่มีคอลัมน์ที่เกี่ยวข้อง |
| **ย้อนกลับได้มั้ย** | ❌ **ไม่ได้** — ถ้าจะเปลี่ยนต้องรื้อทั้งสัญญาข้ามระบบ |

## §7.3 LOCK-02 · สัญญาข้อมูลออก 🔒

| | |
|---|---|
| **ส่งอะไร** | `code` · `name_th` · `symbol` · `category` · `status` |
| **ปลายทางเก็บอะไร** | **`code` อย่างเดียว** — เก็บเป็นข้อความ ว่างได้ **ไม่ผูกความสัมพันธ์บังคับ ไม่ลบตาม** |
| **ปลายทางเห็นอะไร** | **เฉพาะสถานะ *ใช้งาน*** — กรองที่ฝั่ง server ไม่ใช่ให้ปลายทางกรองเอง |
| **ค่าที่เคยเลือกไว้แล้ว** | ต้องแสดงต่อได้แม้หน่วยนั้นเปลี่ยนเป็น *ไม่ใช้งาน* ภายหลัง |
| **ที่มา** | `_SCOPE_LOCK` · Global Contract #6 (การอ้างอิงแบบหลวม) |
| **สัญญาเต็ม** | `02_API §2.9` |

## §7.4 LOCK-03 · ไม่มีสายอนุมัติ 🔒

| | |
|---|---|
| **เนื้อมติ** | ทะเบียนหน่วยวัด**ไม่อยู่ใน 19 เอกสารที่ต้องเซ็น** ตาม Global Contract #1 |
| **ผลบนจอ** | ไม่มีปุ่มส่งอนุมัติ · ไม่มีสถานะรออนุมัติ · ไม่มีคิวผู้อนุมัติ |
| **แต่ต้องมี** | ที่ว่างรอเชื่อม **4 ช่อง** ในโมเดลและฐานข้อมูล เป็นค่าว่างเสมอ — **ห้ามตัดออกเพราะยังไม่ได้ใช้** |
| **ทำไมต้องเก็บที่ว่างไว้** | วันที่ระบบสายอนุมัติพร้อม จะเสียบได้โดยไม่ต้องย้ายข้อมูล |
| **ที่มา** | Ledger + กติกาเหล็ก #3 |

## §7.5 LOCK-04 · ไม่ส่งสัญญาณแจ้งเตือนเอง 🔒

ทะเบียนนี้ไม่ยิงเหตุการณ์ไปศูนย์แจ้งเตือน — ไอคอนกระดิ่งบนแถบบนเป็น**ที่ว่างรอเชื่อม**
ถ้าวันหลังต้องแจ้งเตือน (เช่น มีคนลบหน่วยที่ใช้อยู่) ให้ทำเป็นข้อเสนอใหม่ ไม่ใช่แอบเพิ่ม

## §7.6 LOCK-05 · แบบแผนของเลนข้อมูลหลัก 🔒

ทะเบียนนี้ต้องหน้าตาและพฤติกรรมเหมือน **ทะเบียนสินค้า** และ **แคตตาล็อกสินค้า** ในเรื่องต่อไปนี้

| # | แบบแผน | ผลที่ต้องเห็น |
|:--:|---|---|
| 1 | สถานะ **3 ค่า เปลี่ยนอิสระ** | ร่าง · ใช้งาน · ไม่ใช้งาน — ไม่มีลำดับบังคับ |
| 2 | **เลือกหลายรายการ** | มีแถบเครื่องมือพร้อมจำนวน |
| 3 | **สถานะระบุในไฟล์นำเข้าได้** | เว้นว่าง = ร่าง |
| 4 | **ส่งออกได้** | ตามตัวกรองปัจจุบัน |
| 5 | **ไม่มีคำอธิบายใต้ช่องกรอก** | นับได้ 0 |
| 6 | **ไม่มีปุ่มลบรายตัว** | ลบผ่านการเลือกหลายรายการเท่านั้น |

> ⚠️ **ที่มาของแบบแผนนี้ยังยืนยันไม่ได้เต็มร้อย** — อ้าง `VD-PDM-01/02/04/11/12/13`
> ซึ่ง**ยังไม่มีต้นทางในเอกสารที่ปิดแล้ว** (`OQ-06`)
> ถ้าตอนทำทะเบียนสินค้าพบว่ามติจริงไม่ตรง **ทะเบียนนี้ต้องรื้อตาม** — จึงต้องยืนยันก่อนส่ง dev

## §7.8 LD-01 · นิยามหมวดหน่วยวัด 6 หมวด ⭐🔒

> **มติสำคัญที่สุดในไฟล์นี้สำหรับทีมที่ทำ feature ปลายทาง**

| | |
|---|---|
| **เนื้อมติ** | **ทะเบียนหน่วยวัดเป็นเจ้าของนิยามหมวด** — feature ปลายทางต้องใช้ชุดเดียวกัน **ห้ามนิยามเอง** |
| **จำนวน** | **6 หมวด** |
| **เคาะเมื่อไหร่** | 2026-08-10 โดยผู้ใช้ (BA) |

### ชุดหมวดที่ล็อกแล้ว

| รหัสหมวด | ชื่อไทย |
|---|---|
| `count` | นับจำนวน |
| `weight` | **ชั่งน้ำหนัก** |
| `volume` | **ตวงปริมาตร** |
| `length` | ความยาว |
| `time` | เวลา |
| `service` | บริการ |

### ทำไมถึงต้องล็อก

หมวดไม่ได้มีไว้แค่จัดกลุ่มให้ดูสวย — **มันคือการ์ดกันการตั้งสูตรแปลงข้ามชนิดของ**
ที่ทะเบียนสินค้า: หน่วยแปลงต้องอยู่หมวดเดียวกับหน่วยฐาน

ถ้าสองระบบใช้หมวดคนละชุด การ์ดนี้จะทำงานผิด เช่น

| ถ้าหมวดไม่ตรงกัน | ผลที่เกิด |
|---|---|
| หน่วย *งาน* ถูกจัดเป็น *นับจำนวน* ที่ปลายทาง | ระบบยอมให้ตั้ง **"1 งาน = 12 กล่อง"** |
| ไม่มีหมวด *ความยาว* ที่ปลายทาง | เมตร/เซนติเมตร ถูกยัดเข้า *นับจำนวน* → ตั้ง **"1 เมตร = 24 ครั้ง"** ได้ |
| ไม่มีหมวด *เวลา* ที่ปลายทาง | ตั้ง **"1 วัน = 6 กล่อง"** ได้ |

### สถานะปัจจุบันของปลายทาง

| | ทะเบียนหน่วยวัด (ต้นทาง) | ทะเบียนสินค้า (ปลายทาง) |
|---|---|---|
| จำนวนหมวด | **6** | ⚠️ **3** |
| ชื่อไทย | ชั่งน้ำหนัก · ตวงปริมาตร | ⚠️ น้ำหนัก · ปริมาตร |
| หน่วย *งาน* อยู่หมวด | **บริการ** | ⚠️ นับจำนวน |

🔴 **ยังไม่ตรงกัน** — รายการที่ปลายทางต้องแก้อยู่ที่ `BRD §11.2` (`RG-01`…`RG-06`) และติดตามที่ `OQ-04`

### ระดับความย้อนกลับได้

**ปานกลาง** — ถ้าเปลี่ยนใจกลับไปใช้ 3 หมวด ต้อง:
ย้ายหน่วยในหมวดที่หายไปกลับเข้า *นับจำนวน* · แก้ข้อมูลตั้งต้น · แก้เอกสารชุดนี้ทั้งแพ็ก ·
และ**ยอมรับว่าการ์ดกันสูตรแปลงข้ามชนิดของจะกันได้ไม่ครบ**

## §7.11 วิธีใช้ไฟล์นี้

| สถานการณ์ | ทำยังไง |
|---|---|
| กำลังทำ feature ที่ต้องให้ผู้ใช้เลือกหน่วยวัด | อ่าน `LOCK-02` + `LD-01` แล้วดึงข้อมูลตาม `02_API §2.9` — **ห้ามทำรายการหน่วยของตัวเอง** |
| กำลังทำเรื่องการแปลงหน่วย | อ่าน `LOCK-01` — ของนั้นอยู่ที่ทะเบียนสินค้า **ไม่ใช่ที่นี่** |
| เจอว่ามติในนี้ขัดกับสิ่งที่ feature ตัวเองต้องการ | **ยกเป็นข้อหารือให้ BA เคาะ ห้ามเลือกข้างเอง** |
| จะเปลี่ยนอะไรในไฟล์นี้ | ต้องได้รับความเห็นชอบจากผู้ใช้ (BA) และ **แจ้งทุก feature ที่อ้างถึง** |
