## §5.2 กติกาของสถานะ

| ข้อ | กติกา |
|---|---|
| 1 | มี 3 สถานะเท่านั้น: **ร่าง · ใช้งาน · ไม่ใช้งาน** — ห้ามเพิ่มค่าอื่น (เช่น *รออนุมัติ* · *เก็บถาวร*) |
| 2 | **ทั้ง 6 เส้นทางระหว่าง 3 สถานะเปิดหมด** — ไม่มีเงื่อนไขว่าต้องผ่านสถานะไหนก่อน |
| 3 | ทุกการเปลี่ยนมีผลทันที **ไม่มีขั้นตรวจ ไม่มีคิวอนุมัติ** |
| 4 | เปลี่ยนสถานะได้ 4 ทาง: ช่องสถานะในฟอร์ม · เมนูในหน้ารายละเอียด · แถบเลือกหลายรายการ · คอลัมน์สถานะในไฟล์นำเข้า |
| 5 | **การเปลี่ยนสถานะไม่ขึ้นกับ `used`** — หน่วยที่ถูกใช้อยู่ก็เปลี่ยนสถานะได้ |
| 6 | ค่าตั้งต้น: ฟอร์ม = **ใช้งาน** · นำเข้าเมื่อเว้นคอลัมน์ = **ร่าง** |

## §5.3 กติกาการตรวจข้อมูล (VR)

| VR | ตรวจอะไร | เมื่อไหร่ | ประเภท | ข้อความ |
|---|---|---|---|---|
| VR-01 | ชื่อไทยไม่ว่าง (และไม่ใช่ช่องว่างล้วน) | ก่อนบันทึก | **บล็อก** | `กรุณากรอกชื่อภาษาไทย` |
| VR-02 | รหัสไม่ซ้ำ (ไม่สนตัวพิมพ์ · ยกเว้นตัวเองตอนแก้) | ก่อนบันทึก | **บล็อก** | `รหัส {X} ถูกใช้แล้ว` |
| VR-03 | หมวดอยู่ใน 6 ค่า | ก่อนบันทึก | **กันไว้ก่อน** | ตัวเลือกปิด — ไม่มีช่องพิมพ์อิสระ |
| VR-04 | สถานะอยู่ใน 3 ค่า | ก่อนบันทึก | **กันไว้ก่อน** | ตัวเลือกปิด |
| VR-05 | ห้ามส่งซ้ำระหว่างกำลังบันทึก | ตอนกดปุ่ม | **กันไว้ก่อน** | ปุ่มถูกปิด + `กำลังบันทึก…` |
| VR-06 | การลบต้องผ่านหน้าต่างยืนยันเสมอ | ก่อนลบ | **กันไว้ก่อน** | หน้าต่างบอกจำนวนลบจริง/ข้าม |
| VR-07 | ถ้าลบจริงได้ 0 รายการ | ตอนเปิดหน้าต่างยืนยัน | **กันไว้ก่อน** | ปุ่มยืนยันถูกปิด |
| VR-08 | นำเข้า — ครบ รหัส/ชื่อไทย/หมวด | ตอนตรวจไฟล์ | **บล็อกรายแถว** | `REQUIRED — ข้อมูลบังคับไม่ครบ` |
| VR-09 | นำเข้า — ชื่อหมวดตรง 6 ค่า | ตอนตรวจไฟล์ | **บล็อกรายแถว** | `BAD_CATEGORY — ไม่มีหมวดนี้` |
| VR-10 | นำเข้า — สถานะตรง 3 ค่า (หรือเว้นว่าง) | ตอนตรวจไฟล์ | **บล็อกรายแถว** | `BAD_STATUS — สถานะไม่ถูกต้อง` |
| VR-11 | นำเข้า — รหัสไม่ซ้ำกับทะเบียน | ตอนตรวจไฟล์ | **บล็อกรายแถว** | `CODE_DUPLICATE — รหัสซ้ำ` |
| VR-12 | นำเข้า — ถ้าไม่มีแถวใดผ่าน | ตอนแสดงผลตรวจ | **กันไว้ก่อน** | ปุ่มยืนยันนำเข้าถูกปิด |

**ลำดับการตรวจแถวในไฟล์นำเข้า (ตายตัว)**

```
ข้อมูลบังคับครบมั้ย  →  หมวดถูกมั้ย  →  สถานะถูกมั้ย  →  รหัสซ้ำมั้ย
```

> คืน**เหตุผลแรกที่เจอ** เท่านั้น — ไม่ต้องไล่เก็บทุกข้อผิดพลาดของแถวเดียวกัน

## §5.5 การจัดการข้อผิดพลาด

| สถานการณ์ | จอต้องทำอะไร |
|---|---|
| ตรวจข้อมูลไม่ผ่าน | ทำขอบช่องที่ผิดให้เห็น + ข้อความใต้ช่องนั้น + **ลิ้นชักเปิดค้าง** + แจ้งเตือนรวม 1 ครั้ง |
| รหัสซ้ำ | เหมือนข้างบน แต่ระบุรหัสที่ชนในข้อความ |
| ไม่พบรายการ (รหัสในที่อยู่หน้าเว็บผิด) | ตกกลับหน้ารายการ **ไม่ค้างจอเปล่า** |
| ไม่มีสิทธิ์ | ข้อความมาตรฐาน + ไม่แสดงปุ่มที่ทำไม่ได้ |
| เชื่อมต่อไม่ได้ | แจ้ง `เกิดข้อผิดพลาด กรุณาลองใหม่` + **ไม่ล้างสิ่งที่ผู้ใช้กรอกไว้** |
| ลบสำเร็จบางส่วน | แจ้งทั้งยอดลบและยอดข้าม พร้อมเหตุผล — ใช้โทนเตือน ไม่ใช่โทนสำเร็จล้วน |
| นำเข้าสำเร็จบางส่วน | เดียวกัน + ตารางแถวที่ถูกข้ามพร้อมสาเหตุ |

> **หลัก:** ข้อผิดพลาดที่ผู้ใช้แก้เองได้ → บอกให้ชัดว่าแก้ตรงไหน
> ข้อผิดพลาดที่แก้เองไม่ได้ → บอกว่าเกิดอะไรและควรทำอะไรต่อ **ห้ามโชว์ข้อความทางเทคนิคดิบ**
