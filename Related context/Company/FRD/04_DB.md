## §4.6 Data Classification & Sensitive Data ⭐

### §4.6.1 Levels (CUBE 4.0)
Public (company name/website) · Internal (org structure/status/audit — **default**) · Confidential (tax_id, ชื่อบุคคล/อีเมล/โทร → mask `***` ถ้า role ไม่ผ่าน, excluded จาก export) · **Restricted** (salary → hidden + audit log ทุกการเข้าถึง + require Restricted Resources approval).

### §4.6.2 Enforcement — DB
RLS by tenant_id; Restricted columns (salary_*) แยก grant / column-level privilege; audit ทุก SELECT บน salary.

### §4.6.3 Enforcement — API
Confidential → mask ใน response ถ้า role ไม่ผ่าน; Restricted → omit field เว้น role มี ACL + log access (02_API §Calls).

### §4.6.4 Enforcement — UI
Confidential → `***` ; Restricted (salary band) → ซ่อนใน list/detail เว้นมีสิทธิ์ (P-06 position).

### §4.6.5 Enforcement — Audit/Export
Confidential → excluded column ใน CSV export ถ้า role ไม่ผ่าน; Restricted → excluded + require approval; ทุก mutation เขียน Immutable Master Data Log (S01-07).

### §4.6.6 Policy Center Linkage
salary_min/salary_max → register **Restricted Resources** (Policy Center); การ override classification → Data Classification module. Default Internal ทุก field ที่ไม่ระบุ.
