## §4.4 Migration Strategy

**Initial migration (Phase 1)**
1. สร้าง 9 ตาราง + extension `btree_gist` (สำหรับ EXCLUDE constraint)
2. Seed `T_ss_change_reason` 5 ค่า · `T_ss_pay_component` 4 ค่า (`BASE` · `POS-ALW` · `COL-ALW` · `LOAN-DED`) — `BASE` มี `include_in_band_base = true`
3. Seed `T_ss_consumer_usage` 4 แถว สถานะ `pending` (ปลายทางยังไม่มีจริง)
4. สร้าง trigger กัน UPDATE/DELETE ตาม P-2′/P-4′
5. **ไม่มีการ seed ตัวเลขค่าแรงขั้นต่ำ** — ค่าอยู่ที่ HR Configuration (P-8′)

**Data migration:** ไม่มีข้อมูลเดิม (feature ใหม่) · การนำเข้าครั้งแรกจากไฟล์ HR **ไม่อยู่ในรอบนี้** (NS-06) — ถ้าจำเป็นให้ทำเป็นสคริปต์ครั้งเดียวที่ผ่าน validation ชุดเดียวกับ API

## §4.6 Data Classification & Sensitive Data ⭐

### §4.6.1 Classification Levels (CUBE 4.0 Standard)
`Public` < `Internal` < `Confidential` < `Restricted` — feature นี้แตะสูงสุดที่ **Restricted**

### §4.6.2 Default Rule
**ไม่มี field ใดใน feature นี้เป็น `Public`** — ค่าเริ่มต้นของทุก field คือ `Internal` และยกระดับขึ้นเมื่อ (ก) เป็นจำนวนเงินที่ผูกกับบุคคล → `Restricted` (ข) เป็นเหตุผล/ธง/ช่วงกระบอกที่บอกนัยเรื่องค่าตอบแทน → `Confidential`

### §4.6.3 Enforcement Mapping

| Classification | บังคับใช้อย่างไร |
|---|---|
| Restricted | ปิดบังที่ **ชั้น API** (`maskMoney`) ก่อนออกจากเซิร์ฟเวอร์ (OQ-FRD-04) · เข้ารหัสตอนเก็บ (S06-05) · ทุกการอ่านถูกบันทึก audit (FN-36) · ห้ามอยู่ใน log/trace |
| Confidential | เห็นได้เฉพาะ role ที่มีสิทธิ์อ่านโครง · ไม่บันทึก audit รายครั้ง |
| Internal | เห็นได้ทุก role ที่เข้าถึง feature |

### §4.6.4 PII Overlay (Independent Flag)
`employee_id` · `employee_name_snapshot` · `created_by` / `changed_by` (+ snapshot ชื่อ) = **PII** — ต่างจาก classification เชิงความลับ · การเก็บ snapshot ชื่อเป็นข้อผูกพันของ LD-4C-02 (ประวัติต้องอ่านได้แม้ต้นทางหาย) จึง **ไม่ลบ** แต่ปิดบังได้ตามคำขอสิทธิ์เจ้าของข้อมูลที่ Policy Center

### §4.6.5 Security Bible Domain Mapping

| Domain | ใช้กับอะไรในแพ็กนี้ |
|---|---|
| D2 Authentication & Session | ทุก endpoint · role มาจาก login (ไม่มี persona switch จริง) |
| D7 PII Protection | `base_amount` · รายการประจำ · ชื่อพนักงาน — masking + encryption |
| D9 Audit Logging | ทุก mutation + **ทุกการอ่านข้อมูล Restricted** |
| D15 Admin Actions | ปิดใช้/เปิดใช้ระดับ · override Module Linkage |
| D17 Multi-Tenant Isolation | `tenant_id` ทุกตาราง + ทุก query |
| D-CLASS Data Classification | §4.6 ทั้งหมด (ดู `05_RULES §5.7`) |

### §4.6.6 Linkage with Policy Center

| สิ่งที่ต้องลงทะเบียน | ที่ Policy Center |

## §4.8 Performance Considerations

| จุด | มาตรการ |
|---|---|
| as-of read รายคน | `ix_ss_rate_asof` + query `effective_date <= :date AND (effective_to IS NULL OR effective_to >= :date)` |
