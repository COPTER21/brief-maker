## §7.1 Locked Decisions

### LD-01 · Archetype = Q-document เต็มรูป
registry F072 ประกาศ `arch: Q-document` → ใช้ **Pattern Q + B2 v2** ได้เต็มรูป (wizard 5 ขั้น · เลขที่เอกสาร · view 4 แท็บ · แบบพิมพ์ A4 · ลายเซ็น)
**ไม่ใช่ DIVERGENCE** เพราะ registry ประกาศไว้ — ต่างจากฟีเจอร์ `arch: master` ที่ห้ามมี surface เหล่านี้

### LD-02 · Pack Variant = FULL
fallback จาก BRD: pages=3(+6 overlay) · **states=5** · approval=Yes · money=Yes → เข้าเงื่อนไข `states ≥ 4` → **FULL** (9 files + INDEX)

### LD-03 · ไม่รัน `brd-generator-full`
Mode B — `2_BRD/BRD_F-PUR-PR.md` **APPROVED** (C01–C23 · 23/23) มาแล้วจาก BA lane → คัดเข้า `02_BRD/` ตรง ๆ
คัด `PREBRIEF` + `FUNCTION_CHECKLIST` เข้ามาด้วยเพื่อให้ dev อ่านเจตนาต้นทางได้ในที่เดียว

### LD-04 · ไม่มีค่านโยบายใดอยู่ในโค้ดฟีเจอร์
วงเงินอนุมัติ · รูปแบบเลขเอกสาร · นโยบายเก็บสำเนา · ช่องทางแจ้งเตือน · เกณฑ์งบ — **อยู่ที่ทะเบียนกลางทั้งหมด**
`MOCK_DOA_TIERS` ในต้นแบบถือตัวเลข 50,000/500,000 แต่ผูก `doa_entry_ref: DOA-041/042/043` ชี้ทะเบียน DOA กลาง และเป็นค่า `[ASSUMED]` ของ **OQ-01**
→ **ห้ามอ่านเป็นค่าจริง** · ตอนต่อระบบจริงต้องมาจาก `ENG-DOA-RESOLVE` เท่านั้น

### LD-05 · จุดตรวจงบเป็นของจำลองล้วน (LOCK-FW)
`FN-07 checkBudgetMock` คืน `{ok, remaining, budget_code, mock:true}` · **ห้าม implement logic งบจริง ห้ามรอ W7**
ผล "ไม่พอ" เป็น **คำเตือน ไม่ block** (BR-07) · สัญญา `{ok, remaining, budget_code}` เป็น `[ASSUMED contract]` (A-01) ต้องยืนยันกับเจ้าของ W7

### LD-06 · ใบประกาศครบ 5 ใบ — ไม่มีใบที่ตกหล่น
`dec: doa, ntf, csq, doccfg, pdfdoc` → ออกครบ 5 ใบ (รับจาก `5_DECLARATIONS/` ของ BA lane)
**repo นี้ไม่มี `csq-declaration` skill และไม่มี pdfdoc spec generator** — เป็นช่องว่างของ toolchain (80 และ 28 ฟีเจอร์ใน registry) แต่ไม่กระทบ pack นี้เพราะต้นน้ำส่งใบมาให้แล้ว

### LD-07 · HTML ถูกคัดมาโดยตรง แล้วแก้เฉพาะ 2 เรื่องที่ gate บังคับ
ไฟล์มาจาก `1_HTML/F-PUR-PR.html` · **ไม่ได้ regenerate ใหม่** (ไม่รัน `html-generator-v9`)
แก้ 2 เรื่องเท่านั้นในขั้น 7R — ทั้งคู่เป็นการ **บังคับใช้กติกาที่มีอยู่แล้ว ไม่ใช่การออกแบบใหม่**: LD-08 และ LD-09

### LD-09 · ★ ถอดศัพท์ภายในออกจากข้อความที่ผู้ใช้เห็น (iron rule #81) 14 จุด
`ENG-NOTIFY` · `mock` · `soft-reference` · `My Approval` · `Phase A` · `backend` · รหัสฟีเจอร์ (`F007`/`F009`/`F012`/`F019`/`F073`) · รหัส wave (`W3`) · คำว่า `feature`
ทั้งหมดอยู่ใน toast · field-help · section title — **อยู่ในกรอบ "ถ้อยคำ" ที่ HANDOFF §4 อนุญาตให้ปรับ**
รายการเต็ม: `01_HTML/_UX_CHECK_REPORT.md §3`
> จุดที่ร้ายแรงที่สุดคือ **ปุ่มในลิ้นชัก** (`เทียบราคาผู้ขาย (F073) — ยังไม่อยู่ในขอบเขตรอบนี้`) เพราะเป็น affordance จริงของฟีเจอร์ ไม่ใช่ scaffolding ของเมนูข้าง
> **ไม่แตะ** comment ในโค้ด (`ENG-DOC-NUM` · `ENG-NOTIFY.emit` · `TODO:`) — ไม่ขึ้นจอ และเป็นที่ที่ contract ควรอยู่

### LD-10 · SC-06 ทำคนละแบบกับถ้อยคำใน PREBRIEF
PREBRIEF SC-06 เขียนว่า *"ยอดสุทธิเกินวงเงิน slot ที่เลือก → **เตือนที่ step 5**"*

**ตัดสิน: ยึดพฤติกรรมของระบบ** เพราะทำให้เจตนาหลัก (ได้ผู้อนุมัติระดับที่ครอบยอดเสมอ) เป็นจริงและแข็งแรงกว่า
→ **เปิด OQ-07 ให้ BA แก้ถ้อยคำ SC-06** · ห้ามปล่อยเงียบ
