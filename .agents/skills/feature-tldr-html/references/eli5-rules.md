# ELI5 Writing Rules — เขียนให้เด็ก 5 ขวบเข้าใจ

เปิดไฟล์นี้ตอน **Step 3**. นี่คือหัวใจของ skill — ถ้าข้ามขั้นนี้ หน้าปกจะกลายเป็น FRD ย่อ (ไร้ประโยชน์).

---

## 7 กฎการเขียน

1. **1 ประโยค = 1 ใจความ** — ยาวเกิน 2 บรรทัดคือยาวไป ตัด
2. **คำที่แม่ค้าตลาดเข้าใจ** — ถ้าต้องเปิด google แปล = ผิด
3. **บอก "ทำอะไร" ไม่ใช่ "ทำงานยังไง"** — คนอ่านอยากรู้ผลลัพธ์ ไม่ใช่กลไก
4. **เลี่ยงคำคลุมเครือ:** จัดการ / ดำเนินการ / ระบบรองรับ / บริหารจัดการ / ประมวลผล → บอกให้ชัดว่าทำอะไร
5. **มีตัวเลข/ตัวอย่างจริง ใส่เลย** — "เวลาเด้งออก" ลอยๆ สู้ "เด้งออกหลังนั่งเฉย 15 นาที" ไม่ได้
6. **กริยานำหน้าข้อ "ทำได้"** — เพิ่ม/แก้/ลบ/ค้นหา/กรอง/พิมพ์/ส่ง/ดาวน์โหลด/นำเข้า (ไม่ใช่ "การจัดการ...")
7. **ห้ามศัพท์ระบบเด็ดขาด** — ดูตารางแปลด้านล่าง

---

## Glossary — ศัพท์ระบบ → ภาษาคน

| ห้ามเขียน (ศัพท์ระบบ) | ให้เขียนแทน |
|---|---|
| field / column / attribute | ช่องกรอก / ข้อมูล |
| record / entity / row | รายการ / ข้อมูล 1 ชุด |
| API / endpoint / call | (ตัดออก — คนอ่านไม่ต้องรู้) / "ดึงข้อมูลจาก..." |
| validate / validation | ตรวจว่ากรอกถูกไหม |
| RLS / row-level security | แต่ละบริษัทเห็นแค่ข้อมูลตัวเอง |
| enum / dropdown option | ตัวเลือกที่กำหนดไว้ให้เลือก |
| FK / foreign key / reference | โยงไปหา... / อ้างอิงจาก... |
| CRUD | เพิ่ม-ดู-แก้-ลบ |
| soft delete / archive | เก็บเข้าคลัง (ไม่ลบจริง ยังเรียกกลับได้) |
| append-only / immutable log | ประวัติที่แก้/ลบไม่ได้ เก็บไว้ตลอด |
| state / status transition | เปลี่ยนสถานะ (เช่น ร่าง → รออนุมัติ → อนุมัติ) |
| threshold | เส้นแบ่ง / ค่าที่ตั้งไว้ |
| idempotent / concurrency | (ตัดออก — เรื่องเบื้องหลัง ไม่ต้องบอก) |
| payload / request body | ข้อมูลที่ส่งไป |
| DOA / delegation of authority | สายอนุมัติ (ใครอนุมัติได้ถึงวงเงินเท่าไหร่) |
| cross-field validation | กฎที่หลายช่องต้องสัมพันธ์กัน |
| pagination | แบ่งหน้า (โหลดทีละหน้า) |
| aggregate / rollup | รวมยอด / สรุปยอด |
| master data / lookup | ข้อมูลหลักที่ตั้งไว้ให้เลือก (เช่น รายชื่อสินค้า) |
| audit log / audit trail | บันทึกว่าใครทำอะไรเมื่อไหร่ |
| route / hash route / `#/...` | หน้า... (แปลงเป็นชื่อหน้าภาษาคน) |
| tenant | บริษัทลูกค้าแต่ละราย |

## ตัวอย่าง Before / After

**① ฟีเจอร์คืออะไร**
- ❌ FRD: "F-SEC-14 provides configurable session timeout policy with cross-field validation on idle/absolute/warn thresholds enforced at the tenant level via RLS."
- ✅ หน้าปก: "ตั้งกฎว่าให้คนล็อกอินค้างไว้ได้นานแค่ไหนก่อนระบบเด้งออกเอง — เพื่อความปลอดภัย ถ้าลืมล็อกเอาต์แล้วเดินหนีไป ระบบจะเตะออกให้เอง แต่ละบริษัทตั้งกฎของตัวเองได้"

**② ทำได้**
- ❌ "รองรับการ configure absolute_timeout, idle_timeout, warn_before_timeout"
- ✅ "ตั้งเวลาได้ 3 แบบ: (1) นั่งเฉยกี่นาทีถึงเด้ง (2) ใช้งานรวมนานสุดกี่ชั่วโมงถึงเด้ง (3) เตือนก่อนเด้งกี่นาที"

**③ ทำไม่ได้**
- ❌ "Out of scope: MFA enrollment, password rotation policy"
- ✅ "ยังตั้งเรื่องรหัสผ่าน หรือการยืนยันตัวตน 2 ชั้น (OTP) ที่นี่ไม่ได้ — อันนั้นอยู่คนละหน้า"

**⑥ กฎห้ามพลาด**
- ❌ "Rule R-05: absolute_timeout > idle_timeout (blocking); warn_before < idle_timeout (blocking); admin_timeout ≤ user_timeout"
- ✅ "⚠️ เวลา 3 ตัวต้องเรียงให้ถูก ไม่งั้นเซฟไม่ได้: เวลานั่งเฉย ต้องน้อยกว่า เวลาใช้งานรวมสูงสุด · เวลาเตือนก่อนเด้ง ต้องน้อยกว่า เวลานั่งเฉย · กฎของแอดมิน ต้องเข้มกว่าหรือเท่ากับ ของผู้ใช้ทั่วไป"
