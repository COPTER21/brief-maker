# Kickoff checklist

## 1. ยืนยันแพ็กบรีฟ

- แสดง candidate ที่พบจริงใน `BRIEF_ROOT`
- ให้ผู้ใช้เลือกหรือระบุ path เอง
- ถ้า path ไม่มีจริง ให้ถามใหม่ ห้ามเลือกตัวแทน

## 2. โหลด context

- list `CENTRAL_PLAN` ก่อน แล้วอ่านทุกไฟล์ที่พบ
- อ่าน HTML เป็น markup; ถ้ายาวให้อ่านส่วนที่เกี่ยวข้องแต่ห้ามข้ามไฟล์
- อ่านทุกไฟล์ในแพ็กบรีฟที่ผู้ใช้ยืนยัน
- ตรวจ artifact เดิมของ feature ใน `OUTPUT_ROOT`
- อ่าน `LEGACY_CONTEXT` เฉพาะส่วนที่เกี่ยวข้อง
- ใช้ Codex memory/context ที่ระบบเปิดให้เข้าถึงเมื่อมี และตรวจว่าไฟล์ที่ memory อ้างถึงยังมีจริงก่อนนำมาใช้; ห้ามสร้างหรือ hardcode path memory แบบ Claude Code

## 3. ตรวจ contract

- หา `PREBRIEF_*.md`
- หา `FUNCTION_CHECKLIST_*.md` หรือ `_SEED_NOTES.md`
- นับ `FN` ทั้งหมดและ `FN-40` ที่ต้องทดสอบเชิงลบ
- ถ้าไม่มี checklist ให้สกัดรายการ FN จาก PREBRIEF และบันทึกไว้ใน E2E ภายหลัง
- ตรวจความขัดแย้งระหว่าง brief, checklist, global contracts และ artifact ที่ล็อกแล้ว
- ตรวจ OQ, dependency, wave และ edge เข้า/ออก
- คำกล่าวอ้างว่า “ผ่าน v8/E2E แล้ว” ไม่ใช่หลักฐาน ต้องวัดใหม่

## 4. รายงาน approval gate แรก

รายงาน:

- แผนกลางที่อ่าน พร้อมรายชื่อไฟล์จริง
- แพ็กบรีฟที่ยืนยัน พร้อมรายชื่อไฟล์จริง
- artifact/dependency ที่ต้องอิงและเหตุผล
- wave และ edge เข้า/ออก
- งานที่ทำไว้แล้วและ step ที่ค้าง
- จุดที่ต้องตัดสินใจทั้งหมด; ถ้าไม่มีให้เขียนว่า “ไม่มี”

ยื่นบล็อกนี้ตามลำดับเดิมโดยไม่ทำเครื่องหมายแนะนำและไม่หาหลักฐานมาตัดสินแทน:

```text
feature นี้เกี่ยวกับ declaration ตัวไหนบ้าง (เลือกได้หลายตัว / ไม่เลือกก็ได้)
1) doccfg-declaration — ออกเอกสารที่มีเลขรัน
2) doa-declaration    — มีสายอนุมัติ
3) ntf-declaration    — มี event แจ้งเตือน
0) ไม่ใช้สักตัว
?) ยังไม่รู้ — ถามใหม่ที่จุดหยุด 2
```

- เก็บตัวเลือกของผู้ใช้ไว้ใช้ตลอด workflow
- ที่จุดหยุดหลัง step 5 ให้ทวนตัวเลือกหนึ่งบรรทัดและอนุญาตให้เปลี่ยน
- หลัง step 7 ให้รันเฉพาะตัวที่เลือก การเลือกไว้ถือเป็นคำสั่งแล้ว ไม่ต้องถามซ้ำ
- ถ้าเลือก `0` ห้ามทักเรื่อง declaration ซ้ำระหว่างทาง
- ถ้าเลือก `?` ให้ถามอีกครั้งเฉพาะที่จุดหยุดหลัง step 5
- ห้ามเดารหัส สายอนุมัติ หรือ event; ถ้าข้อมูลปลายทางไม่พอให้ยกเป็น OQ
- ที่ step 12 ให้บันทึก `declaration รอบนี้: ...` หรือ `declaration รอบนี้: ไม่มี`

จบด้วยข้อความว่าหลังอนุมัติจะทำ `1→5` และหยุดให้ตรวจ ห้ามเริ่ม step 1 ใน turn เดียวกับ kickoff
