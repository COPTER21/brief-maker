# FUNCTION_CHECKLIST Template

ไฟล์: `FUNCTION_CHECKLIST_[F-code]_[Name].md` — เอกสารติ๊กสำหรับทีมที่ทำต่อ
เปิดอ่านจบใน 5 นาที · 1 FN = ความสามารถ 1 ข้อที่ทดสอบด้วยตาได้ · ใช้ไฟล์เดียวทั้ง chain
(WF = wireframe review · DEV = ตอน dev ทำจริง · QA = ตอนทดสอบ)

★ md นี้เป็น **source of truth** ของ `FUNCTION_CHECKLIST_[F-code].html` (checklist ติ๊กได้/ส่งผลได้ —
สร้างด้วย `scripts/build_checklist_html.py`) — parser อ่านโครงข้างล่างนี้ตรง ๆ **ห้ามเปลี่ยนโครง**:
- หมวด: `## หมวด N · ชื่อ` (1 หมวด = 1 หน้าใน HTML) · หัวตารางทุกหมวด `| FN | ต้องทำอะไรได้ | trace | WF | DEV | QA |`
  (คอลัมน์หลัง trace = ด่าน — เพิ่ม `UAT` ได้ถ้าจำเป็น แต่ต้องเหมือนกันทุกหมวด)
- แถว: `| FN-XX | ข้อความ | trace | ☐ | ☐ | ☐ |` — id ขึ้นด้วย `FN-` ห้ามซ้ำ · trace คั่นด้วย `·` หรือ `,` ·
  tag `[STD]/[AI-DRAFT]` ใส่ท้ายข้อความได้ (HTML แสดงเป็น badge)
- section สุดท้าย `## สิ่งที่ไม่รองรับ ...` เป็น bullet `- ข้อความ — [มติ/OQ-x] เหตุผล` (แยก why หลัง " — ")

กติกา:
- FN เขียนภาษา "ทดสอบด้วยตาได้" — มีประธาน+การกระทำ+ผลที่เช็คได้ ไม่ใช่ภาษา spec
- ทุก S-XX ใน PREBRIEF ต้องมี ≥1 FN · ทุก FN ต้องมี trace
- หมวด "ไม่รองรับ" บังคับมี — กัน scope งอกเงียบ ๆ และกันทีมเข้าใจว่าตกหล่น
- ไฟล์นี้แนบเข้า pack ส่ง dev เสมอ (ทั้ง .md และ .html) และ qc-coverage-checker ใช้เทียบได้
- แก้ข้อความ/เพิ่ม FN = แก้ที่ md แล้ว build .html ใหม่ — ห้ามแก้ใน HTML โดยตรง (ผลติ๊กอยู่ใน
  localStorage ของเครื่องผู้เช็ค ไม่หายเมื่อ build ใหม่ตราบที่ FN id เดิม)
