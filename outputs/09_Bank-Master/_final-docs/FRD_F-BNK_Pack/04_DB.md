## §4.2 Per-Table Schema

> **⭐ Data Classification required (R10):** every field carries `Classification` (Public / Internal / Confidential / Restricted). **Default = Internal.** See §4.6.

### T_bank (E1 — Bank list)

**Purpose:** Bank directory. Preset rows (ธปท. 22) are read-only seed; custom rows are user-created foreign banks.

| Column | Type | Null | Default | Classification | PII | Description |
|---|---|---|---|---|---|---|
| `code` | varchar(3) | YES | — | Internal | — | ธปท. (BOT) code, 3 digits. PK for preset; custom may be null → use `id` |
| `id` | uuid | NO | gen_random_uuid() | Internal | — | Surrogate PK (stable for both preset + custom) |
| `tenant_id` | uuid | YES | — | Internal | — | NULL for global presets; set for custom banks; RLS |
| `name_th` | varchar(120) | NO | — | Internal | — | Bank name (Thai) |
| `abbr` | varchar(16) | NO | — | Internal | — | Short code (uppercase), e.g. KBANK, SCB |
| `swift` | varchar(11) | NO | — | Internal | — | SWIFT/BIC — 8 or 11 alnum (BR-BNK-04) |
| `type` | varchar(10) | NO | 'local' | Internal | — | enum: `local` / `foreign` |
| `color` | varchar(7) | YES | — | Internal | — | brand hex (identity/fallback token only — no `.bank-logo`) |
| `is_custom` | boolean | NO | false | Internal | — | true = user-created (editable/deletable); false = preset (read-only, R-12) |
| `used_count` | integer | NO | 0 | Internal | — | derived: # accounts referencing this bank; controls delete guard (BR-BNK-08 / W1) |
| `created_at` | timestamp | NO | NOW() | Internal | — | audit |
| `created_by` | uuid | YES | — | Internal | — | FK → T_user (null for seed) |

**Constraints:**
- PRIMARY KEY (id)
- UNIQUE (tenant_id, code) WHERE code IS NOT NULL
- CHECK (type IN ('local','foreign'))
- CHECK (swift ~ '^[A-Z0-9]{8}$' OR swift ~ '^[A-Z0-9]{11}$') — BR-BNK-04
- CHECK (is_custom = true OR created_by IS NULL) — presets have no creator
- **App-guard (not DB):** preset rows (`is_custom=false`) reject UPDATE/DELETE (R-12); custom DELETE allowed only when `used_count = 0` (BR-BNK-08 / W1)

**Indexes:**
- IDX_bank_tenant ON (tenant_id)
- IDX_bank_custom ON (is_custom)

**RLS:** `USING (tenant_id IS NULL OR tenant_id = current_setting('app.current_tenant')::uuid)` — presets visible to all tenants; customs isolated.

### T_company_bank_account (E2 — the master transaction)

**Purpose:** One row per company bank account. Holds the sensitive account number.

| Column | Type | Null | Default | Classification | PII | Description |
|---|---|---|---|---|---|---|
| `id` | uuid | NO | gen_random_uuid() | Internal | — | PK (display id BA-NNN derived) |
| `tenant_id` | uuid | NO | — | Internal | — | RLS |
| `company_id` | uuid | NO | — | Internal | — | FK → T_company (scope key) |
| `bank_code` | varchar(3) | YES | — | Internal | — | soft-ref → T_bank.code (nullable, no cascade — Contract #6) |
| `bank_id` | uuid | YES | — | Internal | — | soft-ref → T_bank.id (stable ref) |
| `acc_no` | varchar(32) | NO | — | **Restricted** | — | **SENSITIVE** — numeric 10–15 digits. Stored encrypted-at-rest (C-ENC-01). Masked to last-4 by default; full reveal ACL-gated + audited (BR-BNK-09) |
| `acc_no_last4` | varchar(4) | NO | — | Confidential | — | Denormalized last-4 for masked display without decrypting `acc_no` |
| `acc_name` | varchar(160) | NO | — | **Confidential** | **Yes** | Account holder name (PDPA scope) |
| `acct_type` | varchar(10) | NO | — | Internal | — | enum: `savings` / `current` / `fixed` |
| `branch` | varchar(120) | YES | — | Confidential | — | Branch name |
| `gl_code` | varchar(20) | NO | — | Confidential | — | soft-ref → T_chart_of_account (inbound; required before use — BR-BNK-11) |
| `currency` | varchar(3) | NO | 'THB' | Internal | — | **THB only, readonly (BR-BNK-10).** Column exists to enable multi-currency later without schema change (OQ-2) |
| `status` | varchar(10) | NO | 'active' | Internal | — | enum: `active` / `inactive` / `archived` (archived = terminal) |
| `default_pay` | boolean | NO | false | Internal | — | ≤1 true per company (BR-BNK-02) |
| `default_receive` | boolean | NO | false | Internal | — | ≤1 true per company (BR-BNK-02) |
| `used_in_doc` | boolean | NO | false | Internal | — | derived: referenced by any doc (PV/RV/Recon/Payroll); controls archive-lock (BR-BNK-06) |
| `created_at` | timestamp | NO | NOW() | Internal | — | audit |
| `created_by` | uuid | NO | — | Internal | — | FK → T_user |
| `updated_at` | timestamp | NO | NOW() | Internal | — | audit + optimistic lock source |
| `updated_by` | uuid | YES | — | Internal | — | FK → T_user |
| `version` | integer | NO | 1 | Internal | — | Optimistic locking (PR-2) → `If-Match` / 409 |

**Constraints:**
- PRIMARY KEY (id)
- **UNIQUE (tenant_id, company_id, acc_no)** — accNo unique per company (BR-BNK-01)
- CHECK (acct_type IN ('savings','current','fixed'))
- CHECK (status IN ('active','inactive','archived'))
- CHECK (currency = 'THB') — R-10 lock this phase (remove/relax when OQ-2 resolves via toggle, not schema change)
- CHECK (acc_no ~ '^[0-9]{10,15}$') — BR-BNK-03 (range from config `accNo_length_range`; DB check is backstop)
- **Partial unique (default enforcement — BR-BNK-02):**
  - `CREATE UNIQUE INDEX uq_default_pay ON T_company_bank_account (tenant_id, company_id) WHERE default_pay = true;`
  - `CREATE UNIQUE INDEX uq_default_receive ON T_company_bank_account (tenant_id, company_id) WHERE default_receive = true;`
- **No FK cascade** on `bank_code`/`bank_id`/`gl_code` (nullable soft-ref — Contract #6)
- **No hard delete** — status→archived only (Contract #7; enforced at API/app layer, no DELETE endpoint on accounts)

**Indexes:**
- IDX_cba_company_status ON (tenant_id, company_id, status)
- IDX_cba_bank ON (tenant_id, bank_code)
- IDX_cba_gl ON (tenant_id, gl_code)

**RLS:** `USING (tenant_id = current_setting('app.current_tenant')::uuid)`

### T_bank_audit_log (E3 — append-only, 2 streams)

**Purpose:** Immutable audit. One table, two streams keyed by `account_id` (account stream) OR `bank_code` (bank stream). Never UPDATE/DELETE (append-only — Contract #7). Newest-first display (`unshift` semantics → ORDER BY created_at DESC).

| Column | Type | Null | Default | Classification | PII | Description |
|---|---|---|---|---|---|---|
| `id` | uuid | NO | gen_random_uuid() | Internal | — | PK |
| `tenant_id` | uuid | NO | — | Internal | — | RLS |
| `account_id` | uuid | YES | — | Internal | — | FK → T_company_bank_account (account stream; null for bank stream) |
| `bank_code` | varchar(3) | YES | — | Internal | — | FK → T_bank.code (bank stream; null for account stream) |
| `bank_id` | uuid | YES | — | Internal | — | FK → T_bank.id |
| `action` | varchar(24) | NO | — | Internal | — | enum below |
| `detail` | text | YES | — | Confidential | — | human-readable detail; **MUST NOT contain full account number** (log last-4 only) |
| `actor` | uuid | NO | — | Internal | — | FK → T_user (who performed) |
| `created_at` | timestamp | NO | NOW() | Internal | — | timestamp (immutable) |

**`action` enum (verbatim from HTML `AUDIT_META` + `pushAudit`/`pushBankAudit` — HTML is source of truth):**
Account stream: `created` · `edited` · `revealed` · `set-default` · `deactivated` · `activated` · `archived`
Bank stream: `bank-added` · `bank-edited` · `bank-removed`

> **⚠️ Section-M drift note:** BRD §6 E3 listed the default action as `default-changed`; the gated HTML uses **`set-default`** and also has **`bank-edited`** (not in BRD list). Per R14 HTML fidelity, the enum follows the HTML. See 01_UI §1.9 Section M.

**Constraints:**
- PRIMARY KEY (id)
- CHECK (account_id IS NOT NULL OR bank_code IS NOT NULL) — exactly one stream
- CHECK (action IN ('created','edited','revealed','set-default','deactivated','activated','archived','bank-added','bank-edited','bank-removed'))
- **Append-only:** REVOKE UPDATE, DELETE on T_bank_audit_log (grant INSERT + SELECT only)

**Indexes:**
- IDX_audit_account ON (tenant_id, account_id, created_at DESC)
- IDX_audit_bank ON (tenant_id, bank_code, created_at DESC)
- IDX_audit_reveal ON (tenant_id, action, created_at DESC) WHERE action = 'revealed' — anomaly/threshold monitoring (BRD §17.4: reveal > 50/user/day)

**RLS:** `USING (tenant_id = current_setting('app.current_tenant')::uuid)`

## §4.3 Relationships (ER Diagram)

```
T_company (1) ──< (N) T_company_bank_account          [scope key]
T_bank (1) ──(soft-ref, no cascade)──< (N) T_company_bank_account.bank_code
T_chart_of_account (1) ──(soft-ref, inbound)──< (N) T_company_bank_account.gl_code
T_company_bank_account (1) ──< (N) T_bank_audit_log   [account stream: account_id]
T_bank (1) ──< (N) T_bank_audit_log                   [bank stream: bank_code]
T_company_bank_account ──(picker/soft-ref, snapshot on pick)──▶ PV · RV · Bank Recon · Payroll
```
- All cross-master FKs are **nullable, no cascade** (Global Contract #6).

## §4.4 Migration Strategy

### Initial migration
- [ ] Create T_bank, T_company_bank_account, T_bank_audit_log + RLS + indexes.
- [ ] **Seed T_bank with ธปท. 22 presets** (`is_custom=false`, `tenant_id=NULL`, code/name_th/abbr/swift/type/color) — read-only seed.
- [ ] Configure column-level encryption for `acc_no` (C-ENC-01) + populate `acc_no_last4` on write.
- [ ] REVOKE UPDATE/DELETE on T_bank_audit_log (append-only).

### Data migration (legacy Registry accounts — OQ-BNK-06)
- Source: legacy Registry bank accounts (if any).
- Transformation: map bank → preset code, **backfill `gl_code`** (accounts without GL flagged non-compliant), populate `acc_no_last4`, encrypt `acc_no`.
- Rollback: keep legacy table read-only until reconciliation sign-off.

## §4.6 Data Classification & Sensitive Data ⭐ (R10)

### §4.6.1 Classification Levels
| Level | นิยาม | ในฟีเจอร์นี้ | UI Behavior | Export Behavior |
|---|---|---|---|---|
| Public | เผยแพร่ภายนอกได้ | (none) | — | — |
| Internal | เห็นได้เฉพาะคนใน (default) | status, defaults, bank list, audit timestamps | แสดงปกติ (authenticated) | export ได้ทุก internal role |
| Confidential | จำกัด role | `acc_name`(PII), `branch`, `gl_code`, `acc_no_last4`, audit `detail` | mask `***`/`—` ถ้า role ไม่ผ่าน | excluded column ถ้า role ไม่ผ่าน |
| **Restricted** | จำกัดถึงระดับ person (ACL) | **`acc_no` (full account number)** | **masked last-4; full hidden until `canRevealFull` reveal + audit** | **excluded + require Restricted Resources approval; mask always on export (OQ-BNK-03)** |

### §4.6.2 Default Rule
- Default = **Internal** (never Public). Every non-Internal field is explicit in §4.2.

### §4.6.3 Enforcement Mapping
| Classification | DB Layer | API Layer | UI Layer | Audit |
|---|---|---|---|---|
| Internal | RLS (tenant) | JWT auth | — | mutation |
| Confidential | RLS + column ACL | role check | mask `***` / `—` if no permission | view + mutation |
| **Restricted (`acc_no`)** | RLS + **encrypt at rest** + row ACL (Restricted Resources) | **role + `canRevealFull` ACL check at reveal endpoint** | **masked last-4; reveal hidden unless permitted; button gated** | **view (reveal) + mutation + export attempts — every reveal writes `revealed` audit** |

### §4.6.4 PII Overlay
- `acc_name` → Confidential + **PII** (PDPA scope; encrypt at rest recommended).
- `acc_no` → Restricted + **not PII of a natural person per se** (it is a financial identifier) but treated as sensitive financial data (D5) with the strongest controls.

### §4.6.5 Security Bible Domain Mapping
| Domain | เกี่ยวข้องกับ |
|---|---|
| D5 (Financial) | `acc_no`, `gl_code` → audit mandatory; masking |
| D7 (PII) | `acc_name` → PDPA scope + encrypt at rest |
| D9 (Audit) | all mutations + **all reveals** → T_bank_audit_log (append-only) |

### §4.6.6 Linkage with Policy Center
- `acc_no` (Restricted) → **Restricted Resources registry** (ACL per-record) + **Data Classification module**. ⚠️ **Registration status = OPEN — see 00_OVERVIEW OQ-BNK-06.**
- `acc_name` (PII) → PDPA consent scope.
- Classification defaults set at FRD/schema build-time; Policy Center may override at runtime (with audit).

## §4.8 Performance Considerations

| Query pattern | Optimization |
|---|---|
| List accounts by company + status (P-01) | IDX_cba_company_status |
| Masked list (no decrypt) | read `acc_no_last4` — never decrypt `acc_no` for lists |
| Bank delete guard (used_count) | IDX_cba_bank + maintained `used_count` on T_bank |
| Reveal anomaly monitor | IDX_audit_reveal (partial, action='revealed') |
| Picker (active only, cross-module) | IDX_cba_company_status WHERE status='active' |
