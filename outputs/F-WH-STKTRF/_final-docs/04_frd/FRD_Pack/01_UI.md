## 1.1 P-01 List

- Visible anchors: `ใบย้ายสินค้า`, `สร้างใบย้ายสินค้า`, tabs `ทั้งหมด`, `รอฉันรับ`, `อยู่ระหว่างทาง`.
- Search includes document number, warehouse, item, and creator. Secondary filters include source, destination, mode, status/date/reason.
- Table includes document, date, source, destination, mode, creator, transfer reason, total quantity/value, status, actions. Container must use horizontal scrolling; cells must not overlap or clip.
- Empty-search and no-data states are distinct and offer reset/create actions.
- Disabled actions use `.disabled-tip` with a visible reason; do not rely on native `title` for disabled controls.

## 1.2 P-02 Five-step wizard

1. Source/duplicate choice.
2. Main data: source/destination warehouses, dates, transfer reason, derived mode and read-only transit location.
3. B2 v2 line editor: item, source bin, available, quantity, UOM, destination bin, unit cost/value; column alignment must remain stable.
4. File upload using actual `<input type=file>` interaction and attachment list.
5. Review totals, destination recipient context, approver selection, save draft/submit.

Draft displays `ร่าง — ออกเลขอัตโนมัติเมื่อส่งอนุมัติ`. Submit calls DOCCFG; draft creation must not allocate a number.

## 1.3 P-03 View and state actions

- Header shows code, mode, route, status, creator and allowed actions.
- Receive is enabled only for `in_transit`/`partial`, for destination-warehouse users who are not the shipper, with positive actual remaining quantity.
- Reversal is offered only for completed states and creates a new approval-pending document. Original status changes to `reversed` only when reversal completes.
- Shipment uses an in-product confirmation modal. All mutation controls disable while busy and expose progress text.
- Transit/receipt tables scroll horizontally when required.

## 1.4 Overlay dismissal and accessibility

- Escape order: combobox → row menu → modal → create drawer → view drawer.
- Modal cancel closes without mutation; clicking `ยกเลิก` in approver picker means close/cancel only.
- Focus returns to the launcher; visible labels/ARIA names identify filters, fields, tabs and actions.
- Error text appears adjacent to the failing field/action and is also announced by toast/live region.

## 1.5 State/action matrix

| State | Primary action | Secondary |
|---|---|---|
| draft | edit / submit | cancel |
| pending_approval | current assignee approve/reject | cancel if still no movement |
| approved | direct move or ship | cancel |
| in_transit / partial | destination receive | return; shortage flow |
| moved / closed / closed_diff | print / reversal | audit |
| cancelled / returned / reversed | view/print/audit | no mutation |

Every visible mutation maps to 02_API and 03_LOGIC. HTML prototype comments `BACKEND`, `DOCCFG`, `DOA`, `NTF`, `CSQ` are integration anchors, not client-side authority.
