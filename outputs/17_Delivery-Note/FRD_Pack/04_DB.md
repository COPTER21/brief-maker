# 04_DB — F-WH-DN Delivery Note

## §4.1 Tables

`delivery_note`, `delivery_note_pack`, `delivery_note_line`, `delivery_tracking`, `delivery_attempt`, `delivery_pod`, `delivery_manual_transition`, `delivery_audit`, plus transactional outbox. Foreign module IDs are soft references; no FK across module ownership boundaries.

## §4.3 Relationships

`delivery_note 1:N pack/line/tracking/attempt/manual_transition/audit`; `delivery_note 1:0..1 pod`. Unique `(tenant_id,dn_no)`, `(dn_id,pack_id)`, `(dn_id,attempt_no)`, `(dn_id,tracking.sequence)`.

## §4.4 Indexes and constraints

- indexes: tenant+status+ship_date, tenant+creation_mode+source_type, pack_id, source ref GIN, assignee+status, audit dn+at
- checks: quantity nonnegative; rejected≤qty; attempt_no≥1; tracking sequence positive
- manual mode check: source refs and gi_ref null; reference mode needs ≥1 pack
- idempotency/outbox unique keys prevent duplicate mutation/event
- audit rows immutable by application role

## §4.6 Data classification enforcement

### §4.6.1 Levels

Public is explicitly publishable; Internal is operational; Confidential includes identifiable/contact/delivery evidence; Restricted needs highest policy controls. This feature has no known Restricted field.

### §4.6.2 DB

Tenant RLS, encryption at rest for confidential snapshots, immutable audit and least-privilege service roles.

### §4.6.3 API

Field-level projection by role, signed media references, no tenant scope from body, masked phone where full value is unnecessary.

### §4.6.4 UI/export

Hide mutation controls by permission but enforce on backend; minimize PII in tables/toasts/print; export/print is audited.

### §4.6.5 Audit/log

Log IDs/hashes and outcomes, not full address/phone/signature content; correlation IDs link engine/outbox failures.

### §4.6.6 Policy linkage

Any future Restricted field must be registered in Restricted Resources; classification overrides belong to central Data Classification policy.
