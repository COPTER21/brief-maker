## §1.2 Per-Page Detail

### P-01: รายการเงื่อนไขชำระเงิน
**Purpose:** จุดกลางค้นหา/กรอง/จัดการเงื่อนไขทั้งหมด
**Pattern:** A — list-view (จาก §1.0)

**ERP Context:**
- Sidebar active: "เงื่อนไขชำระเงิน" (module "การเงิน" expanded) · shell-bar ขาว + breadcrumb "การเงิน › เงื่อนไขชำระเงิน"
- ph-title "เงื่อนไขชำระเงิน" + ph-count "`N` เงื่อนไข"

**Components (canonical, จาก html-generator-v8 catalog):**
- **Stat cards ×4** (กดกรอง toggle-off): ทั้งหมด / ใช้งาน / ไม่ใช้งาน / ร่าง — meta ต่อใบ
- **Filter bar:** search-box ("ค้นหารหัส หรือชื่อเงื่อนไข...") + type combobox (`sdd` filterType, 7 ค่า + "ทุกประเภท", แต่ละ option มี sub-desc)
- **Bulk bar** (โผล่เมื่อ select ≥1): "เลือก N รายการ" + ปุ่ม ใช้งาน / ไม่ใช้งาน / ร่าง / **ลบ** (danger) / ยกเลิก
- **Data table** (`.data-table` fixed layout, ใน `.tbl-scroll` sticky thead): checkbox · รหัส (+ ⭐ default) · ชื่อเงื่อนไข (+EN) · ประเภท (pill) · สรุปเงื่อนไข (termSummary) · สถานะ (pill) · จัดการ (ปุ่มแก้ไขเท่านั้น)
- **Table footer:** caption + "แสดง N จาก M เงื่อนไข"
- **Empty:** "ไม่พบเงื่อนไขที่ตรงกับการค้นหา"

**Actions:**
| Action | Triggers | Calls (API) |
|---|---|---|
| Click row | เปิด view drawer (P-04) | F-PAY-API-03 GET /payment-terms/:id |
| Click "เพิ่มเงื่อนไข" | เปิด create form (P-02) | — (navigate) |
| Click ปุ่มแก้ไข (row) | เปิด edit form (P-03) | F-PAY-API-03 |
| Search input | filter table (client/server) | F-PAY-API-01 GET /payment-terms?search= |
| Type filter pick | filter | F-PAY-API-01 ?type= |
| Stat card click | filter by status (toggle-off) | F-PAY-API-01 ?status= |
| Checkbox / Select all | bulk selection | — |
| Bulk set status | เปลี่ยนสถานะหลายรายการ | F-PAY-API-06 POST /payment-terms/bulk-status |
| Bulk ลบ | เปิด confirm modal (P-05) | — (navigate) |

**States:** Loading (skeleton table) · Empty (ไม่พบรายการ) · Error (retry) · Loaded.
**Permissions:** Finance Admin = ทุก action · Finance Viewer = ดู/ค้นหาเท่านั้น (ไม่มีปุ่ม create/edit/bulk).

### P-02 / P-03: เพิ่ม / แก้ไขเงื่อนไขชำระเงิน
**Purpose:** สร้าง/แก้ไข term โดย field ปรับตาม 7 ประเภท
**Pattern:** B — drawer (.standard 680px), single-step (จาก §1.0)

**Sections (observed `renderForm`):**
1. **ข้อมูลทั่วไป:** รหัส (Code, uppercase, required) · ชื่อ TH (required) · ชื่อ EN · ประเภทเงื่อนไข (`sdd` type combobox, required, `onTypeChange` สลับ field set)
2. **การตั้งค่าเฉพาะประเภท** (แปรตาม `type` — ดูตารางล่าง) + Due basis (`sdd`, ยกเว้น Direct)
3. **การใช้งานในเอกสาร:** checkbox grid 7 เอกสาร แยกกลุ่ม "ฝั่งซื้อ (P2P)" / "ฝั่งขาย (S2C)" + chk-count "N เลือก" · Direct ปิด po/quotation/so (is-disabled + "ไม่รองรับ")
4. **ตั้งค่าทั่วไป:** สถานะ (select 3 ค่า, default active) · toggle "ตั้งเป็นค่า Default" (1/ประเภท)

**Per-type field set (observed `onTypeChange` + `renderForm`):**
| type | fields ที่แสดง | trigger |
|---|---|---|
| full_prepay | (trigger only) + due_basis | dropdown, default after_full |
| full_postpay | net_days (0=ทันที) + discount(opt) + due_basis | dropdown, default immediate |
| credit | net_days (>0) + discount(opt) + due_basis | **lock badge "ทันที (ล็อกตามประเภท)"** (LD-08b) |
| deposit | deposit_method(3) + deposit_value(≤100 if %) + remaining_timing(3) + net_days + due_basis | dropdown, default after_deposit (after_deposit เฉพาะ deposit) |
| installment | schedule editor (add/remove งวด ≥2, %, due_type, desc) + live total + due_basis | dropdown, default immediate |
| partial_delivery | net_days ต่อรอบ (optional) + due_basis(=delivery) | dropdown, default immediate |
| direct_payment | expense_category(3) + note "ไม่ผ่าน PR/PO/QUO→SO" | **ไม่มี trigger** (noTrigger) · ไม่มี due_basis |

**Actions:**
| Action | Triggers | Calls (API) |
|---|---|---|
| เปลี่ยนประเภท | `onTypeChange` reset field set | — (client) |
| เพิ่ม/ลบงวด | `addInst`/`removeInst` (disabled ≤2) | — (client) |
| toggle use_in | `toggleUseIn` | — (client) |
| toggle default | `toggleDefault` | — (client) |
| "บันทึกและสร้าง" | `submitTerm()` validate → create | F-PAY-API-02 POST /payment-terms |
| "บันทึกการแก้ไข" | `submitTerm()` validate → update | F-PAY-API-04 PUT /payment-terms/:id |
| "ยกเลิก" / X / Esc | close drawer | — |

**States:** validation error (field `is-invalid` + `field-error` + toast) · edit prefill · Direct-disabled docs.
**Permissions:** Finance Admin only.

## §1.3 User Journey (Happy Path — สร้าง Credit S-01)

```
Finance Admin เปิด P-01 (List)
  ↓ กด "เพิ่มเงื่อนไข"
P-02 drawer เปิด (default type=credit, net_days=30, due_basis=invoice_date)
  ↓ เลือกประเภท "เครดิต" (onTypeChange → net_days + discount + trigger lock badge)
  ↓ กรอก code (uppercase) / ชื่อ TH / net_days (>0) / discount (optional) / due_basis
  ↓ เลือก use_in ≥1 (จาก 7 เอกสาร) · สถานะ · (optional) Default
  ↓ กด "บันทึกและสร้าง" → submitTerm() validate
  ├─ ผ่าน → POST /payment-terms (F-PAY-API-02) → close drawer → toast "สร้างเงื่อนไขชำระเงินแล้ว" (success)
  └─ ไม่ผ่าน → field is-invalid + toast error (ไม่ปิด drawer)
```

### Branch: เปลี่ยนสถานะ (S-08, no approval)
```
P-04 view → "เปลี่ยนสถานะ" menu → เลือก 1/3 ค่า → PATCH /:id/status → toast "เปลี่ยนสถานะเป็น [label] แล้ว"
หรือ P-01 bulk bar → set status → POST /bulk-status → toast "เปลี่ยนสถานะ N รายการเป็น [label] แล้ว"
```

### Branch: bulk ลบ (S-09)
```
P-01 select ≥1 → bulk "ลบ" → P-05 modal (บอกลบ/ข้าม) → "ลบ D รายการ" → POST /bulk-delete
→ close → toast "ลบแล้ว D รายการ · ข้าม M รายการที่ถูกใช้งาน" (info ถ้ามีข้าม / success ถ้าไม่มี)
```
