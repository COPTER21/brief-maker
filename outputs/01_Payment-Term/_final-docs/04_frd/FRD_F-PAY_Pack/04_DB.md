> **Audience:** DBA / Backend developer

## §4.1 Table Overview

| Table | Purpose | Owner Feature | Multi-tenant |
|---|---|---|---|
| `T_payment_term` | Master record เงื่อนไขการชำระเงิน (1 ใน 7 ประเภท) | F-PAY (this) | YES (RLS) |
| `T_payment_term_installment` | งวดการชำระ (child, เฉพาะ type=installment) | F-PAY (this) | YES (via parent) |

> **use_in** เก็บเป็น `text[]` (array) ใน `T_payment_term` (7 ค่า enum) — ไม่แยก child table (small fixed set, query แบบ contains). Alternative child table `T_payment_term_use_in` = acceptable ถ้า DBA ต้องการ index แบบ relational (บันทึกเป็น decision, ไม่ blocking).
> **snapshot:** เอกสารปลายทางเก็บ code + config ของ term ในตารางของตัวเอง (ไม่อยู่ใน pack นี้) — **soft-ref, no FK cascade** (Central Plan LD-4C-02).

## §4.2 Per-Table Schema

> **Data Classification (v5.1):** ทุก field ระบุ `Classification` (Public / Internal / Confidential / Restricted). **Default = Internal**. Feature นี้ = master config การเงิน, **ไม่มี PII**, highest = **Internal** (ควบคุมเชิงเงินบังคับที่เอกสารปลายทาง ไม่ใช่ตัว master). ดู §4.6.

### T_payment_term

**Purpose:** Master record ต่อ 1 เงื่อนไขการชำระเงิน

| Column | Type | Null | Default | Classification | PII | Description |
|---|---|---|---|---|---|---|
| `id` | uuid | NO | gen_random_uuid() | Internal | — | PK (prototype ใช้ `t{seq}`) |
| `tenant_id` | uuid | NO | — | Internal | — | FK → T_tenant; RLS |
| `code` | varchar(32) | NO | — | Internal | — | รหัส, **UPPERCASE, unique/tenant** (BR-01) |
| `name` | varchar(160) | NO | — | Internal | — | ชื่อเงื่อนไข (TH) |
| `name_en` | varchar(160) | YES | — | Internal | — | ชื่อเงื่อนไข (EN) |
| `type` | varchar(20) | NO | — | Internal | — | enum 7 ค่า (§4.2a) — fix ต่อ record |
| `trigger` | varchar(20) | YES | per-type | Internal | — | immediate / after_deposit / after_full · null สำหรับ direct_payment · Credit locked=immediate (LD-08b, BR-10) |
| `due_basis` | varchar(20) | YES | 'invoice_date' | Internal | — | invoice_date / eom / delivery · null สำหรับ direct_payment (BR-13) |
| `net_days` | integer | YES | — | Internal | — | ≥0. Credit >0 (BR-02) · Postpay ≥0 · Deposit = ส่วนที่เหลือ · Partial = ต่อรอบ (optional) |
| `discount_pct` | numeric(5,2) | YES | — | Internal | — | ส่วนลดจ่ายเร็ว % (Credit, optional, 1 ช่วง AD-02) |
| `discount_days` | integer | YES | — | Internal | — | ภายในกี่วัน · >0 และ < net_days (BR-05) |
| `deposit_method` | varchar(10) | YES | — | Internal | — | percent / fixed / manual (Deposit) |
| `deposit_value` | numeric(15,2) | YES | — | Internal | — | % หรือ บาท · percent → 0<x≤100 (BR-03) · manual → null |
| `remaining_timing` | varchar(20) | YES | — | Internal | — | after_delivery / after_receipt / per_contract (Deposit) |
| `expense_category` | varchar(20) | YES | — | Internal | — | utility / contract / other (Direct) |
| `use_in` | text[] | NO | '{}' | Internal | — | ≥1 ค่าจาก 7 เอกสาร (BR-06). **ไม่มี 'pr'** (D-08) |
| `is_default` | boolean | NO | false | Internal | — | 1 ตัว/ประเภท · ต้อง status=active (BR-07) |
| `status` | varchar(10) | NO | 'active' | Internal | — | draft / active / inactive (อิสระ 3 ค่า) |
| `used` | integer | NO | 0 | Internal | — | (ระบบ) จำนวนเอกสารอ้าง — guard ลบ. **นิยามจริง = OQ-PAY-07** |
| `approver_role` | varchar(40) | YES | **null** | Internal | — | DOA placeholder (no approval) |
| `approved_by` | uuid | YES | **null** | Internal | — | DOA placeholder |
| `approved_at` | timestamptz | YES | **null** | Internal | — | DOA placeholder |
| `approval_chain` | jsonb | YES | **null** | Internal | — | DOA placeholder |
| `created_at` | timestamptz | NO | NOW() | Internal | — | Audit (append-only) |
| `updated_at` | timestamptz | NO | NOW() | Internal | — | Audit + optimistic lock (AD-04) |
| `created_by` | uuid | NO | — | Internal | — | FK → T_user |
| `updated_by` | uuid | YES | — | Internal | — | FK → T_user |
| `version` | integer | NO | 1 | Internal | — | Optimistic locking (EC-01 / AD-04) |

**Constraints:**
- PRIMARY KEY (id)
- UNIQUE (tenant_id, code) — code unique/tenant (BR-01)
- CHECK (type IN ('full_prepay','full_postpay','deposit','installment','partial_delivery','credit','direct_payment'))
- CHECK (status IN ('draft','active','inactive'))
- CHECK (trigger IS NULL OR trigger IN ('immediate','after_deposit','after_full'))
- CHECK (due_basis IS NULL OR due_basis IN ('invoice_date','eom','delivery'))
- CHECK (type <> 'credit' OR (net_days IS NOT NULL AND net_days > 0)) — BR-02
- CHECK (deposit_method <> 'percent' OR (deposit_value > 0 AND deposit_value <= 100)) — BR-03
- CHECK (discount_pct IS NULL OR (discount_days IS NOT NULL AND discount_days > 0 AND discount_days < net_days)) — BR-05
- CHECK (array_length(use_in,1) >= 1) — BR-06
- **Partial-unique index** default (ดู Indexes) — BR-07
- Editing allowed แม้ used>0 (AD-01) — **ไม่มี** trigger/constraint ล็อกการแก้เมื่อ used>0
- Delete guard used>0 = enforced ที่ logic/API (F-PAY-FN-07), ไม่ใช่ DB (soft — bulk ข้าม)

**Indexes:**
- IDX_pt_tenant_status ON (tenant_id, status)
- IDX_pt_tenant_type ON (tenant_id, type)
- **UNIQUE IDX_pt_default_per_type ON (tenant_id, type) WHERE is_default = true** — enforce 1 default/ประเภท (BR-07)
- IDX_pt_code ON (tenant_id, code)
- IDX_pt_use_in GIN (use_in) — downstream picker query
- IDX_pt_created_at ON (created_at DESC)

**RLS Policy:**
```sql
CREATE POLICY tenant_isolation ON T_payment_term
  USING (tenant_id = current_setting('app.current_tenant')::uuid);
```

### T_payment_term_installment

**Purpose:** งวดการชำระ (เฉพาะ type=installment) — ≥2 งวด, รวม pct = 100% (BR-04)

| Column | Type | Null | Default | Classification | PII | Description |
|---|---|---|---|---|---|---|
| `id` | uuid | NO | gen_random_uuid() | Internal | — | PK |
| `tenant_id` | uuid | NO | — | Internal | — | RLS |
| `payment_term_id` | uuid | NO | — | Internal | — | FK → T_payment_term (ON DELETE CASCADE ภายใน master เดียวกัน) |
| `seq` | integer | NO | — | Internal | — | ลำดับงวด (1..N) |
| `pct` | numeric(5,2) | NO | — | Internal | — | สัดส่วนงวด (0–100) |
| `days` | integer | NO | 0 | Internal | — | จำนวนวัน (สำหรับ days_after_delivery) |
| `due_type` | varchar(24) | NO | — | Internal | — | on_doc / days_after_delivery / manual |
| `description` | varchar(200) | YES | — | Internal | — | รายละเอียดงวด |

**Constraints:**
- PRIMARY KEY (id)
- FOREIGN KEY (payment_term_id) REFERENCES T_payment_term(id) ON DELETE CASCADE
- CHECK (due_type IN ('on_doc','days_after_delivery','manual'))
- CHECK (pct >= 0 AND pct <= 100)
- UNIQUE (payment_term_id, seq)
- **Application-enforced** (ENG-PT-01): count ≥ 2 AND SUM(pct)=100 per payment_term_id (BR-04)

**Indexes:** IDX_pti_term ON (payment_term_id, seq)

> **Note:** CASCADE นี้เป็น **internal composition** (งวดของ master เดียวกัน) — ไม่ใช่ soft-ref downstream. Downstream doc snapshot งวดทั้งชุด ณ เวลาสร้าง (ไม่ FK).

## §4.3 Relationships (ER)

```
T_payment_term (1) ──< (N) T_payment_term_installment   [internal composition, CASCADE]
T_tenant (1) ──< (N) T_payment_term                     [RLS isolation]
T_user  (1) ──< (N) T_payment_term (created_by/updated_by)

T_payment_term ──(soft-ref: snapshot code+config, NO FK)──▶ PO / AP Invoice / Payment Voucher   [ฝั่งซื้อ]
               ──(soft-ref: snapshot, NO FK)─────────────▶ SO / Quotation / AR Invoice / Receipt [ฝั่งขาย]
               ──(drives)────────────────────────────────▶ Warehouse/GRN/Ship  (ENG-PT-02)
               ──(drives)────────────────────────────────▶ Accounting/GL (ENG-PT-01 · deposit VAT Hook-2 · cash-discount Hook-3)
```
- ทุก downstream edge = **soft-reference (snapshot, no FK cascade)** — แก้/ปิด master ไม่ย้อนแก้เอกสารเก่า.

## §4.6 Data Classification & Sensitive Data

### §4.6.1 Levels (CUBE 4.0)
Public / Internal / Confidential / Restricted — นิยามมาตรฐาน (ดู `04_db.template` §4.6.1).

### §4.6.2 Default Rule
- **Default = Internal** (ทุก field ใน §4.2). ห้าม default Public.

### §4.6.3 Feature classification decision
- **Highest level = Internal.** master config การเงินส่วนกลาง — เห็นได้ทุก authenticated finance role; **ไม่มี PII, ไม่มี Restricted/Confidential field** ในตัว master.
- เหตุผล: ตัวเลข config (net_days/discount/deposit%) = นิยาม policy กลาง ไม่ใช่ยอดเงิน transactional. ยอดเงินจริง/ควบคุมเชิงเงิน (P4) เกิดที่**เอกสารปลายทาง** (PO/Invoice/Payment) — คนละ feature.
- **หมายเหตุ downstream:** เมื่อ term ถูก snapshot ลง vendor/customer-specific doc ค่านั้นอาจ Confidential ในบริบทเอกสารนั้น — enforce ที่ feature ปลายทาง ไม่ใช่ที่นี่.

### §4.6.4 PII Overlay
- ไม่มี field ใดเป็น PII (pii_flag = false ทั้งหมด). D7 = N/A.

### §4.6.5 Security Bible Domain Mapping
| Domain | เกี่ยวข้อง |
|---|---|
| **D5 (Financial config):** ทุกการแก้ master → audit log mandatory (ใครแก้เงื่อนไขการเงิน) |
| **D9 (Audit):** ทุก mutation → T_audit_log (append-only) |
| **D17 (Multi-tenant):** RLS by tenant_id |
| D7 (PII) | N/A — ไม่มี personal data |

### §4.6.6 Linkage with Policy Center
- **ไม่มี Restricted field** → ไม่ต้อง register Restricted Resources.
- DOA placeholder (approver_role/approved_by/approved_at/approval_chain) = Internal, null → wire Policy Center DOA ภายหลัง (ไม่ใช่ sprint นี้).
