```
T_training_course (1) ──< (N) T_training_session (1) ──< (N) T_training_enrollment
```

## §4.6 Data Classification & Sensitive Data

### §4.6.1 Levels — ใช้ 4 ระดับมาตรฐาน (Public/Internal/Confidential/Restricted)
### §4.6.2 Default = Internal (ห้าม default Public) — ทุก field ใน §4.2 ระบุครบ

### §4.6.3 Enforcement Mapping

| Classification | DB | API | UI | Audit |
|---|---|---|---|---|
| Internal | RLS (tenant) | JWT | — | mutation |
| Confidential (emp snapshot/PII · gap_ref · approver · eval_comment) | RLS + column ACL | role check | mask ถ้าไม่ผ่าน | view + mutation |
| **Restricted (budget · มูลค่า EC · ต้นทุนต่อหัว)** | RLS + row/col ACL | role + ACL | **mask `••••••`** ถ้าไม่ unmask (viewer) | view + mutation + export |

### §4.6.4 PII Overlay
- `emp_snapshot` (name/position/dept) → Confidential + **PII** (PDPA scope)
- `approver_id` → Confidential + PII
- `budget` / มูลค่า EC → Restricted + **ไม่ PII** (ข้อมูลเงินองค์กร)

### §4.6.5 Security Bible Domain Mapping
- **D5 (Financial):** budget / EC → audit mandatory + Restricted
- **D7 (PII):** emp_snapshot / approver → PDPA scope + no PII in logs (ใช้ id ref)
- **D9 (Audit):** ทุก mutation → T_training_audit_log (append-only)

### §4.6.6 Linkage with Policy Center
- Restricted (budget/EC/ต้นทุนต่อหัว) → **Restricted Resources registry** (OQ ใน 00_OVERVIEW §0.8 · wire ตอน dev)
- PII (emp_snapshot/approver) → **PDPA consent scope**
- masking (FN-94) enforce ที่ API + UI (maskMoney) — ดู 03_LOGIC F-HR-TRAIN-FN-19
