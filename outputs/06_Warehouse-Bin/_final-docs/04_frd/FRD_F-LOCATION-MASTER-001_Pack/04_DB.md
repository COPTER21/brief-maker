Constraints:

- XOR: exactly one of `area_id`, `rack_id` is non-null
- direct Area parent requires `T_area.allows_direct=true`
- unique partial indexes per parent: `(tenant_id,rack_id,code)` and `(tenant_id,area_id,code)`
- `capacity_value > 0`
- status in `active,inactive,blocked,frozen,full,decommissioned`
- reason required for blocked/frozen; `full` is integration-derived; decommissioned is terminal in V1

`hasStock` is not persisted as source of truth in this table; resolve via Inventory contract before guarded mutations.

## §4.3 Relationships

```text
Company.T_branch 1 ~~ N T_warehouse (soft reference, no cascade)
T_warehouse 1 ─< N T_zone 1 ─< N T_area 1 ─< N T_rack
                                      ├─< N T_location (direct, allowed only)
                                      └──── T_rack 1 ─< N T_location
all owned nodes 1 ~~ N T_location_audit (logical immutable reference)
T_location_type_config 1 ─< N T_location
```

## §4.4 Migration Strategy

1. create type config and hierarchy tables parent-first
2. add constraints, partial unique indexes and tenant RLS
3. seed 10 type codes idempotently
4. create append-only audit table/permissions
5. rollback drops owned objects child-first only before production data; after go-live use forward migration/archive `[AI-DEFAULT]`

No legacy data source was supplied: ไม่พบข้อมูลในบทสนทนา.

## §4.5 Indexes and Query Paths

- each table: `(tenant_id,parent_id,code)`, `(tenant_id,status)`, `(tenant_id,updated_at desc)`
- `T_location`: `(tenant_id,location_type_code,status)`, trigram/full-text index on code/name only if measured `[AI-DEFAULT]`
- audit: `(tenant_id,node_type,node_id,occurred_at desc)`, unique `(tenant_id,correlation_id,node_id,action)` for idempotent append

## §4.6 Data Classification & Sensitive Data

| Highest level | PII fields | Enforcement |
|---|---|---|
| Internal | none | tenant RLS + authenticated API + mutation audit |

- Default is Internal; no field is Public, Confidential or Restricted in current scope
- branch/actor IDs are references only; APIs must not denormalize personal profile data into audit payloads
- secrets, tokens and credentials must never enter business or audit fields

## §4.7 Retention

- active masters retained while referenced; decommission rather than hard-delete Location
- audit retention period: ไม่พบข้อมูลในบทสนทนา; configure under platform audit policy, append-only
- parent hard-delete policy remains block-by-default pending OQ-LOC-04
