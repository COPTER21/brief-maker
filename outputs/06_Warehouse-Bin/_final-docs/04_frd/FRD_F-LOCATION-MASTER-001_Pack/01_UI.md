## §1.1 Route Model and Patterns

SPA นี้ไม่มี hash route. Route ที่ใช้จริงคือ state:

| Surface | State route | Pattern |
|---|---|---|
| P-01 Warehouse & Bin — List view | `state.view='list'; state.sel.level='root'` | A list + N shell |
| P-02 Location ทั้งหมด | `state.sel.level='all-locations'` | A list/filter/bulk |
| P-03 Hierarchy view | `state.view='hierarchy'` | NON-STANDARD hierarchy tree |
| D-01 Parent create/edit | `state.drawer.mode='create|edit'` | B form |
| D-02 Location create/edit | `state.drawer.level='location'; step=1|2` | B multi-step |
| D-03 Bulk generate | `state.drawer.mode='bulk'` | B batch form |
| D-04 Node detail | `state.drawer.mode='view'` | C view drawer |
| M-01 Status reason | `state.modal.level='status-reason'` | D confirmation |
| M-02 Delete/decommission | `state.modal.open=true` | D destructive confirmation |

## §1.2 Page and Action Contracts

### P-01 Warehouse & Bin — List view

- Renderer: `renderPage()` → `renderListContent()`
- Visible heading: `Warehouse & Bin`
- Visible subtitle: `โครงสร้างจัดเก็บ 5 ระดับ Warehouse › Zone › Area › Rack › Location — แม่แบบตำแหน่งของทุกคลัง`
- Drill row updates `state.sel`; breadcrumb returns to selected ancestor
- Calls API-01 for root/child list, API-04 for detail; create/edit actions require `canManage`

### P-02 Location ทั้งหมด

- Entry: stat `Location`; heading `Location ทั้งหมด (ทุกคลัง · ข้ามชั้น)`
- Search placeholder: `ค้นหา รหัส/ชื่อตำแหน่ง...`
- Filters: Location type + status; checkbox selection reveals bulk bar
- Calls API-03; detail API-04; bulk status API-18; bulk UOM API-19
- Empty title: `ไม่พบรายการ`; empty description is taken verbatim from `listCard()` based on filters

### P-03 Hierarchy view

- Renderer follows `state.view='hierarchy'`
- Calls API-02; selection opens D-04
- NON-STANDARD pattern remains subject to OQ-LOC-02; do not replace without decision

### D-01 Warehouse/Zone/Area/Rack

- Renderer: `renderSimpleForm()`; submit: `submitForm(this)`
- Header: `${isEdit?'แก้ไข':'เพิ่ม'} ${LEVEL_LABEL[lv]}`
- Primary label: create=`ยืนยันสร้าง`, edit=`บันทึกการแก้ไข`
- Warehouse branch picker only active branches; stored inactive branch stays readable in edit/view
- API mapping: Warehouse API-05/06, Zone API-07/08, Area API-09/10, Rack API-11/12

### D-02 Location

- Renderer: `renderLocationForm()`; submit: `submitLoc(this)`
- Header: create=`เพิ่ม Location`, edit=`แก้ไขตำแหน่ง`
- Step 1=`Parent & ข้อมูลหลัก`; Step 2=`ความจุ & พฤติกรรม`
- Navigation: `ถัดไป`; final primary=`ยืนยันสร้าง` / `บันทึกการแก้ไข`
- Parent is Rack XOR Area; direct Area requires `allows_direct=true`
- Create API-14; edit API-15. Edit must persist `storage_uom` only when Inventory reports `hasStock=false` despite current mock gap

### D-03 สร้าง Location จำนวนมาก

- Renderer: `renderBulkDrawer()`; title=`สร้าง Location จำนวนมาก`
- Subtitle=`สร้าง rack + location จาก template (atomic)`
- Preview includes `ตัวอย่างรหัสที่จะได้ (5 ตัวแรก):` and total
- Primary label dynamically `สร้าง {total} ตำแหน่ง`
- API-17 commits full batch atomically; mock one-row insert is not production behavior

### D-04 Node detail

- Renderer: `renderViewDrawer()`; calls API-04/API-21
- `แก้ไข` visible only when `canManage`; close label=`ปิด`

### M-01 บล็อก/Freeze ตำแหน่ง

- Renderer: `renderModal()` with `state.modal.level='status-reason'`
- `เหตุผล` required; empty feedback=`กรอกเหตุผลก่อน`
- Confirm label=`ยืนยัน`; API-16 single / API-18 bulk

### M-02 ลบ/ปลดระวาง

- Renderer: `renderModal()`; submit `confirmModal()`
- Parent node uses API-13 and is blocked when children exist
- Location uses API-20 and requires `hasStock=false`; audit append is mandatory despite current mock gap

## §1.3 Journey

```text
P-01 root → drill Warehouse/Zone/Area/Rack → D-04 detail
       ├─ stat Location → P-02 → select → bulk status/UOM
       ├─ canManage → D-01 parent CRUD
       ├─ canManage → D-02 Location wizard
       └─ canManage → D-03 atomic generation
Location pill → M-01 reason (blocked/frozen)
Detail/action → M-02 delete parent or decommission Location
```

## §1.4 State-driven UI Matrix

| Condition | UI behavior |
|---|---|
| `canManage=false` | hide create/edit/delete/status/bulk mutation controls; read remains |
| `hasStock=true` | UOM mutation skipped/disabled; decommission blocked |
| status `full` | display derived state; no manual menu option |
| status `blocked`/`frozen` | reason stored and visible in detail/audit |
| Area `allows_direct=false` | direct Location next step blocked with exact VR-07 text |
| request pending | submit disabled/busy; repeated click does not create duplicate |
| empty result | render `ไม่พบรายการ` state |
| API error | keep entered form state and show server-mapped UI message |

## §1.5 Exact Validation Microcopy

| Condition | Exact text from HTML |
|---|---|
| empty code | `กรุณากรอกรหัส` |
| empty name | `กรุณากรอกชื่อ` |
| empty branch | `กรุณาเลือกสาขาสังกัด` |
| missing controlled temperature | `กรุณากรอกช่วงอุณหภูมิ` |
| missing Rack | `กรุณาเลือก Rack` |
| missing Area | `กรุณาเลือก Area` |
| invalid direct Area | `Area นี้ไม่อนุญาตวางตำแหน่งตรง — เพิ่ม Rack ก่อน` |
| empty Location code | `กรุณากรอกรหัสตำแหน่ง` |
| capacity ≤ 0 | `ความจุต้องมากกว่า 0` |
| duplicate sibling code | `รหัสซ้ำภายใน parent เดียวกัน` |
| missing reason | `กรอกเหตุผลก่อน` |
| invalid generation count | `template ไม่ถูกต้อง` |
| stocked decommission | `ตำแหน่งนี้ยังมีสต็อกอยู่ — ต้องย้ายสต็อกออก (stock=0) ก่อนปลดระวาง` |

Success text is constructed by `done()`, `submitLoc()`, `submitBulk()`, `bulkStatus()`, `bulkUom()` and `quickAdd()`; implementation must preserve those exact templates rather than invent alternatives.

## §1.6 Overlay and Dismiss Rules

- Drawer and modal render through their existing portal containers; overlay must not be clipped by table/card stacking context
- Escape closes the topmost overlay only; dirty forms require confirmation `[AI-DEFAULT]`
- destructive confirm remains disabled while `blockReason()` returns a guard reason
- restore focus to the invoking control after dismiss `[AI-DEFAULT]`

## §1.7 Accessibility and Responsive

- Desktop-base responsive behavior follows the authoritative v8 skill; retain readable table overflow and drawer adaptation
- keyboard users can reach breadcrumb, row actions, checkbox bulk controls, drawer footer and modal buttons
- icon-only row actions retain `title`/accessible label such as `แก้ไข`
- status meaning must not depend on color alone
