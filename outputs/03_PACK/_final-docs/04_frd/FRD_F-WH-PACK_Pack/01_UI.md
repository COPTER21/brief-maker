## §1.2 UI State Model

- List: queue/packs tab, search, warehouse/status/owner filters, loading/empty/error/loaded, CSV export.
- Pack: `in_progress` shows stepper, remaining lines, scanner, active carton and closed cartons; other states show summary + closed cartons.
- Action enablement derives from API permissions and guards; UI disabled state is advisory only.
- All tab/overlay/button visible strings must be extracted verbatim from HTML by UI brief/test generators. Do not create alternate labels in implementation.

## §1.4 Operational Journey

1. Open queue → inspect job → start.
2. Open one carton from master/custom.
3. Scan/type/add; adjust/remove/undo; remaining and weight refresh without losing focus.
4. Close carton; print label; F3 opens next carton when remaining exists.
5. Finish only at remaining zero/no active carton; print slip.
6. wh_lead may reopen before DN; cancel requires reason; DN result locks all edits.

## §1.5 Keyboard and Interaction

- Enter on scan input adds parsed quantity/code; empty Enter follows HTML’s close-carton behavior.
- F2 closes active carton; F3 opens next; Ctrl+Z reverses one logical operation; Escape closes top overlay.
- scanner regains focus after successful allocation; rerender must preserve text/scroll where HTML does.
- Do not rely on inline HTML handler names as backend contract.

## §1.6 Permissions and Sensitive UI

- Viewer never sees start/edit/cancel/DN buttons.
- Packer mutation controls display only for owned/assigned packs.
- Shipped state removes all mutation controls for every role.
- Customer/ship-to/contact and employee identity are Confidential; exports/prints require scoped permission and audit.

## §1.7 Required States

| State | Expected UI |
|---|---|
| loading | skeleton/progress; no duplicate submit |
| empty queue/filter | explicit empty/no-result with reset path |
| 403 | permission message; no mutation control |
| 409 stale | preserve input where safe; prompt refresh |
| 422 business rule | anchor reason beside action/field |
| 503 DN/print | pack remains in current business state; retry path |

## §1.8 Accessibility/Responsive Acceptance

Keyboard reachability, visible focus, semantic labels for icon buttons, modal focus trap/restore, no horizontal body scroll at 1024/1280. These are mandatory acceptance criteria despite the waived prototype UX gate.

## §1.9 BACKEND Anchors

Frontend models bind only to API response fields and machine-readable `error.code`; never parse Thai message to decide logic. Status values: `in_progress`, `packed`, `shipped`, `cancelled`; job queue state is separate.
