# 04_DB — F-WH-PACK Packing

## §4.1 Tables

| Table | Purpose | Tenant RLS |
|---|---|:---:|
| `T_packing_job` | idempotent source work | ✓ |
| `T_pack` | pack header/lifecycle | ✓ |
| `T_pack_box` | carton state/snapshot | ✓ |
| `T_pack_box_item` | picked-line allocations | ✓ |
| `T_pack_label` | print versions/status | ✓ |
| `T_pack_audit` | append-only evidence | ✓ |
| `T_pack_outbox` | integration/notification delivery | ✓ |

## §4.2 Schemas

### T_packing_job

| Column | Type | Null | Classification | Description |
|---|---|:---:|---|---|
| id, tenant_id, warehouse_id | uuid | no | Internal | PK/scope |
| pick_id, pick_no | uuid/varchar | no | Internal | Picking reference |
| source_type, source_ref | varchar | no | Internal | current confirmed source_type=`sales_order` |
| status | varchar | no | Internal | queued/active/completed/cancelled |
| idempotency_key, request_hash | varchar | no | Internal | replay safety |
| assignee_id | uuid | yes | Confidential/PII | ownership |
| version | int | no | Internal | optimistic lock |
| created_by/at, modified_by/at | uuid/timestamptz | no | Internal | audit |

Constraints: unique `(tenant_id,pick_id,source_type,source_ref)`; unique `(tenant_id,idempotency_key)` with request hash check.

### T_pack

Fields: `id`, `tenant_id`, `job_id`, `pack_no`, `warehouse_id`, `station_id`, `assignee_id`, `status`, `ship_method`, `note`, customer/ship-to/source snapshots JSONB, totals, `started_at`, `packed_at`, `dn_ref`, cancel fields, `version`, audit fields. `dn_ref` unique per tenant when non-null. Confidential fields: customer/ship-to/contact/assignee.

### T_pack_box

Fields: `id`, tenant/pack, `box_no`, `status(active|closed)`, master ID plus code/name/dimension/tare/capacity snapshots, `computed_weight`, `actual_weight`, `closed_at`, `label_version`, `version`, audit fields. Unique `(tenant_id,pack_id,box_no)`. Partial unique index guarantees one `status='active'` per pack.

### T_pack_box_item

Fields: `id`, tenant/pack/box, `source_line_id`, item ID/code/name/UOM/lot/expiry/location snapshots, `qty numeric(18,6)`, weight snapshot, free/cold flags, audit fields. Check qty>0. Unique grouping may be `(box_id,source_line_id,lot_snapshot)`.

### T_pack_label

Fields: `id`, tenant/pack/box, `document_type`, `version`, `status(valid|invalidated|failed)`, `payload_snapshot`, template/version, rendered URI/hash, printed actor/time/reason, invalidation actor/time/reason, audit fields. Unique `(tenant_id,box_id,version,document_type)`.

### T_pack_audit

Fields: immutable `id`, tenant/warehouse/pack/box, action, from/to state, actor, reason, before/after JSON, result, correlation/request IDs, occurred_at. Deny UPDATE/DELETE to app role.

### T_pack_outbox

Fields: event ID, tenant, aggregate type/id, event type/version, payload, dedupe key, status, attempts, next attempt, last error, created/published timestamps. Unique dedupe key.

## §4.3 Relationships

```text
T_packing_job 1 ── N T_pack 1 ── N T_pack_box 1 ── N T_pack_box_item
                              ├── N T_pack_label
                              ├── N T_pack_audit
                              └── N T_pack_outbox
```

## §4.4 Integrity and Migration

- RLS on every table; FK includes tenant where supported or application invariant plus RLS.
- Check status enums and nonnegative weight/tare/capacity.
- Trigger/constraint prevents pack-box allocation sum exceeding immutable source picked qty; service transaction also verifies.
- Index list by `(tenant_id,warehouse_id,status,created_at desc)`, owner, source ref, pack_no; audit cursor `(tenant_id,pack_id,occurred_at,id)`.
- Initial migration only; no legacy data migration. Seed no mock weights or DN contracts.

## §4.5 Retention

Pack/box/label business records retained per enterprise document policy (proposed 7 years [AI-DEFAULT]); outbox delivered payload may purge after policy window; audit retention follows central audit policy. Print binaries may have a shorter configurable retention while payload/hash evidence remains.

## §4.6 Classification Enforcement

Internal uses tenant RLS; Confidential uses role/warehouse scope, view/export audit, mask/omit unauthorized contact data. Do not put full address/contact in generic application logs or notification payloads.

## §4.7 Performance

Avoid loading full audit/label binaries in pack list. Use projections, cursor paging, batch source line reconciliation, numeric decimal arithmetic and streaming CSV.
