# PRINT SPEC — ใบปรับยอดสต๊อก (ADJ)

> เอกสารประกอบสำหรับ Dev — แนบคู่กับ BRD/FRD ของ **F-WH-STKADJ** (Stock Adjustment)
> ไฟล์คู่: `ADJ_template.html` (master, Sarabun ฝัง base64) + `ADJ_sample.pdf` (ตัวอย่าง A4)
> สร้างจาก skill **thai-doc-pdf-generator** · body ประกอบจาก `patterns/blocks.md` · head/CI/font ฝังโดย `build_html.py`
> ⚠️ **override เฉพาะเลนนี้: ปี = ค.ศ. ล้วน** (GOLDEN_RULES §1 · TASTE_LOG · PREBRIEF OB-14) — แม้ `thai-standards.md` ของ skill จะยกตัวอย่างเป็น พ.ศ. ก็ตาม ให้ยึด **ค.ศ.** ทุกวันที่

## 1. สรุป
- **ประเภทเอกสาร:** ใบปรับยอดสต๊อก / Stock Adjustment Note · `doc_type` **ADJ** · เลขที่ `ADJ-YYYY-NNNN` (ปี ค.ศ.)
- **ชนิด:** เอกสารธุรกรรม**ภายในองค์กร** (ไม่ส่งให้คู่ค้าภายนอก) มีตารางบรรทัด + สายอนุมัติ
- **ขนาด:** A4 แนวตั้ง (210×297mm), ขอบ 14mm — **ห้าม override**
- **ฟอนต์:** Sarabun (ฝัง base64 ใน HTML — ไม่พึ่ง network)
- **CI:** CUBE NATIVE (Navy #0B1D3A / Primary #0B5CFF / Teal #00A88E) — ผ่าน class เท่านั้น
- **Renderer:** Playwright/Chromium → `print_background`, `prefer_css_page_size`
- **ที่มาข้อมูล:** ADJ entity ตาม PREBRIEF §3.1/§3.2 · เลขรัน = **ENG-DOC-NUM** (doccfg) · สำเนา = **ENG-DOC-STORE**
- **สร้างเมื่อ:** พิมพ์ได้ตั้งแต่สถานะ `รออนุมัติ` ขึ้นไป (มีเลขที่แล้ว) — ดู §5 กติกาพิมพ์
- **★ ต่างจากเอกสารขาย:** **ไม่มีบล็อก VAT / ส่วนลด** และ **ไม่มีช่องเซ็นฝั่งคู่ค้า** (ใบภายในล้วน · PREBRIEF §3.6)

## 2. โครงหน้า (ตาม pattern เอกสารตาราง)
```
.doc-page
├── .doc-content
│   ├── HEADER   โลโก้ + ชื่อบริษัท + ที่อยู่ + เลขผู้เสียภาษี (สำนักงานใหญ่) + หัวเรื่อง "ใบปรับยอดสต๊อก / STOCK ADJUSTMENT NOTE"
│   ├── META     เลขที่ · วันที่เอกสาร · วันที่มีผล · ประเภทการปรับ · สถานะ · หน้า x/y
│   ├── PARTIES  ซ้าย = คลัง/สาขาที่ปรับ (รหัส + ชื่อ + ที่อยู่คลัง) · ขวา = ผู้จัดทำ (ชื่อ + ตำแหน่ง) + ศูนย์ต้นทุน + จำนวนไฟล์แนบ
│   ├── ITEMS    ตารางรายการปรับยอด (§3) — คอลัมน์เหตุผลบังคับทุกบรรทัด
│   └── NOTES+TOTALS  ซ้าย = หมายเหตุ + หลักฐาน + ข้อความบังคับ · ขวา = บล็อกยอดรวม (§4) · จำนวนเงินตัวอักษรเต็มกว้างใต้ foot-grid
└── .doc-bottom  (ดันชิดล่างหน้าอัตโนมัติ)
    ├── SIGNATURES  3 ช่อง (§5)
    └── FOOTER      เอกสารภายใน + เลขที่ + วันที่พิมพ์ (ค.ศ.) + หน้า
```

## 3. Field Mapping — ITEMS (loop `lines[]`, 1 row = 1 บรรทัด)

| ช่องในเอกสาร | Source (entity.field) | Format | จัดชิด | หมายเหตุ |
|---|---|---|---|---|
| # | `line_no` | เลข | กลาง (`.col-no`) | |
| ช่องเก็บ (bin) | `bin_code` + `<span class="sub">` คลัง · โซน · `location_type` | ข้อความ | ซ้าย | เช่น `A-01-01-A · WH-BKK-01 · โซน A · storage` |
| สินค้า | `item_name` + `<span class="sub">` `item_code` | ข้อความ | ซ้าย | soft-ref — เก็บข้อความ ณ เวลาเลือก (BR-22) |
| หน่วย | `uom` | ข้อความ | กลาง (`.ctr`) | อ่านอย่างเดียวจาก Item Master |
| ยอดระบบ | `system_qty_snapshot` | `#,##0.00` | ขวา (`.num`) | snapshot ตอนเลือก bin+สินค้า |
| ยอดที่ถูกต้อง | `correct_qty` | `#,##0.00` | ขวา (`.num`) | |
| ผลต่าง | `delta_qty` = `correct_qty − system_qty` | `+#,##0.00` / `−#,##0.00` | ขวา (`.num`) | **มีเครื่องหมายเสมอ** · ชิป `.tag--ok` (+) / `.tag--danger` (−) |
| ต้นทุน/หน่วย | `unit_cost_ref` | `#,##0.00` | ขวา (`.num`) | **mock** จาก Item Master → `FWD-WIRE: valuation engine` (W5 · gap G-01) |
| มูลค่าที่ปรับ | `line_amount` = `delta_qty × unit_cost_ref` | `+#,##0.00` / `−#,##0.00` | ขวา (`.num`) | |
| เหตุผล | `reason_code` → ชื่อเหตุผล + `<span class="sub">` รหัส (+ คำอธิบายเพิ่มเมื่อ `RS-99`) | ข้อความ | ซ้าย | **ห้ามว่าง** (BR-06) · กลุ่มต้องตรงทิศ +/− (BR-07) |

**กติกาตาราง**
- หัวตาราง = แถบ navy เข้ม ตัวอักษรขาว (`.items thead th`) · เนื้อตาราง minimal ไม่มีเส้นแนวตั้ง/zebra
- **ไม่มีคอลัมน์ VAT / ส่วนลด / "bin ปลายทาง"** — ปรับยอดไม่ใช่รายการภาษีและไม่ใช่การย้าย (BR-05 · §3.6)
- ความกว้างคอลัมน์ตั้งด้วย `style="width:..mm"` บน `<th>` (รวม 182mm พอดีพื้นที่พิมพ์) — ไม่แก้ base.css
- แถว +/− ใช้สีชิปต่างกันได้ แต่ **เครื่องหมาย +/− คือตัวหลัก อ่านออกเมื่อพิมพ์ขาวดำ**
- bin กลุ่มพิเศษ (`quarantine`/`damage`) ให้ระบุประเภทใน `sub` ให้เด่น (เช่น `QA-01 (quarantine)` · `DM-01 (ของเสีย)`)
- เกิน 1 หน้า → หัวตารางซ้ำทุกหน้า (`thead{display:table-header-group}`) + อัปเดต `หน้า x/y` ใน META

## 4. บล็อกยอดรวม (TOTALS) + กติกาคำนวณ

| บรรทัด | สูตร | รูปแบบ | หมายเหตุ |
|---|---|---|---|
| บรรทัดปรับเพิ่ม (+) / ปรับลด (−) | นับตามทิศของ `delta_qty` | `n / n` | ช่วยตรวจเร็ว |
| มูลค่าปรับเพิ่มรวม | `Σ line_amount` ของบรรทัด + | `+#,##0.00` | |
| มูลค่าปรับลดรวม | `Σ line_amount` ของบรรทัด − | `−#,##0.00` | |
| ★ **มูลค่าที่ปรับรวม (ค่าสัมบูรณ์)** | `abs_adjustment_amount = Σ \|line_amount\|` | `#,##0.00` | **แถบ navy เข้ม (`.totals__grand`) — ตัวเลขหลักของใบ** เพราะเป็น **ฐานสายอนุมัติ DOA** (BR-09 · gap G-02) |
| มูลค่าสุทธิ (+/−) | `net_adjustment_amount = Σ line_amount` | `−#,##0.00` | บรรทัดรอง **ใต้** ค่าสัมบูรณ์ (ห้ามสลับลำดับให้เด่นกว่า) |
| จำนวนเงินตัวอักษร | `baht_text(abs_adjustment_amount)` | ไทย | เต็มกว้าง (`.baht-text`) ใต้ foot-grid — คิดจาก **ค่าสัมบูรณ์** |

- Format ทุกช่องเงิน `#,##0.00` (ROUND_HALF_UP) + class `num` (ชิดขวา) · ผลต่าง/มูลค่า/สุทธิ **มีเครื่องหมาย +/− เสมอ** (ใช้ `−` U+2212)
- จำนวนเงินตัวอักษร: `python scripts/baht_text.py <abs_adjustment_amount>` — sample = `สองหมื่นสามพันห้าร้อยเจ็ดสิบห้าบาทถ้วน`
- **ข้อความบังคับใต้ TOTALS** (กันเข้าใจผิดเรื่องบัญชี):
  > "มูลค่าตามใบนี้คำนวณจากต้นทุนอ้างอิงในทะเบียนสินค้า — รายการบัญชีจริงเกิดเมื่อระบบบัญชีบันทึกรายการ"
- ★ **ห้ามสลับลำดับ:** ค่าสัมบูรณ์ต้องเด่นกว่ายอดสุทธิเสมอ — ใบผสม +/− ที่สุทธิใกล้ศูนย์ต้องไม่ดูเหมือน "แทบไม่ได้ปรับอะไร" (gap G-02)
- **ไม่มี VAT / ส่วนลด / WHT** ในบล็อกนี้ — ปรับยอดสต๊อกไม่ใช่รายการภาษี (PREBRIEF §3.6)

## 5. ช่องลายเซ็น (SIGNATURES) — 3 ช่อง (ล็อกตาม Pattern Q / iron rule #98)

| ช่อง | ใคร | Source | หมายเหตุ |
|---|---|---|---|
| 1 | **ผู้จัดทำ** | `creator` (ชื่อ + ตำแหน่ง) | คนจริง เสมอ |
| 2 | **ผู้อนุมัติ** (ตามสาย DOA) | `approver_slot[]` (ชื่อ + ตำแหน่ง + วันที่ **ค.ศ.**) | พิมพ์ผู้อนุมัติล่าสุดที่ resolve จริง · **ห้ามพิมพ์รหัส role** · สายเต็ม 1–4 ขั้นดูที่ tab ลายเซ็นในระบบ |
| 3 | **ผู้ผ่านรายการ (หัวหน้าคลัง)** | `posted_by` (ชื่อ + ตำแหน่ง + วันที่ผ่านรายการ **ค.ศ.**) | **เว้นว่างถ้ายังไม่ post** (sample = รออนุมัติ → ช่องนี้ว่าง) |

> **ไม่มีช่องเซ็นคู่ค้า** (ต่างจาก RTV) — ใบภายในล้วน · ลายเซ็น + footer อยู่ใน `.doc-bottom` ชิดล่างหน้าเสมอ

## 6. กติกาการพิมพ์ (ตาม Design Rules + PREBRIEF §7)
- A4 แนวตั้ง · lean type 9pt · หัวตารางเส้นบาง navy · ลายเซ็น+footer ชิดล่าง (`.doc-bottom`)
- หัวตารางซ้ำทุกหน้า (`thead{display:table-header-group}`) · ห้ามตัด row กลาง (`tr{break-inside:avoid}`) · ลายเซ็น `break-inside:avoid`
- **ทุกวันที่บนใบ = ปี ค.ศ.** รวมวันที่ในช่องลายเซ็นและ footer (OB-14)
- ตัวเลขเงินทุกช่อง `#,##0.00` + `.num` (ชิดขวา) · ผลต่าง/มูลค่า **มีเครื่องหมาย +/− เสมอ**
- **ลายน้ำสถานะ (`status_watermark`, ระบบเติมตอน bind):** ก่อน `อนุมัติแล้ว` → "ตัวอย่าง" · `ยกเลิก` → "ยกเลิก" · `กลับรายการแล้ว` → "กลับรายการ" (+ พิมพ์เลขใบกลับรายการใน META) — ใบที่ยกเลิก/กลับรายการ **ห้ามพิมพ์ออกมาเหมือนใบปกติ**
- **ห้ามพิมพ์คำว่า "ใบนับสต๊อก / นับรอบ / count sheet / blind count"** ที่ใดในเอกสาร (BR-24 · scope lock)
- เก็บสำเนาผ่าน **ENG-DOC-STORE** เท่านั้น (DOCCFG_BRIEF §3) — feature ไม่เก็บไฟล์เอง

3. **META วันที่:** ใช้ป้าย "วันที่เอกสาร" + "วันที่มีผล" ตาม BA §2 (แยกจากกันชัดเจน)
4. **Sample:** เลือก `ADJ-2026-0003` (ใบผสม 4 บรรทัด) เพื่อโชว์ทั้งแถว + และ − และ Σ|มูลค่า| ตามที่ระบุใน task/PREBRIEF §8
5. **ค่าที่เติมเพิ่มเป็น placeholder** (BA spec ไม่ได้ระบุตัวเลข): ยอดระบบ/ยอดที่ถูกต้องรายบรรทัด, ต้นทุน/หน่วย (derive จากมูลค่าที่ PREBRIEF §8 ให้), รหัสสินค้า, ชื่อผู้จัดทำ/ผู้อนุมัติ — ทั้งหมดเป็น mock สมจริง ต้องแทนตอน bind
