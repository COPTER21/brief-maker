## §4.3 Relationships
```
branches (ext soft-ref) ─1:N→ warehouses ─1:N→ zones ─1:N→ areas ─1:N→ racks ─1:N→ locations(parent_type=rack)
areas ─1:N→ locations(parent_type=area, allows_direct=true)     [locations.parent = rack XOR area]
th_geo (ext read-only) → warehouses(address)
locations → (referenced by) Inventory/GR/Picking/… via location_id + full_path (contract, 02_API §2.9)
```
No hard delete; no cascade delete. Archive/decommission = status flip + audit.

## §4.4 Indexes & Constraints
- `UNIQUE(warehouses.code)` — system-wide (BR-004).
- `UNIQUE(zones.code, warehouse_id)`, `UNIQUE(areas.code, zone_id)`, `UNIQUE(racks.code, area_id)`, `UNIQUE(locations.code, parent_type, coalesce(rack_id,area_id))`.
- `CHECK(locations: (rack_id IS NOT NULL) <> (area_id IS NOT NULL))` — XOR (BR-002).
- `CHECK(locations.cap_val > 0)` (BR-006).
- `CHECK(zones: NOT temp_controlled OR (temp_min<=temp_max))` (BR-008).
- Index on FK columns + `status` (drill/filter perf, SLA §17.1 ≤2s).
- Uniqueness **enforced at DB** (not client-only) — EC-15/concurrency.

## §4.6 Data Classification (4-level + enforcement)
1. **Public** — geo reference (province/district/subdistrict/postcode): read-only, no restriction.
2. **Internal** (default, all owned columns) — RBAC-gated read/write; feature-scoped.
3. **Confidential** — none.
4. **Restricted** — none.
- **Enforcement mapping:** DB (RBAC via app + IDOR check on id) · API (role gate every mutation, §16.3) · UI (perms() button gating §1.4) · Audit (WORM append-only, every mutation).
- **PII overlay** (separate from classification): `created_by`/`modified_by`/audit `by` = actor identity. No customer/personal data.
- **Policy Center linkage:** no Restricted → no Restricted Resources registry wire needed. (Confirmed OQ — none open.)
