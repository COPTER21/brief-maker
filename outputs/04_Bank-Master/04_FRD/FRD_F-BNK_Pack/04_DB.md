## §4.1 Table Overview

| Table | Purpose | Owner Feature | Multi-tenant |
|---|---|---|---|
| `T_bank_account` | Master record บัญชีเงินฝากธนาคารจริง (ธนาคาร × สาขา × เลขบัญชี) | F-BNK (this) | YES (RLS) |

> **posting_group** เก็บเป็น `varchar` (code ของ GL Posting Group, kind=bank) — **soft-ref, NO FK** ไปยัง F-PG. GL resolve บัญชีเงินฝาก (account_1) ผ่านกลุ่มตอน post (F-PG BR-08). **master ไม่เก็บเลข COA เงินฝากตรง.**
> **ไม่มี child table** (ต่างจาก F-PAY installment) — บัญชี 1 แถวจบ.
> **snapshot:** เอกสารปลายทาง (Receipt/PV) เก็บ code บัญชี + ค่า ณ เวลาบันทึก ในตารางของตัวเอง (ไม่อยู่ใน pack นี้) — soft-ref, no FK cascade.

**Constraints:**
- PRIMARY KEY (id)
- UNIQUE (tenant_id, code) — code unique/tenant (BR-08)
- **UNIQUE (tenant_id, `regexp_replace(account_no,'\D','','g')`)** — account_no unique **เทียบตัดขีด** registry-wide (BR-01) → implement เป็น unique index บน expression / generated column `account_no_digits`
- CHECK (bank IN ('KBANK','SCB','BBL','KTB','TTB','BAY','GSB','UOB','OTHER')) — seed config (BR-10)
- CHECK (account_type IN ('savings','current','fixed'))
- CHECK (status IN ('draft','active','inactive'))
- CHECK (currency = 'THB') — THB-only (BR-09)
- CHECK (char_length(regexp_replace(account_no,'\D','','g')) BETWEEN 10 AND 12) — BR-01
- CHECK (promptpay_id IS NULL OR char_length(regexp_replace(promptpay_id,'\D','','g')) IN (10,13)) — BR-06
- CHECK (use_receive OR use_pay) — ≥1 ฝั่ง (BR-03)
- CHECK (NOT default_receive OR (use_receive AND status='active')) — DEFAULT_GUARD (BR-03)
- CHECK (NOT default_pay OR (use_pay AND status='active')) — DEFAULT_GUARD (BR-03)
- **Partial-unique index** ★ ต่อฝั่งทั้งระบบ (ดู Indexes) — BR-03
- **IR-BNK-01 (used>0):** ล็อก `bank` + `account_no` = enforced ที่ logic/API (FN-02 save guard), ไม่ใช่ DB constraint (แก้ field อื่นได้)
- Delete guard used>0 = enforced ที่ logic/API (FN-07), soft (bulk ข้าม)

**Indexes:**
- IDX_bnk_tenant_status ON (tenant_id, status)
- IDX_bnk_tenant_bank ON (tenant_id, bank)
- **UNIQUE IDX_bnk_default_receive ON (tenant_id) WHERE default_receive = true** — 1 ★รับ/ระบบ (BR-03)
- **UNIQUE IDX_bnk_default_pay ON (tenant_id) WHERE default_pay = true** — 1 ★จ่าย/ระบบ (BR-03)
- IDX_bnk_code ON (tenant_id, code)
- IDX_bnk_acct_digits ON (tenant_id, regexp_replace(account_no,'\D','','g')) — dedup + reconciliation lookup
- IDX_bnk_created_at ON (created_at DESC)

## §4.3 Relationships (ER)

```
T_bank_account (master)
    │
    ├─(soft-ref: posting_group = code, NO FK)──▶ GL Posting Group (F-PG / F-0.19, kind=bank)
    │        กลุ่ม bank: account_1 = บัญชีเงินฝาก (COA type=asset), account_2 = NULL
    │        GL resolve บัญชีเงินฝาก "ผ่านกลุ่ม" ตอน post (external GL engine, F-PG BR-08)
    │
    ├─(referenced by / snapshot code+ค่า, NO FK)──▶ Receipt (ฝั่งรับ)   [ยังไม่ทำ · OQ-BNK-04]
    ├─(referenced by / snapshot code+ค่า, NO FK)──▶ Payment Voucher (ฝั่งจ่าย) [ยังไม่ทำ · OQ-BNK-04]
    ├─(drives)──────────────────────────────────▶ external GL engine (post ผ่านกลุ่ม)
    ├─(future)──────────────────────────────────▶ Bank Reconciliation
    └─(CUT · OQ-BNK-01=NO)──────────✗────────────▶ Payment Method (F-0.20)

T_tenant (1) ──< (N) T_bank_account   [RLS isolation]
T_user  (1) ──< (N) T_bank_account (created_by/updated_by)
```
- ทุก downstream/upstream edge = **soft-reference (no FK cascade)** — แก้/ปิดบัญชี ไม่ย้อนแก้เอกสารเก่า (snapshot).
- **master ไม่เก็บเลข COA เงินฝากตรง** — resolve ผ่านกลุ่มเสมอ (มาตรฐาน BC Bank Posting Group).

## §4.6 Data Classification & Sensitive Data

### §4.6.1 Levels (CUBE 4.0)
Public / Internal / Confidential / Restricted — นิยามมาตรฐาน (ดู `04_db.template` §4.6.1).

### §4.6.2 Default Rule
- **Default = Internal** (field ทั่วไปใน §4.2). ห้าม default Public.

### §4.6.3 Feature classification decision
- **Highest level = Confidential.** เพราะ `account_no` (เลขบัญชีเงินฝาก) + `promptpay_id` (เบอร์/เลขภาษี) = ข้อมูลอ่อนไหวทางการเงิน — รั่วแล้วเกิดความเสียหายได้.
- Field อื่น (config การเงิน: bank/type/★/status/posting_group) = **Internal** — เห็นได้ทุก authenticated finance role.
- ควบคุมเชิงเงิน transactional (P4) เกิดที่ **เอกสารปลายทาง** (Receipt/PV/GL) — คนละ feature.

### §4.6.4 PII Overlay
- `account_no` = Yes (bank account number) · `promptpay_id` = Yes (phone / tax-id). D7/D11 masking = **ต้อง** ที่ view header (`maskAcct`) + read access log.
- Field อื่น = pii_flag false.

### §4.6.5 Security Bible Domain Mapping
| Domain | เกี่ยวข้อง |
|---|---|
| **D2 (Auth):** JWT + RBAC (Admin/Viewer/Consumer) |
| **D5 (Financial config):** ทุกการแก้ทะเบียนบัญชี → audit log mandatory |
| **D9 (Audit):** ทุก mutation → change log (append-only, tab ประวัติ) |
| **D11 (Masking/Sensitive):** account_no/promptpay_id mask + read access log |
| **D15 (Admin actions):** status/★/delete logged พร้อม actor |
| **D17 (Multi-tenant):** RLS by tenant_id |

### §4.6.6 Linkage with Policy Center
- **ไม่มี Restricted field** → ไม่ต้อง register Restricted Resources. **แต่มี Confidential field** (account_no/promptpay_id) → masking + access log บังคับ (C6/C11) · ระดับ masking ในตาราง/def-grid = **OQ-BNK-08** (Security).
- DOA placeholder (approver_role/approved_by/approved_at/approval_chain) = Internal, null → wire Policy Center DOA ภายหลัง (ไม่ใช่ sprint นี้).
