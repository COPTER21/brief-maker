## §4.6 Data Classification & Sensitive Data

### §4.6.1 Levels — ใช้ 4 ระดับมาตรฐาน (Public/Internal/Confidential/Restricted)
### §4.6.2 Default = Internal (ห้าม default Public) — ทุก field ใน §4.2 ระบุครบ

### §4.6.3 Enforcement Mapping

| Classification | DB | API | UI | Audit |
|---|---|---|---|---|
| Internal | RLS (tenant) | JWT | — | mutation |
| Confidential (emp snapshot/PII · approver · reject_reason) | RLS + column ACL | role check | mask ถ้าไม่ผ่าน | view + mutation |
| **Restricted (grand · unit_price · line_total · advance_offset · มูลค่า FC/EC)** | RLS + row/col ACL | role + ACL | **mask `฿ •••••`** ถ้าไม่ unmask (ใบคนอื่น สำหรับ mask:true role) | view + mutation + export |

### §4.6.4 PII Overlay
- `emp_snapshot` (name/position/dept/cc) → Confidential + **PII** (PDPA scope)
- `approver_id` / `approver_name` → Confidential + PII
- `grand` / `unit_price` / มูลค่า FC/EC → Restricted + **ไม่ PII** (ข้อมูลเงินองค์กร)

### §4.6.5 Security Bible Domain Mapping
- **D5 (Financial):** grand/unit_price/เพดาน/ทดรอง/FC/EC → audit mandatory + Restricted + DOA (มีวงเงิน)
- **D7 (PII):** emp_snapshot / approver → PDPA scope + no PII in logs (ใช้ id ref)
- **D9 (Audit):** ทุก mutation → T_expense_audit_log (append-only)

### §4.6.6 Linkage with Policy Center
- Restricted (ตัวเงินทั้งหมด · FC/EC) → **Restricted Resources registry** (OQ ใน 00_OVERVIEW §0.8 · wire ตอน dev)
- PII (emp_snapshot/approver) → **PDPA consent scope**
- masking (FN-94) enforce ที่ API + UI (maskM · ใบของตน/ผู้อนุมัติ/เจ้าหน้าที่ เห็นเต็ม · ใบคนอื่น mask) — ดู 03_LOGIC F-HR-EXPENSE-FN-18
