## §1.2 Per-Page Detail

### P-01: ทะเบียน (Registry) — default
**Purpose:** ทะเบียนความยินยอมกลาง (triple key) + สถิติ + กรองทุกมิติ
**Pattern:** A — list-view

**ERP Context:** Sidebar active "ความยินยอม PDPA" · page tabs (`.ptabs`) 4 แท็บ · shell-bar ตาม v6 spec (Sync Read)

**Components used:**
- Page tabs `.ptab` (registry/requests/purposes/resolve)
- Stat cards (toggle filter) — ยินยอมอยู่ / ถอน / ใกล้หมดอายุ / ทั้งหมด (`toggleStat()`, `purposeStats`/registry stats)
- Data Table triple (subject × purpose × channel + status pill + expiry) — `registryRowsHTML()`
- Filter Bar: search + status + channel + purpose (`setFilter()`, `resetFilters()`)
- Toolbar actions: "ส่งออก CSV" (`exportCsv()`) + "สร้างคำขอ" (`openReqCreate({})`)

**Actions:**
| Action | Triggers | Calls (API) |
|---|---|---|
| Click row | เปิด consent drawer (หลักฐาน 5 + timeline + ต่ออายุ/ถอน) | F058-API-15 GET /consent/registry/:id |
| Filter/search change | refresh table | F058-API-14 GET /consent/registry?... |
| Toggle stat card | filter by stat (near-expiry ฯลฯ) | F058-API-14 / F058-API-18 |
| "สร้างคำขอ" | เปิด reqCreate drawer | (form) → F058-API-07 |
| "ส่งออก CSV" | download CSV | client-side (utility เดโม · toast "ส่งออก N รายการเป็น CSV แล้ว") |

**States:** Loading (skeleton) · Empty ("ยังไม่มีรายการในทะเบียน") · Loaded (table) · Filtered-empty

**Permissions:** auditor = read only (ไม่มีปุ่มสร้างคำขอ/ถอน)

### P-03: วัตถุประสงค์ (Purposes)
**Purpose:** จัดการ purpose + ช่องทาง + อายุ + **เอกสารนโยบาย versioned (อัปโหลด)**
**Pattern:** A — list-view + stats

**Actions:**
| Action | Triggers | Calls (API) |
|---|---|---|
| "สร้างวัตถุประสงค์" (dpo เท่านั้น) | เปิด purCreate drawer + upload block | F058-API-02 POST /consent/purposes |
| Click row | เปิด purView drawer (version list) | F058-API-03 GET /consent/purposes/:code |
| "ออกเวอร์ชันใหม่" | newVersion modal + upload | F058-API-04 POST /consent/purposes/:code/versions |
| "ปิดวัตถุประสงค์" | closePurpose confirm | F058-API-05 POST /consent/purposes/:code/close |
| Click ชื่อเอกสาร (`.doc-link`) | เปิด document viewer (DSP-01 z=--z-pop) | F058-API-03 (โหลด body) |

**Permissions:** officer = read · dpo = สร้าง/แก้/ปิด · auditor = read (แสดง chip "เฉพาะ DPO แก้ไขได้" เมื่อไม่มีสิทธิ์)

**Validation (observed):** สร้าง purpose ต้องมี name + ≥1 channel + อายุ 1–120 + **แนบเอกสาร** — ไม่งั้น toast warning ("กรอกชื่อวัตถุประสงค์" / "เลือกช่องทางอย่างน้อย 1" / "อายุต้องอยู่ระหว่าง 1–120 เดือน" / "ต้องแนบเอกสาร PDPA")

---

### P-04: ตรวจสิทธิ์ (Resolve simulator) — read-only
**Purpose:** จำลอง `POST /consent/resolve` ให้ dev แคมเปญทดสอบ
**Pattern:** K — read-only simulator (ไม่มี mutation · LOCK #9 ตอบอย่างเดียว)

**Actions:**
| Action | Triggers | Calls (API) |
|---|---|---|
| เลือก subject + purpose + channel → "ตรวจสิทธิ์" | `runResolve()` → `resolveConsent()` | F058-API-20 POST /consent/resolve |
| แสดงผล | result card (allowed/reason) + `resolveResultHTML()` + ตัวอย่าง JSON (`jsonColor()`) | — |

**States:** ยังไม่กรอกครบ → toast "เลือกให้ครบทั้ง 3 ช่องก่อนตรวจสอบ" · never_asked → allowed:false + reason (ไม่ error)

---

### P-05: มุมมองผู้รับ (Recipient read+sign view) — full-screen surface
**Purpose:** จำลองหน้าที่เจ้าของข้อมูลเห็นเมื่อกดลิงก์ในคำขอ — **REPLACED ปุ่มจำลอง in-drawer เดิม**
**Pattern:** Full-screen overlay (z=--z-recipient 70, เหนือ ERP + drawer)

**Flow (observed):** `openRecipientView(reqId)` → `recipientViewHTML()` render → เจ้าของ:
1. **อ่านเอกสาร** — ปุ่ม "อ่านเอกสาร · <docName>" (`toggleRecipientDoc()`) แสดง policy body รายวัตถุประสงค์
2. **ยืนยันตัวตน** — `.rcp-verify` checkbox (`toggleRecipientVerify()`) — **จำเป็นก่อนส่ง** (mock · idMethod จริง = OQ-03)
3. **ยินยอม/ไม่ยินยอมรายวัตถุประสงค์** — `setRecipientChoice()` (per-purpose granted/declined)
4. **ส่ง** — `submitRecipient()` → verify guard → `applyAnswers()` → registry rows + evidence 5 + history + supersede คู่เดิม

**Guards (observed toast):**
- ไม่ verified → "กรุณายืนยันตัวตนก่อนส่งคำตอบ" (warning)
- เลือกไม่ครบทุก purpose → "กรุณาเลือกยินยอม/ไม่ยินยอมให้ครบ..." (warning)
- สำเร็จ → "บันทึกคำตอบแล้ว · ยินยอม N · ปฏิเสธ M (เก็บหลักฐานครบ 5 อย่าง)" (success)

**Calls:** F058-API-12 GET /consent/recipient/:token (load) · F058-API-13 POST /consent/recipient/:token/answer (submit)

## §1.4 User Journey (Happy Path)

```
DPO/officer เริ่มที่ #/consent/purposes
  ↓ สร้างวัตถุประสงค์ + อัปโหลดเอกสาร v1 (F058-API-02) → versions:[{v:1}]
officer → #/consent/requests → "สร้างคำขอ" (single-screen)
  ↓ เลือก subject + purposes[] + channel (F058-API-07) → link + QR · status=draft
  ↓ ส่งทางอีเมล (F058-API-09) → status=pending (mock toast)
เจ้าของข้อมูล เปิดลิงก์ → recipient view (P-05)
  ↓ อ่านเอกสาร → ยืนยันตัวตน → ยินยอม/ไม่ยินยอมรายข้อ → ส่ง (F058-API-13)
  ↓ applyAnswers → registry rows (granted/declined ต่อ purpose) + evidence 5 + history + supersede + CSQ event
officer/auditor → #/consent/registry → click row → หลักฐาน 5 + timeline (F058-API-15)
ระบบปลายทาง (campaign) → POST /consent/resolve ก่อนส่งทุกครั้ง (F058-API-20)
  → 200 + allowed + reason + JSON ล็อกฟิลด์
```

### Branch: ถอน / ต่ออายุ / ออกเวอร์ชันใหม่
```
ถอน: consent drawer → M-withdraw → เหตุผล+ช่องทาง → doWithdraw (F058-API-17)
     → status=withdrawn ทันที (ไม่อนุมัติ) + history + CSQ consent.withdrawn (reversal_of=grantEvent)
ต่ออายุ: near-expiry ≤30 วัน → M-renew → createRequestRecord(refOld) (F058-API-19)
     → คำขอใหม่อ้างเดิม (ไม่แก้ expiresAt เดิม) + CSQ consent.renew_requested
เวอร์ชันใหม่: purpose → M-newVersion → upload → doPublishVersion (F058-API-04)
     → v+1 + toast "ออกเอกสาร vN แล้ว · M รายการต้องขอใหม่" + CSQ policy.version_published
```
