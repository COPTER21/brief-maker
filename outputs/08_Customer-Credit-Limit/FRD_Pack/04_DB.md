# 04_DB — F-CUST-CL-001

## 4.1 Tables
`T_credit_profile`, `T_credit_change_request`, `T_credit_approval_step`, `T_credit_audit_event`; outstanding balances remain external projections.

## 4.2 Core columns
| Table | Column | Type | Classification | PII |
|---|---|---|---|---|
| profile | customer_id, credit_limit, is_credit_hold, risk_level, last_review_at | uuid/decimal/bool/enum/timestamp | Confidential | — |
| request | request_no, current_limit, requested_limit, reason, approval_status, doa_entry_ref, current_step, version | text/decimal/text/enum/int | Confidential | reason: Yes |
| approval_step | request_id, step_no, approver_role_id, signer_user_id, signed_at, status | uuid/int/text/timestamp/enum | Confidential | signer: Yes |
| audit | event_id, aggregate_id, event_type, payload, actor_user_id, occurred_at | uuid/jsonb/text/timestamp | Confidential | actor: Yes |

## 4.3 Constraints / indexes
- unique `profile.customer_id`; unique `request.request_no`; unique `(request_id, step_no)`.
- foreign keys preserve profile/request integrity; audit table has no update/delete path for application roles.
- index profile status/hold/risk and request approval_status; optimistic `version` on request.

## 4.6 Classification enforcement
Internal is default; these business fields are Confidential. API returns only allowed fields by role, audit access is permissioned, and changes are traceable. My Profile identity remains reference data under its owning feature.
