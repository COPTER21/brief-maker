## §1.2 Per-Page Detail

### P-01: ตำแหน่งที่เปิด (Requisition list)
**Purpose:** เปิดอัตรา · ส่งอนุมัติ DOA · ประกาศ · ปิด — ทะเบียน requisition
**Pattern:** A — list-view

**Components:** Data Table (position/dept/grade/band/status/filled) · Filter Bar (search + status select + ล้างตัวกรอง) · Action Toolbar (ปุ่ม "เปิดอัตราใหม่" — `RC.persona!=='viewer'`) · Drawer v2 (view/form) · status pill (เปิดรับ=success · อนุมัติแล้ว/รอประกาศ=info · ปิดแล้ว=muted) · chip "ไม่มีแผน" (amber, no-manpower)

**Actions:**
| Action | Triggers | Calls (API) |
|---|---|---|
| Click row | Open req view drawer (D-02) | F127-API-03 GET /requisitions/:id |
| "เปิดอัตราใหม่" | Open req form (M-01) | (drawer local) → save F127-API-02 |
| "แก้ไข" (draft) | `openReqEdit` | F127-API-04 PUT /requisitions/:id |
| "ส่งอนุมัติเปิด" | DOA modal (M-03) | F127-API-05 submit-approval |
| อนุมัติ/ไม่อนุมัติ | `reqApprove` | F127-API-06 approve |
| "ประกาศรับ" | `reqAnnounce` | F127-API-07 announce |
| "ปิดอัตรา" | confirm | F127-API-08 close |
| Filter change | refresh | F127-API-01 GET /requisitions?... |

**States:** Loading (skeleton) · Empty (`emptyStateHTML()` "ยังไม่มีอัตรา") · Loaded · viewer = ปุ่มสร้างซ่อน.
**Permissions:** recruiter/manager = full · viewer = read-only (guard `viewerRO()` 15 จุด).

---

### P-02: คลังผู้สมัคร (Candidate Pool)
**Purpose:** ทะเบียนผู้สมัคร · consent PDPA · RESTRICTED masking · ตรวจซ้ำ
**Pattern:** A — list-view (+ state-driven mask)

**Components:** Data Table (ชื่อ/ติดต่อ(masked)/ตำแหน่งที่สนใจ/stage/consent) · Filter Bar (search + stage select) · `contactCell` = mask เมื่อ `!consent.ok` หรือ role ไม่ผ่าน → `<span class="masked"><i lucide=lock></i>ต้องได้รับความยินยอมก่อน</span>` · chip "เคยสมัคร" (dup) · chip "RESTRICTED · ปิดบังตามบทบาท" · ปุ่ม "เพิ่มผู้สมัคร"

**Actions:**
| Action | Triggers | Calls |
|---|---|---|
| Click row | Open candidate drawer (D-01) | F127-API-11 GET /candidates/:id |
| "เพิ่มผู้สมัคร" | Open cand form (M-02) | save F127-API-10 |
| Filter change | refresh | F127-API-09 GET /candidates?... |

**States:** Empty "ยังไม่มีผู้สมัคร" · masking driven by role (`PERSONAS.unmask`: recruiter unmask / manager+viewer mask) + consent.

---

### P-03: บอร์ดสรรหา (Pipeline kanban)
**Purpose:** เลื่อนสถานะ pipeline + guard consent/offer accepted
**Pattern:** L — kanban (5 คอลัมน์)

**Components:** Kanban columns (STAGES: สมัครใหม่/คัดกรอง/สัมภาษณ์/ข้อเสนอ/รับเข้าทำงาน) · `kbCard` ปุ่ม "ถัดไป" (`canFwd` require `consent.ok`) + "←" (back) · terminal pill (rejected/withdrawn/talent_pool)

**Actions:**
| Action | Triggers | Calls |
|---|---|---|
| "ถัดไป/←" | `candMoveStage(dir)` | F127-API-14 move-stage |
| board → ขั้นข้อเสนอ | require offer object | route to D-01 offer tab |
| board → hired | require offer.accepted | F127-API-22 hire (via M-06) |
| Card click | Open D-01 | F127-API-11 |

**Guards (observed):** dir>0 บล็อกถ้า `!consent.ok` (toast "ยังไม่ได้รับความยินยอม PDPA — เลื่อนสถานะไม่ได้") · เข้า offer ต้องมี offer (toast "ไปขั้น 'ข้อเสนอ' ให้สร้างข้อเสนอในลิ้นชักผู้สมัคร") · เข้า hired ต้อง offer.accepted (toast "ต้องให้ผู้สมัครตอบรับข้อเสนอก่อน") · viewer guard.

---

### P-04: รายงานการสรรหา (Funnel)
**Purpose:** funnel conversion + time-to-hire + filter · export
**Pattern:** K — report

**Components:** Funnel bars (สมัคร→สัมภาษณ์→ข้อเสนอ→รับ) · stat card "Time-to-hire เฉลี่ย" · filter select "กรองตามอัตรา" (`RC.f.report.req`) · Export CSV (stub)

**Actions:** filter → `buildFunnelReport` (F127-API-24) · Export → stub toast "ส่งออกรายงาน (CSV) — ต่อ dev" (F127-API-25 · dev binds).
**States:** empty funnel เมื่อ 0 candidate.

---

### D-01: ลิ้นชักผู้สมัคร (4 tabs)
**Pattern:** C — view drawer tabbed · tabs = `detail / assess / offer / history`

- **detail:** ข้อมูลผู้สมัคร (mask ตาม role) · consent banner + ปุ่ม "บันทึกความยินยอม" (`candSetConsent`) · retention_until display-only (`retentionLabel()` — Policy Center) · dup chip
- **assess:** นัดสัมภาษณ์ (M-04) · scorecard 1-5 + comment (`pickScore/saveScore`) · snapshot ผู้สัมภาษณ์ (ชื่อ+ตำแหน่ง) · gate consent
- **offer:** สร้างข้อเสนอ (grade/start_date/salary + band scale) · in-band check + เหตุผลถ้านอกช่วง · `submitOffer` → DOA (M-03) · offer status timeline (pending→approved→sent→accepted/declined) · freeze version_id
- **history:** `historySection()` "ประวัติ (append-only)" — audit log ทุก action

---

### D-02: ลิ้นชักอัตรา
**Pattern:** C view / B form. reqViewDrawer แสดง: header + fields + approval timeline (`approvalSection()`) + "ผู้สมัครในอัตรานี้" (linked) + acts (draft→แก้ไข/ส่งอนุมัติ · approved→ประกาศ · open→ปิด). reqFormDrawer = create/edit form.

## §1.3 User Journey (Happy Path)

```
recruiter เริ่มที่ P-01 (#/recruit/req)
  ↓ "เปิดอัตราใหม่" → M-01 form → submitReq (F127-API-02) → req.status=draft
  ↓ "ส่งอนุมัติเปิด" → M-03 DOA slot picker → submitDoa (F127-API-05) → pending
  ↓ manager อนุมัติครบทุก slot (F127-API-06) → approved
  ↓ "ประกาศรับ" (F127-API-07) → open
  ↓ P-02 "เพิ่มผู้สมัคร" → M-02 + consent + ผูกอัตรา → submitCand (F127-API-10) → applied
  ↓ P-03 board เลื่อน คัดกรอง→สัมภาษณ์ (F127-API-14, guard consent)
  ↓ D-01 assess: นัดสัมภาษณ์ (F127-API-15 + NTF) → scorecard (F127-API-16)
  ↓ D-01 offer: สร้างข้อเสนอ (F127-API-17, band freeze) → DOA (F127-API-18/19) → ส่ง (F127-API-20)
  ↓ ผู้สมัครตอบรับ (F127-API-21) → offer.accepted
  ↓ M-06 "รับเข้าทำงาน + ส่งเข้า On/Offboard?" → hireCandidate (F127-API-22)
      → filled++ · req auto-close เมื่อ filled≥count · ยิง event recruit.candidate.hired (OQ-15 fire-and-forget)
```

### Branch: Approval flow (DOA)
```
req/offer status = draft/pending:
  ├─ Approver (manager slot) เห็นใน DOA modal
  ├─ อนุมัติครบทุก slot → status approved + NTF
  └─ ไม่อนุมัติ → กลับ draft + เหตุผล
```

### Branch: เส้นแยก (terminal)
```
ทุกขั้น pipeline:
  ├─ ไม่ผ่าน (M-05) → rejected → เก็บ talent_pool (default)
  ├─ ถอนตัว → withdrawn + reason
  └─ offer declined → withdrawn
```

## §1.6 Empty States & Errors (UI)

| State | UI behavior (verbatim จากจอ ถ้ามี) |
|---|---|
| No requisition | `emptyStateHTML()` "ยังไม่มีอัตรา" + CTA เปิดอัตรา |
| No candidate | "ยังไม่มีผู้สมัคร" |
| Filter 0 result | empty state + "ล้างตัวกรอง" |
| Consent ขาด (เลื่อน) | toast "ยังไม่ได้รับความยินยอม PDPA — เลื่อนสถานะไม่ได้" |
| Required ขาด | toast "กรุณากรอกข้อมูลที่ไฮไลต์ให้ครบ" + field-level `.is-invalid` (border danger) + focus ตัวแรก (FIX-05) |
| Double-submit | ปุ่ม disabled + `loader-2` spin (RC.busy · FIX-07) |
| viewer เรียก mutation | toast "สิทธิ์อ่านอย่างเดียว" |
| API 403 | "ไม่มีสิทธิ์" |
| API 500 | "เกิดข้อผิดพลาด — กรุณาลองใหม่" + retry |
