## §4.6 Data Classification & Sensitive Data ⭐

### §4.6.1 Classification Levels (CUBE 4.0)
| Level | นิยาม | ตัวอย่างใน feature นี้ | UI | Export |
|---|---|---|---|---|
| Public | เผยแพร่ภายนอก | — (ไม่มี) | ปกติ | ทุก role |
| Internal (default) | คนในบริษัท | status, code, stage, audit timestamp | ปกติ | internal role |
| Confidential | จำกัด role | offer.salary, scorecard.score, band_snapshot, hiring_manager | mask *** ถ้า role ไม่ผ่าน | excluded ถ้าไม่ผ่าน |
| **Restricted** | จำกัดถึง person (ACL) | **candidate.name / contact / resume** | hidden/mask + audit access | require Restricted Resources approval |

### §4.6.2 Default Rule
Default = **Internal**. ห้าม Public โดยลืม. candidate PII = **Restricted** (ไม่ใช่ default).

### §4.6.3 Enforcement Mapping
| Classification | DB | API | UI | Audit |
|---|---|---|---|---|
| Internal | RLS tenant | JWT | — | mutation |
| Confidential | RLS + column ACL | role check | mask if no permission | view + mutation |
| **Restricted** | RLS + row ACL (Restricted Resources) | role + ACL check | hide/mask + consent gate | view + mutation + export |

### §4.6.4 PII Overlay
- `candidate.name/contact/resume` → **Restricted + PII** (จำกัด person + PDPA scope)
- `hiring_manager / interviewer_snapshot` → Confidential + PII (employee data snapshot)
- `offer.salary` → Confidential, **ไม่ PII** (ไม่ใช่ personal data ผู้สมัคร)

### §4.6.5 Security Bible Domain Mapping
| Domain | เกี่ยวกับ |
|---|---|
| **D7 (PII/PDPA):** candidate PII → consent gate (BR-02) + retention (OQ-16) + encrypt at rest (contact/resume) |
| **D9 (Audit):** ทุก mutation + **การเข้าถึง Restricted** → T_recruit_audit |
| **D17 (Multi-tenant):** RLS ทุกตาราง |

### §4.6.6 Linkage with Policy Center
- candidate PII (Restricted) → **Restricted Resources registry** (OQ-R1 · รอบนี้ role masking แทน per-person ACL)
- PII fields → **PDPA consent scope** (consent gate + retention config)
- `retention_until` → อ่านจาก Policy Center config runtime (ห้าม hardcode · OQ-16)
