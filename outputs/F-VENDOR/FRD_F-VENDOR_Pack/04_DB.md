# 04_DB — F-VENDOR ทะเบียนคู่ค้า

> **Audience:** DBA, Backend, Security  
> **Principles:** PostgreSQL, tenant RLS, soft archive, append-only audit, field classification required

---

## §4.1 Table Overview

| Table | Purpose | Multi-tenant |
|---|---|---|
| `T_vendor` | identity, lifecycle และค่า default ของคู่ค้า | YES |
| `T_vendor_contact` | ผู้ติดต่อหลายรายการ | YES |
| `T_vendor_address` | ที่อยู่หลายรายการ + billing/shipping role | YES |
| `T_vendor_bank_account` | บัญชีธนาคารและ verification state | YES |
| `T_vendor_attachment` | metadata และ object reference ของเอกสาร | YES |
| `T_vendor_kyc_review` | ผล KYC/sanctions review แบบ append-only | YES |
| `T_vendor_approval_step` | snapshot ของ approval chain ต่อรอบ submit | YES |
| `T_vendor_audit_event` | WORM business audit trail | YES |

**Constraints**

- PK `id`; unique `(tenant_id, vendor_code)`
- partial unique `(tenant_id, country_code, tax_id_hash)` where `tax_id_hash is not null`
- `credit_limit >= 0`; `withholding_tax_rate between 0 and 30`
- `status in (draft,pending_kyc,pending_approval,active,blocked,inactive,blacklisted)`
- `kyc_status in (pending,passed,failed,expired)`
- blacklist cannot transition out; enforced in function + immutable audit

**Indexes**

- `IDX_vendor_tenant_status (tenant_id,status,updated_at desc)`
- `IDX_vendor_tenant_type (tenant_id,vendor_type)`
- trigram/FTS index on normalized `vendor_code, legal_name, display_name`
- `IDX_vendor_tax_hash (tenant_id,country_code,tax_id_hash)`

## §4.4 Transaction Boundaries

- Create/update aggregate (`T_vendor`, contacts, addresses, unverified banks) commit ใน transaction เดียว
- KYC decision, vendor state change, review row และ audit event commit atomically
- Approval decision, step update, vendor state/version และ audit commit atomically
- หากเขียน audit ไม่สำเร็จ mutation ต้อง rollback `[AI-DEFAULT]`
- Object upload แยกสองช่วง: upload+scan ก่อน แล้วค่อย commit attachment metadata; orphan object cleanup เป็น background job

### §4.4.1 Migration Strategy

1. สร้างตาราง, constraints, indexes และ RLS โดยยังไม่เปิด endpoint
2. register classification/PII fields กับ Policy Center
3. import legacy vendor เป็น `inactive` หรือสถานะที่ mapping ยืนยันได้; รายการกำกวม quarantine
4. สร้าง keyed hash จาก decrypted tax/bank data ใน controlled migration
5. reconcile counts/hash และ audit import batch
6. rollback ใช้ disable feature flag + restore backup; ห้ามลบ WORM audit

ไม่มี codebase ปัจจุบัน จึงต้องให้ DBA ปรับ naming เฉพาะ migration framework โดยคง logical contract นี้

## §4.6 Data Classification Enforcement

### §4.6.1 Classification Levels

| Level | API/UI | Storage | Audit |
|---|---|---|---|
| Internal | authenticated + tenant | RLS | mutation |
| Confidential | role/field policy; mask เมื่อไม่ผ่าน | encrypt sensitive columns | view + mutation |
| Restricted | Finance/Admin/explicit ACL; default exclude | strong encryption + key separation | view, mutation, export attempt |

### §4.6.2 Default Rule

- Default classification is Internal
- Public ต้องระบุ explicit; feature นี้ไม่มี Public field
- ห้าม downgrade classification ผ่าน payload หรือ client-side code

### §4.6.3 Enforcement Mapping

- PII flag แยกจาก classification และอยู่ใน PDPA inventory
- Tax ID: masked patternตาม approved HTML; full valueเฉพาะ Finance/Compliance/Admin
- Bank account: masked สำหรับทุก roleยกเว้น Finance/Admin
- ห้ามใส่ tax ID, bank number, address detail, KYC note หรือ attachment content ใน application log
- Search tax ID ใช้ normalized keyed hash; ห้าม deterministic encryption โดยไม่มี key separation

### §4.6.4 PII Overlay

- ทุก column ใน §4.2 มี PII flag แยกจาก classification
- PII=true ต้องอยู่ใน PDPA inventory, support data-subject handling ตาม legal basis และมี encryption/access audit
- vendor ที่เป็นนิติบุคคลยังอาจมี PII ใน contact, bank account, reason/note และ audit actor

### §4.6.5 Security Domain Mapping

| Domain concern | Applied control |
|---|---|
| Financial/Restricted | encryption, ACL, view/mutation audit |
| PII/PDPA | classification + PII inventory + minimization |
| Audit | append-only WORM, 7-year minimum |
| Multi-tenant | RLS + trusted tenant session |
| File security | private storage + allowlist + malware scan |

### §4.6.6 Policy Center Linkage

- register all non-Internal fields with Data Classification
- register bank, sanctions evidence, private attachments and protected audit snapshots with Restricted Resources
- runtime policy may strengthen access but may not downgrade schema default without governed change
- final ACL/policy set is OQ-06

## §4.7 RLS Baseline

```sql
USING (tenant_id = current_setting('app.current_tenant_id')::uuid)
WITH CHECK (tenant_id = current_setting('app.current_tenant_id')::uuid)
```

Tenant header จาก clientเป็นเพียง transport hint; middleware ต้อง derive/validate กับ token claim และ set DB session context
