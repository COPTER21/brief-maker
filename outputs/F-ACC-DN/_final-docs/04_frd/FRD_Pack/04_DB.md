### V_vendor_credit_ledger (view — display-only, FN-20)
Aggregate: `SELECT partner, vendor_name, SUM(vendor_credit) AS credit_balance, COUNT(*) AS dn_count FROM T_debit_note WHERE status IN ('approved','sent') AND vendor_credit > 0.005 GROUP BY partner, vendor_name`.
> flow ใช้/ตัดยอด (หักใบถัดไป/ขอคืน/อายุ) = **OQ-DN-06** — ยังไม่ทำ. รอบนี้ read-only.

## §4.3 Relationships (ER)

```
ap_invoice (F-ACC-APINV) ──(1:N soft, inv)──▶ T_debit_note ──(1:N)──▶ T_debit_note_line ──(soft src_line)──▶ ap_invoice_line
rtv_return (W3-LITE mock) ──(referenced, RTV)──▶ T_debit_note
T_dn_reason_master (1) ──< (N) T_debit_note (reason)
T_debit_note ──(1:N)──▶ T_dn_attachment · T_dn_audit
T_debit_note ──(effect on approve)──▶ ap_open_item(dn_applied=applyToAp) · V_vendor_credit_ledger(vendorCredit) · input_vat_line(negative, gated vendorCn) · journal_entry(mock)
approval_chain / approval_history = jsonb snapshot บน header (freeze ณ ส่ง)
```

## §4.6 Data Classification & Sensitive Data
### §4.6.1 Levels — Public / Internal (default) / Confidential (role AP+ผู้อนุมัติ) / Restricted (ไม่ใช้ที่นี่)
### §4.6.2 Default = Internal (ห้าม Public โดยลืม)
### §4.6.3 Enforcement
| Classification | DB | API | UI | Audit |
|---|---|---|---|---|
| Internal | RLS(tenant) | JWT | — | mutation |
| Confidential (amount/vendor PII/reason_text/vendorCn) | RLS + role | role check | mask ถ้า role ไม่ผ่าน | view+mutation |
### §4.6.4 PII overlay: vendor_name/tax_id/bill_to/sales_rep = Confidential + PII (PDPA scope) · amounts/vendorCn = Confidential + non-PII
### §4.6.5 Security Bible: D5 (amount→audit mandatory + Confidential) · D7 (PII encrypt at rest, บุคคล→mask ใน CSQ payload) · D9 (all mutation→T_dn_audit)
### §4.6.6 Policy Center linkage: field classification → Data Classification module · PII → PDPA consent scope. (ไม่มี Restricted → ไม่ต้อง register Restricted Resources)
