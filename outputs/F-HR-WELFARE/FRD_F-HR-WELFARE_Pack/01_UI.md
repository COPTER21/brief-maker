## §1.2 Per-Page Detail

### P-01: ทะเบียนสวัสดิการ (registry)
**Purpose:** จัดการประเภทสวัสดิการ (master, versioned). **Pattern:** A.
**ERP Context:** Sidebar active "สวัสดิการ" (1 เมนู #104) · tab "ทะเบียนสวัสดิการ".
**Components:** Data Table (ชื่อ/หมวด/โควตา-วงเงินต่อปี/กลุ่มที่มีสิทธิ์/วันมีผล/สถานะ/จัดการ) · Action "สร้างประเภท" · row action (ดู/แก้/ปิดใช้).
**Actions:**
| Action | Triggers | Calls (API) |
|---|---|---|
| "สร้างประเภท" | open drawer `benefit-create` | (form) → F-HR-WELFARE-API-02 |
| แก้ | open drawer `benefit-edit` | F-HR-WELFARE-API-04 |
| ปิดใช้ | modal `archiveBenefit` | F-HR-WELFARE-API-05 |
| ดู | drawer `benefit-view` | F-HR-WELFARE-API-03 |
**States:** loading (skeleton) · empty ("ยังไม่มีประเภท" CTA สร้าง) · loaded. **Permissions:** create/edit/archive = admin เท่านั้น (`canApprove` guard).

### P-02: คำขอใช้สิทธิ์ (requests)
**Purpose:** list คำขอ + filter สถานะ. **Pattern:** A.
**Components:** status filter `[ทุกสถานะ · ร่าง · รออนุมัติ · อนุมัติแล้ว · ไม่อนุมัติ · ยกเลิก · ระงับ · กลับรายการแล้ว]` (L2437) · Table (เลขที่คำขอ/ผู้ยื่น/ผู้ใช้สิทธิ์/ประเภท/มูลค่า/วันที่ใช้สิทธิ์/สถานะคำขอ/สถานะจ่าย) · Action "สร้างคำขอใช้สิทธิ์".
**Actions:**
| Action | Triggers | Calls |
|---|---|---|
| "สร้างคำขอใช้สิทธิ์" | drawer `request-create` | F-HR-WELFARE-API-09 |
| click row | drawer `request-view` (4 tab) | F-HR-WELFARE-API-10 |
| filter สถานะ | client filter (list โหลดจาก API-08) | F-HR-WELFARE-API-08 |
**States:** empty ("ยังไม่มีคำขอ" + CTA) · loaded. Value column masked ตาม role (FN-94).

### P-03: คงเหลือรายคน (balance)
**Purpose:** ค้นคน → สิทธิ์/โควตา/ยอดใช้/คงเหลือ ต่อ type + ผู้ติดตาม. **Pattern:** A + search-select.
**Components:** combobox `balEmp` (avatar → ชื่อ → ตำแหน่ง·แผนก · #102) · ตารางสิทธิ์ (ปีสิทธิ์ 2569) · sub-list ผู้ติดตาม · joiner note / leaver note.
**Actions:** เลือกพนักงาน → `render()` (API-16). เพิ่มผู้ติดตาม → drawer `dependent-create`. ลบผู้ติดตาม → modal `removeDep`.
**States:** empty ("เลือกพนักงานเพื่อดูสิทธิ์คงเหลือ") · leaver ("พนักงานพ้นสภาพ … คงเหลือหยุด") · no-eligible ("กลุ่ม … ไม่มีสิทธิ์…").

### P-04: รายงาน (report)
**Purpose:** usage report ตามประเภท/กลุ่ม/ช่วง. **Pattern:** K (view only · **no print/PDF**).
**Components:** stat cards (คำขอทั้งหมด · ใกล้เต็มโควตา ≥80% · …) · filter type/group/from/to (`state.repFilter`, `render()` จริง) · table + agg · empty state.
**Actions:** filter change → API-17. **Permissions:** admin/manager; masking มูลค่าตาม role.

## §1.3 User Journey (Happy Path — คำขอใช้สิทธิ์)

```
พนักงาน/HR เริ่มที่ P-02 คำขอใช้สิทธิ์
  ↓ กด "สร้างคำขอใช้สิทธิ์" → drawer request-create
[เลือกผู้ยื่น · self/dependent · type (เฉพาะ "มีสิทธิ์ ณ วันยื่น") · มูลค่า/จำนวน · วันที่ · แนบไฟล์]
  ↓ (API-09 POST /requests · eligibility+remaining pre-check)  status = pending(ยื่น)
[ส่งอนุมัติ → modal doa slot picker: เลือกคนขั้น 1 หัวหน้า → ขั้น 2 HR]
  ↓ (API-11 submit · GET /doa/resolve · freeze chain)  ขั้น 1 = current
[ขั้น 1 หัวหน้าสายงาน กด "อนุมัติ" (modal approve)]
  ↓ (API-12 approve · one-step advance FIX-03)  ขั้น 1 = approved · ขั้น 2 = current · status ยัง pending
[ขั้น 2 HR สวัสดิการ กด "อนุมัติ" (ขั้นสุดท้าย)]
  ↓ (API-12 · FIX-02 re-check eligibility+เพดาน) → status = approved
      · ตัดคงเหลือ (live ledger) · CSQ EC (welfare.granted) · pay = pending (hook) · NTF welfare_request_result
[ผู้ยื่นอ่านผล + สถานะจ่าย (display-only) ใน drawer request-view]
```

### Branch: Reversal (กลับรายการ — OQ-WEL-01)
```
status = approved + role ∈ {admin,manager} (canApprove)
  → ปุ่ม "กลับรายการ" ปรากฏใน drawer request-view (เฉพาะ approved && canApprove)
  → modal reverse (เหตุผลบังคับ)
  → (API-15) status = reversed (append-only) · คืนคงเหลือ (usedByPerson นับเฉพาะ approved)
      · CSQ EC reverse (negative offset) · ถ้า pay=sent → payrollClawback=true (flag)
      · NTF welfare_request_reversed
```

### Branch: Reject / Cancel / Revoke
```
pending → reject (modal · เหตุบังคับ) → rejected · ไม่ตัดคงเหลือ · NTF
draft/pending → cancel (modal) → cancelled · ไม่กระทบคงเหลือ
ทุกสถานะก่อน closed + leaver signal → revoked · คงเหลือหยุด · NTF welfare_eligibility_ended
```
