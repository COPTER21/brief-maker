# 04_DB — F-HR-WELFARE · Welfare (สวัสดิการ)

> **Audience:** DBA / Backend developer
> **Naming:** Tables = `T_welfare_*`, Fields = `snake_case`
> **Key principle:** Balance = **computed live** จาก ledger (คำขอ approved) — ไม่เก็บซ้ำ (BR-05). Audit = append-only, no hard delete (LK-5).

## §4.6 Data Classification & Sensitive Data

### §4.6.1 Levels (CUBE 4.0)
Public / Internal (default) / Confidential (mask ตาม role) / **Restricted** (hidden + audit access + Restricted Resources ACL).

### §4.6.2 Default Rule
Default = **Internal**. ห้าม default Public. Field ≠ Internal ระบุชัดใน §4.2.

### §4.6.3 Enforcement Mapping
| Classification | DB | API | UI | Audit |
|---|---|---|---|---|
| Internal | RLS (tenant) | JWT auth | — | mutation |
| Confidential (employee/dependent snapshot, reason) | RLS + column ACL | role check (`canSeePerson`/`canSeeDependent`) | mask `•••` | view+mutation |
| Restricted (`value`, dependent.name) | RLS + row ACL | role + ACL (`canSeeValue`; dependent = admin only) | hidden/`•••` + audit access | view+mutation+export |

### §4.6.4 PII Overlay
- `employee snapshot` → Confidential + PII · `dependent.name/rel/dob` → Restricted/Confidential + PII (PDPA scope).
- `value` → Restricted + ไม่ PII (financial, ไม่ใช่ personal data).

### §4.6.5 Security Bible Domain Mapping
- **D5 (Financial):** `value` → audit log mandatory; EC forward/reverse คู่กัน (BR-09/BR-11).
- **D7 (PII):** dependent/employee snapshot → encrypt at rest + PDPA scope.
- **D9 (Audit):** ทุก mutation → T_welfare_audit_log (append-only).

### §4.6.6 Policy Center Linkage
- classification → Data Classification module · Restricted (`value`, dependent) → Restricted Resources registry · PII → PDPA consent scope.
- **OQ-05:** masking ต้อง enforce ที่ **backend** ไม่ใช่แค่ UI (guard read ของ request คนอื่นตรง URL).

### §4.6.7 Balance / Exposure = Computed (no stored table)
- **remaining** = `benefit_type.quota − SUM(request.value|amount WHERE status='approved' AND employee+benefit_year+code match)`. `usedByPerson()` (HTML L2266) นับเฉพาะ `approved` ⇒ `reversed` คืนยอดเอง (ไม่ปรับซ้ำ) — BR-05/BR-11.
- **never negative-clamp ใน logic** (BR ledger) — ถ้าติดลบ = สัญญาณ over-approval, ต้องเห็น (display อาจ clamp แต่ค่าจริงไม่).
- **exposure** = `COUNT/SUM(request WHERE employee+benefit match AND status='pending' AND id≠current)` — display-only (OQ-WEL-03), ไม่ soft-reserve.
