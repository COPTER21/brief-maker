## Section 2 · Business Context

### 2.1 ปัญหา / โอกาส
องค์กรมีสวัสดิการหลายประเภท (ประกันสุขภาพ · ตรวจสุขภาพ · ค่าเล่าเรียนบุตร · กองทุนสำรองเลี้ยงชีพ) แต่การบริหารสิทธิ์ทำกระจัดกระจาย (Excel/กระดาษ) — ไม่มีทะเบียนกลางที่บอกได้ว่าใครมีสิทธิ์อะไร โควตา/วงเงินเท่าไร ใช้ไปเท่าไร คงเหลือเท่าไร ทำให้: อนุมัติเกินสิทธิ์ · ไม่มีรอยตรวจสอบ · มูลค่าสวัสดิการที่เป็นเงินได้พนักงานไม่เข้าระบบภาษี (7C).

### 2.2 เป้าหมาย business
1. ทะเบียนกลางของประเภทสวัสดิการต่อกลุ่มพนักงาน (โควตา/วงเงินต่อปีต่อคน · effective dating)
2. คำขอใช้สิทธิ์ → อนุมัติผ่าน DOA → ตัดคงเหลือ — โปร่งใส ตรวจสอบได้ append-only
3. มูลค่าสวัสดิการที่อนุมัติเข้าเงินได้พนักงานอัตโนมัติ (CSQ · 7C · EC)
4. **ไม่จ่ายเงินเอง** — ส่งสถานะให้ Payroll/Expense จ่าย (single source of truth ของการจ่ายอยู่ปลายทาง)

### 2.3 ตัวชี้วัดความสำเร็จ (วัดได้)

| ตัวชี้วัด | Baseline ปัจจุบัน | Target | วัดยังไง / จากไหน | วัดเมื่อไหร่ | คู่ §17.3 |

## Section 3 · Scope

### 3.1 In Scope (ทำอะไร)
1. ทะเบียนประเภทสวัสดิการ (benefit type) — สร้าง/แก้เป็นเวอร์ชัน/ปิดใช้ (soft archive) · กลุ่มมีสิทธิ์ · โควตา/วงเงิน/ปี · effective_date · ครอบผู้ติดตาม?
2. ผู้ติดตาม (คู่สมรส/บุตร/บิดา/มารดา) — ชื่อ · ความสัมพันธ์ · วันเกิด · สถานะใช้สิทธิ์
3. คำขอใช้สิทธิ์ (ตัวเอง/ผู้ติดตาม) — เลือกประเภทที่มีสิทธิ์ ณ วันยื่น · จำนวน/มูลค่า · แนบหลักฐาน
4. ส่งอนุมัติผ่าน **DOA** (slot picker เลือกคน 2 ขั้น · ไม่ hardcode สาย)
5. อนุมัติ → ตัดคงเหลือ + บันทึกมูลค่าเข้า 7C · EC + ส่งสถานะจ่าย (hook)
6. ไม่อนุมัติ / ยกเลิก (ก่อนอนุมัติ) / ระงับเพราะพ้นสภาพ (revoke)
7. **กลับรายการ (reversal)** ของคำขอที่อนุมัติแล้ว — append-only (OQ-WEL-01)
8. คงเหลือรายคนต่อ type + exposure ของคำขอที่ยังค้าง (OQ-WEL-03 · display-only)
9. สิทธิ์เปิด/ปิดตาม joiner/leaver signal (hook On/Offboard)
10. รายงานการใช้สิทธิ์ตามแผน/กลุ่ม/ช่วง + filter
11. RESTRICTED masking · audit append-only

## Section 7 · User Stories & Acceptance Criteria

> รูปแบบ Given-When-Then · description ห้ามมีคำว่า "และ" · ทุก Story ≥ 2 AC. (แต่ละ Story map FN)

- **US-01 (FN-01)** เป็น HR Admin ฉันสร้างประเภทสวัสดิการพร้อมกลุ่ม/โควตา/effective ได้.
  - AC1: Given ฟอร์มสร้าง, When กรอกครบ + ยืนยัน, Then บันทึกเป็น active + audit.
  - AC2: Given quota ≤ 0, When ยืนยัน, Then บล็อก + ข้อความ "โควตา/วงเงินต้องมากกว่า 0".
- **US-02 (FN-02)** เป็น HR Admin ฉันแก้ประเภทเป็นเวอร์ชันใหม่โดยเวอร์ชันเก่ายังอ้างอิงได้.
  - AC1: Given เวอร์ชัน active, When ออกเวอร์ชันใหม่ effective หลังเดิม, Then เก่า→archived + effTo=วันก่อนหน้า.
  - AC2: Given วันมีผลใหม่ ≤ เดิม, When บันทึก, Then บล็อก "ช่วงมีผลทับกันไม่ได้".
- **US-03 (FN-03/91)** เป็น HR Admin ฉันปิดใช้ประเภท (soft archive) โดยคำขอเก่ายังอ่านได้.
  - AC1: Given ปิดใช้ผ่าน confirm, Then status=archived ไม่ลบข้อมูล.
  - AC2: Given มีคำขอค้างอ้างอยู่, When เปิด confirm, Then เตือนจำนวนใบที่ค้าง.
- **US-04 (FN-05/06)** เป็น HR Admin ฉันเพิ่มผู้ติดตามให้พนักงานได้.
  - AC1: Given บุตรอายุ > 20, When บันทึก, Then บล็อก.
  - AC2: Given ผู้ติดตาม ≥ 3, When เปิดฟอร์ม, Then เตือนเกินเกณฑ์.
- **US-05 (FN-07)** เป็นผู้ยื่น ฉันสร้างคำขอเลือกประเภทที่มีสิทธิ์ ณ วันยื่นเท่านั้น.
  - AC1: Given เลือก type + self/dependent, Then combobox แสดงเฉพาะที่มีสิทธิ์.
  - AC2: Given แนบหลักฐาน, Then ไฟล์แสดงในรายการแนบ.
- **US-06 (FN-08/12)** เป็นผู้ยื่น ฉันส่งอนุมัติผ่าน DOA โดยเลือกคนในแต่ละขั้น.
  - AC1: Given เปิด slot picker, When ยังเลือกไม่ครบทุกขั้น, Then ส่งไม่ได้.
  - AC2: Given ส่งแล้ว, Then สาย DOA freeze + timeline แสดงชั้นปัจจุบัน.
- **US-07 (FN-09/10)** เป็นผู้ยื่น ฉันเห็นคงเหลือก่อนขอ ระบบกันไม่ให้ขอเกิน.
  - AC1: Given ขอ ≤ คงเหลือ, Then note "มีสิทธิ์ · คงเหลือ …".
  - AC2: Given ขอ > คงเหลือ, Then note danger + ปุ่มส่ง disabled.
- **US-08 (FN-11)** เป็นผู้ยื่น เมื่อยื่น type ที่ไม่มีสิทธิ์ ระบบบล็อกพร้อมบอกเหตุ.
  - AC1: Given นอกกลุ่ม/นอกช่วง, Then บล็อก + เหตุ.
  - AC2: Given พ้นสภาพ, Then บล็อก + เหตุ.
- **US-09 (FN-13)** เป็นผู้อนุมัติขั้นสุดท้าย เมื่ออนุมัติ ระบบตัดคงเหลือ + บันทึก 7C EC + ส่งสถานะจ่าย.
  - AC1: Given อนุมัติ, Then re-check เพดาน (FIX-02) ผ่านก่อนตัด.
  - AC2: Given อนุมัติแล้ว, Then history เพิ่ม "ตัดคงเหลือ + 7C EC + ส่งสถานะจ่าย".
- **US-10 (FN-14)** เป็นผู้อนุมัติ ฉันไม่อนุมัติพร้อมเหตุ ระบบไม่ตัดคงเหลือ + แจ้งผู้ยื่น.
  - AC1: Given เหตุผลว่าง, Then ไม่อนุมัติไม่ได้.
  - AC2: Given ไม่อนุมัติ, Then status=rejected + NTF.
- **US-11 (FN-15)** เป็นผู้ยื่น/Admin ฉันยกเลิกคำขอก่อนอนุมัติได้ ไม่กระทบคงเหลือ.
  - AC1: Given status draft/pending, Then ยกเลิกได้.
  - AC2: Given approved, Then ปุ่มยกเลิกไม่ปรากฏ (ต้องใช้กลับรายการ).
- **US-12 (FN-16)** เป็นระบบ เมื่อพนักงานพ้นสภาพ คำขอค้างถูกระงับ + คงเหลือหยุด.
  - AC1: Given leaver signal, Then คำขอค้าง → revoked.
  - AC2: Given last-day = null, Then ถือว่ายังทำงาน (ไม่ revoke).
- **US-13 (FN-17)** เป็นผู้ยื่น ฉันเห็นสถานะจ่ายที่อ่านจากปลายทางแบบ display-only.
  - AC1: Given approved, Then payPill แสดงสถานะจ่าย.
  - AC2: Then ไม่มีปุ่ม CRUD การจ่าย.
- **US-14 (FN-18)** เป็นระบบ เมื่อพนักงานเข้าใหม่เข้ากลุ่ม สิทธิ์เปิดอัตโนมัติ.
  - AC1: Given joiner signal, Then note "สิทธิ์เปิดอัตโนมัติ".
  - AC2: Then คงเหลือคำนวณจากปีสิทธิ์.
- **US-15 (FN-19)** เป็น HR/Manager ฉันดูรายงานการใช้สิทธิ์ตามแผน/กลุ่ม/ช่วง + filter.
  - AC1: Given เลือก filter, Then ตาราง+agg อัปเดตจริง.
  - AC2: Given ไม่มีข้อมูล, Then empty state.
- **US-16 (FN-13/OQ-WEL-01 · reversal)** เป็นผู้มีสิทธิ์อนุมัติ ฉันกลับรายการคำขอที่อนุมัติแล้วแบบ append-only.
  - AC1: Given status=approved + canApprove, Then ปุ่ม "กลับรายการ" ปรากฏ.
  - AC2: Given กลับรายการ + เหตุผล, Then status=reversed · คืนคงเหลือ · EC reverse · (ถ้าจ่ายแล้ว) flag clawback · ข้อมูลเดิมคงอยู่.
- **US-17 (OQ-WEL-03 · exposure)** เป็นผู้อนุมัติ ฉันเห็นคำขอ pending อื่นบนสิทธิ์เดียวกันเพื่อไม่อนุมัติเกิน.
  - AC1: Given tab คงเหลือ, Then แสดง "คำขอรออนุมัติอื่น: N ใบ · รวม …".
  - AC2: Then เป็น display-only ไม่ล็อก/reserve.

## Section 10 · Edge Cases

### 10.1 Edge Cases ที่ RIF/PREBRIEF ระบุ (☑ ยืนยันแล้ว)
- ☑ leaver ระหว่างคำขอค้าง → revoke (S-13) · null last-day ≠ ยังทำงาน (BR-06)
- ☑ eligibility ผิดกลุ่ม/ผิดช่วง = บล็อกพร้อมเหตุ (ห้ามบล็อกเงียบ · S-10)
- ☑ ใช้บางส่วน — คงเหลือถูกต้อง ใช้ต่อรอบหน้าได้ (S-08)
- ☑ ขอเกินคงเหลือ → บล็อก + แสดงยอด (S-09)
- ☑ ปิดใช้ type ที่มีคำขอค้าง → เตือนจำนวนใบ (FIX-06)
- ☑ กลับรายการหลังจ่ายแล้ว → flag Payroll clawback (OQ-WEL-01)
