## §1.2 Per-Page Detail

### P-01 · รอบประเมิน (`cycle`)
**Purpose:** รายการรอบ + สร้างรอบจาก HR Config + ปิดรอบ.
**Pattern:** A (list) + B (drawer `newCycle`/`viewCycle`) + D (modal `closeCycle`).

**Components:** Data Table (รหัส/รอบประเมิน/ช่วงเวลา/แบบประเมิน/สถานะ) · Drawer v2 · Confirm Modal 440.

**Actions:**
| Action | Trigger | Calls (API) |
|---|---|---|
| Click row | เปิด drawer `viewCycle` | F131-API-03 GET /cycles/:id |
| "สร้างรอบประเมิน" (hr only) | เปิด drawer `newCycle` | — (โหลด lookup F131-API-05) |
| เลือกรอบจาก ตั้งค่า HR + "สร้างและเปิดกรอก" | submit | F131-API-02 POST /cycles |
| "ปิดรอบ" (hr only, in `viewCycle`) → modal → "ปิดรอบ" | submit | F131-API-04 POST /cycles/:id/close |

**States:** Loaded table · closed cycle → pill "ปิดรอบ" (pill-muted) · per-person status ใน drawer + overdue pill.
**Permissions:** สร้าง/ปิดรอบ = `curRole().manage` (hr). ปุ่มไม่ render ให้ role อื่น.

**Microcopy (verbatim):**
- drawer note: "รอบ/แบบฟอร์ม/เกณฑ์คะแนน อ่านจาก ตั้งค่า HR — หน้านี้ไม่สร้าง/แก้ฟอร์มกลาง"
- validation: "กรุณาเลือกรอบจากตั้งค่า HR"
- success: "สร้างรอบ · เปิดกรอก · แจ้งเตือนผู้เข้าร่วมแล้ว"
- close modal: "ปิดรอบจะล็อกการแก้ไขทั้งหมด (soft archive) — ย้อนกลับไม่ได้" · success: "ปิดรอบแล้ว · ล็อกการแก้ไข (soft archive)"

### P-02 · แบบประเมินรายคน (`appr`)
**Purpose:** รายการแบบประเมิน (scoped+masked) + KPI editor + self + mgr + drawer 4 tabs.
**Pattern:** A (list + search/filter) + C (view drawer tabs: รายละเอียด / KPI-คะแนน / สอบทาน / ประวัติ).

**Components:** Search input · Status filter (`w180`: ทุกสถานะ/ตั้งเป้า/ประเมินตนเอง/หัวหน้าประเมิน/รอสอบทาน/เผยแพร่ผล) · Data Table · empty state · overdue banner · Drawer v2 tabbed · KPI editor (add/del rows + weight tag).

**Actions:**
| Action | Trigger | Calls (API) |
|---|---|---|
| ค้นหา/filter | `refreshView()` client filter | F131-API-06 GET /appraisals?... |
| Click row | เปิด drawer `viewAppr` (tab detail) | F131-API-07 GET /appraisals/:id |
| tab KPI → "บันทึกเป้า/KPI" (goal, hr) | submit | F131-API-08 PUT /appraisals/:id/kpis |
| tab KPI → "บันทึกประเมินตนเอง" (self, staff) | submit | F131-API-09 POST /appraisals/:id/self |
| tab KPI → "บันทึกผลหัวหน้า" (mgr, mgr∥hr) | submit | F131-API-10 POST /appraisals/:id/manager-review |
| overdue banner "ส่งการเตือน" | submit | F131-API-15 POST /appraisals/:id/reminder |

**States:** empty ("ไม่พบแบบประเมินที่ค้นหา" / "ลองปรับคำค้นหรือล้างตัวกรอง") · overdue banner ("มี N แบบประเมินเกินกำหนด — ต้องเตือนผู้ประเมิน") · closed cycle → read-only banner ("รอบนี้ปิดแล้ว — ดูได้อย่างเดียว แก้ไขไม่ได้") · weight tag ok/bad ("น้ำหนักรวม 100%" / "น้ำหนักรวม N% ≠ 100").
**Permissions:** list กรองด้วย `scopeSelf()` (staff=SELF · mgr=DEPT · hr=ALL). คะแนน/decision/gap ของผู้อื่น = `mask()` หรือไม่อยู่ใน DOM. KPI editable เฉพาะ goal+manage · self เฉพาะ self stage · mgr เฉพาะ mgr stage + (mgr∥manage). tabDetail ของผู้อื่น (staff/mgr นอก scope) → RESTRICTED note, ไม่มีข้อมูลใน DOM.

**Microcopy:** ดู 06_TESTS §6.10 (ยึด verbatim จากจอ).

### P-03 · สอบทาน + ผล & Gap (`review`)
**Purpose:** team-calibration + คิวสอบทาน (staged DOA) + ผลเผยแพร่ + hooks (Training/Movement/Succession) + PIP + re-open.
**Pattern:** section stack (team calib table + queue table + published list) + staged modal `doaCalib` + modal `pip` + modal `reopen`.

**Sections (order):**
1. **Calibration ระดับทีม** (`teamCalibHTML`, ผู้สอบทานเท่านั้น · scoped) — เทียบคะแนน/เกรดทั้งทีม + distribution (mock adjust). มติ OQ-PERF-04 KEPT.
2. **รอสอบทาน (calibration · DOA)** — queue (ซ่อนจาก staff) → ปุ่ม "สอบทาน (DOA)".
3. **ผล & Gap (เผยแพร่แล้ว)** — per-person: decision · masked score · PIP/re-open/hook buttons.

**Actions:**
| Action | Trigger | Calls (API) |
|---|---|---|
| "สอบทาน (DOA)" / "เริ่มสอบทาน + เลือกผู้สอบทาน" | modal `doaCalib` (จังหวะ 1: 2 slot ว่าง) | — |
| "ส่งสอบทาน" (เลือกครบ 2 ขั้น) | submit — freeze reviewers, คง calibration | F131-API-11 POST /appraisals/:id/calibration/send |
| "บันทึกผลสอบทานขั้น N" / "บันทึกผล + เผยแพร่ผล" (ขั้นสุดท้าย) | submit per-stage | F131-API-12 POST /appraisals/:id/calibration/stage |
| "เปิดแผน PIP" (decision ทบทวน) | modal `pip` → submit | F131-API-13 POST /appraisals/:id/pip |
| "เปิดแก้ไขผล" (published, hr) | modal `reopen` (reason บังคับ) → submit | F131-API-14 POST /appraisals/:id/reopen |
| "ส่งไปอบรม" (มี gap) | submit hook | F131-API-16 POST /appraisals/:id/dispatch/training |
| "ส่งเรื่องปรับตำแหน่ง/เงินเดือน" | submit event | F131-API-17 POST /appraisals/:id/dispatch/movement |
| "ส่งเข้า Succession Planning" (top/ผ่าน) | submit hook | F131-API-18 POST /appraisals/:id/dispatch/succession |

**Staged DOA modal `doaCalib` (2 จังหวะ — FIX-06):**
- จังหวะ 1 (`!a.approvals`): slot 1 "หัวหน้าสายงาน" + slot 2 "ผู้สอบทาน (HRBP/ผู้บริหาร)" — **ว่างทั้งคู่** (`value:null`, ผู้ส่งค้นหา/เลือกคนจริง) → ปุ่ม "ส่งสอบทาน" (freeze, status คง calibration).
- จังหวะ 2 (`a.approvals`): timeline ต่อขั้น (done/current/pending) — ผู้สอบทานขั้น current บันทึกผลของตน (stamp at+actor). ขั้นสุดท้ายมี dropdown "ผลการตัดสิน" (ผ่าน/ทบทวน (เปิด PIP)/ไม่ผ่าน) → "บันทึกผล + เผยแพร่ผล" → published + CSQ + notif.

**Permissions:** ปุ่ม mutation ทุกตัว = `sec.can('doCalib')` (manage). staff เห็นเฉพาะผลตนเอง (queue ซ่อน). mgr = DEPT-scoped.

**Microcopy:** ดู 06_TESTS §6.10.

### P-04 · รายงาน (`report`)
**Purpose:** stat tiles (แบบประเมินในรอบ / เผยแพร่ผลแล้ว / ทบทวน PIP) + distribution funnel + filter รอบ.
**Pattern:** K-lite (report, no print). Filter `select w220` (ทุกรอบ / รายชื่อรอบ). Buckets: ต่ำ (<3.0) / ปานกลาง (3.0–3.9) / ดี (4.0–4.5) / ดีเยี่ยม (>4.5).
**Actions:** filter change → F131-API-19 GET /reports/distribution?cycle=.
**Permissions:** respect RESTRICTED masking ตาม role scope (นับ aggregate เฉพาะ appraisal ที่ role เห็น).

## §1.3 User Journey (Happy Path)

```
HR เริ่มที่ tab "รอบประเมิน"
  ↓ "สร้างรอบประเมิน" → เลือกรอบจาก ตั้งค่า HR (#107) → "สร้างและเปิดกรอก"   [F131-API-02]
  ↓ (cycle status: draft → open) + notif "รอบเปิด"
HR → tab "แบบประเมินรายคน" → เปิด appraisal → tab KPI → ตั้งเป้า/KPI (Σ=100) → "บันทึกเป้า/KPI"   [F131-API-08]
  ↓ (appraisal: goal → self)
พนักงาน → tab KPI (self stage) → ให้คะแนนตนเอง 1–5 + note → "บันทึกประเมินตนเอง"   [F131-API-09]
  ↓ (self → mgr)
หัวหน้า → tab KPI (mgr stage) → ให้คะแนน + note → "บันทึกผลหัวหน้า" (weighted score)   [F131-API-10]
  ↓ (mgr → calibration)
HR → tab "สอบทาน" → "สอบทาน (DOA)" → เลือกผู้สอบทาน 2 ขั้น (ว่าง) → "ส่งสอบทาน"   [F131-API-11] (คง calibration, freeze)
  ↓ ผู้สอบทานขั้น 1 → "บันทึกผลสอบทานขั้น 1"   [F131-API-12]  (stamp at/actor · ยังไม่เผยแพร่)
  ↓ ผู้สอบทานขั้น 2 (สุดท้าย) → เลือก decision → "บันทึกผล + เผยแพร่ผล"   [F131-API-12 isLast]
  ↓ (calibration → published) + CSQ perf.result.published (per-person) + notif "ผลเผยแพร่"
HR → tab "สอบทาน + ผล & Gap" → ส่ง event/hook: Training (มี gap) / Movement / Succession (top)   [F131-API-16/17/18]
```

### Branch: decision "ทบทวน" → PIP
```
ขั้นสุดท้าย decision = "ทบทวน (PIP)" → published + gap default
  → "เปิดแผน PIP" → modal (gap/ระยะ/แผน) → "เปิดแผน PIP"   [F131-API-13]
```

### Branch: re-open published (OQ-PERF-01)
```
published (open cycle, hr) → "เปิดแก้ไขผล" → modal (เหตุผลบังคับ)
  → append-only audit (ใครแก้/เมื่อ/เหตุผล) · a.status → mgr · decision เคลียร์ · approvals ลบ   [F131-API-14]
  → เดิน flow ใหม่ (mgr → calibration → published) · staged DOA ซ้ำ · CSQ ยิงซ้ำ per-person
```

### Branch: ปิดรอบ (terminal lock)
```
HR → viewCycle → "ปิดรอบ" → confirm → cycle status = closed
  → ทุก mutation ต่อ appraisal ในรอบ block (guard cascade layer 1)   [F131-API-04]
```
