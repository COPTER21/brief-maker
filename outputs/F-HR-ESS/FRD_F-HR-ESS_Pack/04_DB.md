# 04_DB — F-HR-ESS · ESS Portal (พนักงานทำเอง)

> **Audience:** DBA / BE dev
> **Purpose:** Read-model / source-of-record refs + own tables + Field Dictionary + Data Classification (R10)
> **🚨 หลักการ:** ESS = **aggregator (read-only view layer)** — **ไม่มี entity/table ธุรกิจของตัวเอง** (BRD §6). ESS อ่าน read-model/view ของ owner feature (self-scope) และมี **ตารางเดียวของตัวเอง = access-audit** (append-only). ไม่มี running number · ไม่มี snapshot ธุรกิจ · ไม่มี write-back ไป owner feature.

| # | Read Surface (view/read-model) | Owner feature (source of record) | ESS อ่านอะไร | Scope | หมายเหตุ |

| SR-1 | Payslip PS-1 | Payroll (F-HR-PAYROLL) | สลิป + ประวัติ + YTD | self | **all-or-nothing · RESTRICTED** (LK-3) |

| SR-3 | OT / Attendance | OT/Attendance | OT เดือน + การสแกน | self | [ASSUMED] |
| SR-4 | Shift schedule | ระบบกะ/บันทึกเวลา (Time · W2) | ตารางกะสัปดาห์นี้ | self | [ASSUMED] · ESS ไม่แก้กะ |

## §4.2 Own Table — `T_ess_access_audit` (append-only · FN-93 · LK-6)

> ตารางเดียวที่ ESS เป็นเจ้าของ. บันทึก "การเข้าถึงข้อมูลของตัวเอง" ทุกครั้งที่เปิด surface/RESTRICTED. **append-only** — ไม่มี UPDATE/DELETE. ใช้แสดง "ประวัติการเข้าถึงข้อมูลของฉัน" (profile drawer) + feed self-access ให้ ENG-CSQ (SecC).

| Column | Type | Null | Classification | PII | Description |
|---|---|---|---|:--:|---|
| `id` | uuid (pk) | NO | Internal | — | รหัสรายการ audit |
| `tenant_id` | uuid | NO | Internal | — | RLS multi-tenant |
| `employee_id` | varchar | NO | Confidential | Yes | เจ้าของข้อมูล = ผู้เข้าถึง (self · เท่ากันเสมอ) |
| `surface` | varchar | NO | Internal | — | payslip / leave / ot / shift / expense / cert / welfare / training / profile / notify |
| `record_ref` | varchar | YES | Internal | — | id ของ record ที่เปิด (เช่น PS-2568-07) — soft ref, ไม่ FK |
| `action` | varchar | NO | Internal | — | `view` (default) · `reveal_restricted` (กดแสดงข้อมูลปิดบัง) |
| `csq_event` | varchar | YES | Internal | — | event id ที่ยิงเข้า SecC — **[ASSUMED · OQ-ESS-01]** (ห้าม hardcode) |
| `accessed_at` | timestamptz | NO | Internal | — | เวลาเข้าถึง (server time) |
| `ip` / `user_agent` | varchar | YES | Confidential | — | บริบทการเข้าถึง (security) |

**Constraints:** append-only (revoke UPDATE/DELETE ที่ role) · RLS `tenant_id` + `employee_id = current_user_employee_id` · index (`employee_id`, `accessed_at DESC`).

> **หมายเหตุ:** ESS **ไม่** เก็บสำเนา payslip/leave/expense ฯลฯ ของตัวเอง — อ่าน live จาก owner ทุกครั้ง (ลด attack surface · display-only by design). audit เก็บแค่ "ใครเปิดอะไรเมื่อไหร่" ไม่เก็บเนื้อข้อมูล.

## §4.3 Field Dictionary (read-through · จาก HTML mock → owner contract)

> ค่าเหล่านี้ ESS **อ่าน** ไม่ได้เก็บ. Classification = ระดับที่ ESS **แตะขณะแสดง** (enforce จริงที่ owner + backend ESS). masking = ESS ต้องปิดบังก่อนส่งถึง client.

| Field (read) | Surface | Type | Classification | PII | Masking (ESS) |
|---|---|---|---|:--:|---|
| `payslip.net` / `gross` / `deduct` / `ytd.*` | payslip | money | **Restricted** | — | all-or-nothing (เห็นทั้งใบ/ไม่เห็น) · self only |
| `payslip.period` / `pay_date` / `status` | payslip | text/date | Confidential | — | self only |
| `national_id` | profile | text | **Restricted** | Yes | mask `X-XXXX-XXXXX-56-7` · reveal ปุ่ม (self) → log `reveal_restricted` |
| `bank_account_no` | profile | text | **Restricted** | Yes | mask `••••••3456` · reveal (self) |
| `email` / `phone` / `dept` / `branch` / `start_date` | profile | text | Confidential | Yes | self only |
| `leave.*` / `expense.*` / `cert.*` / `training.*` | หลาย | mixed | Confidential | — | self only |
| `notification.*` | notify | text | Internal | — | self feed only |
| `shift.*` | shift | text | Internal | — | self only |

## §4.4 Relationships
```
พนักงาน (self) ──(1:N read)──▶ [Payslip·Leave·OT·Attendance·Shift·Expense·Cert·Welfare·Training·Profile·Notification]  (owner-owned)
ESS Portal    ──(aggregate/read-only, no FK write-back)──▶ ทุก surface ข้างบน
ESS Portal    ──(1:N append)──▶ T_ess_access_audit   (own · append-only)
"ยื่นคำขอ"     ──(deep-link/navigate, no data write)──▶ owner feature (leave/ot/expense/profile/cert)
```
**ไม่มี** entity ของ ESS นอกจาก audit · **ไม่มี** running number · **ไม่มี** state/lifecycle table.

## §4.5 Data Classification (R10) — enforcement mapping

| Level | Fields (ESS แตะ) | Enforcement (DB / API / UI / Audit) |
|---|---|---|
| **Restricted** | national_id, bank_account_no, payslip money/YTD | DB: owner-owned + RLS · API: ESS GET self-scope only, mask ก่อนตอบ · UI: masked + reveal (self) · Audit: `reveal_restricted` logged |
| **Confidential** | profile (email/phone/dept), leave/expense/cert/training records | API: self-scope 403 คนอื่น · Audit: `view` logged |
| **Internal** | notification feed, shift, audit metadata | self-scope · standard |
| **Public** | — (ไม่มี field public-facing) | — |

**Default = Internal** (ไม่มี field ที่ default Public). Restricted fields เป็น **read-through จาก owner** — register Restricted Resources ทำที่ owner feature; ESS อ้างอิงและ enforce masking/self-scope ซ้ำที่ backend (**OQ-ESS-05** · ห้าม enforce แค่ UI).
