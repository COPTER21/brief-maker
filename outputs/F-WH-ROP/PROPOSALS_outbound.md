# F-WH-ROP — เรื่องที่ต้องประสานต่อ

วันที่สรุป: 18 กันยายน 2569  
สถานะฟีเจอร์: เอกสารและต้นแบบพร้อมให้ผู้ใช้ตรวจรอบปิดงาน

## ต้องส่งต่อเจ้าของระบบอื่น

| ลำดับ | เรื่องที่ต้องยืนยัน/ดำเนินการ | เจ้าของ | ผลต่อ F-WH-ROP |
|---:|---|---|---|
| 1 | ยืนยัน `CSQ-ROP-01` เป็นรหัส profile จริง หรือแจ้งรหัสจาก Profile Registry | เจ้าของ F-CSQ-01 | ยังไม่ขวางการทดสอบ แต่ขวางการลงทะเบียน CSQ จริง |
| 2 | ยืนยันว่า `master.changed` มีในคำศัพท์ event กลางแล้วหรือจำเป็นต้องขึ้นทะเบียนใหม่ พร้อมค่า `trigger_status` ที่ถูกต้อง | เจ้าของ F-CSQ-01 | ต้องได้คำตอบก่อน POST register |
| 3 | ตัดสินว่าเปิด/ปิดนโยบายเติมสินค้า (`enabled`) ถือเป็น sensitive change ที่ต้องส่ง SecC หรือไม่ | Strike / PM/BA | ตอนนี้เอกสารระบุเป็น `[DEFAULT — รอยืนยัน]` |
| 4 | ยืนยัน Data Classification ของ Inventory Config ว่าค่า Min/Max/Safety/Lead Time/ADU Window ไม่ต้องปกปิด | เจ้าของข้อมูล Inventory | ต้องยืนยันก่อนใช้ข้อมูลจริงใน event |
| 5 | ให้ F072 รองรับที่มาของ PR ว่าเกิดจาก Reorder Point และเก็บข้อมูลอ้างอิงสินค้า คลัง และรอบตรวจ | เจ้าของ F072 | เป็นงานอีกฟีเจอร์ ห้ามแก้ F072 จากแพ็กนี้; ต้องพร้อมก่อนเชื่อมจริง |
| 6 | แก้ BASE-KIT typography ให้ใช้ตัวแปรขนาดตัวอักษรกลาง | เจ้าของ Design System | ไม่ขวางฟีเจอร์; ลงทะเบียนแล้วที่ `DSP-07` |

## ข้อสรุปที่ล็อกแล้ว

- F085 ส่ง CSQ เฉพาะตอนบันทึกการเปลี่ยนนโยบายสำคัญ โดยใช้ `master.changed` เข้า SecC
- การพบยอดต่ำเป็น Notification เท่านั้น ไม่ส่งเข้า CSQ
- การสร้างและวงจรชีวิตของ PR เป็นความรับผิดชอบของ F072 ไม่ประกาศซ้ำใน F085
- F085 สร้างเฉพาะ PR Draft และห้ามส่งอนุมัติอัตโนมัติ

## สถานะคำถามเปิด

- รายการ 1–5 ยังเปิดอยู่ แต่ไม่ขวางการรีวิว HTML, FRD และ UAT รอบนี้
- รายการ 1–5 ต้องปิดก่อนลงทะเบียน contract และเชื่อมระบบจริง
- ไม่มี source conflict หรือช่องว่างทางธุรกิจที่ขวางการส่งแพ็กให้ผู้ใช้ตรวจ
