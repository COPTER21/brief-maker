## §4.2 Per-Table Schema

> **Default classification = Internal.** Financial amounts = Confidential (จำกัด role AR/ผู้อนุมัติ). ไม่มี field ระดับ Restricted (person-ACL).

## §4.3 Relationships (ER)

```
ar_invoice (F094) ──(1:N soft, ref_invoice)──▶ T_credit_note ──(1:N)──▶ T_credit_note_line ──(soft src_line)──▶ ar_invoice_line
sales_return (F090 mock) ──(referenced, RET)──▶ T_credit_note
T_cn_reason_master (1) ──< (N) T_credit_note (reason)
T_credit_note ──(1:N)──▶ T_cn_attachment · T_cn_audit
T_credit_note ──(effect on approve)──▶ ar_open_item(cn_applied) · vat_output_line(negative) · journal_entry(mock)
approval_chain / approval_history = jsonb snapshot บน header (freeze ณ ส่ง)
```

## §4.6 Data Classification & Sensitive Data
### §4.6.1 Levels — Public / Internal (default) / Confidential (role AR+ผู้อนุมัติ) / Restricted (ไม่ใช้ที่นี่)
### §4.6.2 Default = Internal (ห้าม Public โดยลืม)
### §4.6.3 Enforcement
| Classification | DB | API | UI | Audit |
|---|---|---|---|---|
| Internal | RLS(tenant) | JWT | — | mutation |
| Confidential (amount/customer PII/reason_text) | RLS + role | role check | mask ถ้า role ไม่ผ่าน | view+mutation |
### §4.6.4 PII overlay: customer_name/tax_id/bill_to/sales_rep = Confidential + PII (PDPA scope) · amounts = Confidential + non-PII
### §4.6.5 Security Bible: D5 (amount→audit mandatory + Confidential) · D7 (PII encrypt at rest, บุคคล→mask ใน CSQ payload) · D9 (all mutation→T_cn_audit)
### §4.6.6 Policy Center linkage: field classification → Data Classification module · PII → PDPA consent scope. (ไม่มี Restricted → ไม่ต้อง register Restricted Resources)
