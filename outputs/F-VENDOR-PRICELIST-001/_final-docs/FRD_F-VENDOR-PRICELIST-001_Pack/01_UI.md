## §1.2 Per-Surface Contract

### P-01 รายการราคาคู่ค้า

**Visible anchors:** `รายการราคาคู่ค้า`, `Import`, `Batch Entry`, `เปรียบเทียบราคา`, `สร้างรายการราคา`, `ทุกรายการ`, `แยกตามคู่ค้า`.

**Structure:** page header → KPI cards → view tabs → search/status toolbar → table. Flat table displays full vendor code and full product code. Vendor view groups records and links to P-02.

| Action | Result | API |
|---|---|---|
| Search `ค้นหาคู่ค้า สินค้า หรือรหัส` | filter by vendor name/code and product name/code | API-01 |
| Status filter | draft/pending_approval/active/inactive | API-01 |
| Click row | open P-05 | API-02 |
| Create | open P-04 create | API-03/05 |
| Edit draft | open P-04 with editable identity | API-04/05 |
| Active pencil | open P-04 as new Price Version; identity locked | API-07 |
| Power/restore | open P-07 | API-08 |

**States:** loading skeleton, loaded, filtered empty, no-data empty, 403 masked/disabled, error + retry. Price numbers must never appear in DOM/API payload for unauthorized roles.

### P-02 รายการราคาตามคู่ค้า

Header shows vendor name + full vendor code. `สร้างรายการราคา` is available only when the current F-VENDOR status is `active`; otherwise show `คู่ค้าไม่พร้อมใช้งาน`. Create drawer preselects and locks vendor with helper text explaining why.

### P-03 Batch Entry

**Visible anchors:** `Batch Entry`, `เพิ่มแถว`, `ตรวจสอบและส่งอนุมัติ`, `ผ่าน N แถว`, `ต้องแก้ N แถว`.

- Vendor and Product cells are searchable master dropdowns, not free text.
- Product choice refreshes UOM to only base/default and `T_product_uom.can_buy=true` choices.
- Each row has delete control; at least one editable row remains.
- Empty rows are ignored. Started but incomplete/invalid rows are highlighted and block submit.
- Successful submit returns to P-01 and all created records appear as `รออนุมัติ`.
- Submit button has in-progress disabled state; retry uses the same idempotency key.

### P-04 Create / Edit / New Version Drawer

**Step 1 — คู่ค้าและสินค้า**

- `คู่ค้า *`: search by code/name from active F-VENDOR.
- `สินค้า *`: search by code/name from active+purchasable Product Master.
- `Purchase UOM *`: dropdown constrained by selected product.
- `สกุลเงิน *`: defaults from selected vendor.
- In draft edit all identity fields may change and are revalidated.
- In Active → new version, vendor/product/UOM/currency are locked and every locked control shows a lock label + helper.
- To change UOM/currency of an Active item, action `สร้างรายการใหม่จากรายการนี้` opens clone mode and requires identity change before saving/submitting.

**Step 2 — เงื่อนไขราคา / สรุปก่อนส่ง**

Fields: ประเภทราคา, ราคาตั้ง, ราคาต่อจำนวน, ส่วนลด %, ค่าขนส่งต่อหน่วย, ภาษีซื้อ, เริ่มใช้, สิ้นสุด, เหตุผล. Review shows target version, post-submit status `รออนุมัติ`, change percentage, current approval path, current policy threshold and SLA.

Buttons: `ยกเลิก`, `บันทึกร่าง`, `ถัดไป`, `กลับ`, `ยืนยันและส่งอนุมัติ`. Closing with unsaved changes should use the application-wide dirty-form guard in production.

### P-05 View Drawer

Header shows product, status, price-list reference, vendor code/name and context actions.

| Tab | Content |
|---|---|
| `ภาพรวม` | vendor/product identity, price formula breakdown, effective range and trace explanation |
| `ประวัติราคา` | current version and earlier immutable versions |
| `Approval & Audit` | requester, approver, change %, resolved approval path, SLA |

Pending records expose `ปฏิเสธ` and `อนุมัติ`; inactive exposes `เปิดใช้งาน`; draft exposes `แก้ไขร่าง`; active exposes `สร้างราคาฉบับใหม่`.

### P-06 เปรียบเทียบราคา

**Visible anchors:** `เปรียบเทียบราคา`, `สินค้า`, `ปริมาณ`, `วันที่ใช้ราคา`, `สกุลเงินเปรียบเทียบ`, `คำนวณ`.

- Product is a search dropdown from active+purchasable master data.
- Result does not change until the user presses `คำนวณ`.
- While inputs differ from the last run, show dirty state in the run bar.
- Candidate set: Active VPL + active vendor + active/purchasable product + matching date and tier.
- Results are sorted landed unit cost converted to THB ascending.
- First row shows the compact trophy/rank marker and accessible label meaning “ราคาดีที่สุด”.
- FX unavailable/stale: exclude affected candidate or block result with explicit reason; do not assume rate.

### P-07 Confirmation Modals

| Type | Title | Required input | Success |
|---|---|---|---|
| approve | `อนุมัติราคาฉบับนี้หรือไม่?` | none; SoD checked server-side | `อนุมัติแล้ว` |
| reject | `ปฏิเสธราคาฉบับนี้หรือไม่?` | `เหตุผล *` | `ส่งกลับเป็นร่างแล้ว` |
| deactivate | `ปิดใช้งานรายการราคา?` | none | `ปิดใช้งานรายการแล้ว` |
| activate | `เปิดใช้งานรายการราคา?` | current vendor/product eligibility | `เปิดใช้งานรายการแล้ว` |

### P-08 Import Vendor Price List

Flow displayed as four sections: `เลือกไฟล์` → `ตั้งค่าการนำเข้า` → `ผลการตรวจสอบ` → `ตัวอย่างข้อมูล`.

- Accept CSV UTF-8 only; template action provides current column contract.
- Human-facing modes: `เพิ่มรายการใหม่และอัปเดตรายการเดิม` and `แทนที่รายการที่ยังไม่ถูกนำไปใช้`.
- Preview shows full vendor/product codes, UOM, price and row result.
- `ยืนยันนำเข้า` stays disabled before validation.
- Commit returns P-01, shows outcome summary, and new/updated rows are `รออนุมัติ`.
- Duplicate stable external ID + same content is skipped idempotently; invalid rows are not committed.

## §1.3 Journeys

### J-01 Create and approve

P-01 Create → P-04 Step 1 select active vendor + active/purchasable product/UOM → Step 2 enter price/reason → `ยืนยันและส่งอนุมัติ` → pending_approval → different authorized approver opens P-05 → approve confirm → Active on effective date.

### J-02 New version

P-01 active row pencil → P-04 identity locked → change price/effective dates/reason → submit → old version stays usable until approved version reaches effective date → approval activates new immutable version and supersedes prior applicable version.

### J-03 Batch/import

P-03 rows or P-08 CSV → validate all master references and duplicates → confirm → atomic commit of accepted set → P-01 pending_approval records.

### J-04 Deactivate/reactivate

Active → confirm deactivate → Header inactive and excluded from resolve/compare. Inactive → confirm activate → revalidate vendor/product and no overlap → Active; historical versions stay immutable.

|---|---|---|
| `vendor_price_submitted_event` | resolved approver | in-app approval task |
| `vendor_price_approved_event` | requester + subscribed downstream | status refresh; effective activation schedule |

## §1.6 Error / Empty / Loading States

- No list data: CTA `สร้างรายการราคา` for permitted user.
- Search no match: empty message with reset-filter action.
- 409 stale data: inform user data changed and reload current record; never silently overwrite.
- Master invalidated between select and submit: keep input visible, show current invalid state, block mutation.
- 422 overlap/duplicate: anchor message at effective range or identity section.
- Network outcome unknown: keep operation key and offer safe retry; do not create a second record.

## §1.7 Accessibility & i18n

- Every interactive element must be a native control or have equivalent keyboard semantics.
- Search dropdown supports Arrow keys, Enter, Escape, clear, `aria-expanded`, listbox/option semantics.
- Drawer/modal has focus trap, close button, Escape dismissal one layer at a time, and restores focus to opener.
- Visible focus indicator and WCAG AA contrast are mandatory.
- Table actions have accessible names beyond icon/title; best-price marker exposes text for assistive tech.
- Thai labels shown above are verbatim HTML anchors; production strings must be mapped to i18n keys without changing visible wording.

## §1.8 HTML Alignment Notes

- Company/Site are intentionally not visible inputs; implementation derives company and defaults site to null.
- UI prototype simulates latency with timers; production must wait for specific API completion/state, not fixed delay.
- Prototype fixtures are illustrative only. Vendor UUID/code/status must come from F-VENDOR and Product UUID/UOM/status from Product Master at runtime.
