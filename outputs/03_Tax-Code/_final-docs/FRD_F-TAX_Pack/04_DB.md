## §4.1 Table Overview

| Table | Purpose | Owner Feature | Multi-tenant |
|---|---|---|---|
| `T_tax_code` | ทะเบียนรหัสภาษีกลาง (master) | F-TAX (this) | YES (RLS) |

> **Soft reference (LOCK-SOFT-REF):** ปลายทาง (Item Master / เอกสาร / GL Posting Setup) เก็บแค่ `code` (string) — **ไม่มี FK cascade**. ไม่มีตาราง junction/ref ใน feature นี้.
> **`used_count` = mock ปัจจุบัน** (OQ-TAX-04). ของจริง = derived count จากสินค้า+เอกสารทุกใบที่อ้าง code (นับข้ามโมดูล — ไม่ใช่ FK). ห้ามเปิด hard-delete/รายงานความถูกต้องจาก field นี้จนกว่า sync จริง.

## §4.2 Per-Table Schema

> **Data Classification:** ทุก field ระบุ 1 ใน 4 ระดับ. **Default = Internal**. Feature นี้ = **Internal ทั้งหมด** (ไม่มี PII / ไม่มี Restricted) — เป็น reference master data ระดับระบบ.

### T_tax_code

**Purpose:** 1 แถว = 1 รหัสภาษี (นิยาม code/name/type/rate/status + audit + DOA placeholder)

| Column | Type | Null | Default | Classification | PII | Description |
|---|---|---|---|---|---|---|
| `id` | uuid | NO | gen_random_uuid() | Internal | — | PK |
| `tenant_id` | uuid | NO | — | Internal | — | FK → T_tenant; RLS (1 ERP = 1 company) |
| `code` | varchar(32) | NO | — | Internal | — | รหัสภาษี · **unique case-insensitive per tenant** (BR-01) · เว้นว่าง→auto (VATxx/WHTxx/TAXxx) · **immutable when used_count>0 (IR-TAX-01)** |
| `name_th` | varchar(160) | NO | — | Internal | — | ชื่อไทย (required, BR/VR-01) · editable เสมอ |
| `name_en` | varchar(160) | YES | — | Internal | — | ชื่ออังกฤษ (optional) · editable เสมอ |
| `category` | varchar(10) | NO | 'vat' | Internal | — | enum: `vat` / `wht` / `exempt` (fix 3 ค่า, LOCK-TYPE-3) · **immutable when used_count>0** |
| `rate` | numeric(5,2) | NO | — | Internal | — | อัตรา % · CHECK 0–100 · **exempt→0 เสมอ (LOCK-EXEMPT-0)** · **immutable when used_count>0** · precision 2 ทศนิยม `[AI-DEFAULT ← EC-A5]` (OQ-TAX-RATE-PREC) |
| `status` | varchar(10) | NO | 'draft' | Internal | — | enum: `draft` / `active` / `inactive` · เปลี่ยนอิสระ (LOCK-STATUS-FREE) · form create default = `active`; import status ว่าง = `draft` (BR-08) |
| `used_count` | integer | NO | 0 | Internal | — | จำนวนสินค้า/เอกสารที่อ้าง — **read-only, mock** (OQ-TAX-04). ของจริง = derived, ห้าม client เขียน |
| `created_by` | varchar(120) | NO | — | Internal | — | ผู้สร้าง (audit, BR-10) — production = FK → T_user |
| `created_at` | timestamptz | NO | NOW() | Internal | — | Audit |
| `updated_by` | varchar(120) | NO | — | Internal | — | ผู้แก้ล่าสุด (audit) |
| `updated_at` | timestamptz | NO | NOW() | Internal | — | Audit + optimistic lock ref |
| `version` | integer | NO | 1 | Internal | — | Optimistic locking (`If-Match`) `[AI-DEFAULT — Phase 2.5 PR-2]` |
| `approver_role` | varchar(60) | YES | NULL | Internal | — | **DOA placeholder = NULL เสมอ (LOCK-DOA-NULL)** — เตรียมเชื่อม Policy Center |
| `approved_by` | uuid | YES | NULL | Internal | — | DOA placeholder = NULL |
| `approved_at` | timestamptz | YES | NULL | Internal | — | DOA placeholder = NULL |
| `approval_chain` | jsonb | YES | NULL | Internal | — | DOA placeholder = NULL |

**Constraints:**
- PRIMARY KEY (`id`)
- **UNIQUE (`tenant_id`, `lower(code)`)** — case-insensitive uniqueness (BR-01 · EC-01 · กัน concurrent EC-A3) — implement via unique index บน `(tenant_id, lower(code))`
- CHECK (`rate` >= 0 AND `rate` <= 100) — BR-02
- CHECK (`category` IN ('vat','wht','exempt')) — LOCK-TYPE-3
- CHECK (`status` IN ('draft','active','inactive'))
- **CHECK (`category` <> 'exempt' OR `rate` = 0)** — LOCK-EXEMPT-0 enforce ที่ DB (นอกเหนือ UI/logic)
- CHECK (`used_count` >= 0)

**Indexes:**
- `UX_tax_code_tenant_lower_code` UNIQUE ON (`tenant_id`, lower(`code`))
- `IDX_tax_code_tenant_status` ON (`tenant_id`, `status`) — filter + lookup active
- `IDX_tax_code_tenant_category` ON (`tenant_id`, `category`) — filter ประเภท
- `IDX_tax_code_created_at` ON (`created_at` DESC)

**RLS Policy:**
```sql
CREATE POLICY tenant_isolation ON T_tax_code
  USING (tenant_id = current_setting('app.current_tenant')::uuid);
```

## §4.3 Relationships (ER Diagram)

```
T_tenant (1) ──< (N) T_tax_code        [RLS isolation]

T_tax_code.code  ◀┈┈(soft ref, no FK)┈┈  ItemMaster.tax_group      (เลือกเฉพาะ status='active')
T_tax_code.code  ◀┈┈(soft ref, no FK)┈┈  Sales/PurchaseDoc.line    (ใช้ rate คำนวณ VAT/WHT)
T_tax_code.code  ◀┈┈(soft ref, no FK)┈┈  GL_Posting_Setup          (map code → บัญชี GL)
```
- ทุกความสัมพันธ์ปลายทาง = **soft reference** (เก็บ `code` string, ไม่มี FK/cascade) → LOCK-SOFT-REF
- ไม่มี hard delete ตัวที่ `used_count > 0` (BR-05)

## §4.6 Data Classification & Sensitive Data

### §4.6.1 Classification Levels (CUBE 4.0 Standard)
| Level | นิยาม | ใช้ใน feature นี้? |
|---|---|---|
| Public | เผยแพร่ภายนอกได้ | ไม่ (ไม่ default Public) |
| **Internal** | เห็นได้เฉพาะคนในบริษัท (default) | **✅ ทุก field** |
| Confidential | จำกัด role | ไม่มี |
| Restricted | จำกัดถึง person (ACL) | ไม่มี |

### §4.6.2 Default Rule
- Default = **Internal**. ไม่มี field ใด default Public. Feature นี้ไม่มี field ที่ยกระดับเกิน Internal.

### §4.6.3 Enforcement Mapping (สำหรับ Internal)
| Classification | DB | API | UI | Audit |
|---|---|---|---|---|
| Internal | RLS (tenant) | JWT auth | — | mutation log (BR-10) |

### §4.6.4 PII Overlay
- **ไม่มี PII field** (pii_flag = false ทุก column). `created_by`/`updated_by` = ชื่อผู้ใช้ระบบ (audit reference), ไม่ใช่ personal data ของลูกค้า → ไม่เข้า PDPA scope ของ feature นี้.

### §4.6.5 Security Bible Domain Mapping
| Domain | เกี่ยวข้อง |
|---|---|
| Audit | ทุก mutation → audit (created/updated by+at) |
| Data Integrity | unique constraint + IR-TAX-01 guard + exempt CHECK |
| Access Control | RBAC deferred (OQ-TAX-06) |
| **ไม่ trigger** | Financial-PII, Encryption (ไม่มี PII/amount ในตาราง) |

### §4.6.6 Linkage with Policy Center
- ไม่มี Restricted/Confidential/PII → ไม่ต้อง register Restricted Resources / PDPA scope.
- DOA placeholder fields (approver_*) เตรียม wire Policy Center อนาคต (ปัจจุบัน = null).
