# 04_DB — F-BOM-001 สูตรการผลิต (Bill of Materials)

> **Audience:** DBA + Backend + Security  
> Target relational model: PostgreSQL-compatible. All tenant-owned queries are protected by RLS.

## §4.1 Entity Relationship

```text
T_bom_header (1) ─────< T_bom_line
      │
      └──────────────< T_bom_audit_log (append-only, retained after BOM deletion)

Item/UoM/MO are external module contracts; codes are soft references validated by service adapters.
```

## §4.5 Constraints and Indexes

```sql
ALTER TABLE T_bom_header
  ADD CONSTRAINT ck_bom_status
    CHECK (status IN ('draft','active','inactive')),
  ADD CONSTRAINT ck_bom_out_qty
    CHECK (out_qty > 0),
  ADD CONSTRAINT ck_bom_default_active
    CHECK (NOT is_default OR status = 'active');

ALTER TABLE T_bom_line
  ADD CONSTRAINT ck_bom_line_qty CHECK (qty > 0),
  ADD CONSTRAINT ck_bom_line_scrap CHECK (scrap_pct BETWEEN 0 AND 100);

CREATE UNIQUE INDEX ux_bom_code
  ON T_bom_header (tenant_id, code);
CREATE UNIQUE INDEX ux_bom_parent_version
  ON T_bom_header (tenant_id, parent_code, version_normalized);
CREATE UNIQUE INDEX ux_bom_one_default
  ON T_bom_header (tenant_id, parent_code)
  WHERE is_default = true;
CREATE UNIQUE INDEX ux_bom_line_no
  ON T_bom_line (tenant_id, bom_id, line_no);
CREATE UNIQUE INDEX ux_bom_component
  ON T_bom_line (tenant_id, bom_id, component_code);
CREATE INDEX ix_bom_list_status_modified
  ON T_bom_header (tenant_id, status, modified_date DESC);
CREATE INDEX ix_bom_parent
  ON T_bom_header (tenant_id, parent_code, is_default DESC);
CREATE INDEX ix_bom_audit_resource
  ON T_bom_audit_log (tenant_id, bom_id, changed_at DESC);
```

`version_normalized` must be produced by one shared normalizer in FN-05 and verified against the same DB collation/normalization strategy. A raw `lower(version)` shortcut is insufficient for every Unicode case; migration tests lock the chosen behavior.

## §4.6 Data Classification (R10 / D-CLASS)

### §4.6.1 Field coverage

Every stored column is classified in §4.2–§4.4. Derived/API fields:

| Field | Classification | Reason |
|---|---|---|
| `used` | Internal | operational reference count |
| `standard_cost` | Confidential | product cost |
| `line_cost`, `total_cost`, `unit_cost` | Confidential | derived commercial cost |
| Item name/image/UoM display | Internal | master display data |
| authorization decision details | Restricted | policy internals; never returned |

No BOM business field is PII. Actor IDs in audit are Confidential because they identify a person/account.

### §4.6.2 API enforcement

- default deny cost projections; require explicit cost-view permission
- unauthorized list/detail returns `null` cost and `cost_masked=true`, not a reversible obfuscation
- MO contract never returns cost
- errors and logs never include raw access tokens, cookies, secrets, or full policy payloads

### §4.6.3 UI enforcement

The server decides visibility. UI hides or masks cost columns consistently in list/detail/form and never derives cost from hidden raw response fields.

### §4.6.4 Export/print

Export/print are out of scope. If introduced later, Confidential columns require a new scope review and explicit access/audit design.

### §4.6.5 Audit enforcement

Log access to cost-bearing responses per Policy Center requirement; log all mutations with sanitized before/after. Do not place secrets or entire upstream payloads in JSON diffs.

### §4.6.6 Classification change

Any downgrade/override is managed centrally through Policy Center; this feature does not implement classification administration.

## §4.7 Row-Level Security

Application sessions set a verified tenant context. RLS policies require `tenant_id` equality for SELECT/INSERT/UPDATE/DELETE on all three tables. Foreign-key/service operations verify header and line tenant match. Cross-tenant IDs resolve as not found to avoid enumeration.

## §4.8 Migration and Rollback

1. create tables and append-only grants
2. add constraints/indexes/RLS policies
3. seed the dedicated internal code sequence `[AI-DEFAULT]`
4. deploy adapters/service, then routes
5. verify unique/default concurrency and RLS with integration tests

This is a new feature: no legacy row backfill was identified. Rollback disables routes first; do not drop tables/audit automatically. Data-removal authorization is not present in this conversation.

## §4.9 Data Integrity Boundaries

- external Item/UoM codes are soft references because their modules own lifecycle; validate current status/type/category at each mutation
- existing rows remain readable if a master is later deactivated; new save behavior follows BR-15 provisional policy
- MO usage is not denormalized as a trusted header field
- default change and status change occur in the same transaction
- cost projections are current-as-of reads, not accounting postings or immutable historical valuation
