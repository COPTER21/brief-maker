## §6.1 Acceptance Criteria
| AC | Given / When / Then | อ้าง |
|---|---|---|
| AC-01 | owner สร้าง ใส่ใบเบิก+ยอด+2 รายการ → ยอดคำนวณสด · focus ไม่หลุด · บันทึกได้เลข ACL-YYYY-NNNN | S-01 BR-01/02 FN-03 |
| AC-02 | กดถัดไปตอนว่าง → บล็อก + ช่องแดง + toast "กรุณากรอกข้อมูลให้ครบถ้วน" | VR-01..03 |
| AC-03 | เหลือคืน>0 → ขั้นแนบแสดงบัญชีบริษัทจาก config + เตือนแนบสลิป | S-02 BR-06 |
| AC-04 | ส่ง → modal slot = จำนวนขั้น DOA · ค่าเริ่มจาก resolve · ผู้ขอไม่อยู่ในรายชื่อ · ไม่เลือก = แดง | S-03 VR-04 |
| AC-05 | อนุมัติเรียงขั้น 1→2→3 → เคลียร์แล้ว · PDF เก็บ approved_final | S-04 |
| AC-06 | ขั้น 2 เหลือคืน>0 ไม่มีสลิป → กดรับเคลียร์ไม่ได้ (422 REFUND_SLIP_REQUIRED / toast) | S-05 BR-04 |
| AC-07 | ไม่อนุมัติ/ไม่รับเคลียร์ (เหตุผลบังคับ) → ร่าง เลขเดิม · แถบส่งกลับแก้ไข | DEC-08 BR-DOA-03 |
| AC-08 | ใช้เกิน → ยอดติดลบแดง · PDF "-x" + "ลบ…" · อนุมัติครบ → acl_overspent_approved | S-06 EC-02 |
| AC-09 | PDF ทุกสถานะ 1 หน้า · ลายเซ็น = ผู้ขอ + 1/ขั้น · ≥10 แถว · HTML render = server render | S-07 |
| AC-10 | ยกเลิก: owner/การเงิน · ร่าง/รออนุมัติ · เหตุผลบังคับ | S-08 |
| AC-11 | การเงินเห็นทุกใบ · CSV ตามตัวกรอง | S-09 |
| AC-12 | doc_type ปิดใช้ → ปุ่มสร้าง disabled + แถบแดง | EC-07 |
| AC-13 | ตั้ง DOA 1 / 3 / 6 ขั้น → PDF มีช่องลงชื่อ 2 / 4 / 7 ช่อง (6 ขั้น = 2 แถว 4+3) · ขั้นของ role-finance-officer ใช้คำ รับเคลียร์/ไม่รับเคลียร์ · บล็อกลงชื่อไม่ถูกตัดกลาง | BR-12 · FN-08 |
