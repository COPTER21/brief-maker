### 3.1 รายการซ้ำ
- **หัวข้อการประเมิน (Performance Item)** — บนกระดาษ 4 แถว (min_rows) · ช่องในแถว: หัวข้อการประเมิน (Performance Item), คะแนนเฉลี่ย, คะแนนที่ได้

### 3.2 ตัวเลือก
- **ประเภท (สินค้า / บริการ)** (เลือกได้หลายข้อ): สินค้า → ใช้ช่อง สินค้า : (Goods Specific) : · บริการ → ใช้ช่อง บริการ : (Service Specific) :
- **ระบบการบริหารงานที่ได้รับรองมาตรฐานต่างๆ** (เลือกได้หลายข้อ): GMP (Good Manufacturing Practice Codex Alimentarius) · ISO (International Organization for Standardization) · HACCP (เครื่องหมายรับรองมาตรฐานการผลิต) · Halal (สนง.คณะกรรมการกลางอิสลามแห่งประเทศไทย) · มอก. (เครื่องหมายมาตรฐานผลิตภัณฑ์อุตสาหกรรม) · อย. (เครื่องหมายรับรองจากสำนักงานคณะกรรมการอาหารและยา) · Q (กระทรวงเกษตรและสหกรณ์) · อื่นๆ → ใช้ช่อง อื่นๆ
- **สรุปผลการประเมิน (Evaluate Summary)** (เลือกได้ข้อเดียว): น้อยกว่า  6  :  ผู้ขาย/ผู้ให้บริการ ที่ไม่ผ่านการพิจารณา (Fail,Non qualified) · มากกว่า หรือ เท่ากับ 6  :  ผู้ขาย/ผู้ให้บริการ ที่ผ่านการพิจารณา (Pass)
- **คำตัดสินผู้จัดทำ (แผนกจัดซื้อ)** (เลือกได้ข้อเดียว): เห็นด้วย (Agree / Acknowledge) · ไม่เห็นด้วย (Not Agree)
- **คำตัดสินผู้อนุมัติ** (เลือกได้ข้อเดียว): อนุมัติ (Approve) · ไม่อนุมัติ ( Not Approve)

### 3.3 สูตร + ค่าคงที่บนกระดาษ
- สูตร: คะแนนรวม (คะแนนเฉลี่ย) = `Σ criteria[].max_score` = 10 ตามกระดาษ
- สูตร: คะแนนรวม (คะแนนที่ได้) = `Σ criteria[].score` ต้นฉบับ Excel แสดง 0 เมื่อยังไม่กรอก
- สูตร: สรุปผลการประเมิน (Evaluate Summary) : = `F11 < pass_threshold ? fail : pass` pass_threshold = 6 บนกระดาษ → อ่านจาก config
- ค่าคงที่ "หัวข้อการประเมิน 4 ข้อ + เกณฑ์ย่อย (3-5 วันทำการ · 0.5-1% · 24 ชม. · 3 วันทำการ)" = เกณฑ์การประเมินผู้ขาย → ควรอ่านจาก `VendorEvaluationConfig.criteria[].text` (ห้าม hardcode)
- ค่าคงที่ "คะแนนเฉลี่ย 3 / 4 / 2 / 1 (รวม 10)" = คะแนนเต็มต่อหัวข้อ → ควรอ่านจาก `VendorEvaluationConfig.criteria[].max_score` (ห้าม hardcode)
- ค่าคงที่ "น้อยกว่า 6 / มากกว่า หรือ เท่ากับ 6" = เกณฑ์ผ่านการประเมิน → ควรอ่านจาก `VendorEvaluationConfig.pass_threshold` (ห้าม hardcode)
- ค่าคงที่ "รายการมาตรฐาน GMP · ISO · HACCP · Halal · มอก. · อย. · Q · อื่นๆ" = ตัวเลือกมาตรฐานที่รับรอง → ควรอ่านจาก `VendorEvaluationConfig.certifications[]` (ห้าม hardcode)

### 3.5 ข้อมูลตัวอย่างที่ขัดกัน → กฎตรวจที่ควรมี
- หัวคอลัมน์ "คะแนนเฉลี่ย" แต่ค่า 3/4/2/1 รวม 10 คือคะแนนเต็มของแต่ละหัวข้อ ไม่ใช่ค่าเฉลี่ย → **คงคำ "คะแนนเฉลี่ย" ตามกระดาษ (G5) · ระบบใช้เป็นคะแนนเต็ม: คะแนนที่ได้ต้องอยู่ระหว่าง 0 ถึงคะแนนเต็มของหัวข้อ (บล็อก) · เสนอลูกค้าเปลี่ยนคำเป็น "คะแนนเต็ม"**
- กระดาษให้ติ๊ก ☐ ผ่าน/ไม่ผ่าน เอง ทั้งที่ผลขึ้นกับคะแนนรวมกับเกณฑ์ 6 → **ระบบติ๊กให้จากคะแนนรวม (ห้ามผู้ใช้เลือกขัดกับคะแนน) · คะแนนรวม < 6 = ไม่ผ่าน**
- คะแนน < 6 ต้องให้ "ผู้จัดการฝ่ายจัดซื้อ และผู้บริหาร" พิจารณา แต่กระดาษมีช่องลงชื่ออนุมัติแค่ผู้จัดการแผนกจัดซื้อ (ไม่มีช่องผู้บริหาร) · ใช้คำ ฝ่าย/แผนก ไม่ตรงกัน → **ผลไม่ผ่าน → สายอนุมัติเพิ่มขั้น ผู้บริหาร (เงื่อนไขกำหนดที่ DOA กลาง: TODO: DOA engine) · ช่องลายเซ็น PDF เพิ่มตามขั้นจริง**
- กระดาษไม่กำหนดว่ากรอกจำนวนเต็มหรือทศนิยม และไม่มีช่องเหตุผลรายหัวข้อ → **รับ 0 ถึงคะแนนเต็ม ทศนิยม 1 ตำแหน่ง · ต้องกรอกครบ 4 หัวข้อก่อนส่ง (บล็อก)**
- สะกดผิด: Pratice · เครื่อหมาย · มาตราฐาน · อุสาหกรรม · Quatation → **แก้คำสะกดผิดชัดเจน (G5) ยกเว้นคำในวงเล็บอังกฤษ Quatation คงไว้ได้ — เลือกแก้เป็น Quotation**
- นามสกุล .xlsx แต่เป็นไฟล์ Excel 97-2003 (.xls) · ชื่อชีต PUR-FM-001 (REV.00) ไม่ตรง Doc No. FM-PUR-01 → **ยึด Doc No. FM-PUR-01 จาก header/footer**
