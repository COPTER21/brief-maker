## Drop ledger (เคสที่ไม่ยกเข้าแบบทดสอบฉบับผู้ใช้)
| TC | ชื่อเคส | เหตุผลที่ตัด | ใครทดสอบแทน |
|---|---|---|---|
| TC-S03 | สายอนุมัติเป็น dynamic (เพิ่ม/ถอดขั้นที่ DOA กลาง) | ต้องสั่งผ่าน console (`__QA__.doa.push` / `pop`) — ผู้ใช้ทั่วไปทำไม่ได้ | ทีม QA/dev ด้วยชุด AI agent + ทดสอบระดับ API |

## หมายเหตุสำหรับผู้ทดสอบ
1. ข้อมูลตัวอย่างทั้งหมดเป็น **ชื่อสมมติและเลขบัตรปิดบัง** — ห้ามกรอกข้อมูลส่วนบุคคลจริงลงใน prototype (เอกสารนี้เป็นหนังสือยินยอม PDPA ต้องเข้มกว่าปกติ)
2. เคสสิทธิ์ให้สลับผู้ใช้ที่มุมขวาบน (เดโมเท่านั้น ระบบจริงใช้บัญชีที่ล็อกอิน)
3. ผลที่ไม่ตรงกับคำว่า "ผ่านเมื่อ" ให้ติ๊กไม่ผ่านพร้อมบันทึกหลักฐาน
4. เกณฑ์ที่มาจากมติ AI-DEFAULT (รอลูกค้ายืนยัน) ถ้าไม่ผ่านอาจแปลว่ามติผิด ไม่ใช่โปรแกรมผิด
5. คำที่สะกดไม่เหมือนกันในเอกสาร (บูท/บูธ · "ข้อมูลส่วนของบุคคล") เป็นไปตามต้นฉบับของลูกค้า — **ไม่ใช่ข้อผิดพลาดของระบบ**
