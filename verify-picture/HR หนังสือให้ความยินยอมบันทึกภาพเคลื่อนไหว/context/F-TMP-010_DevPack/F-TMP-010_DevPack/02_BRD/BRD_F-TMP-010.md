## 1. Business Context
### 1.1 ปัญหา / โอกาส
บริษัทจัดบูธกิจกรรมแล้วถ่ายภาพ/วิดีโอผู้ร่วมกิจกรรมไปใช้ในสื่อการตลาดและประชาสัมพันธ์ วันนี้หนังสือให้ความยินยอมเป็นกระดาษที่เซ็นหน้างานแล้วเก็บเป็นปึก ทำให้ (1) ทีมสื่อไม่รู้ว่าภาพของใครเผยแพร่ได้บ้าง (2) ไม่รู้ว่าหนังสือที่เซ็นเป็นฉบับไหน เมื่อแก้ถ้อยคำแล้วของเก่ายังอ้างได้หรือไม่ (3) เมื่อเจ้าของข้อมูลใช้สิทธิถอนความยินยอม ไม่มีที่บันทึกให้ทีมสื่อหยุดใช้ภาพ และ (4) กรณีผู้ร่วมกิจกรรมเป็นผู้เยาว์ ไม่มีการตรวจอย่างเป็นระบบว่ามีผู้ปกครองรับรองครบหรือไม่ ซึ่งเป็นความเสี่ยงทางกฎหมายโดยตรง

### 1.2 เป้าหมาย
ขึ้นหนังสือฉบับนี้เป็นเอกสารในระบบ CUBE โดยหน้าตาแบบพิมพ์เหมือนกระดาษเดิม 1:1 เก็บ **หลักฐานความยินยอมรายข้อ** พร้อม **ผู้ให้ความยินยอม · บูธกิจกรรม · ช่วงเวลากิจกรรม · ฉบับ (revision) ของหนังสือ** บังคับให้ผู้เยาว์มีผู้ปกครองรับรอง และรองรับ **การถอนความยินยอม** ที่ผูกกับใบเดิม

### 1.3 ตัวชี้วัด
| ตัวชี้วัด | ค่าเป้าหมาย |
|---|---|
| ผู้ร่วมกิจกรรมที่ภาพถูกนำไปเผยแพร่และมีหนังสือยินยอมในระบบ | 100% ของกิจกรรมที่จัดหลังขึ้นระบบ |
| เวลาค้นหาหลักฐานความยินยอมของผู้ร่วมกิจกรรม 1 ราย | < 1 นาที (จากเดิมค้นกระดาษหน้างาน) |
| ใบของผู้เยาว์ที่มีผู้ปกครองรับรองครบ | 100% (ระบบบล็อกการยืนยันถ้าไม่ครบ) |
| คำขอถอนความยินยอมที่บันทึกพร้อมวันที่และผู้บันทึก | 100% |

### 1.4 ที่มา
- ไฟล์ลูกค้า `หนังสือให้ความยินยอมบันทึกภาพเคลื่อนไหว.docx` → `FORM_SPEC.json` (อ่านระดับช่อง 17 ช่อง) → `PREBRIEF_REQ-TMP-010_v2.md`

## 2. Scope
### 2.1 In Scope
1. หน้ารายการหนังสือให้ความยินยอม (ค้นหา · ตัวกรองสถานะ/ผลความยินยอม/ช่วงอายุ · ส่งออก CSV)
2. สร้าง/แก้ไขร่าง 3 ขั้น (ข้อมูลผู้ให้ความยินยอม › เอกสารแนบ › ตรวจสอบและยืนยัน) — เลือก **ยินยอม / ถอนความยินยอม รายข้อ** ตามรายการของฉบับนั้น
3. ส่วนผู้เยาว์: เมื่ออายุผู้ให้ความยินยอมต่ำกว่าเกณฑ์ใน config ระบบเปิดช่องผู้ปกครอง + ผู้เยาว์ และบังคับกรอกให้ครบก่อนยืนยัน
4. ยืนยันความยินยอม → ออกเลขที่ · บันทึกวันที่ให้ความยินยอม · snapshot ฉบับของหนังสือ · เก็บสำเนา PDF เป็นหลักฐาน
5. ถอนความยินยอม (ทั้งฉบับหรือรายข้อ) พร้อมวันที่ ผู้บันทึก และเหตุผล — ใบเดิมคงอยู่เป็นหลักฐาน
6. แบบพิมพ์ Replica A4 เหมือนกระดาษเดิม (ทุกสถานะ) + PDF Preview ในหน้าจอ
7. เอกสารแนบ (Document Center) · สิทธิ์การมองเห็นตามมติ G8

### 2.2 Out of Scope
1. **การบังคับใช้ผลความยินยอมกับงานสื่อ/การตลาด** (เช่น บล็อกการอัปโหลดภาพของคนที่ถอนความยินยอม) — DEC-02 ไม่ส่งต่อระบบอื่นรอบนี้ ประกาศ event ไว้ใน FRD แต่ยังไม่ยิง
2. การแก้ถ้อยคำ/ออกฉบับใหม่ของหนังสือ (เป็นงานของ ConsentPurpose master + F-DOCCFG revision)
3. การเก็บความยินยอมของบุคลากรภายใน (ใช้ FM-HRM-31 · รหัส PDC แทน)
4. ลายมือชื่ออิเล็กทรอนิกส์แบบภาพ/ใบรับรอง (DEC-07 ใช้ข้อความ "ยืนยันในระบบ")
5. การเชื่อมคลังสื่อ (Digital Asset) เพื่อผูกภาพแต่ละไฟล์กับใบยินยอม — เสนอเป็นงานรอบถัดไป (OQ-06)

### 2.3 Assumptions
- ผู้ร่วมกิจกรรมเป็น **บุคคลภายนอก** ไม่มีระเบียนในระบบ → เจ้าหน้าที่ประจำบูธเป็นผู้บันทึกใบแทน และเป็นเจ้าของใบในระบบ — **OQ-01**
- Organization มีค่า `legal_name`, `logo`, `contact_address` และ PdpaPolicy มี `contact_email`, `minor_age_threshold` ให้ snapshot ตอนออกเลข
- รายการความยินยอม 3 ข้อมาจาก ConsentPurpose master ที่ผูกกับ revision ของหนังสือ
- เลขบัตรประชาชนเก็บเป็นข้อมูลยืนยันตัวตนของผู้ให้ความยินยอม และต้องถูกจำกัดการมองเห็น — **OQ-04**

## 4. User Journey
### 4.1 Happy Path
1. ผู้ร่วมกิจกรรมเดินเข้าบูธ → เจ้าหน้าที่เปิด "สร้างหนังสือยินยอม"
2. กรอก เขียนที่ · ชื่อ-อายุ-เลขบัตรประชาชนของผู้ให้ความยินยอม · สถานที่บูธ · ช่วงเวลากิจกรรม
3. อ่านถ้อยคำข้อ 1–3 ให้ผู้ร่วมกิจกรรม แล้วเลือก "ยินยอม" หรือ "ถอนความยินยอม" ครบทุกข้อ
4. แนบไฟล์ประกอบ (ถ้ามี) → ตรวจสอบ → ยืนยันความยินยอม
5. ระบบออกเลขที่ บันทึกวันที่ให้ความยินยอม snapshot ฉบับของหนังสือ และเก็บสำเนา PDF เป็นหลักฐาน
6. ทีมสื่อค้นจากรายการว่าภาพของผู้ร่วมกิจกรรมรายนี้เผยแพร่ได้หรือไม่

### 4.2 Alternative
- **ผู้เยาว์:** กรอกอายุต่ำกว่าเกณฑ์ใน config → ส่วนผู้ปกครองเปิดอัตโนมัติ → ต้องกรอกผู้ปกครองและผู้เยาว์ให้ครบจึงยืนยันได้ (ปุ่ม "คัดข้อมูลผู้เยาว์จากผู้ให้ความยินยอม" ช่วยลดการพิมพ์ซ้ำ)
- **ไม่ยินยอมบางข้อ:** เลือก "ถอนความยินยอม" ตั้งแต่ต้นรายข้อ — ใบยังยืนยันได้ แต่ข้อนั้นไม่มีผล
- **ถอนภายหลัง:** เจ้าของใบหรือผู้ดูแลเปิดคำสั่ง "ถอนความยินยอม" เลือกข้อที่ถอน ใส่เหตุผล → ใบเปลี่ยนสถานะเป็น "ถอนความยินยอม" และ PDF แสดงบันทึกการถอน
- **ยกเลิกใบ:** ทำได้เฉพาะสถานะร่าง/รอพิจารณา พร้อมเหตุผลบังคับ (DEC-07 G7)

## 8. Business Rules + Validation
### 8.1 ถ้อยคำและค่าคงที่ (DEC-04 · DEC-12)
- ถ้อยคำกฎหมายทุกย่อหน้าคัดตรงตัวจากต้นฉบับ รวมคำสะกดที่ไม่สม่ำเสมอ ("บูทกิจกรรม" ในย่อหน้านำ vs "บูธกิจกรรม" ในข้อ 1–2 · "ข้อมูลส่วนของบุคคล" ในข้อ 3 · "เป็นผู้ปกครองของ ข้าพเจ้า") — แก้ได้เฉพาะโดยออก revision ใหม่ของหนังสือ
- ชื่อบริษัท ที่อยู่ อีเมลติดต่อ และเกณฑ์ผู้เยาว์ อ่านจาก config (`Organization.*` · `PdpaPolicy.*`) ห้าม hardcode

### 8.2 การกรอก (DEC-06 · DEC-13)
| กฎ | ผล |
|---|---|
| ชื่อ · อายุ · เลขบัตรประชาชนของผู้ให้ความยินยอม ต้องครบ | บล็อกการไปขั้นถัดไป |
| อายุต้องเป็นตัวเลข 1–120 | บล็อก |
| สถานที่บูธ · วันเริ่ม · วันสิ้นสุด ต้องครบ | บล็อก |
| วันสิ้นสุดกิจกรรมต้องไม่ก่อนวันเริ่ม | บล็อก |
| ข้อ 1 ข้อ 2 และ ข้อ 3 ต้องเลือกอย่างใดอย่างหนึ่ง ห้ามเว้นว่าง | บล็อก |
| ห้ามเพิ่มช่องที่กระดาษไม่มี | ข้อกำหนดการออกแบบ |

### 8.3 ผู้เยาว์ (DEC-04 · DEC-11)
- อายุผู้ให้ความยินยอม < `PdpaPolicy.minor_age_threshold` → ต้องกรอกผู้ปกครอง (ชื่อ อายุ เลขบัตร) และผู้เยาว์ (ชื่อ อายุ เลขบัตร) ครบจึงยืนยันได้
- ค่าเริ่มต้นของช่องผู้เยาว์เสนอเท่ากับผู้ให้ความยินยอม แก้ได้
- เกณฑ์อายุอ่านจาก config — **ห้าม hardcode เลข 20 ใน logic**

### 8.4 การถอนความยินยอม (DEC-15 · DEC-16)
- ถอนได้เฉพาะใบสถานะ `confirmed` · เลือกได้ทั้งฉบับหรือเฉพาะข้อที่เคย "ยินยอม"
- ต้องระบุเหตุผล · บันทึกวันที่และผู้บันทึก
- ถอนข้อใดข้อหนึ่งไม่กระทบข้ออื่น · ไม่ย้อนผลการเผยแพร่ที่ทำไปแล้วโดยชอบ

### 8.5 ระดับความยืดหยุ่น
| เรื่อง | ระดับ | เหตุผล |
|---|---|---|
| รายการความยินยอม 3 ข้อ | **Config (ผูก revision)** | เปลี่ยนถ้อยคำ = ออกฉบับใหม่ ไม่แก้โค้ด |
| เกณฑ์อายุผู้เยาว์ | **Config** | กฎหมาย/นโยบายเปลี่ยนได้ |
| จำนวนขั้นอนุมัติ | **Config (DOA กลาง)** | รอบนี้ 0 ขั้น เพิ่มได้ภายหลัง |
| รูปแบบเลขที่เอกสาร | **Config (F-DOCCFG)** | |
| ช่องตามกระดาษ | **Fixed ต่อ revision** | เปลี่ยน = ออกแบบพิมพ์ใหม่ |

## 9. Edge Cases
| # | กรณี | ผลที่ต้องการ |
|---|---|---|
| EC-01 | ผู้ให้ความยินยอมอายุเท่ากับเกณฑ์พอดี | ไม่ถือเป็นผู้เยาว์ (เกณฑ์คือ "ต่ำกว่า") |
| EC-02 | กรอกอายุผู้เยาว์แล้วแก้กลับเป็นผู้ใหญ่ | ระบบล้างข้อมูลผู้ปกครอง/ผู้เยาว์ตอนบันทึก ไม่ติดค้างในใบ |
| EC-03 | ชื่อผู้เยาว์ไม่ตรงกับชื่อผู้ให้ความยินยอม | อนุญาต (กระดาษมี 2 ช่อง) แต่เตือนให้ตรวจ — ระบบเสนอค่าเดียวกันเป็นค่าเริ่มต้น |

| EC-05 | ถอนความยินยอมใบที่ถอนไปแล้ว | ปุ่มถอนไม่แสดง (เงื่อนไข `confirmed` เท่านั้น) |
| EC-06 | ชื่อ/สถานที่ยาวมาก | แบบพิมพ์ใช้ `layout.dense` ทดสอบแล้วในสถานะ long-withdrawn |
| EC-07 | DOA กลางเพิ่มขั้นหลังจากมีใบในระบบแล้ว | ใบเก่าคง chain เดิม (snapshot ตอนส่ง) · ใบใหม่ใช้สายใหม่ |
| EC-08 | ผู้ร่วมกิจกรรมคนเดิมมาหลายกิจกรรม | แยกใบตามช่วงกิจกรรม — ไม่รวมใบ |
| EC-09 | เลขบัตรประชาชนซ้ำกับใบเดิมในกิจกรรมเดียวกัน | เตือน "เคยมีใบในกิจกรรมนี้แล้ว" ไม่บล็อก — **OQ-05** |
| EC-10 | แบบเอกสาร IMC ถูกปิดใช้งานที่ F-DOCCFG | สร้างใบใหม่ไม่ได้ · ใบเดิมยังเปิดดู/พิมพ์ได้ |

## 12. Dev Summary "ใบสั่ง"
1. ตาราง `media_consent` + `media_consent_line` + `media_consent_withdrawal` ตาม §5 — `choice` และเลขบัตรประชาชนเป็น **Restricted**
2. เลขที่จาก ENG-DOC-NUM (`IMC`) ตอนบันทึกครั้งแรก · ตรวจ `DOC.active` ที่ F-DOCCFG ก่อนออกเลข
3. รายการความยินยอมอ่านจาก ConsentPurpose master ที่ผูก revision — **ห้าม hardcode ถ้อยคำในโค้ด**
4. เกณฑ์ผู้เยาว์อ่านจาก `PdpaPolicy.minor_age_threshold` — **ห้าม hardcode เลข**
5. ช่องลายเซ็นใน PDF วนจาก `approval_chain` + ช่องผู้ปกครองตามกระดาษ — **ห้าม fix จำนวน**
6. แบบพิมพ์ใช้ `print/form.tpl.html` ตัวเดียวกับ prototype (logic-less) + `print_config.json`
7. ใบที่ยืนยันแล้ว immutable — เปลี่ยนเจตนาใช้คำสั่งถอนความยินยอมเท่านั้น
8. สิทธิ์การมองเห็นตาม §3 — ร่างของคนอื่นต้องไม่รั่ว

## 14. Security & Compliance
- **Data Classification:** `data_subject_citizen_id` · `guardian_citizen_id` · `minor_citizen_id` · `media_consent_line.choice` = **Restricted** · ชื่อและอายุ = Confidential
- ข้อมูลผู้เยาว์ต้องจำกัดผู้เห็นเข้มกว่าปกติ และห้ามส่งออกใน CSV (CSV มีเฉพาะ "ผู้เยาว์/บรรลุนิติภาวะ")
- หลักฐานความยินยอมเก็บเป็น PDF แบบแก้ไม่ได้พร้อม revision ของหนังสือ (ENG-DOC-STORE · `snapshot.approved_final = true`)
- การถอนความยินยอมแจ้ง `role-compliance` แบบปิดไม่ได้
- ข้อมูลส่วนบุคคลจากไฟล์ลูกค้าห้ามใช้เป็นข้อมูลตัวอย่าง — prototype และแบบพิมพ์ใช้ชื่อสมมติ + เลขบัตรปิดบัง + โลโก้ placeholder
