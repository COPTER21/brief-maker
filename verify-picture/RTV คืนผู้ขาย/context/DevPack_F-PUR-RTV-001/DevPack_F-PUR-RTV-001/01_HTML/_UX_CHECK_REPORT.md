## 2.5 ★★ บั๊กระดับ BLOCK อีก 2 ข้อ ที่เจอในรอบตรวจที่สอง (แก้แล้ว)

> ทั้งสองข้อ **ทุกด่านเชิงกลให้ผ่านหมด** — `audit.sh` FAIL=0 · `node --check` ผ่าน · `pageerror` ตอนโหลดหน้า = 0
> เจอได้เพราะ **ไล่อ่าน CSS/JS แล้วเดินเส้นทางจริงทุกปุ่ม** ไม่ใช่เพราะสคริปต์ตัวไหน

### 2.5.1 ป๊อปอัปช่องค้นหาทะเบียนถูกบังทั้งไฟล์ → **DOA slot picker ใช้ไม่ได้**

**อาการ:** `.combo-pop` ใช้ `z-index: var(--z-dropdown)` = **40** ขณะที่ลิ้นชัก = **51** · กล่องโต้ตอบ = **61**
ป๊อปอัปถูก portal ไปที่ `#overlay-root` (ซึ่งเป็น `z-index: auto`) จึงไปแข่งชั้นกับลิ้นชัก/กล่องโต้ตอบโดยตรง **แล้วแพ้**

**พิสูจน์ก่อนแก้:**
```
openSubmitModal('RTV-2026-0003') → โฟกัสช่อง "ค้นหาชื่อผู้อนุมัติ…"
.combo-pop  → z-index 40 · parent #overlay-root · rect 333×280 · มีรายชื่อจริง 3 คน
document.elementFromPoint(กลางป๊อปอัป) → ".slot-row is-err"
covered: TRUE        ← ผู้ใช้มองไม่เห็นและกดไม่ได้
```
เหมือนกันในลิ้นชัก wizard (ช่องเลือกที่จัดเก็บ · `cb-in-line-loc-…`) → **`covered: TRUE`**

**ความรุนแรง — ทำไมถึงเป็น BLOCK:**
ข้อนี้ทำให้ **`LD-04` / HANDOFF §3 L4 (DOA slot picker เลือกคนจริง) ซึ่งเป็นข้อที่ล็อกแน่นที่สุดของฟีเจอร์ ใช้งานไม่ได้เลย**
→ `BR-10` · `FN-15` · `FN-16` ทำไม่ได้ → **S-07 (ส่งอนุมัติ) เดินไม่ถึง** → และ S-08 · S-11 · S-12 ที่อยู่ปลายน้ำก็เดินไม่ถึงผ่านหน้าจอทั้งสาย

**แก้:** `--z-dropdown: 40` → **`65`**
ลำดับชั้นหลังแก้: `sticky 19 · shell 20 · backdrop 50 · drawer 51 · modal 61 · ` **`dropdown 65`** ` · toast 70`
เลือก 65 เพราะต้องสูงกว่ากล่องโต้ตอบ (61) — combobox ใช้ร่วมกันทั้งในลิ้นชักและกล่องโต้ตอบ — แต่ต่ำกว่า toast (70) ที่ต้องอยู่บนสุดเสมอ

**พิสูจน์หลังแก้:** `covered: false` · เลือก "สมชาย ทองใบ · หัวหน้าคลังกลาง" ได้จริง · สถานะ error หาย · ปุ่ม `ส่งอนุมัติ` เปลี่ยนเป็นกดได้ (`disabled = false`) — ดู `_shots/10_modal_submit_doa.png`

### 2.5.2 ปุ่ม "ยกเลิกใบ" ในเมนูแถวเรียกฟังก์ชันที่ไม่มีอยู่

**อาการ:** บรรทัด 1330 เรียก `openReasonModal(id, 'cancel')` — **ไม่มีการประกาศฟังก์ชันนี้ในไฟล์เลย** (`typeof openReasonModal === 'undefined'`)

**พิสูจน์ก่อนแก้:** กดปุ่มจริงจากเมนู ⋮ ของแถวในหน้ารายการ
```
row menu items: ["เปิดดูใบ", "แก้ไขร่าง", "ยกเลิกใบ"]
click "ยกเลิกใบ" → modal opened? FALSE
pageerror: "openReasonModal is not defined"
```

**ทำไมด่านเดิมจับไม่ได้:** การตรวจ `pageerror` ทำตอนโหลดหน้าและตอนเดินแท็บ/กล่องโต้ตอบผ่าน API ภายใน — **ไม่ได้กดปุ่มในเมนูแถว** · บั๊กเกิดเฉพาะตอนกด

**แก้:** `openReasonModal(id,'cancel')` → **`openModal('cancel', id)`** ซึ่งมีจริงและเป็นตัวเดียวกับที่ปุ่ม `ยกเลิก` ในลิ้นชักเรียกอยู่แล้ว

**พิสูจน์หลังแก้:** กดจากเมนูแถว → กล่องยกเลิกเปิดพร้อมช่องเหตุผลบังคับ · `pageerror = 0` ✅

## 8. สรุปสำหรับคนอ่านเร็ว

- ไฟล์ที่รับมา **ตรงกับรายงานต้นน้ำทุก byte** และผ่านด่านเชิงกลเกือบทั้งหมดตั้งแต่แรก
- สิ่งที่ต้นน้ำมองไม่เห็นคือ **ศัพท์ภายในรั่วขึ้นจอ 8 จุด** — `self_audit` รายงาน `jargon_leak = 0` แต่ของจริงมี และ **จุดหนักที่สุดอยู่บน KPI หน้าแรก**
- แก้แล้ว 8 จุดโดย **ย้าย marker ไปเป็นคอมเมนต์** — trace ไม่หาย · ผู้ใช้เห็นภาษาคน
- โครง Pattern Q **ถูกต้องทุกข้อ** (ชื่อ step · แท็บ · grid · ความกว้าง drawer · ช่องเซ็น) ต่างจาก F-PUR-PR ที่ชื่อ step ผิด
- **CSS ไม่มี parse break** (ต่างจาก F-WH-GRN) · responsive ผ่านครบ 7 ความกว้าง
- ของที่ต้องส่งต่อให้ FRD/TC คือ **สิทธิ์อนุมัติที่ยังไม่บังคับจริง** และ **"ทิ้งร่าง" ที่ยุบรวมกับ "ยกเลิก"**
