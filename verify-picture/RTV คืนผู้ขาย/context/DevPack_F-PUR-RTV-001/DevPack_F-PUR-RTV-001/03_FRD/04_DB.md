### §4.2.1 คอลัมน์คำนวณ — ไม่เก็บใน DB (สำคัญมาก · `DR-01`)

| ค่า | สูตร | คำนวณที่ |
|---|---|---|
| `base_qty` (ฐานคืนได้) | `qty_over` เมื่อเหตุผล = `over` · มิฉะนั้น `qty_qc_failed` ถ้า > 0 · มิฉะนั้น `qty_received − qty_qc_failed` · **เป็น 0 เสมอเมื่อของถูกใช้ต่อแล้ว** | `ENG-RTV-01` |
| `qty_returned_before` | `Σ qty_return` ของบรรทัดเดียวกันจากใบคืนใบอื่นที่ `status ∈ {returned, closed}` | `ENG-RTV-01` |
| `qty_returnable` (ยอดคืนได้คงเหลือ) | `max(0, base_qty − qty_returned_before)` | `ENG-RTV-01` |
| `qty_remaining_after` (คงเหลือคืนได้หลังใบนี้) | `max(0, qty_returnable − qty_return)` | `ENG-RTV-01` |
| `line_net_amount` · `line_vat_amount` · `line_total` | ตาม `vat_mode` — ดู `ENG-RTV-02` | `ENG-RTV-02` |
| `line_state` | `คืนได้ / คืนบางส่วนแล้ว / คืนครบแล้ว / ของถูกใช้ต่อแล้ว` | `ENG-RTV-01` |
| `total_before_vat` · `total_vat` · `total_grand` (ระดับใบ) | `Σ` ทุกบรรทัด — ดู `ENG-RTV-02` | `ENG-RTV-02` |

> **ห้ามเก็บ `qty_returnable` เป็นคอลัมน์จริง** — `DR-01` บังคับให้คำนวณสดจากฐานคืนได้ลบยอดคืนสะสม เพราะยอดคืนสะสมเปลี่ยนได้จากใบคืนใบอื่นตลอดเวลา · การเก็บค่าค้างไว้ = ตัวเลขเพี้ยนเงียบ
> **`approval_base_amount` เป็นข้อยกเว้นที่ต้องเก็บ** — เป็น snapshot ของมูลค่า ณ เวลาส่งอนุมัติ ห้ามคำนวณใหม่ (ไม่งั้นแก้ราคาที่ GRN แล้วสายอนุมัติที่ freeze ไว้จะเพี้ยนย้อนหลัง)

## §4.4 Soft-reference contract (LOCK-01 · BR-24)

ทุก `*_ref` เป็น **อ้างอิงแบบหลวม** — ไม่มี FK constraint · เว้นว่างได้ · **ต้องเก็บ `*_name` snapshot คู่กับ `*_ref` ทุกตัวที่แสดงบนจอหรือในใบพิมพ์** เพื่อให้ค่าที่หายจากทะเบียนต้นทางยังแสดงข้อความเดิมได้ (`item_name` · `person_name` · `person_position` เป็นตัวอย่างที่บังคับ) · ใบเก่าต้องไม่พังเมื่อทะเบียนหลักถูกลบหรือเปลี่ยนชื่อ (`EC-14`)

## §4.6 Data Classification — 4 ระดับ + การบังคับใช้

| ระดับ | ความหมาย | มีในฟีเจอร์นี้ | การบังคับใช้ (DB / API / UI / Audit) |
|---|---|:--:|---|
| **Public** | เปิดเผยสาธารณะได้ | ❌ ไม่มี | — |
| **Internal** | พนักงานในองค์กรเข้าถึงได้ตามสิทธิ์ | ✅ ส่วนใหญ่ | **DB:** สิทธิ์ระดับ role · **API:** ต้อง authenticate + จำกัดขอบเขตคลังของผู้ใช้ · **UI:** ตาม `02_API §2.4` · **Audit:** บันทึกการกระทำ |
| **Confidential** | ข้อมูลเชิงพาณิชย์/การเงิน | ✅ `unit_price` · `discount_pct` · `approval_base_amount` · `credit_amount_actual` + ยอดที่คำนวณจากค่าเหล่านี้ (`line_total` · `total_grand`) | **DB:** column-level grant · **API:** ตัด field ออกจาก response ของ role ที่ไม่มีสิทธิ์เห็นราคา (ผู้ตรวจคุณภาพ) · **UI:** ซ่อนคอลัมน์ราคา/จำนวนเงิน/มูลค่าที่คืน สำหรับ role นั้น · **Audit:** บันทึกทุกการอ่าน |
| **Restricted** | ต้องขออนุมัติรายครั้ง | ❌ ไม่มี | — (**ไม่ต้อง wire Restricted Resources registry**) |

**PII overlay:** `requester` · `shipper` · `vehicle_no` · `vendor_receiver` · `person_id/name/position` · `*_by` — PII ระดับ `Internal` (ชื่อพนักงาน/คู่ค้า/ทะเบียนรถ) · **PDPA applicable แต่ไม่ใช่ข้อมูลอ่อนไหว** · การลบตามคำขอเจ้าของข้อมูล **ต้องไม่ลบแถว `T_rtv_audit` และ `T_rtv_approval`** (ใช้ pseudonym แทน) เพราะสองตารางนี้เป็นหลักฐานการอนุมัติตาม SOX (`C-07`)

> ⚠️ **ยอดที่คำนวณได้ก็เป็น Confidential** — ผู้ตรวจคุณภาพที่ถูกตัด `unit_price` ออกจาก response ต้องถูกตัด `line_total` · `total_grand` · `approval_base_amount` ออกด้วย ไม่งั้นย้อนราคาได้จากยอดรวมหารจำนวน

## §4.8 ข้อกำหนดเชิงธุรกรรม (transaction)

| การกระทำ | ขอบเขต transaction | หมายเหตุ |
|---|---|---|
| ส่งอนุมัติ | ออกเลขเอกสาร + เขียน `T_rtv_approval` (ทุกขั้น) + ตั้ง `approval_base_amount` + `status = pending` + audit | **ทั้งชุดหรือไม่ทำเลย** · ออกเลขล้มเหลว = ไม่มีใบครึ่ง ๆ (`DOC_NUMBER_UNAVAILABLE`) |
| **บันทึกส่งคืน** ★ | `status = returned` + INSERT `T_rtv_movement` ทุกแถว + เขียนยอดคืนสะสมกลับ GRN + ตั้งล็อกกลับรายการที่ GRN + audit | **ทั้งชุดหรือไม่ทำเลย** (`DR-03`) · ต้อง **lock บรรทัดใบรับของ** ระหว่าง transaction กัน 2 ใบคืนตัดของก้อนเดียวกันพร้อมกันจนยอดติดลบ |
| **กลับรายการ** ★ | `status = reversed` + INSERT movement ตรงข้ามทุกแถว (`reversal_of`) + หักยอดคืนสะสมคืนที่ GRN + audit | **ห้ามลบแถวเดิม** (`DR-04`) |
| ปิดใบ | `status = closed` + ข้อมูลเครดิต + audit | ไม่แตะสต๊อก ไม่แตะ GRN |
| ยิง `ENG-NOTIFY` / `ENG-CSQ` | **นอก transaction** | ล้มเหลวต้องไม่ย้อนการตัดสต๊อก |
