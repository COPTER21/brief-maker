## §1.1 Pages — anatomy

### P-01 · หน้ารายการใบคืนสินค้า (`#/`)

**หัวหน้า:** `ใบคืนสินค้าผู้ขาย (Return to Vendor)` + ป้ายนับ `N รายการ · รอดำเนินการ M` + คำโปรย *"คืนของที่รับเข้ามาแล้วแต่ไม่รับไว้ กลับคืนผู้ขาย — อ้างใบรับของ (GRN) → อนุมัติตามวงเงิน → ตัดสต๊อกออกจาก quarantine/location → ตามเครดิตจากผู้ขาย"*

### P-02 · ขั้น 1 — เลือกแหล่งที่มา

หัวขั้น: `เลือกแหล่งที่มาของใบคืนสินค้า` + hint *"คืนของต้องอ้างใบรับของ (GRN) ที่บันทึกรับเข้าแล้วเสมอ — ของที่ไม่มีใบรับให้ใช้ปรับปรุงสต๊อกแทน"*

tile 2 ช่อง:
- **`จากใบรับของ (GRN)`** (`.tile-btn.on`) — *"ดึงบรรทัดที่มีของค้าง quarantine หรือของที่รับเกิน"*
- **`คืนของที่ไม่มีใบรับของ`** (`.tile-btn.is-off`) — *"ไม่รองรับ — ใช้ปรับปรุงสต๊อก (W3Q) แทน"* · กดแล้ว toast *"คืนของที่ไม่มีใบรับของ — ไม่รองรับในรอบนี้ ให้ใช้ปรับปรุงสต๊อก (W3Q)"*
> ⚠️ ทั้งข้อความย่อยและ toast ยังมีรหัสคลื่น `(W3Q)` ติดอยู่ — **ต้องทบทวนถ้อยคำก่อนขึ้นใช้งานจริง** (`07_LOCKED LD-18`)

การ์ด **`ใบรับของที่คืนได้ (n/N)`** + ช่องค้นด่วน (`พิมพ์เลขที่ GRN / PO / ผู้ขาย… แล้วกด Enter` → `grnEnter()`)
ตารางใบรับของ: `เลขที่ · วันที่รับ · ผู้ขาย · PO · คืนได้ · สถานะ · (ปุ่ม)`
- ใบที่เลือกได้: แถวคลิกได้ + ป้าย `คืนได้` + ปุ่ม `ใช้ใบนี้`
- ใบที่เลือกไม่ได้: `opacity .55` + ป้ายสีเทาบอกเหตุผลจาก `grnBlockReason()` ตรง ๆ — **`ใบรับของยังเป็นร่าง — ยังไม่มีของเข้าคลัง`** / **`ใบรับของถูกกลับรายการแล้ว`** / **`คืนครบแล้ว — ไม่มีของคงเหลือให้คืน`** · คอลัมน์ "คืนได้" แสดง `—`
- ใบที่เลือกแล้ว: ป้าย `เลือกแล้ว`

ท้ายหน้า: ยังไม่เลือก → note *"เลือกใบรับของก่อน ระบบจะดึงสินค้า จำนวนที่คืนได้ ราคา และ location ที่ของอยู่จริงมาให้อัตโนมัติ"* · เลือกแล้ว → note สีเขียว *"ดึงจาก {GRN} · {ผู้ขาย} · N บรรทัด — ราคา/VAT มาจากใบรับของ แก้ที่ใบคืนไม่ได้"*

### P-03 · ขั้น 2 — ข้อมูลหลักใบคืนสินค้า

### P-08 · ลิ้นชักดูเอกสาร — แท็บรายละเอียด (landing)

**หัวลิ้นชัก:** eyebrow `ใบคืนสินค้าผู้ขาย (Return to Vendor)` → เลขที่ (หรือ `ยังไม่ออกเลข`) + ป้ายสถานะ → บรรทัดสรุป `{ผู้ขาย} · ผู้ขอคืน {ชื่อ} · จาก {GRN} · มูลค่าที่คืน ฿{ยอด}`
**ปุ่มตามสถานะ** (`renderViewDrawer()`):

| สถานะ | ปุ่มที่โผล่ (ซ้าย → ขวา) |
|---|---|
| `draft` | `ยกเลิก` (แดง) · `แก้ไข` · `ส่งอนุมัติ` |
| `pending` | `ไม่อนุมัติ` (แดง) · `ส่งกลับแก้` · `อนุมัติ` (เขียว) |
| `approved` | `ยกเลิก` (แดง) · `บันทึกส่งคืน` |
| `returned` | `กลับรายการ` (แดง) · `บันทึกเครดิต · ปิดใบ` |
| `closed` / `cancelled` / `reversed` | **ไม่มีปุ่มกระทำ** — สถานะปลายทาง |

ปุ่มถาวรทางขวา: `ทำสำเนา` · `พิมพ์` · `ดาวน์โหลด` · `ปิด`
ท้ายลิ้นชัก: `แก้ไขล่าสุด {เวลา} · โดย {ชื่อ}` + เมื่อ `returned`/`closed` เพิ่ม **`ของออกจากคลังแล้ว ล็อกแก้ไข`** พร้อมไอคอนกุญแจ

**ลำดับ section ในแท็บรายละเอียด (Rule #101 landing):**
แบนเนอร์ (ยกเลิก / กลับรายการ / ถูกส่งกลับแก้ / **ไม่เปิดยอดค้างรับกลับ PO** — แบนเนอร์สุดท้ายแสดง**ทุกใบเสมอ**)
→ ข้อมูลเอกสาร → สถานะ (เอกสาร · ความคืบหน้าการอนุมัติ · **สถานะเครดิตจากผู้ขาย**) → เอกสารอ้างอิง (GRN · PO · **สถานะการล็อกใบรับของ**) → คู่ค้าและผู้รับผิดชอบ (+ ที่อยู่ส่งคืน) → **เครดิตจากผู้ขาย (ยังไม่ลงบัญชี)** → รายการสินค้าที่คืน → **เอกสารแนบ (N ไฟล์ · Document Center)** → ข้อมูลระบบ (สร้างโดย · แก้ไขล่าสุด · **ทะเบียน DOA**)

ป้ายสถานะเครดิต (`creditPill()`): `ได้รับเครดิตแล้ว` (closed) / `รอเครดิตจากผู้ขาย` (returned) / `ยังไม่ถึงขั้นเครดิต` (อื่น ๆ)
สถานะการล็อกใบรับของ (`grnLockedByRtv()`): `ล็อกแล้ว — กลับรายการใบรับของไม่ได้` / `ยังไม่ล็อก (ของยังไม่ออก)`

## §1.3 Journey (happy path)

`#/` → `สร้างใบคืนสินค้า` → `#/create` ขั้น ① เลือกใบรับของที่ยังมีของคืนได้ → ขั้น ② เหตุผลคืนหลัก + วันที่ + ผู้ขอคืน + คลัง → ขั้น ③ กรอกจำนวนคืน (หรือ `คืนทั้งหมดที่คืนได้`) + เหตุผล/location รายบรรทัด → ขั้น ④ แนบรูปสภาพสินค้า → ขั้น ⑤ ตรวจทาน → `บันทึกและส่งอนุมัติ` → หน้าต่าง DOA เลือกคนจริงทุกขั้น → **ได้เลข `RTV-YYYY-NNNN`** → `#/view/:id`
→ ผู้อนุมัติเปิดแท็บ `ลายเซ็น / อนุมัติ` กด `อนุมัติ` จนครบสาย → ใบเป็น `อนุมัติแล้ว` → พิมพ์ใบจากแท็บ `PDF Preview` → ของขึ้นรถ → `บันทึกส่งคืน` (**สต๊อกถูกตัดที่นี่ · GRN ถูกล็อก**) → ได้เอกสารเครดิตจากผู้ขาย → `บันทึกเครดิต · ปิดใบ` → `ปิดใบ`

**เส้นทางสำรอง:** ส่งกลับแก้ → กลับเป็น `ร่าง` **เลขเดิม** → แก้แล้วส่งใหม่ (**สาย resolve ใหม่ตามมูลค่าใหม่**) · ไม่อนุมัติ → `ยกเลิก` · ยกเลิกก่อนของออก → `ยกเลิก` · ผู้ขายตีของกลับ → `กลับรายการ` (movement ตรงข้าม)

## §1.4 z-index contract — ⚠️ มีข้อบกพร่องที่ต้องแก้ตอนทำของจริง

**ค่าที่ประกาศจริงใน `:root` ของต้นแบบ:**

| ชั้น | token | ค่าในต้นแบบ |
|---|---|---|
| sticky header ตาราง | `--z-sticky` | 19 |
| shell / sidebar | `--z-shell` | 20 |
| dropdown / เมนูแถว / **ป๊อปอัปคอมโบ** | `--z-dropdown` | **40** |
| backdrop ของลิ้นชัก | `--z-backdrop` | 50 |
| ลิ้นชัก (`.drawer-host`) | `--z-drawer` | **51** |
| กล่องโต้ตอบ (`.modal-backdrop`) | `--z-modal` | **61** |
| toast | `--z-toast` | 70 |

### ⚠️ ข้อบกพร่อง (พิสูจน์แล้ว — `OQ-RTV-13` · `07_LOCKED LD-16`)

`#overlay-root` ไม่มีกฎ CSS ของตัวเอง (ไม่ positioned · ไม่มี z-index) จึง **ไม่สร้าง stacking context** → ลูกของมัน (`.combo-pop` · `.menu-fixed` ที่ z-index 40) ไปแข่งกับ `.drawer-host` (51) และ `.modal-backdrop` (61) ใน stacking context ราก **แล้วแพ้ทั้งคู่**

ผลที่วัดได้จริง (Chromium 1440×960 · `document.elementFromPoint` ที่กลางป๊อปอัป):

| จุดที่ใช้คอมโบ | ผล |
|---|---|
| ขั้น 2 — ผู้ขอคืน / คลัง / ศูนย์ต้นทุน | ป๊อปอัปเปิดจริง (z 40) แต่ **ถูกลิ้นชัก (z 51) บังทั้งแผง** — `elementFromPoint` คืน `.field-help` ของลิ้นชัก |
| ขั้น 3 — `ตัดออกจาก` (location ต้นทางรายบรรทัด) | เหมือนกัน |
| **หน้าต่างส่งอนุมัติ — ตัวเลือกผู้อนุมัติคนจริง** | **ถูกกล่องโต้ตอบ (z 61) บัง · `pop.contains(elementFromPoint) = false`** |
| หน้าต่างกลับรายการ — location รับของกลับ | เหมือนกัน |

**กระทบอะไร:** ตัวเลือกผู้อนุมัติคนจริงคือหัวใจของ `LOCK-03` และ `BR-10` — เมื่อป๊อปอัปถูกบัง ผู้ใช้เลือกด้วยเมาส์ไม่ได้ (เส้นทางคีย์บอร์ด ↓ + Enter ยังทำงาน เพราะ `comboKey()` ไม่พึ่งการมองเห็น)

**สัญญาที่ dev ต้องใช้ในของจริง** (ห้ามลอก z-index ของต้นแบบมาตรง ๆ):

| ชั้น | ค่าที่ถูกต้อง | เหตุผล |
|---|---|---|
| backdrop ลิ้นชัก | 50 | คงเดิม |
| ลิ้นชัก | 51 | คงเดิม |
| กล่องโต้ตอบ | 61 | คงเดิม |
| **overlay portal (`#overlay-root`)** | **≥ 70** (และต้อง `position: fixed; inset: 0; pointer-events: none;` โดยลูกเปิด `pointer-events: auto`) | ป๊อปอัปคอมโบ/เมนูแถวต้องลอยเหนือทั้งลิ้นชักและกล่องโต้ตอบเสมอ |
| toast | **สูงกว่า overlay portal** (เช่น 90) + ขยับ `bottom` ขึ้นเมื่อมี overlay เปิด | toast ต้องอ่านออกแม้ตอนมีลิ้นชัก/กล่องโต้ตอบ (บทเรียนจากเลน GRN) |

## §1.5 Esc chain + การปิด overlay (`closeTopOverlay()`)

ลำดับบังคับเมื่อกด `Escape`: **ป๊อปอัปคอมโบ** → **เมนูแถว** → **กล่องโต้ตอบ** → **ลิ้นชัก** (ปิดแล้ว `navigate()` กลับ: ลิ้นชักแก้ไข → `#/view/:id` · ลิ้นชักสร้าง/ดูเอกสาร → `#/`)
คลิกนอกพื้นที่: backdrop ของลิ้นชักและกล่องโต้ตอบเรียก `closeTopOverlay()`/`closeModal()` · คอมโบปิดด้วย `mousedown` นอกกรอบ (`comboOutside()`)
