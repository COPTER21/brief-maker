# Section 2: Business Context

## 2.1 ปัญหา / โอกาส

ทุกวันนี้ของที่รับเข้ามาแล้วแต่ **ไม่รับไว้** (QC ไม่ผ่าน · ผู้ขายส่งเกิน · ของผิดสเปค) จบลงด้วยการคุยกันนอกระบบ:

| # | ปัญหาที่เกิดจริง | ผลกระทบ |
|---|---|---|
| P1 | ของที่ QC ไม่ผ่านค้างอยู่ในพื้นที่กักกันโดยไม่มีใครรู้ว่าจะคืนเมื่อไหร่ | พื้นที่คลังเต็ม · มูลค่าคงคลังพองเกินจริง · เลยกำหนดที่ผู้ขายรับคืนได้ |
| P2 | คืนของโดยไม่มีเอกสาร — ใช้ใบส่งของเขียนมือ | ของออกจากคลังโดยไม่มีร่องรอย · ตรวจนับไม่ตรง · เสี่ยงของหายผ่านช่องทาง "คืนของ" |
| P3 | คืนของแล้วไม่มีใครตามเครดิตจากผู้ขาย | จ่ายเงินเต็มทั้งที่คืนของไปแล้ว |
| P4 | ไม่มีคนอนุมัติก่อนของออก | ปล่อยทรัพย์สินออกจากคลังโดยไม่มีผู้รับผิดชอบ |
| P5 | คืนแล้วยอดที่ใบสั่งซื้อเพี้ยน — บางคนคิดว่าต้องเปิดยอดค้างรับกลับ บางคนคิดว่าไม่ต้อง | รับของซ้ำ/ตกหล่น · รายงานยอดค้างรับเชื่อไม่ได้ |

**โอกาส:** ทำให้ "การคืนของ" เป็นเอกสารในระบบที่ผูกกลับไปที่ใบรับของต้นทาง มีคนอนุมัติก่อนของออก ตัดสต๊อกจริง และตามเครดิตได้จนจบ

# Section 3: Scope

## 3.1 In Scope

| # | ขอบเขต |
|---|---|
| IS-01 | สร้างใบคืนสินค้าโดยอ้างใบรับของ (GRN) ที่บันทึกรับเข้าแล้วและยังมีของคืนได้ |
| IS-02 | เลือกบรรทัดและจำนวนที่จะคืน โดยระบบคุมเพดานตามของที่มีอยู่จริง (หักที่เคยคืนไปแล้ว) |
| IS-03 | ระบุเหตุผลคืนต่อบรรทัด (ชำรุด / ผิดสเปค / บรรจุภัณฑ์เสียหาย / ใกล้หมดอายุ / รับเกิน / อื่น ๆ) |
| IS-04 | ระบุที่อยู่ของของที่จะตัดออก (พื้นที่กักกัน หรือพื้นที่จัดเก็บปกติ) รายบรรทัด |
| IS-05 | สายอนุมัติตามมูลค่าที่คืน โดยเลือก **คนจริง** ต่อขั้นตอนส่งอนุมัติ |
| IS-06 | บันทึกส่งคืน = ตัดสต๊อกออกจริง (บันทึกความเคลื่อนไหวแบบต่อท้ายอย่างเดียว) |
| IS-07 | พิมพ์ใบคืนสินค้า A4 ให้ผู้ขายเซ็นรับ (ก่อนอนุมัติพิมพ์ได้แค่ตัวอย่าง) |
| IS-08 | บันทึกเลขเอกสารเครดิตจากผู้ขายเพื่อปิดใบ |
| IS-09 | ยกเลิกก่อนของออก และกลับรายการหลังของออก (พร้อมเหตุผลบังคับ) |
| IS-10 | แนบเอกสารประกอบ (รูปของเสีย · ใบส่งคืน · ใบตอบรับ · เอกสารเครดิต) |
| IS-11 | หน้ารายการพร้อมตัวชี้วัด ค้นหา ตัวกรอง และส่งออก CSV |
| IS-12 | ล็อกใบรับของต้นทางไม่ให้กลับรายการหลังของถูกคืนไปแล้ว |

## 5.2 Alternative Paths

### 5.2.1 ส่งกลับแก้ (Sendback)
ผู้อนุมัติเห็นว่าจำนวนไม่ตรงที่ตกลง → ระบุเหตุผล → ใบกลับเป็นร่างโดย**ใช้เลขเดิม** → ผู้จัดทำแก้แล้วส่งใหม่ → **สายอนุมัติคำนวณใหม่ตามมูลค่าใหม่** และต้องเลือกคนใหม่ทุกขั้น

### 5.2.2 ยกเลิกก่อนของออก
ผู้ขายยอมลดราคาแทนการรับคืน → ยกเลิกใบ (ระบุเหตุผล) → สต๊อกไม่ถูกกระทบ → ของกลับไปนับเป็น "ของที่คืนได้" ตามเดิม

### 5.2.3 กลับรายการหลังของออก
ผู้ขายปฏิเสธรับคืน/ของถูกตีกลับ → หัวหน้าคลังกลับรายการ (ระบุเหตุผล + ที่อยู่ที่รับของกลับ) → เกิดความเคลื่อนไหวตรงข้าม **ของเดิมยังอยู่ในประวัติ** → ยอดคืนสะสมที่ใบรับของถูกหักคืน

### 5.2.4 ของถูกใช้ต่อไปแล้ว
บรรทัดที่ของถูกจัดเก็บ/เบิกออกไปแล้ว → ระบบไม่ให้เลือกคืน พร้อมบอกว่าเอกสารใดใช้ของไป (รอบนี้เป็นข้อมูลจำลอง รอ W3Q)

| พื้นที่กักกัน (Quarantine) | ที่เก็บของที่ตรวจไม่ผ่าน ยังไม่ถือเป็นของใช้ได้/ขายได้ |
| ยอดคืนได้ | จำนวนที่ยังคืนได้จริงของบรรทัดนั้น = ฐานคืนได้ − ที่เคยคืนไปแล้ว |
| กลับรายการ (Reversal) | การยกเลิกผลของเอกสารที่ทำไปแล้ว ด้วยการสร้างรายการตรงข้าม โดยไม่ลบของเดิม |
| เครดิตจากผู้ขาย | สิทธิที่จะได้เงิน/ส่วนลดคืนจากผู้ขายหลังคืนของ ปกติออกเป็นใบลดหนี้ (CN) ฝั่งบัญชีเจ้าหนี้ |
| การมอบอำนาจ (DOA) | ทะเบียนกลางที่กำหนดว่าเอกสารแต่ละช่วงวงเงินต้องผ่านตำแหน่งใดบ้าง |
| อ้างอิงแบบหลวม (Soft-reference) | อ้างข้อมูลจากทะเบียนอื่นโดยไม่บังคับความสัมพันธ์ เว้นว่างได้ ไม่พังเมื่อต้นทางเปลี่ยน |
| ต่อท้ายอย่างเดียว (Append-only) | บันทึกที่เพิ่มได้อย่างเดียว แก้หรือลบของเดิมไม่ได้ |
| เลขอนุญาตคืน (RMA) | เลขที่ผู้ขายออกให้ก่อนยอมรับของคืน |

## C. Note พิเศษ — เครดิตจากผู้ขาย (ตามที่ CHECKLIST W3P กำหนดให้เขียนใน BRD)

1. **ขอบเขตรอบนี้:** ใบคืนสินค้า **ไม่ออกใบลดหนี้และไม่ลงบัญชี** — ทำได้แค่ (ก) แสดงมูลค่าที่คาดว่าจะได้เครดิต (ข) ป้ายสถานะ "รอเครดิตจากผู้ขาย" (ค) บันทึกเลขเอกสารเครดิตของผู้ขายเพื่อปิดใบ
2. **เจ้าของงานจริง:** ใบลดหนี้ (CN) และการล้างภาระ GR/IR เป็นของ **บัญชีเจ้าหนี้ใน W5** — ในโค้ดต้นแบบมี marker `FWD-WIRE: JE posting` ทุกจุดที่เกี่ยวข้อง (คู่กับ `TODO: JE posting` ในเอกสาร)
3. **มูลค่าที่ส่งต่อ:** ยอดก่อนภาษี · ภาษีมูลค่าเพิ่ม · มูลค่าที่คืนรวม รายบรรทัดและทั้งใบ — พอสำหรับตั้งใบลดหนี้เมื่อ W5 พร้อม
4. **ข้อควรระวังตอนต่อ W5:** ห้ามให้ทั้งใบคืนและฝั่งเจ้าหนี้ยิงผลกระทบท่อเดียวกันซ้ำ (ดู `CSQ_BRIEF` CSQ-Q2) และต้องตกลงวิธีลงบัญชีเมื่อเครดิตที่ได้จริงน้อยกว่ามูลค่าที่คืน (Q3)
5. **ภาษีมูลค่าเพิ่มบนใบคืน** เป็นตัวเลขอ้างอิงเพื่อพิมพ์เอกสารเท่านั้น — ภาระภาษีจริงเกิดที่ใบลดหนี้ฝั่งเจ้าหนี้
