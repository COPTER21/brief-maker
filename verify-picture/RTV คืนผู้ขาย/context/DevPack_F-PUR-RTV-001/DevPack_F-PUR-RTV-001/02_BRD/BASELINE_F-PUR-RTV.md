# BASELINE — F-PUR-RTV · RTV คืนผู้ขาย (Return to Vendor)

> เทียบ feature กับ ERP standard ระดับโลก · 2026-09-10 · wave W3P · module Purchase
> **`[OFFLINE BASELINE]`** — WebSearch ใช้ไม่ได้ในรอบนี้ (server error ทั้ง 2 query ที่ยิง: SAP MM 122/161 + Odoo return picking) → baseline สร้างจากความรู้ ERP ของ runner เอง ไม่มี citation ภายนอก · ทีม vibe/Phase B ตรวจซ้ำได้เมื่อเน็ตกลับมา
> ระบบอ้างอิง: **SAP S/4HANA MM** (Return Delivery 122 / Return PO + movement 161 · Credit Memo) · **Odoo Inventory/Purchase** (Return Picking + Vendor Credit Note) · **Dynamics 365 SCM** (Purchase Return Order + RMA number + Disposition code) · **NetSuite** (Vendor Return Authorization → Item Fulfillment → Vendor Credit) · **ERPNext** (Purchase Receipt "Return" + Debit Note)

---

## 1. ระบบอ้างอิงทำอะไรบ้าง (สรุปท่ามาตรฐาน)

| ระบบ | ท่ามาตรฐานของการคืนของผู้ขาย |
|---|---|
| **SAP MM** | 2 ท่า: (ก) **Return Delivery (mvt 122)** อ้าง GR เดิมโดยตรง — ใช้เมื่อคืนเร็วหลังรับ · (ข) **Returns PO / Return item (mvt 161)** — ใบสั่งซื้อชนิดคืน มีเอกสารของตัวเอง เดินสายอนุมัติได้ · ทั้ง 2 ท่าออก **Credit Memo (MIRO)** ล้าง GR/IR · reason for movement บังคับ · ของที่ blocked stock ต้องปลดก่อนหรือคืนจาก blocked โดยตรง |
| **Odoo** | Return Picking จาก receipt เดิม (ระบุจำนวนคืนต่อบรรทัด) → stock ออกจาก location · ออก **Vendor Credit Note** จาก bill เดิม · reason = ข้อความอิสระ |
| **D365 SCM** | **Purchase Return Order** (PO ที่จำนวนติดลบ) + **RMA number จากผู้ขาย** + **Disposition code** (คืน/เปลี่ยน/ทิ้ง) · charge ค่าคืนของได้ · workflow อนุมัติได้ |
| **NetSuite** | **Vendor Return Authorization** (ต้องได้ authorize ก่อน) → Item Fulfillment (ของออก) → **Vendor Credit** (เครดิต) — แยก 3 ใบชัดเจน |
| **ERPNext** | Purchase Receipt ติดธง `is_return` อ้างใบเดิม + **Debit Note** ฝั่งบัญชี |

**ท่ากลางที่ทุกระบบเหมือนกัน:** คืนของ = **เอกสารใหม่ที่อ้างใบรับเดิม** (ไม่ใช่การแก้ใบรับ) · ของออกจาก stock ด้วย movement ของตัวเอง · เหตุผลคืนบังคับ · ต้องมีเอกสารเครดิต/ตั้งลูกหนี้กับผู้ขายตามมา

## 2. Must-have (M) — ไม่มีไม่ถือว่าเป็น RTV

| # | ความสามารถ | เหตุผลว่าทำไมเป็น must | CUBE รอบนี้ |
|---|---|---|---|
| **M-01** | คืนของ **อ้างใบรับ (GRN) + บรรทัดที่รับจริง** — ไม่ใช่คืนลอย ๆ | ต้อง trace ได้ว่าของก้อนไหน ผู้ขายราย ไหน ราคาเท่าไร | ✅ ใน scope (CHECKLIST) |
| **M-02** | **เหตุผลคืนบังคับต่อบรรทัด** (QC ไม่ผ่าน / รับเกิน / ผิดสเปค / ชำรุด) | ใช้ประเมินผู้ขาย + เป็นหลักฐานเจรจาเครดิต | ✅ ใน scope |
| **M-03** | **จำนวนคืน ≤ จำนวนที่คืนได้จริง** ของบรรทัดนั้น (กันคืนเกิน / คืนซ้ำ) | invariant ของ stock — คืนเกินของที่มี = ยอดติดลบ | ✅ ใน scope |
| **M-04** | **ตัด stock ออกจาก quarantine / location ที่ของอยู่จริง** เมื่อ post | ของออกจากคลังจริง มูลค่าคงคลังลด | ✅ ใน scope (CHECKLIST ระบุตรง) |
| **M-05** | **movement append-only** — คืนแล้วแก้ไม่ได้ · ยกเลิกด้วย reversal เท่านั้น | audit ทางบัญชี/คลัง | ✅ ล็อกทั้งเลน |
| **M-06** | **เลขเอกสารรัน + พิมพ์ใบคืนของ A4** ให้ผู้ขายเซ็นรับ | ของออกจากคลังต้องมีเอกสารคู่กับรถ | ✅ `RTV-YYYY-NNNN` + pdfdoc |
| **M-07** | **สายอนุมัติก่อนของออก** (คืนของ = ปล่อยทรัพย์สินออกจากคลัง) | control ป้องกันของหายผ่านช่องทาง "คืนของ" | ✅ DOA slot picker คนจริง |
| **M-08** | **ผูกเครดิต/ลูกหนี้กับผู้ขาย** (Credit Memo / CN / Debit Note) | ไม่งั้นคืนของแล้วเงินหาย | ⚠️ **note ใน BRD + mock** — CN ฝั่ง AP = W5 (`TODO: JE posting`) |
| **M-09** | **สถานะเอกสารครบวงจร** (ร่าง → รออนุมัติ → อนุมัติ → ส่งคืนแล้ว → ปิด/ยกเลิก) | ของยังไม่ออก vs ออกแล้ว ต้องแยกกันชัด | ✅ ใน scope |
| **M-10** | **หลายใบ RTV ต่อ 1 GRN** (ทยอยคืน) + ยอดคืนสะสมต่อบรรทัด GRN | ของเสียถูกพบไม่พร้อมกัน | ✅ ใน scope |
| **M-11** | **audit trail append-only** ทุก event | governance | ✅ ล็อกทั้งเลน |
| **M-12** | **เอกสารแนบ** (รูปของเสีย · ใบส่งคืน · ใบตอบรับผู้ขาย) | หลักฐานเจรจา | ✅ Pattern Q landing |
| **M-13** | **ข้อมูลการขนส่งคืน** (วันที่ส่งคืน · ผู้ส่ง/ขนส่ง · ผู้รับฝั่งผู้ขาย) | ของออกจริงต้องรู้ว่าใครเอาไป | ✅ ใน scope |
| **M-14** | **บล็อกการคืนของที่ถูกใช้ต่อไปแล้ว** (ถูกเบิก/ย้ายออก) | กันคืนของที่ไม่มีอยู่แล้ว | ✅ ใน scope (soft-check + mock ฝั่ง W3Q) |
| **M-15** | **ผลกระทบต่อ PO/GRN ต้นทางถูกนิยามชัด** (คืนแล้วยอดค้างรับเปิดกลับไหม) | ไม่นิยาม = ยอดค้างรับเพี้ยนทั้งระบบ | ⚠️ **`OQ-RTV-01 [ASSUMED]`** — ตัดสินรอบนี้ (ตอบ OQ-GRN-03) |
| **M-16** | **มูลค่าที่คืน** ต่อบรรทัด/ทั้งใบ (ราคาจาก GRN/PO · VAT) | ใช้ตั้งเครดิตและรายงาน | ✅ ใน scope (B2 v2 totals) |

**สรุป must-have: 16 ข้อ — อยู่ใน scope เต็ม 14 · mock โดยเจตนา 1 (M-08 เครดิต → W5) · ตัดสินด้วย [ASSUMED] 1 (M-15)**

## 3. Nice-to-have (N) — มาตรฐานมี แต่ **ไม่อยู่รอบนี้**

| # | ความสามารถ | อยู่ที่ไหน/ทำไมตัด |
|---|---|---|
| N-01 | **RMA number จากผู้ขาย** (D365/NetSuite) — เลขอนุญาตคืนจากผู้ขาย | รอบนี้เก็บเป็น **field ข้อความ optional** ได้ แต่ไม่มี workflow ขออนุญาตแยกใบ |
| N-02 | **Disposition code** (คืน / เปลี่ยนของใหม่ / ซ่อม / ทิ้งซาก) | รอบนี้มีแต่ "คืนผู้ขาย" — เปลี่ยนของใหม่/ทิ้งซาก = backlog |
| N-03 | **Replacement flow อัตโนมัติ** (คืนแล้วเปิดใบรับของทดแทนให้เอง) | backlog — ผูกกับ OQ-RTV-01 |
| N-04 | **ค่าใช้จ่ายในการคืน** (ค่าขนส่งคืน / restocking fee) | backlog — ต้องมี Landed Cost (F069 · W4) ก่อน |
| N-05 | **Vendor scorecard / quality rating** จากสถิติการคืน | Vendor Performance = feature อื่น |
| N-06 | **Lot / Serial / วันหมดอายุ** ของที่คืน | ไม่มี Lot master ในเลนนี้ (ตรงกับ GRN N-01) |
| N-07 | **คืนของข้าม GRN หลายใบในใบเดียว** | รอบนี้ 1 RTV = 1 GRN (เหมือน GRN 1:1 กับ PO · S-22 ของ GRN) |
| N-08 | **คืนของที่ไม่มี GRN** (คืนของเก่าที่ไม่รู้ที่มา) | ใช้ **Stock Adjustment (W3Q)** แทน — ตรงกับมติ GRN S-17 |
| N-09 | **Credit Note / Debit Note จริง + ล้าง GR/IR** | **W5** — รอบนี้ mock + `TODO: JE posting` |
| N-10 | **พิมพ์ label/barcode สำหรับกล่องส่งคืน · RF scan** | backlog (ตรงกับ GRN N-04) |
| N-11 | **ติดตามสถานะฝั่งผู้ขาย** (ผู้ขายรับของคืนแล้ว/ปฏิเสธ) | รอบนี้จบที่ "ส่งคืนแล้ว" + แนบใบตอบรับ |
| N-12 | **ต้นทุนเฉลี่ย/FIFO ที่ใช้ตอนตัดของออก** | Inventory Valuation (F070 · W4) — รอบนี้ใช้ราคาจาก GRN/PO ตรง ๆ |

## 4. Out-of-scope (ยืนยันว่าไม่ทำ · ห้าม scope creep)

- Credit Note / AP invoice matching / JE posting จริง — **W5**
- Putaway bin · Stock Adjustment · Stock Transfer — **W3Q**
- Landed Cost · Inventory Valuation — **W4**
- Budget Control hook — **W7** (ไม่เกี่ยว RTV โดยตรง)
- PR / Compare Vendors — **W2-PUR-LITE**
- การทำลายซาก (scrap) · การขายซาก · ประกันภัยสินค้า
- Vendor portal / EDI แจ้งผู้ขายอัตโนมัติ

## 5. Gap vs CUBE (สิ่งที่ PREBRIEF ต้องเติมให้ครบ)

| G | ช่องว่างที่เห็น | ต้องเติมที่ |
|---|---|---|
| **G-01** | **แหล่งของที่คืนได้ต้องนิยามให้แคบและตรวจได้** — ไม่ใช่ "GRN line ไหนก็ได้" แต่ต้องเป็น **ของที่ยังอยู่ใน quarantine (จาก QC ไม่ผ่าน) หรือของในคลังที่ยังไม่ถูกใช้ต่อ** พร้อม **ยอดคงเหลือคืนได้** ต่อบรรทัด (หักที่เคยคืนไปแล้ว) | PREBRIEF §3.2 "จำนวนคืนได้คงเหลือ" + BR กันคืนซ้ำ (M-03/M-10/M-14) |
| **G-02** | **เหตุผลคืนต้องผูกกับเหตุผล QC ของ GRN** — GRN มี master เหตุผลไม่ผ่าน (ชำรุด/ผิดสเปค/บรรจุภัณฑ์เสียหาย/ใกล้หมดอายุ/อื่น ๆ · OQ-GRN-06) · RTV ต้องเติม **"รับเกิน"** ที่ GRN ไม่มี | PREBRIEF §3.2 เหตุผลคืน + §3.4 config + ตอบ OQ-GRN-06 บางส่วน |
| **G-03** | **ผลต่อ PO ต้นทาง (M-15)** — GRN นับยอดรับทั้งก้อนรวมของ quarantine (GRN BR-11) · ถ้า RTV คืน ยอดค้างรับควรเปิดกลับไหม | **`OQ-RTV-01 [ASSUMED]`** — ตัดสินใน PREBRIEF §2/§5.2/§10 + เขียนชัดใน BRD |
| **G-04** | **เครดิตจากผู้ขาย (M-08)** — ต้องมีตัวเลข "มูลค่าที่คาดว่าจะได้เครดิต" + ป้ายสถานะเครดิต (mock) ให้ W5 ต่อได้ | PREBRIEF §3.3 + §7 + **BRD section เครดิตผู้ขาย/CN** |
| **G-05** | **DOA ของ RTV ผูกกับอะไร** — วงเงิน = **มูลค่าของที่คืน** (ไม่ใช่วงเงินสั่งซื้อ) · ต้องประกาศ matrix ให้ตั้งที่ DOA กลาง | DOA_BRIEF + PREBRIEF §5 (transition รออนุมัติ) |
| **G-06** | **ยกเลิก/กลับรายการหลังของออกไปแล้ว** — ของกลับมาจากผู้ขาย ต้องเป็น movement ย้อนกลับ ไม่ใช่ลบใบ | PREBRIEF S-reversal + BR movement append-only |
| **G-07** | **ล็อกใบ GRN ต้นทาง** — GRN BR-16 บอกว่า GRN ที่ของถูก RTV แล้ว **กลับรายการไม่ได้** → RTV ต้องบอก GRN ว่าบรรทัดนี้ถูกใช้แล้ว | PREBRIEF §9 เส้นออกกลับ GRN + BR |
| **G-08** | **ผู้เกี่ยวข้องคนจริง** — ผู้ขออนุมัติ · ผู้อนุมัติ (DOA slot) · ผู้ส่งของคืน · ผู้รับฝั่งผู้ขาย — ห้าม role ID | PREBRIEF §3.1 + tab ลายเซ็น |

## 6. สรุป verdict baseline
- must-have **16/16** อยู่ใน PREBRIEF ที่จะเขียน (2 ข้อเป็น mock/[ASSUMED] โดยเจตนาตามกติกา forward-wire: M-08 → W5 · M-15 → OQ-RTV-01)
- nice-to-have 12 ข้อ **ระบุชัดว่าไม่อยู่รอบนี้** พร้อมเจ้าของ wave — ต้องไปโผล่ในหมวด "สิ่งที่ไม่รองรับ" ของ FUNCTION_CHECKLIST เพื่อกัน scope creep
- gap G-01..G-08 = **รายการบังคับ** ที่ S1 ต้องเติม และ S1.5 ต้องตรวจซ้ำ
