## 1. สรุป + ผู้ใช้ + สิทธิ์

**ทำอะไร** [แผน]
RTV (ใบคืนสินค้าผู้ขาย) คือเอกสารที่ใช้ **ส่งของที่รับมาแล้วแต่ไม่รับไว้ กลับคืนผู้ขาย** โดยอ้างกลับไปที่ **GRN line** ที่รับของก้อนนั้นเข้ามา. RTV คือ **ทางออกทางเดียวของของที่อยู่ใน quarantine** (`OQ-GRN-01 [ASSUMED]` — QC ไม่ผ่านต้องรับเข้า quarantine ก่อนเสมอ ห้ามปฏิเสธที่หน้าประตู) และใช้กับของที่ **รับเกิน** หรือ **ผิดสเปค** ที่ยังอยู่ในคลังและยังไม่ถูกใช้ต่อ.

RTV เป็นจุดที่ (1) **ของออกจากคลังจริง** — เกิด movement ออกแบบ append-only จาก quarantine/location ที่ของอยู่, (2) **ต้องผ่านสายอนุมัติ (DOA)** เพราะการคืนของ = การปล่อยทรัพย์สินออกจากคลัง — วงเงินอิงจาก **มูลค่าของที่คืน**, และ (3) เป็นต้นทางของ **เครดิตจากผู้ขาย (Credit Note ฝั่ง AP)** ซึ่งรอบนี้ยัง **ไม่ post จริง** (mock + `TODO: JE posting` · W5).

**เส้นแบ่งที่ห้ามสลับกัน** [แผน · OB-1/OB-7]
- **GRN reversal (GRN S-08)** = "บันทึกรับผิด" — ของไม่ได้มาจริง/ลงใบผิด → ยอดรับสะสมที่ PO **ถูกหักคืน** และ PO ถอยสถานะ
- **RTV (feature นี้)** = "ของมาถึงจริงแล้ว แต่เราไม่รับไว้" → เป็นธุรกรรมใหม่กับผู้ขาย · **ไม่แตะยอดรับสะสมที่ PO** (`OQ-RTV-01 [ASSUMED]` · §10)

**ผู้ใช้ + สิทธิ์** [AI-DRAFT]

| Role | เห็นอะไร | ทำอะไรได้ |
|---|---|---|
| เจ้าหน้าที่คลัง | RTV ทุกใบของคลังตัวเอง + บรรทัด GRN ที่มีของคืนได้ | สร้าง/แก้ร่าง · ส่งอนุมัติ · แนบไฟล์ · **บันทึกส่งคืน (ของออก)** เมื่อใบ `อนุมัติแล้ว` |

| ผู้ตรวจคุณภาพ (QC) | RTV ที่อ้าง GRN ที่ตัวเองตรวจ (อ่านอย่างเดียว) | ยืนยันเหตุผลคืน/แนบหลักฐานสภาพสินค้า |

## 7. Data behaviour

- **เลขรัน**: `RTV-YYYY-NNNN` ออกจาก **F-DOCCFG** ผ่าน doccfg-declaration — **ออกตอนส่งอนุมัติ** (ต่างจาก GRN ที่ออกตอน post เพราะ RTV ต้องมีเลขให้ผู้อนุมัติอ้างและพิมพ์ไปกับรถ) · ร่างยังไม่มีเลข · ปี = **ค.ศ.** (OB-4 · BR-21)
- **DOA**: สายอนุมัติ + จุดตัดวงเงินมาจาก **DOA engine (F-DLG-001)** ตาม **มูลค่าที่คืนรวม** — feature **ประกาศ** ผ่าน doa-declaration เท่านั้น **ห้าม hardcode** · ตอนส่งอนุมัติ **snapshot สาย + คนจริงต่อ slot** แบบ append-only · แก้มูลค่าแล้วส่งใหม่ = re-resolve (BR-11)
- **Soft-reference (LD-4C-02)**: Vendor · Item · UOM · Warehouse/Location · Cost Center = combobox picker · **ไม่ FK validate · nullable** — ค่าที่หายจาก master ยังแสดงเป็นข้อความเดิม ไม่พัง (BR-24)
- **Inventory movement append-only** (OB-7 · BR-13..BR-16): บันทึกส่งคืน → movement **ออก** จาก location ต้นทางของแต่ละบรรทัด (quarantine หรือ location ปกติ) · **ห้ามลบ ห้ามแก้** · กลับรายการ = สร้าง movement ตรงข้ามผูกกับใบเดิม (ของเดิมยังอยู่ในประวัติ)
- **quarantine** (`OQ-GRN-01 [ASSUMED]`): RTV คือ **ทางออกทางเดียว** ของของใน quarantine — ยอด quarantine ลดเมื่อ RTV `ส่งคืนแล้ว` เท่านั้น
- **ยอดคืนสะสมที่ GRN line**: เขียนโดย RTV เท่านั้น · append-only · ใช้คำนวณ "ยอดคืนได้คงเหลือ" ของใบถัดไป (S-03) · **ล็อกไม่ให้ GRN กลับรายการ** (BR-20)
- **PO**: **RTV ไม่เขียนอะไรกลับ PO เลย** — ยอดรับสะสมเป็นของ GRN เท่านั้น (OB-11) · `OQ-RTV-01 [ASSUMED]` (§10) ต้องถูกยกไปเขียนใน BRD ให้ชัด
- **เครดิตผู้ขาย (OB-8 · G-04)**: ส่งคืนแล้ว → ป้าย **"รอเครดิตจากผู้ขาย"** พร้อมมูลค่าที่คาดว่าจะได้ (`Dr เจ้าหนี้การค้า / Cr สินค้าคงคลัง หรือ GR-IR clearing ตามที่ W5 กำหนด`) — **รอบนี้เป็น mock ไม่ post JE** (`TODO: JE posting` · W5) · **ใบลดหนี้ (CN) ตัวจริงออกที่ฝั่ง AP ใน W5**
- **Stock availability (S-23)**: การตรวจว่าของยังอยู่ที่ location จริง (ยังไม่ถูก Putaway ย้าย/ถูกเบิก) = **mock** `TODO: stock availability check` (W3Q)
- **Soft archive**: ร่างที่ทิ้ง / ใบที่ยกเลิก / ใบที่กลับรายการ = ซ่อนจาก list ปกติ แต่ค้นเจอผ่าน filter "รวมที่ยกเลิก/กลับรายการ" — **ไม่มี hard delete** (BR-22)
- **Audit append-only**: ทุก event ต่อท้ายอย่างเดียว รวมการตัดสินของผู้อนุมัติรายคน · แถว audit แก้/ลบไม่ได้
- **เอกสารแนบ**: ผูก Document Center · แสดงในโซนเอกสารแนบของ landing ตาม Pattern Q
- **แจ้งเตือน**: ประกาศ event ผ่าน **ntf-declaration** เท่านั้น — **ไม่ประกาศซ้ำ** `doa_pending` / `doa_result` (มาจาก DOA engine อัตโนมัติ)
- **Threshold/เกณฑ์ทุกตัว** (คืนช้ากว่าเกณฑ์ · วันที่ย้อนหลัง · เตือนคืนซ้ำ) → **NC rules / config** ไม่อยู่ feature code (OB-17)
- **วันที่**: แสดง **ค.ศ. ล้วน** ทั้งหน้าจอและ PDF (BR-23)
