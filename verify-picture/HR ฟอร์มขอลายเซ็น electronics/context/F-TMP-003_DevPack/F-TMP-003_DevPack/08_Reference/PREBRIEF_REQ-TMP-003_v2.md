### 3.2 ตัวเลือก
- **กรณี** (เลือกได้ข้อเดียว): 1.ขอมีลายเซ็นดิจิทัลครั้งแรก · 2.ขอมีลายเซ็นดิจิทัลใหม่ เนื่องจาก · 3.ขอเปลี่ยนลายเซ็นดิจิทัล → ใช้ช่อง โปรดระบุ ชื่อเดิม, นามสกุลเดิม, ชื่อใหม่, นามสกุลใหม่, ชื่อใหม่(ภาษาอังกฤษ), นามสกุลใหม่(ภาษาอังกฤษ)
- **เนื่องจาก (กรณีที่ 2)** (เลือกได้ข้อเดียว): ลายเซ็นหมดอายุ · ไฟล์ลายเซ็นสูญหาย · ลืมรหัสผ่าน
- **ประเภทการเปลี่ยน (กรณีที่ 3)** (เลือกได้ข้อเดียว): เปลี่ยนชื่อ → ใช้ช่อง โปรดระบุ ชื่อเดิม, ชื่อใหม่, ชื่อใหม่(ภาษาอังกฤษ) · เปลี่ยนชื่อสกุล → ใช้ช่อง นามสกุลเดิม, นามสกุลใหม่, นามสกุลใหม่(ภาษาอังกฤษ) · เปลี่ยนทั้งชื่อและนามสกุล → ใช้ช่อง โปรดระบุ ชื่อเดิม, นามสกุลเดิม, ชื่อใหม่, นามสกุลใหม่, ชื่อใหม่(ภาษาอังกฤษ), นามสกุลใหม่(ภาษาอังกฤษ)
- **สำหรับเจ้าหน้าที่** (เลือกได้ข้อเดียว): ดำเนินการได้ · ไม่สามารถดำเนินการได้ เนื่องจาก → ใช้ช่อง ไม่สามารถดำเนินการได้ เนื่องจาก

### 3.5 ข้อมูลตัวอย่างที่ขัดกัน → กฎตรวจที่ควรมี
- ต้นฉบับใส่ข้อความ "สำหรับเจ้าหน้าที่" ไว้ใน header จึงพิมพ์ซ้ำทุกหน้า รวมหน้า 1 ที่ยังไม่ถึงบล็อกเจ้าหน้าที่ → **หัวกระดาษมีเฉพาะโลโก้องค์กร · ข้อความ "สำหรับเจ้าหน้าที่" แสดงเฉพาะหัวบล็อกเจ้าหน้าที่เท่านั้น**
- ต้นฉบับวางช่องชื่อเดิม/ชื่อใหม่ไว้นอกกรอบกรณีที่ 3 จึงดูเหมือนต้องกรอกทุกกรณี → **ช่อง F11–F16 เปิดใช้และบังคับกรอกเฉพาะเมื่อเลือกกรณีที่ 3 · กรณี 1/2 ต้องว่าง**
- ต้นฉบับมีช่องชื่อใหม่และนามสกุลใหม่ครบเสมอ แม้ติ๊กเปลี่ยนเฉพาะชื่อหรือเฉพาะนามสกุล → **เปลี่ยนชื่อ → บังคับเฉพาะชื่อใหม่ (ไทย/อังกฤษ) · เปลี่ยนชื่อสกุล → เฉพาะนามสกุลใหม่ · เปลี่ยนทั้งสอง → ครบทั้งคู่**
- ต้นฉบับมีช่องชื่อเดิม/นามสกุลเดิมเฉพาะภาษาไทย แต่ชื่อใหม่มีทั้งไทยและอังกฤษ จึงเทียบคู่ไม่ครบ → **ชื่อเดิมภาษาอังกฤษให้ระบบดึงจากทะเบียนพนักงาน (Employee.first_name_en / last_name_en) มาแสดงคู่กับชื่อใหม่ ไม่เพิ่มช่องใหม่บนกระดาษ (G5)**
- ต้นฉบับไม่ได้ระบุว่าเลือกได้กี่ข้อ และตัวเลือกย่อยของกรณี 2/3 ก็ไม่ระบุ → **กรณีหลักเลือกได้ 1 ข้อ (บังคับ) · เหตุผลกรณี 2 เลือกได้ 1 ข้อ · ประเภทการเปลี่ยนกรณี 3 เลือกได้ 1 ข้อ · ตัวเลือกย่อยบังคับเมื่อเลือกกรณีนั้น**
- ต้นฉบับไม่มีช่องวันที่ที่เจ้าหน้าที่ดำเนินการ และไม่มีเลขที่คำขอกำกับ → **ระบบบันทึกวันเวลาและผู้ดำเนินการจาก audit trail + เลขที่คำขอจากระบบ ไม่เพิ่มช่องบนกระดาษ (G5)**

## 8. กติกา / declaration
- DOA: ถาม (มีช่องลงชื่อผู้อนุมัติ 1 จุด) — gate G2
- DOCCFG: ประกาศ doc_type + print_config (form_code/revision/min_rows/sign_boxes) — ร่างก่อน HTML
- MDOC: ลงทะเบียนแบบเอกสาร (F-DOCCFG / F003) · source=request
- NTF: event ของ feature เอง (เช่น ยกเลิกระหว่างรอ) — DOA ส่งแจ้งรออนุมัติ/ผลเอง
