# PRINT SPEC — คำขอมีและใช้ลายเซ็นดิจิทัล (Digital Signature) (DSR)

> **โหมด:** Replica (แบบฟอร์มลูกค้า FM-HRM-23) · ไฟล์คู่: `DSR_template.html` (master · fonts ฝัง) + `out/<state>.html`
> รอบนี้รันในโหมด **NO-BROWSER** → ยังไม่มี PDF / `_states_sheet.png` / `compare_side.png` (ดู §7)

## 1. สรุป
- ประเภทเอกสาร: คำขอมีและใช้ลายเซ็นดิจิทัล (Digital Signature) / Digital Signature Request Form
- ขนาด: A4 แนวตั้ง · ต้นฉบับ 2 หน้า (หน้า 2 = บล็อกเจ้าหน้าที่) · แบบพิมพ์ระบบรวมเป็นชุดเดียว บล็อกลงชื่ออยู่แถวล่าง
- ฟอนต์: Sarabun (ฝัง base64) · หมึกเดียวตาม `profile.json` (ไม่ใช้สี CI ในเนื้อฟอร์ม)
- Renderer: Playwright/Chromium (ยังไม่ได้รันรอบนี้)

## 2. Field Mapping
ดู `DSR_data-contract.md` (19 ช่องตาม FORM_SPEC + ช่องลงชื่อ dynamic) · ตรง 1:1 กับกระดาษ ไม่เพิ่ม/รวม/แยกช่อง (DEC-06)

## 3. กติกาคำนวณ
ไม่มี — เอกสารนี้ไม่มีสูตรและไม่มีค่าคงที่บนกระดาษ (`FORM_SPEC.formulas = []` · `constants = []`)

## 4. กติกาการพิมพ์
- บล็อกลงชื่อ + footer ชิดล่าง (`.doc-bottom`) · `break-inside: avoid`
- ช่องลงชื่อ = ผู้ขอ + 1 ช่องต่อขั้น DOA · แถวละ ≤ 4 (`sign_layout.max_per_row`) · เกิน 4 ขั้น → `layout.dense`
- คำตัดสินผูก role: `role-mgr-hr` → "ดำเนินการได้ / ไม่สามารถดำเนินการได้" (เปลี่ยนลำดับขั้นที่ DOA กลางแล้วคำไม่ผิดคน)

## 5. สถานะที่ทดสอบ (5 สถานะ · `print/*.data.json`)
| สถานะ | สิ่งที่พิสูจน์ | ช่องลงชื่อ |
|---|---|---|
| `draft` | กรณี 1 · รออนุมัติ · เส้นประวันที่ · ☐ ทั้งหมด · footer "· ร่าง" | 2 |
| `approved` | กรณี 3 เปลี่ยนทั้งชื่อและนามสกุล · ค่าครบทุกช่อง · ☑ ดำเนินการได้ · "พิจารณาในระบบ …" | 2 |
| `rejected` | กรณี 2 ลืมรหัสผ่าน · ช่องชื่อเดิม/ใหม่เว้นว่าง · ☑ ไม่สามารถดำเนินการได้ + เหตุผล | 2 |
| `long-3signs` | ข้อความยาว (ทำที่/หน่วยงาน) + 3 ขั้น | 4 |
| `approved-doa6steps` | DOA 6 ขั้น → 7 ช่อง 2 แถว (4+3) + `layout.dense` | 4 + 3 |

## 7. ความต่างจากต้นฉบับ (ตั้งใจ) + สิ่งที่ยังต้องทำบนเครื่องที่มี browser
ตั้งใจต่าง:
1. **บล็อกลงชื่อย้ายมาแถวล่างทั้งก้อน** (หลัก form-replica ข้อ 3 · มติ 2026-10-05) — ต้นฉบับวางลายเซ็นผู้ยื่นคำขอกลางหน้า 1 และลายเซ็นเจ้าหน้าที่ที่หน้า 2
2. **ช่องติ๊ก "ดำเนินการได้ / ไม่สามารถดำเนินการได้" อยู่ในกล่องลงชื่อของเจ้าหน้าที่** (decision ผูก role) — ในเนื้อฟอร์มคงหัวข้อ "สำหรับเจ้าหน้าที่" + บรรทัด "เนื่องจาก ……" ไว้ ไม่พิมพ์คำซ้ำ
3. **หัวกระดาษมีเฉพาะโลโก้** — ต้นฉบับใส่ข้อความ "สำหรับเจ้าหน้าที่" ไว้ใน header ของไฟล์ Word จึงพิมพ์ซ้ำทุกหน้า รวมหน้า 1 ที่ไม่เกี่ยว (DEC-12)
4. โลโก้ในตัวอย่างเป็น placeholder · ข้อมูลตัวอย่างเป็นชื่อสมมติทั้งหมด (PDPA)

ยังต้องทำ (`[NO-BROWSER]`):
- `render_states.py` → PDF ทุกสถานะ + `_states_sheet.png` + ยืนยัน "ทุกสถานะ 1 หน้า"
- `compare_original.py orig/SAMPLE.pdf out/approved.pdf --region 0:0.72` → `compare/compare_side.png` + คะแนน (เกณฑ์ ≥ 0.6 · WARN ไม่บล็อกแต่ต้องมีคนดู)
