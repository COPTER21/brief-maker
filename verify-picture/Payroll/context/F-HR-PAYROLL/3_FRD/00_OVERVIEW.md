## §0.3 Scope

### §0.3.1 ทำอะไร

**ตั้ง "รอบจ่ายเงินเดือน" ของงวดหนึ่ง แล้วเดินรอบนั้นผ่าน 9 สถานะ** — ดึงข้อมูลจากต้นทางหกที่เป็น snapshot ที่ตรึงเวอร์ชัน → ตรวจว่าข้อมูลนิ่งพอจะจ่ายหรือยัง → **แปลงชั่วโมง/วัน/ธง ให้เป็นเงินได้กับเงินหัก รวมถึงเงินหักตามกฎหมายสามตัว** → ทบทวนโดยเทียบกับรอบก่อน → ส่งเข้าสายอนุมัติที่ DOA เป็นผู้กำหนด → ปิดรอบซึ่งทำให้ตัวเลขกลายเป็นค่าถาวรที่แก้ไม่ได้ → ออกสลิปรายคนพร้อมเลขที่กับ PDF · แจ้งพนักงาน · ออกไฟล์โอนธนาคาร · ส่ง payload บัญชีให้ปลายทาง

> ⭐ **ประโยคที่นิยาม feature นี้:** ต้นทางทั้งหกเผยแพร่ **ชั่วโมง วัน และธง — ไม่มีจำนวนเงินเลยแม้แต่บาทเดียว** (`LV-6` · `OT-6` · `AT-6` เขียนตรงกันสามใบ) · **ที่นี่คือที่ที่ชั่วโมงกลายเป็นเงิน**

### §0.3.2 ไม่ทำอะไร (10 รายการ — ตรงกับ BRD §14.6.4)

50 ทวิ · ไฟล์ยื่น ภ.ง.ด.1/1ก · แบบนำส่ง สปส.1-10 กับรายงานนำส่งกองทุนสำรองฯ · ตัวช่วยสร้าง/แก้สลิปรายใบ · จ่ายเงินจริง/กระทบยอดธนาคาร · post GL · ใช้ชั่วโมงนอกกะเป็น OT ที่จ่ายได้ · หน้าตั้งค่าใด ๆ · คำนวณงวดที่ปิดแล้วใหม่ · **การเดา/ตั้งค่าเริ่มต้นให้อัตราตามกฎหมาย**

### §0.3.3 ⭐ สิ่งที่ต้องแม่นที่สุดสามข้อ (ถ้าอ่านได้แค่สามบรรทัด ให้อ่านสามบรรทัดนี้)

1. **ไม่มีการเดาตัวเลขในระบบนี้** — ไม่มีค่า → **"ยังไม่มีค่าให้อ่าน" · บรรทัด `ยังคำนวณไม่ได้` (`amount = null` ไม่ใช่ 0) · ยอดรวม "ยังไม่สมบูรณ์" · ส่งอนุมัติไม่ได้** → `03_LOGIC §3.0.1`
2. **การคำนวณอ่านจาก snapshot เท่านั้นตั้งแต่สถานะ "คำนวณแล้ว"** — ดึงใหม่ทำได้ก่อนอนุมัติ ล้างผลคำนวณ เก็บ snapshot เดิม → `03_LOGIC §3.0.2`
3. **รอบที่ปิดแล้วคือค่าถาวร** — ไม่มี transition ออก · ทุกคำสั่งเขียนถูกปฏิเสธ · event ที่มาทีหลังเข้าคิว · การแก้ทุกชนิดคือรอบใหม่ที่อ้างรอบเดิม → `03_LOGIC §3.0.3` (7 ข้อ ทดสอบได้ทุกข้อ)

## §0.7 Multi-Tenant & Security Context

### §0.7.1 ระดับ Classification สูงสุดที่ feature นี้แตะ

⭐ **RESTRICTED** — เป็นระดับสูงสุดของโมดูล HR · field ที่เป็น RESTRICTED: `payroll_run_line.amount` · `rate_used` · `payslip.gross_total`/`deduction_total`/`net_total` · `payroll_run.total_*` · `payroll_run_input_snapshot.payload` (มี `base_amount` อยู่ข้างใน) · เลขบัญชีธนาคารในไฟล์โอน

**ผลที่ตามมา (บังคับ):**
- ทุก field RESTRICTED ต้องผ่าน `F-59 maskAmountByPolicy` ก่อนออกจาก API — **ค่าเริ่มต้นคือปิดบัง ไม่ใช่เปิด**
- **ค่าที่ถูกปิดบังแสดงเป็นเครื่องหมายปิดบัง ไม่ใช่ `0`** (05_RULES `D-CLASS-03`)
- ทุกการเปิดดู/ส่งออกยิง SecC (`payroll.restricted_viewed` · `payroll.bank_file_exported`)
- ⚠️ **ต้อง wire Restricted Resources ที่ Policy Center ก่อน go-live** → `§0.8` OQ

## §0.9 Glossary

| คำ | ความหมาย |
|---|---|
| **รอบจ่าย (`payroll_run`)** | วัตถุหลัก — batch ที่มี lifecycle 9 สถานะ · เลข `PAY-YYYY-NN` |
| **สลิป (`payslip`)** | เอกสารรายคนที่เกิดจากการปิดรอบ · เลข `PS-YYYY-NNNNNN` · immutable |
| **snapshot** | ชุดข้อมูลต้นทางที่อ่านครั้งเดียวแล้วตรึงพร้อมเวอร์ชัน — **การคำนวณอ่านจากที่นี่เท่านั้น** |
| **`ยังคำนวณไม่ได้`** ⭐ | `line_state` ของบรรทัดที่ขึ้นกับค่าที่ยังไม่มี — `amount = NULL` **ไม่ใช่ 0** |
| **fail-closed** ⭐ | ไม่มีค่าให้อ่าน → **ไม่ตัดสิน** แทนที่จะเดา — ระบบไม่จ่ายผิด เพราะจะไม่จ่ายเลย |
| **รอบปรับปรุง** | รอบใหม่ในงวดที่เปิดอยู่ ที่บรรทัดเป็น **ส่วนต่าง** ของงวดที่ปิดแล้ว — **นี่คือ "retro" ของระบบนี้** |
| **รอบกลับรายการ** | รอบใหม่ที่ยอดกลับด้านทั้งรอบ · รอบต้นฉบับไม่ถูกแตะ |
| **`has_material_variance`** | ธงความต่างที่มีนัยสำคัญ — **`NULL` = ตัดสินไม่ได้ → เลือกสายที่ยาวกว่า** |
| **all-or-nothing** | ได้เอกสารเต็มหรือไม่ได้เลย — **ไม่มี rendition ปิดบัง** |
| **`payroll_code`** | รหัสจ่าย — แกนกลางที่เชื่อมทุกต้นทางเข้ากับบัญชี |

## §0.13 ⭐ Published Payroll Surface — สิ่งที่ feature อื่นอ่านได้จากที่นี่

> **Payroll เป็น terminal consumer ของโมดูล HR** — ไม่มี feature HR ใดอ่านต่อจากที่นี่ · ปลายทางทั้งหมดอยู่นอกโมดูล HR
> ⭐ **feature นี้ไม่เขียนกลับต้นทางใดทั้งสิ้น** (`BR-07` · `LOCK-NOWRITE`) — ขาออกมีแค่ **การเผยแพร่ให้ปลายทางมาอ่าน** กับ **hook**

### §0.13.1 อะไรบ้างที่เผยแพร่ (3 surface + 1 hook)

| # | surface | ใครอ่าน | สถานะวันนี้ |
|---|---|---|---|
| **PS-1** | **Payslip Surface** — สลิปรายคน + PDF + ประวัติ + YTD ของเจ้าตัว | **ESS Portal (⏳W6 lane C)** · พนักงานเจ้าของ | ✅ เผยแพร่แล้ว — **W6 ไม่ต้องแก้อะไรที่ฝั่งนี้** |
| **PS-2** | **Closed-Run Totals Surface** — ยอดรวมของรอบที่ปิดแล้ว แยกศูนย์ต้นทุน × `payroll_code` + เงินสมทบนายจ้าง + ภาษีค้างนำส่ง | **ผู้ตรวจสอบ** · Finance · ENG-CSQ | ✅ เผยแพร่แล้ว |
| **PS-3** | **YTD Surface** — ยอดสะสมรายปีต่อคน (เงินได้ · ภาษีหัก · ประกันสังคม · กองทุนสำรองฯ) | **50 ทวิ / ภ.ง.ด.1ก → Accounting** · ESS | ✅ เผยแพร่แล้ว · **เราไม่ออกแบบฟอร์ม** |

### §0.13.2 **PS-1 Payslip Surface** — `GET /api/v1/payroll/payslips`

```
GET /api/v1/payroll/payslips
    ?employee_id=<uuid>        ← บังคับเมื่อผู้เรียกเป็นพนักงาน (ต้องเป็นตัวเอง)
    &company_id=<uuid>         ← บังคับ

GET /api/v1/payroll/payslips/{payslip_no}
GET /api/v1/payroll/payslips/{payslip_no}/pdf     ← คืนสำเนาจากคลัง ไม่ render ใหม่
```

| field | ชนิด | ความหมาย | Classification |
|---|---|---|---|
| `payslip_no` | text | `PS-YYYY-NNNNNN` · immutable · ไม่ reuse | Internal |
| `run_no` · `run_type` | text · enum | รอบที่ออกสลิปนี้ + ชนิดรอบ — ⭐ **ต้องแสดงชนิดรอบเสมอ** เพื่อให้สลิปของรอบปรับปรุงแยกจากสลิปประจำงวดได้ด้วยตาเปล่า | Internal |
| `period_code` · `period_from` · `period_to` · `pay_date` | text · date | งวดกับวันจ่าย | Internal |
| `employee_id` · `employee_name_snapshot` · `employee_code` | uuid · text | เจ้าของสลิป | **PII** |
| `earnings[]` · `deductions[]` | array | `{payroll_code, label, quantity, unit, multiplier, amount, source_ref}` — เรียงตามลำดับการคำนวณ | **RESTRICTED** |
| `gross_total` · `deduction_total` · `net_total` | money | ยอดรวม | **RESTRICTED** |
| `employer_contributions[]` | array | ส่วนสมทบนายจ้าง (SSO · PF) — **แสดงเพื่อความโปร่งใส ไม่หักจากพนักงาน** | **RESTRICTED** |
| `ytd` | object | ยอดสะสมรายปีภาษี (ดู PS-3) | **RESTRICTED** |
| `adjust_section[]` | array | เฉพาะสลิปของรอบปรับปรุง — `{adjust_of_run_no, adjust_of_period_code, reason, amount}` | **RESTRICTED** |
| `payslip_status` | enum | `ออกแล้ว` → `เผยแพร่แล้ว` — **ไม่มี "แก้ไข" ไม่มี "ยกเลิก"** | Internal |
| `pdf_ref` | text | อ้างคลังสำเนา (`ENG-DOC-STORE`) | Internal |
| `source_feature` | const | `F-HR-PAYROLL` | Internal |

**⭐ กติกาการเข้าถึงของ surface นี้ — all-or-nothing:**
- ผู้เรียกที่เป็น **เจ้าของสลิป** → เอกสารเต็ม
- **HR Payroll Officer · Comp Admin · ผู้อนุมัติของรอบ** ในขอบเขตบริษัทนั้น → เอกสารเต็ม + **บันทึก SecC** (`payroll.restricted_viewed` · `view_surface: payslip_other`)
- **ผู้เรียกอื่นทั้งหมด → `403 ERR_PAYSLIP_FORBIDDEN`** พร้อมบันทึก SecC (`payroll.access_denied`)
- ⛔ **ไม่มี rendition ปิดบัง ไม่มีโหมด `masked=true` ของ surface นี้** — ปลายทางที่ขอเอกสารแบบปิดบังจะได้ `403` เหมือนกัน **ห้าม implement rendition ปิดบังเพิ่มภายหลังโดยไม่แก้ FRD** (`LOCK-SLIP403`)

### §0.13.5 **HK-1 GL Hook** — รูปทรงของ payload ที่ Accounting จะมารับ

> **Accounting GL ยังไม่มีในระบบเลย** (`FEATURE_LIST_ALL` Accounting 3/18 — มีแค่ผังบัญชี · กลุ่มลงบัญชี · รหัสภาษี)
> ดังนั้น hook นี้คือ **การประกาศรูปทรงล่วงหน้า** ให้ Accounting มารับได้ทันทีเมื่อมี — **ไม่ post · ไม่ mock หน้าจอบัญชี · Module Linkage ปิด · ไม่บล็อกการปิดรอบ** (`BR-40`)

```
GET /api/v1/payroll/runs/{run_no}/gl-payload      ← ดู/ดาวน์โหลดได้ทันที (สถานะ "รอปลายทาง")
```

| ด้าน | รายการ | คีย์ที่ส่ง |
|---|---|---|
| ค่าใช้จ่าย | **ค่าใช้จ่ายเงินเดือนกับค่าล่วงเวลา** แยก `cost_center` × `payroll_code` | `payroll_code` · `cost_center` · `amount` |
| ค่าใช้จ่าย | **ค่าใช้จ่ายส่วนสมทบนายจ้าง** (ประกันสังคม + กองทุนสำรองฯ) แยก `cost_center` | `payroll_code` · `cost_center` · `amount` |
| เจ้าหนี้ | **ค่าจ้างค้างจ่าย (ยอดสุทธิที่ต้องโอน)** | `payroll_code` · `amount` |
| เจ้าหนี้ | **เงินสมทบประกันสังคมค้างนำส่ง** (ลูกจ้าง + นายจ้าง) | `payroll_code` · `amount` |
| เจ้าหนี้ | **เงินกองทุนสำรองเลี้ยงชีพค้างนำส่ง** (ลูกจ้าง + นายจ้าง) | `payroll_code` · `amount` |
| เจ้าหนี้ | **ภาษีหัก ณ ที่จ่ายค้างนำส่ง** | `payroll_code` · `amount` |

⭐ **ส่ง `payroll_code` + `cost_center` — ไม่ส่งเลขบัญชี** เพราะ mapping `payroll_code → ผังบัญชี` ยังไม่มี (`OQ-PAY-08`) · **การเดา mapping คือการตัดสินเรื่องบัญชีแทน Accounting ซึ่งเราไม่ทำ**
⭐ **payload ครบด้านโดยตัวมันเอง** (ค่าใช้จ่ายรวม = เจ้าหนี้รวม) — และ **รอบที่มีบรรทัด `ยังคำนวณไม่ได้` ปิดไม่ได้ (`BR-19`) จึงไม่มีทางเกิด payload ที่ไม่ครบด้าน**

### §0.13.6 สิ่งที่ **ไม่** เผยแพร่ (และทำไม)

| สิ่งที่ปลายทางอาจอยากได้ | เผยแพร่? | เหตุผล |
|---|:---:|---|

| เลขบัญชีธนาคารเต็ม | ❌ | อยู่ในไฟล์โอนที่ดาวน์โหลดโดยผู้มีสิทธิ์เท่านั้น (SecC) · บนสลิปปิดบังบางส่วนเสมอ |

## §0.15 ⭐ Soft-Reference Read Model (LD-4C-02)

| อ้างถึง | วิธี | ห้าม |
|---|---|---|
| **Employee Master** | เก็บ `employee_id` + **snapshot ของชื่อ/รหัส/ตำแหน่ง/หน่วยงาน/ศูนย์ต้นทุน ณ วันจ่าย** | ❌ FK cascade · ❌ join ข้ามฐานตอน render · ❌ อ่านค่าปัจจุบันมาแสดงบนสลิปที่ออกแล้ว |
| **Salary Structure · Attendance · Leave · OT · HR Config · On/Offboard** | เก็บ **payload ทั้งก้อนใน `payroll_run_input_snapshot`** + `version_id` | ❌ อ่านสดตอนแสดงผลรอบที่คำนวณแล้ว · ❌ เขียนกลับ |
| **เอกสารต้นทาง** (ใบลา · ใบ OT · รายการประจำ · ใบเบิก · คำสั่งโยกย้าย) | เก็บ **เลขที่** ใน `source_ref` ของทุกบรรทัด | ❌ FK · ❌ ทำสำเนาเนื้อหาเอกสารต้นทาง |
| **รอบต้นฉบับ** (ปรับปรุง/กลับรายการ) | เก็บ `references_run_no` + แถวใน `payroll_run_relation` **ที่รอบใหม่** | ⭐ ❌ **เขียนธงกลับลงรอบเดิม** (BR-33 · PI-8) |

**การตรวจเพิ่มเติม (Lane Mode v2 gate):**

- ✅ **ไม่มี event ใหม่ที่ FRD คิดขึ้นเอง** — 7 NTF + 8 CSQ ตรงกับใบประกาศทุกตัว · **`event ⊆ brief`**
- ✅ ⭐ **สองชุด event disjoint สนิท** — NTF ใช้ `payroll.` + ชื่อกริยา/สถานะฝั่งงาน (`inputs_not_settled` · `blocked_missing_legal_config` · `payslip_available` · `bank_file_ready` · `pay_date_approaching`) ส่วน CSQ ใช้ `payroll.` + ชื่อผลลัพธ์ฝั่ง 7C (`employer_contribution_committed` · `withholding_tax_accrued` · `restricted_viewed` · `bank_file_exported` · `access_denied`) · **ชื่อที่ปรากฏทั้งสองชุด (`payroll.run_closed` · `payroll.run_reversed`) เป็น event เดียวกันที่ถูกบริโภคสองทาง — ไม่ใช่การประกาศซ้ำ** และถูกยิงจากจุดเดียวคือ `F-40` (ปิดรอบ) กับ `F-48` (กลับรายการ) แล้ว fan-out ไปทั้ง ENG-NOTIFY กับ ENG-CSQ · **ไม่มีการยิงสองครั้ง** (ตรวจที่ `06_TESTS IA-21`)
- ✅ ⭐ **ไม่มีการประกาศซ้ำ `doa_pending` / `doa_result`** — DOA engine ยิงเอง (`NTF_BRIEF §3` · `LOCK-NTF-DOA`)
- ✅ ⭐ **ไม่ประกาศท่อ `oc` · `dc` ระดับเอกสาร · `sc`** — feature นี้มีการอนุมัติจริงถึง 5 สาย จึงยิ่งต้องไม่ประกาศ DC ซ้ำ (register **422**)
- ✅ ⭐ **ท่อ AC เป็นครั้งแรกของโมดูล HR** — `CSQ-HRMOVE §3` เขียนส่งต่อไว้ว่า *"Payroll เป็นผู้ลงบัญชีค่าจ้าง"* · **AC ที่ประกาศ ≠ การลงบัญชี** — เป็นการบันทึกว่า "ผลทางบัญชีเกิดขึ้นแล้ว" ให้ `ENG-CSQ` (`S-56` ไม่รองรับการ post จริง)
- ✅ ⭐ **ท่อ EC เป็น `basis: computed` ตัวแรกของโมดูล** — ⚠️ **`ENG-CSQ-02` ต้องไม่นับซ้ำกับ EC `basis: declared` ของสี่ต้นทาง (Attendance · OT · Leave · Employee Movement) ซึ่งอ้างถึงชั่วโมง/วันชุดเดียวกัน** → `OQ-CSQ-P1` · **feature นี้ไม่ตัดสินเรื่องการตีมูลค่าเอง**
- ✅ **DIVERGENCE ของท่อประกาศ: ไม่มี** — chip 5 ท่อ = detect `PREBRIEF §12` ทั้ง 5 ท่อ · `_lane/DECL.json.divergence = []`
