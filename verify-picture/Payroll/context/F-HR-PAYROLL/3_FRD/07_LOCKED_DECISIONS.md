## §7.1 Locked Decisions ของ pack นี้

| LD | การตัดสิน | ทางเลือกที่ถูกปฏิเสธ | เหตุผล |
|---|---|---|---|
| **LD-01** ⭐⭐ | **fail-closed แทน default** — ไม่มีค่าตามกฎหมาย = ไม่คำนวณ = ส่งอนุมัติไม่ได้ | ใส่ค่าเริ่มต้นแล้วติดคำเตือน · คำนวณเป็น 0 ไปก่อน | การ default ตัวเลขเรื่องเงิน/กฎหมายคือ **การเดา** และเป็นการ hardcode ค่าที่ต้องมี `effective_date` — governance invariant พัง · **ระบบจะไม่จ่ายผิด เพราะจะไม่จ่ายเลย** |
| **LD-02** ⭐ | **`amount = NULL` เมื่อคำนวณไม่ได้ — ไม่ใช่ `0`** | ใช้ `0` แล้วแยกด้วยธง | `0` เป็นจำนวนเงินที่ถูกต้องได้จริง (คนที่ไม่มี OT เดือนนั้น) — **การใช้ `0` แทน "ไม่รู้" ทำให้สองสถานะปนกันอย่างกู้ไม่ได้** |
| **LD-03** ⭐ | **ประตูกันอยู่ที่ปุ่มส่งอนุมัติ ไม่ใช่ที่ปุ่มคำนวณ** | บล็อกตั้งแต่กดคำนวณ | ต้องให้คำนวณได้เพื่อ **เห็นว่าขาดอะไรบ้าง กี่บรรทัด กี่คน** — บล็อกที่ต้นทางจะทำให้ไม่มีใครรู้ขอบเขตของปัญหา |
| **LD-04** ⭐ | **จุดตัดของสายอนุมัติเป็นธงธุรกิจ ไม่ใช่วงเงิน** | `amount_from`/`amount_to` ตามยอดรวมของรอบ | 3 เหตุผลใน `BRD §5.4.2` — ยอดรวมวัดจำนวนหัวไม่ได้วัดความเสี่ยง · แถบวงเงินจะเก่าเงียบ ๆ · **ยอดรวมเป็นตัวเลขที่ถูกจำกัดสิทธิ์สูงสุดของโมดูล ต้องไม่รั่วเข้าไปในบันทึกการอนุมัติ** |
| **LD-05** ⭐ | **ความสัมพันธ์ระหว่างรอบเก็บที่รอบใหม่ (ตาราง `payroll_run_relation`)** | `UPDATE payroll_run SET reversed_by=... WHERE run_no=<รอบเดิม>` | การเขียนธงลงรอบเดิม **คือการแก้รอบที่ปิดแล้วในอีกรูปแบบหนึ่ง** — `payroll_run` จึง**ต้องไม่มีคอลัมน์** `reversed_by`/`adjusted_by` |
| **LD-06** ⭐ | **`F-44 guardClosedRun` เป็นบรรทัดแรกของทุก mutation handler** | ซ่อนปุ่มบน UI | ปุ่มที่ซ่อนไม่ได้กันคำสั่งที่ยิงตรงเข้า API |
| **LD-07** | **การคำนวณอ่านจาก snapshot เท่านั้นตั้งแต่ `คำนวณแล้ว`** | อ่านสดทุกครั้ง | ต้นทางเปลี่ยนได้ตลอดจนกว่างวดจะปิด — อ่านสดแปลว่า **ยอดที่ผู้อนุมัติเห็นตอนเซ็นกับยอดที่ปิดรอบเป็นคนละตัวเลข** |
| **LD-08** | **การดึงใหม่ล้างผลคำนวณทิ้งเสมอ** | เก็บผลเก่าไว้แล้ว merge | ผลที่คำนวณจาก snapshot ชุดเก่ากับชุดใหม่ปนกันไม่ได้ · การ merge จะสร้างตัวเลขที่ไม่มี snapshot ใดรองรับ |
| **LD-09** | **snapshot เดิมไม่ถูกทับ — ใช้ `superseded_by`** | `UPDATE` แถวเดิม | audit append-only · ต้องอธิบายได้ว่าตอนนั้นอ่านอะไรมา |
| **LD-10** | **ลำดับ D4 → D5 → D6 บังคับที่ระดับ engine** | บังคับที่ลำดับการแสดงผล | สลับลำดับ = ภาษีผิดทุกคน · การแสดงผลไม่ใช่การควบคุม |
| **LD-11** ⭐ | **สลิปเป็น all-or-nothing (403) ไม่ทำ rendition ปิดบัง** | ทำ 2 rendition เหมือน `F-HR-MOVE` / `F-HR-CERT` | สลิปที่ตัวเลขถูกปิดบัง **ไม่มีเนื้อหาเหลือเลย** — ทุกบรรทัดของมันเป็นเงิน · การมอบเอกสารเปล่าทำให้เข้าใจผิดว่าได้ข้อมูลครบ |
| **LD-12** | **`has_material_variance = NULL` → เลือกสายที่ยาวกว่า** | ถือว่า `false` แล้วใช้สายสั้น | ไม่รู้ ≠ ไม่มีนัยสำคัญ · **ปลอดภัยไว้ก่อน ไม่ใช่ปล่อยผ่าน** · และเป็นคนละเรื่องกับการ default ค่าตัวเลข |
| **LD-13** | **Module Linkage ที่ปิดต้องไม่บล็อกการปิดรอบ** | บล็อกจนกว่าปลายทางจะพร้อม | Accounting GL ยังไม่มีในระบบเลย — บล็อกแปลว่า feature นี้ใช้ไม่ได้ตลอดกาล |
| **LD-14** | **`NN` ในเลขรอบเป็นตัวนับเอกสาร ไม่ใช่เลขงวด** | `PAY-<ปี>-<เลขงวด>` | งวดเดียวมีได้หลายรอบ (นอกรอบ/ปรับปรุง/กลับรายการ) · การยกเลิกจะทำให้ลำดับขาดแล้วมีคนอยากเติมกลับ (= reuse) · และเป็นการ format เลขเองซึ่งผิด `LOCK-NUM` |
| **LD-15** ⭐ | **`role-internal-audit` อยู่เฉพาะสายกลับรายการ** | ใส่ทุกสาย | การกลับรายการเป็น **การกระทำเดียวที่ลบผลของรอบที่จ่ายไปแล้ว** · ใส่ทุกสายจะทำให้ขั้นนั้นเป็นพิธีกรรมแล้วหมดความหมายเมื่อต้องใช้จริง |
| **LD-16** | **payload GL ส่ง `payroll_code` + ศูนย์ต้นทุน ไม่ส่งเลขบัญชี** | เดา mapping ไปก่อน | **การเดา mapping คือการตัดสินเรื่องบัญชีแทน Accounting** (`OQ-PAY-08`) |
| **LD-17** | **สถานะ "ส่งไฟล์แล้ว" คนกดยืนยันเอง** | ยืนยันอัตโนมัติเมื่อดาวน์โหลด | การดาวน์โหลด ≠ ธนาคารรับไฟล์ · การจ่ายจริงเป็นของ Finance |
| **LD-18** ⭐ | **บรรทัดตามกฎหมายของรอบที่ปิดแล้วแสดง `ตรึงแล้ว` โดยไม่แสดงจำนวนเงิน** `[ASSUMED]` | แสดงจำนวนเงินตามปกติ | **การแสดงจำนวนเงินของบรรทัดเหล่านั้นเท่ากับการเปิดเผยอัตราที่ ตั้งค่า HR ยังไม่เผยแพร่** — จะทำให้มีอัตราตามกฎหมายปรากฏในระบบทางอ้อม (`PI-1`) · **รอเคาะที่ REVIEW_SHEET** |
