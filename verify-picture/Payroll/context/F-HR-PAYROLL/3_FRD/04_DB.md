# 04_DB — F-HR-PAYROLL · Payroll (เงินเดือน)

> **Audience:** DBA / BE dev
> **R10 Data Classification บังคับ:** ทุกคอลัมน์มี `Classification` (`Public` / `Internal` / `Confidential` / `Restricted`) + ธง `PII` — **ไม่มีคอลัมน์ใด default เป็น `Public`**
> **ระดับสูงสุดที่ feature นี้แตะ: `Restricted`** (`00_OVERVIEW §0.7.1`)
> **กติกาข้ามทุกตาราง:** append-only · **ไม่มี hard delete · ไม่มีคอลัมน์ `deleted_at`** · ใช้ soft archive/สถานะแทน

## §4.6 Data Governance (6 หัวข้อ)

### §4.6.1 Retention
- `payroll_run` · `payroll_run_line` · `payslip` · `payroll_run_input_snapshot` — **เก็บตามอายุการเก็บเอกสารทางภาษี** · ⛔ **ไม่มีการลบ ไม่มี purge** (ขัดกับ audit append-only + ข้อผูกพันทางกฎหมาย)
- `payroll_run_event` — เก็บตลอดอายุของรอบ

### §4.6.2 Archival
soft archive เท่านั้น — รอบที่ยกเลิกยังอยู่พร้อมเลขที่ · snapshot ที่ถูกแทนที่ยังอยู่พร้อม `superseded_by`

### §4.6.3 Encryption
คอลัมน์ `Restricted` ทั้งหมด (โดยเฉพาะ `payload` · `amount` · `net_total` · `bank_account_masked`) — **เข้ารหัสที่ชั้นเก็บ** → `S06-05` (ยกให้ Architect)

### §4.6.4 Access Control
ไม่มีตารางใดถูกอ่านตรงจาก UI — ผ่าน API + **`F-59 maskAmountByPolicy`** เสมอ · **Policy Center เป็นเจ้าของ matrix สิทธิ์** · ต้อง **wire Restricted Resources ก่อน go-live**

### §4.6.5 Audit
`payroll_run_event` (T-07) เป็นไทม์ไลน์หลัก · ทุกตารางมี `created_by`/`updated_by` · ⛔ **ไม่มี hard delete ที่ใดเลย** · ⭐ **`payroll_run.updated_at` ของรอบที่ปิดแล้วเป็นตัวชี้วัดว่ามีใครแอบแก้หรือไม่** (`IA-17`)
