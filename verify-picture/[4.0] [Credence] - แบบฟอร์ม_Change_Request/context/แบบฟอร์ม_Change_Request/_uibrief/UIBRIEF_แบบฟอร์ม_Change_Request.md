## §7 Interaction Spec
- Esc chain: ปฏิทิน → modal → drawer (handler ใน BASE-KIT + be-datepicker capture)
- Wizard ถัดไป: `wizNext()` → `validateMain()` ไม่ผ่าน = อยู่ขั้น 1 + `.is-invalid` + toast "กรุณากรอกข้อมูลให้ครบถ้วน" · วันที่ส่งมอบก่อนวันที่ขอ = ข้อความเตือนใต้ช่อง (ไม่บล็อก)
- พิมพ์ในช่อง = soft update `setF2()` (ไม่ rebuild) · การ์ดสรุปอัปเดต `#sumTypes` `#sumDue` `#sumPlace`
- ส่งอนุมัติ: `openSubmit()` → `.slot-row` ต่อขั้น `resolveDoa()` (ค่าเริ่ม 2 ขั้น ตรวจสอบโดย · อนุมัติโดย) → `confirmSubmit()` · อนุมัติ `confirmApprove()` (sequential · ครบ = อนุมัติแล้ว) · ไม่อนุมัติ/ยกเลิก `confirmReason()` (ไม่อนุมัติ = กลับร่าง)
- ทุก commit ผ่าน `commitRejected()` (prototype จำลอง 409/403/500)
