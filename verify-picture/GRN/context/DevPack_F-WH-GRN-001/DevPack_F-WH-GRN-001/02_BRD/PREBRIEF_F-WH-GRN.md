## 1. สรุป + ผู้ใช้ + สิทธิ์

**ทำอะไร** [แผน]
GRN (ใบรับของ) คือเอกสารที่คลังบันทึกว่า **ของมาถึงจริงเท่าไหร่ สภาพเป็นอย่างไร และเข้าที่ไหน** โดยอ้างกลับไปที่ PO line ที่ยังค้างรับ. GRN เป็นจุดที่ (1) **stock ขยับจริง** — เกิด movement append-only เข้าคลังปลายทาง (ของที่ QC ไม่ผ่านเข้า **quarantine location** ตาม `OQ-GRN-01`), (2) **ยอดรับสะสมกลับไปที่ PO line** ทำให้ PO เดินสถานะ `sent → partially received → closed`, และ (3) เป็นขาที่สองของ 3-way match ที่จะไปตั้ง **GR/IR** ในฝั่งบัญชี — รอบนี้ยัง **ไม่ post JE จริง** (mock + `TODO: JE posting` · W5).
**GRN ไม่มีสายอนุมัติ (ไม่มี DOA)** — การรับของคือการบันทึกข้อเท็จจริง ไม่ใช่การอนุมัติ; สิ่งที่ต้องระบุคือ **คนจริง** ผู้รับของและผู้ตรวจ QC เพื่อความรับผิดชอบและใช้ในแท็บลายเซ็น.

**ผู้ใช้ + สิทธิ์** [AI-DRAFT]

| Role | เห็นอะไร | ทำอะไรได้ |
|---|---|---|

## 5. State Machine

### 5.1 สถานะของ GRN

```
draft ──รับเข้า (post)──▶ posted ──กลับรายการ (reversal)──▶ reversed
  │                          │
  │ ทิ้งร่าง                  └── แก้ไม่ได้ (BR-14) → ต้องกลับรายการแล้วออกใบใหม่ (S-10)
  ▼
soft archive (ไม่มี hard delete)
```

| จาก | ไป | ใครกด | เงื่อนไข | scenario |
|---|---|---|---|---|
| — | `draft` | เจ้าหน้าที่คลัง | เลือก PO ที่ `sent`/`partially received` แล้วดึง line (BR-01/BR-02) | S-06, S-21 |
| `draft` | `draft` | เจ้าหน้าที่คลัง / QC | แก้จำนวนรับ · บันทึกผล QC · ดึงข้อมูลจาก PO ใหม่ (S-18) | S-02, S-11..S-13, S-18 |
| `draft` | **`posted`** | เจ้าหน้าที่คลัง | ผ่าน BR-04..BR-09, BR-17 · มีผู้รับของคนจริง (BR-23) · ได้เลข doccfg | S-01, S-02, S-03, S-07, S-11..S-13, S-20 |
| `draft` | (soft archive) | เจ้าหน้าที่คลัง | ทิ้งร่าง — ไม่กระทบ stock/PO | S-09 |
| `posted` | **`reversed`** | **หัวหน้าคลัง** | ระบุเหตุผล (บังคับ) · ของยังไม่ถูกใช้ต่อ (BR-16) | S-08 |
| `posted` | `draft` | — | **ไม่รองรับ** — แก้ใบที่ post แล้วไม่ได้ (BR-14) | S-10 |
| `reversed` | — | — | สถานะปลายทาง · อ่านอย่างเดียว · ใบใหม่ต้องสร้างใหม่ | S-08 |

> **ไม่มี transition ที่ผ่านการอนุมัติ** — GRN ไม่มี DOA (OB-11) · ไม่มีสถานะ "รอตรวจ QC" แยกใบ: ผล QC บันทึกในใบเดียวกันก่อน post (inspection plan แยก = backlog N-07)

### 5.2 ผลที่ GRN ทำกับสถานะ PO (sync กลับ · OB-3)

| เหตุการณ์ที่ GRN | ผลที่ PO line | ผลที่ PO ใบ |
|---|---|---|
| post · บางบรรทัดยังค้าง | `รับแล้วสะสม += จำนวนรับครั้งนี้` → line `partial` | `sent → partially received` |
| post · ทุกบรรทัดคงเหลือ = 0 (รวมกรณีรับเกินในกรอบ tolerance) | line `closed` | `sent / partially received → closed` |
| post · บรรทัดบริการยืนยันงานเสร็จครบ | line `closed` | เหมือนข้างบน |
| **กลับรายการ (reversal)** | `รับแล้วสะสม −= จำนวนที่เคยรับ` → line กลับเป็น `partial` / `open` | `closed → partially received` · ถ้ายอดรับกลับเป็น 0 ทุกบรรทัด → `partially received → sent` |
| PO ถูก **short-closed** ที่ฝั่ง PO | line `short-closed` | **GRN ใหม่เปิดจาก PO นี้ไม่ได้** (BR-17) |

## 7. Data behaviour

- **เลขรัน**: `GRN-YYYY-NNNN` ออกจาก **F-DOCCFG** ผ่าน doccfg-declaration — **ออกตอน post เท่านั้น** ร่างยังไม่มีเลข · ปี = **ค.ศ.** (OB-8, BR-20)
- **Soft-reference (LD-4C-02)**: Vendor · Item · UOM · Warehouse/Location · Cost Center = combobox picker · **ไม่ FK validate · nullable** — ค่าที่หายจาก master ยังแสดงเป็นข้อความเดิม ไม่พัง (BR-22)
- **Inventory movement append-only** (OB-10 · BR-12/BR-14): post → เกิด movement 2 ชุด (เข้าคลังปกติ / เข้า quarantine) · **ห้ามลบ ห้ามแก้** · กลับรายการ = สร้าง movement ตรงข้ามผูกกับใบเดิม (ของเดิมยังอยู่ในประวัติ)
- **quarantine** (`OQ-GRN-01 [ASSUMED]`): ของที่ QC ไม่ผ่านอยู่ใน quarantine location — **ไม่นับเป็นของขายได้/ใช้ได้** · ออกจาก quarantine ได้ทางเดียวคือ **RTV (feature ถัดไป)** — `TODO: RTV handoff`
- **ยอดรับสะสมที่ PO**: เขียนโดย GRN เท่านั้น (OB-20 · BR-13) · นับ **จำนวนรับครั้งนี้ทั้งก้อน รวมส่วนที่ QC ไม่ผ่าน** (BR-11) — คำถามว่าการคืนของ RTV ต้องเปิดยอดค้างรับกลับที่ PO ไหม = `OQ-GRN-03` (owner Strike · pin ที่ feature RTV)
- **GR/IR** (OB-7 · G-04): post แล้วใบขึ้นป้าย **"รอตั้ง GR/IR"** พร้อมมูลค่า `Dr สินค้าคงคลัง / Cr GR-IR clearing` = ยอดรวมก่อนภาษี — **รอบนี้เป็น mock ไม่ post JE** (`TODO: JE posting` · W5) · ล้าง GR/IR เกิดตอนใบกำกับฝั่ง AP (W5)
- **Putaway**: GRN รับเข้าถึงระดับ **location** เท่านั้น · การจัดเก็บลง **bin** และ putaway strategy = **F-WH-PUTAWAY (W3Q)** — `TODO: putaway handoff` (OB-14)
- **Soft archive**: ร่างที่ทิ้ง / ใบที่กลับรายการ = ซ่อนจาก list ปกติ แต่ค้นเจอผ่าน filter "รวมที่ยกเลิก/กลับรายการ" — **ไม่มี hard delete** (BR-21)
- **Audit append-only**: ทุก event ต่อท้ายอย่างเดียว · การแก้ร่างเก็บค่าก่อน/หลัง · แถว audit แก้/ลบไม่ได้
- **เอกสารแนบ**: ผูก Document Center · แสดงในโซนเอกสารแนบของ landing ตาม Pattern Q
- **แจ้งเตือน**: ประกาศ event ผ่าน **ntf-declaration** เท่านั้น — ห้าม hardcode ช่องทาง/เงื่อนไข · **ไม่มี `doa_pending`/`doa_result`** เพราะ GRN ไม่มี DOA (OB-11)
- **Threshold/เกณฑ์ทุกตัว** (เลขใบส่งของซ้ำ · วันที่รับย้อนหลัง · เกณฑ์ช้ากว่ากำหนด · tolerance) → **NC rules / config** ไม่อยู่ feature code (OB-17)
- **วันที่**: แสดง **ค.ศ. ล้วน** ทั้งหน้าจอและ PDF (BR-19)
