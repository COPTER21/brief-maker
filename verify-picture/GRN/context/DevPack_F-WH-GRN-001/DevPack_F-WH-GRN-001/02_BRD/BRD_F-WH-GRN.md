# Section 2: Business Context

## 2.1 ปัญหา / โอกาส

วันนี้ของที่ผู้ขายส่งมาถูกรับหน้าคลังโดยไม่มีเอกสารกลางที่ผูกกลับไปยังใบสั่งซื้อ ทำให้เกิดปัญหา 5 อย่าง:
1. **ไม่รู้ว่าค้างรับเท่าไร** — จัดซื้อต้องโทรถามคลังทีละใบ ทำให้ตามของและตัดสินใจปิดใบช้า
2. **ของไม่ผ่านตรวจปนกับของดี** — ไม่มีที่พักของที่ชัดเจน ของเสียถูกเบิกไปใช้ต่อโดยไม่ตั้งใจ
3. **รับเกินโดยไม่มีการควบคุม** — ผู้ขายส่งเกินแล้วคลังรับไว้ทั้งหมด กลายเป็นภาระจ่ายเงินเกิน
4. **บัญชีไม่รู้ว่ามีของเข้าแล้วแต่ยังไม่มีใบแจ้งหนี้** — ไม่มีจุดตั้งพักหนี้ (GR/IR) ทำให้ปิดงบแล้วยอดขาด
5. **แก้ย้อนหลังได้เงียบ ๆ** — เมื่อไม่มีเอกสารที่ล็อกและมีประวัติ ความเคลื่อนไหวสต๊อกจึงเชื่อถือไม่ได้

**โอกาส:** ใบรับของเป็นจุดเดียวที่เชื่อม 3 เส้นเข้าด้วยกัน — ของจริงเข้าคลัง · ยอดค้างรับที่ใบสั่งซื้อ · ภาระหนี้ฝั่งบัญชี ทำให้เกิดการจับคู่สามทาง (ใบสั่งซื้อ ↔ ใบรับของ ↔ ใบแจ้งหนี้) ได้ในอนาคต

## 5.2 Alternative Paths

### 5.2.1 รับบางส่วน — ใบสั่งซื้อยังค้างรับ
กรอกจำนวนน้อยกว่ายอดค้างรับ (หรือข้ามบรรทัดด้วยจำนวน 0) → ระบบแสดง "คงเหลือหลังใบนี้" ให้เห็นก่อนบันทึก → บันทึกแล้วใบสั่งซื้อเป็น "รับบางส่วน" และเปิดใบรับรอบถัดไปจากใบเดิมได้

### 5.2.2 ผลตรวจไม่ผ่าน — ของเข้าโซนกักของ
ผู้ตรวจเลือก "ไม่ผ่านบางส่วน/ทั้งหมด" → บังคับจำนวนที่ไม่ผ่าน + เหตุผล + โซนกักของ → บันทึกแล้วเกิดความเคลื่อนไหว 2 เส้น (เข้าคลังปกติเท่าที่ผ่าน · เข้าโซนกักส่วนที่ไม่ผ่าน) → บรรทัดขึ้นป้าย "รอคืนผู้ขาย" ส่งต่อ RTV (จำลอง)

### 5.2.3 กลับรายการ — บันทึกผิด
หัวหน้าคลังกดกลับรายการทั้งใบ + ระบุเหตุผลบังคับ → ระบบสร้างความเคลื่อนไหวตรงข้ามโดยไม่ลบของเดิม → หักยอดรับสะสมคืนที่ใบสั่งซื้อ → ใบสั่งซื้อถอยสถานะ (`closed → partially received` · หรือกลับเป็น `sent` ถ้ายอดรับเหลือศูนย์)

### 5.2.4 ใบสั่งซื้อไม่พร้อมรับของ
ระหว่างที่ยังเป็นร่าง ถ้าใบสั่งซื้อถูกยกเลิกหรือถูกปิดก่อนรับครบ → บันทึกรับเข้าไม่ได้ + ชี้กลับใบสั่งซื้อ (ร่างยังเก็บไว้ได้)

## 5.3 Process Diagram

```
[ของถึงคลัง] → [เลือกใบสั่งซื้อค้างรับ] → [กรอกข้อมูลการส่ง + ผู้รับของ]
      → [กรอกจำนวนรับ] --เกินเพดาน--> [บล็อก + แก้จำนวน]
      → [ผลตรวจคุณภาพ] --ไม่ผ่าน--> [จำนวน + เหตุผล + โซนกักของ]
      → [แนบเอกสาร] → [ตรวจทาน] → [รับเข้าคลัง]
            ├─→ ความเคลื่อนไหวสต๊อก (เข้าคลัง / เข้าโซนกัก)   [ต่อท้ายอย่างเดียว]
            ├─→ ตัดยอดค้างรับ → ใบสั่งซื้อ: รับบางส่วน / ปิดใบ
            ├─→ ป้ายรอตั้ง GR/IR                              [จำลอง · W5]
            ├─→ คิวจัดเก็บลง bin                              [จำลอง · W3Q]
            └─→ ของในโซนกัก → คืนผู้ขาย                        [จำลอง · RTV]
      [กลับรายการ] ←— หัวหน้าคลัง + เหตุผล —→ ความเคลื่อนไหวตรงข้าม + ใบสั่งซื้อถอยสถานะ
```

| S-08 | ในฐานะผู้ตรวจคุณภาพ ฉันต้องการให้ของไม่ผ่านถูกแยกออกจากของดี | ยอดเข้าคลังปกติกับยอดเข้าโซนกักแยกกันชัดในสรุปและในเอกสาร |
| S-09 | ในฐานะเจ้าหน้าที่คลัง ฉันต้องการบันทึกร่างค้างไว้ | ร่างไม่กระทบสต๊อกและใบสั่งซื้อ · ยังไม่มีเลขที่เอกสาร |

| S-11 | ในฐานะเจ้าหน้าที่จัดซื้อ ฉันต้องการเห็นใบสั่งซื้อถูกตัดยอดอัตโนมัติ | รับครบ = ปิดใบ · รับไม่ครบ = รับบางส่วน · ยอดค้างรับตรงทุกบรรทัด |

## 8.1 State Diagram

```
       ┌── ทิ้งร่าง (เก็บเป็นประวัติ) 
draft ─┴─ บันทึกรับเข้า ─▶ posted ── กลับรายการ (เหตุผลบังคับ) ─▶ reversed
                              └── แก้ไม่ได้ (ต้องกลับรายการแล้วออกใบใหม่)
```

## 8.2 State Transition Table

| จาก | ไป | ใครกด | เงื่อนไข |
|---|---|---|---|
| — | `draft` | จนท.คลัง / หัวหน้าคลัง | เลือกใบสั่งซื้อที่ค้างรับ (R01/R02) |
| `draft` | `draft` | จนท.คลัง / ผู้ตรวจ | แก้จำนวน · บันทึกผลตรวจ · ดึงข้อมูลจากใบสั่งซื้อใหม่ |
| `draft` | `posted` | จนท.คลัง / หัวหน้าคลัง | ผ่าน R04–R09 · มีผู้รับของ · ใบสั่งซื้อยังพร้อมรับ |
| `draft` | (เก็บเป็นประวัติ) | จนท.คลัง / หัวหน้าคลัง | ทิ้งร่าง — ไม่กระทบสต๊อก |
| `posted` | `reversed` | **หัวหน้าคลัง** | ระบุเหตุผล + ของยังไม่ถูกใช้ต่อ (R16) |
| `posted` | `draft` | — | **ไม่รองรับ** (R14) |
| `reversed` | — | — | สถานะปลายทาง อ่านอย่างเดียว |

# 📌 หมายเหตุพิเศษ: GR/IR (ตามที่ CHECKLIST W3P บังคับให้มีใน BRD)

**GR/IR (Goods Receipt / Invoice Receipt) คืออะไร:** เมื่อของถึงคลังแต่ใบแจ้งหนี้ยังไม่มา องค์กรมีสินทรัพย์เพิ่มแล้วแต่ยังไม่มีเจ้าหนี้ตัวจริง จึงต้องพักไว้ในบัญชีกลางระหว่างทาง แล้วล้างออกเมื่อใบแจ้งหนี้เข้ามา

| หัวข้อ | รอบนี้ (W3P) | เมื่อถึง W5 |
|---|---|---|
| รายการที่จะเกิด | **เดบิต** สินค้าคงคลัง / **เครดิต** พักหนี้ GR-IR — มูลค่า = ยอดก่อนภาษีของใบรับ | ลงบัญชีจริงตอนบันทึกรับเข้า |
| ภาษีมูลค่าเพิ่ม | ไม่ตั้ง — แสดงเพื่ออ้างอิงเท่านั้น (ภาษีจริงเกิดที่ใบกำกับของผู้ขาย) | ตั้งที่ใบแจ้งหนี้ฝั่งเจ้าหนี้ |
| ของที่ไม่ผ่านตรวจ | รวมอยู่ในมูลค่ารับเข้า (เพราะของเข้ามาจริง) แต่ถูกกันไว้ในโซนกัก | การคืนผู้ขายจะกลับรายการส่วนนี้ |
| การกลับรายการใบรับ | ป้ายเปลี่ยนเป็น "กลับรายการ" — ยังไม่มีรายการบัญชีให้กลับ | ต้องกลับรายการบัญชีคู่กัน |
| การล้างบัญชีพัก | ไม่อยู่ในขอบเขต | ล้างตอนบันทึกใบแจ้งหนี้ (จับคู่สามทาง) |
| สถานะปัจจุบัน | **จำลอง + `TODO: JE posting`** — feature ไม่คำนวณบัญชีเอง ไม่มีตารางบัญชีของตัวเอง | เจ้าของคือระบบบัญชี W5 |
