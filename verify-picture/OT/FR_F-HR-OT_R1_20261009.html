ตรวจแล้ว

  • UX/UI ทั้ง 4 หน้า: ทะเบียนใบ OT (#/ot/list) · ชั่วโมงสะสมและเพดาน (#/ot/cap) · ยืนยันเวลาจริง (#/ot/confirm) · สรุปงวดและการเชื่อมต่อ (#/ot/period)
  • ตัวช่วยสร้าง 5 ขั้น (wizard) · มุมมองใบ 4 แท็บ (รายละเอียด/PDF/ลายเซ็น/ประวัติ) · modal การตัดสิน
  • การตอบสนองของปุ่ม/ลิงก์ · การอัปเดตหน้าจอหลังทำรายการ · ความเรียบร้อยของ layout และ component

ไม่ได้ตรวจ

  • Logic / กฎธุรกิจทั้งหมด (กลไกเพดาน→เลือกสายอนุมัติ 2/3 ชั้น · ตีใบกลับเมื่อ over_cap เปลี่ยน · ส่วนต่างเวลาจริง · state machine) — รอบนี้มอบหมายให้ตรวจเฉพาะ UX/UI
  • สิทธิ์ / ขอบเขตการเห็น (scope own/team/company) / SoD / masking ตาม Policy Center — ต้องใช้ account หลายบทบาท
  • ความแก้ไม่ได้: เลขเอกสารอ่านอย่างเดียว · ประวัติ append-only (ไม่มีปุ่มลบ/แก้) — เป็น Logic/Immutable ต้องยืนยันที่ backend
  • ความถูกต้องของ read model ที่เผยแพร่ปลายทาง (Payroll/ESS/Roster) + เคส 'คืนค่าว่าง' — เป็น Logic ข้ามโมดูล · ปลายทางยัง ⏳ ยังไม่มีตัวจริงให้คลิกข้ามไป
  • ความถูกต้องของข้อความ error ครบทุก code (27 code) และ microcopy verbatim ครบทุกจุด — รอบนี้ยังไม่ได้ไล่ยิงทุกเคส error

#หัวข้อตรวจผลหมายเหตุหลักฐาน
X-01ทำงานหลักจบได้เองโดยไม่ต้องเดาผ่าน——
X-02กดแล้วระบบบอกผลทุกครั้ง (แจ้งเตือน / สถานะเปลี่ยน)มีข้อสังเกตหลายจุดกดแล้วไม่ได้ผล/หน้าจอไม่อัปเดต: (1) หลังทำรายการ create/edit/action หน้าจอไม่ fetch ข้อมูลมาแสดงใหม่ ต้อง refresh เองข้อมูลถึงอัปเดต (2) ปุ่มดาวน์โหลด+พิมพ์ใน drawer กดแล้วเงียบ — ดู BUG-01 (3) ปุ่มส่งออกหน้าสรุปงวด กดแล้วเงียบ — ดู BUG-02—
X-03ข้อความ error บอกว่าผิดที่ไหน แก้ยังไงผ่าน——
X-04ถามยืนยันก่อนลบ / ยกเลิก / สิ่งที่ย้อนไม่ได้ผ่าน——
X-05หน้าว่าง / กำลังโหลด / โหลดไม่สำเร็จ มีทางไปต่อผ่าน——
X-06ความเร็วตอบสนองรับได้ผ่าน——
X-07แท็บ 'สรุปงวดและการเชื่อมต่อ' แสดงโมดูลปลายทางที่ยังไม่ทำรอบนี้ — ต้องให้ BA เคาะมีข้อสังเกตผู้ตรวจพบว่าแท็บนี้นำโมดูลปลายทางที่ตัดสินว่ายังไม่ทำรอบนี้ (เงินเดือน/จัดกะและเวร/ESS = 'รอ') มาแสดง · อย่างไรก็ตามตาม FRD FN-49 แถบ Module Linkage ออกแบบให้แสดงปลายทางครบ 5 รายการรวมที่ยัง 'รอ' แบบ display-only ทิศทางเดียว → อาจเป็นดีไซน์ตั้งใจ ไม่ใช่ข้อบกพร่อง · ยกเป็นข้อให้ BA ยืนยันก่อนชี้ขาด (ห้าม AI ตัดสินเอง)—

4Bug ที่พบ

เรียงจากรุนแรงมากไปน้อย · ทำซ้ำได้ตามขั้นตอน

BUG-01ปุ่มดาวน์โหลด + พิมพ์ ใน drawer (มุมมองใบ) กดแล้วไม่มีอะไรเกิดขึ้นMediumรอแก้
ขั้นตอนทำซ้ำ
  1. เปิดใบ OT ใบใดก็ได้ → เปิด drawer มุมมองใบ
  2. ไปแท็บ PDF (หรือจุดที่มีปุ่มดาวน์โหลด/พิมพ์)
  3. กดปุ่ม 'ดาวน์โหลด' → สังเกตว่าไม่มีไฟล์ถูกดาวน์โหลด
  4. กดปุ่ม 'พิมพ์' → สังเกตว่าไม่มีหน้าต่างพิมพ์/ไฟล์เปิดขึ้น
ผลที่ควรเป็นกดดาวน์โหลด = ได้ไฟล์ใบ OT (PDF) · กดพิมพ์ = เปิดหน้าต่างพิมพ์ของใบ OT ตามแท็บ PDF (Pattern Q)
ผลที่เกิดจริงกดทั้งสองปุ่มแล้วไม่มีอะไรเกิดขึ้น (dead control)
BUG-02ปุ่มส่งออก (export) หน้าสรุปงวด กดแล้วไม่มีอะไรเกิดขึ้นMediumรอแก้
ขั้นตอนทำซ้ำ
  1. ไปหน้า 'สรุปงวดและการเชื่อมต่อ' (#/ot/period)
  2. เลือกงวด → ให้ตารางสรุปต่อคนแสดงผล
  3. กดปุ่ม 'ส่งออก' → สังเกตว่าไม่มีไฟล์ถูกส่งออก
ผลที่ควรเป็นกดส่งออก = ได้ไฟล์สรุปงวด (ชั่วโมงต่อคน แยกตาม rate_type)
ผลที่เกิดจริงกดแล้วไม่มีอะไรเกิดขึ้น (dead control)

5ข้อเสนอแนะ (ไม่ใช่ Bug)

ทำงานถูกตาม spec แล้ว แต่ควรปรับให้ดีขึ้น — ส่งต่อเป็น Enhancement ถ้าทีมเห็นด้วย

#ข้อเสนอเหตุผล
S-01หลังทำรายการ (สร้าง/แก้/อนุมัติ/ยืนยัน) ให้หน้าจอ refetch หรืออัปเดตผลให้เอง ไม่ต้องให้ผู้ใช้กด refreshลดความสับสน 'กดแล้วไม่เห็นผล' ที่ทำให้ผู้ใช้กดซ้ำหรือเข้าใจว่าระบบค้าง
S-02เพิ่ม contrast ของ stepper และปรับขนาดปุ่มในตารางให้กดง่ายขึ้นอ่านสถานะขั้นตอน/กดปุ่มในตารางได้ชัดและแม่นขึ้น
