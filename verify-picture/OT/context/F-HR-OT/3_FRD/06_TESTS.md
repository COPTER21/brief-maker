## §6.2 Invariant Assertions (IA) ⭐ — ตกข้อใดข้อหนึ่ง = **หยุด release**

| IA | ยืนยันอะไร | วิธีทดสอบ | อ้าง |
|---|---|---|---|
| **IA-01** | **ใบที่ยังไม่ `time_confirmed` ไม่ถูกเผยแพร่** | สร้างใบให้ถึง `approved` → เรียก API-20 และ API-21 → **ต้องไม่พบใบนั้น** · จากนั้นยืนยันเวลาจริง → **ต้องพบทันที** | BR-17 · FN-45 · §0.13 |
| **IA-02** | **ไม่มีเส้นทางเขียนกลับไปยัง Attendance · Leave · HR Config** | สแกน endpoint ทั้งหมด + ตรวจ log การเรียกต้นทางว่าเป็น GET ทั้งหมด | BR-05 · AT-5 · LV-5 |
| **IA-03** | **ไม่มีค่านโยบาย (เพดาน · ตัวคูณ · นาทีปัดเศษ) เขียนตายในซอร์ส** | สคริปต์ค้นซอร์สหาตัวเลขที่ตรงกับค่าใน HR Config + ตรวจว่า `resolveCap`/`resolveOtRate` ถูกเรียกจริงทุกเส้นทาง | **P-8** · BR-01 |
| **IA-04** | **ไม่มีรายชื่อผู้อนุมัติหรือลำดับขั้นเขียนตายในซอร์ส** | สแกนหา role id / ชื่อคน ในโค้ด · จำลอง DOA ล่ม → **ต้องได้ `ERR_OT_CHAIN_UNAVAILABLE` ไม่ใช่สาย fallback** | **LOCK-DOA** · BR-10 |
| **IA-05** ⭐ | **ไม่มีตัวเลขชั่วโมงเป็นขอบของ matrix ที่ DOA** — และจำนวนชั้นเปลี่ยนตามเพดานที่ต้นทางประกาศจริง | (1) ตรวจ matrix ทั้ง 2 set: `amount_from = 0` · `amount_to = null` (2) **เปลี่ยนเพดานที่ HR Config จาก 36 เป็น 30 → ใบ 34 ชม. ที่เคยได้ 2 ขั้น ต้องได้ 3 ขั้น โดยไม่แตะ matrix เลย** | **§3.0.2** · BR-09 |
| **IA-06** | **งวดที่ปิดแล้วเปลี่ยนอะไรไม่ได้เลย** | เปิดใบค้างไว้ → ปิดงวด → กดอนุมัติ → **ต้องได้ `ERR_OT_PERIOD_CLOSED`** (ไม่ใช่สำเร็จ) | BR-15 · P-7 |
| **IA-07** ⭐ | **ไม่มีตัวเลขเงินในทุกชั้น** | สแกน: คอลัมน์ DB · key ของทุก response · payload ของทุก event · เนื้อหา PDF · ข้อความบนจอ — หาคำว่า จำนวนเงิน/ราคา/ยอดรวม/สกุลเงิน/สัญลักษณ์เงิน | **LOCK-MONEY** · BR-18 · FN-53 |
| **IA-08** | **ไม่มีความสามารถที่ประกาศว่าไม่รองรับ** | ตรวจว่าไม่มี: การแลกชั่วโมงเป็นวันหยุด · ช่องค่ากะ · หน้าคุมงบ · ตารางจัดกะ · ช่อง on-call | NS-02 · NS-03 · NS-04 · NS-05 · NS-14 |
| **IA-09** | **ไม่มีการลบถาวร** | พยายาม UPDATE/DELETE บนตารางประวัติ → **ต้องถูกปฏิเสธที่ชั้นฐานข้อมูล** · ค้นหาคำสั่ง DELETE ในซอร์ส | **LOCK-AUDIT** · BR-14 |
| **IA-10** | **ไม่มีการปัดเศษด้วยตัวเลขที่เดาเอง** | ป้อนช่วงเวลาที่ได้เศษนาที → ผลลัพธ์ต้องเป็นค่าดิบ · สแกนซอร์สหาค่าคงที่ 15/30/60 นาทีในเส้นทางคำนวณชั่วโมง | BR-30 · OQ-OT-16 |
| **IA-11** | **ไม่มีหน้าจอที่เป็นของ feature อื่น** | ตรวจว่าไม่มี: หน้าตั้งค่าค่านโยบาย · การ์ดผลกระทบ 7 ด้าน · แดชบอร์ดแนวโน้ม · ปุ่มพิมพ์หลายใบ · ปุ่มมอบฉันทะ · ปุ่มสลับบริษัท | NS-07 · NS-11 · NS-12 · NS-13 · NS-15 · NS-16 · NS-17 |

## §6.4 Definition of Done (DoD)

- [ ] ใบ PDF ตรงกับ `PRINT_SPEC.md` ทุกช่อง (รวมกรณี 4 ช่องลงนาม)
- [ ] read model ทั้งสองมุมมองคืนค่าตาม `§0.13` เป๊ะ (ชื่อ field ตรง · ไม่มีช่องเงิน)

- [ ] ลงทะเบียน where-used ที่ 3 ต้นทางแล้ว

## §6.9 Cross-Module Test Cases ⭐

| CM | สถานการณ์ข้ามระบบ | ผลที่ต้องได้ |
|---|---|---|
| CM-01 | **HR Config เปลี่ยนเพดานให้มีผลเดือนหน้า** | ใบของเดือนนี้ยังใช้เพดานเดิม · ใบของเดือนหน้าใช้ค่าใหม่ · **จำนวนชั้นของสายเปลี่ยนตาม โดยไม่แตะ matrix** (IA-05) |
| CM-02 | **HR Config ปิดงวด** | ทุกการเปลี่ยนของงวดนั้นถูกปฏิเสธทันที · สรุปงวดถูกตรึง (IA-06) |

| CM-04 | **Attendance แก้เวลาย้อนหลัง** | ใบที่อ้างวันนั้นติดธง "ต้องทวน" + HR ได้รับแจ้ง · **ตัวเลขในใบไม่เปลี่ยนเอง** |
| CM-05 | **Leave อนุมัติใบลาคร่อมวันที่มีใบ OT ร่างอยู่** | ใบ OT ถูกบล็อกตอน submit พร้อมเลขที่ใบลา |
| CM-06 | **Leave ถอนใบลา** | การบล็อกหายไปหลังอ่านค่าใหม่ (ไม่ใช้ค่า cache ข้ามวัน) |

| CM-11 | **Roster ยังไม่มีตัวจริง** | จุดเชื่อมแสดง "ยังไม่เชื่อม" · ไม่มี error · ใบยังทำงานได้ปกติ |

## §6.10 Microcopy-Aware Expected Text ⭐ (verbatim จากจอจริง)

| จุด | ข้อความที่ QA ต้องเห็นตรงตัว |
|---|---|
| ทะเบียนว่าง | `ไม่พบใบขอ OT ตามเงื่อนไข` |
| คำแนะนำใต้ทะเบียนว่าง | `ลองล้างตัวกรอง หรือกด “สร้างใบขอ OT” เพื่อยื่นใบใหม่` |
| ร่างยังไม่มีเลข | `ยังไม่ออกเลข` |

| ป้ายสถานะ | `ร่าง` · `รออนุมัติ` · `อนุมัติ` · `ยืนยันแล้ว` · `ไม่อนุมัติ` · `ยกเลิก` · `ถอน` |
