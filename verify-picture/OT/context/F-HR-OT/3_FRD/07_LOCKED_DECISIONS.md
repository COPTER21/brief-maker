## §7.1 Locked Decisions (LD)

| LD | การตัดสิน | เหตุผล | ผลถ้ากลับคำ |
|---|---|---|---|
| **LD-OT-01** ⭐ | **จำนวนชั้นของสายอนุมัติเลือกด้วย action id ที่มาจากธง `over_cap` — ไม่ใช่ขอบตัวเลขใน matrix ของ DOA** | ตัวเลขเพดานเป็นพารามิเตอร์ที่มีวันที่มีผลและอยู่ที่ HR Configuration · ใส่ลง matrix = แหล่งความจริงสองที่ + hardcode ค่ากฎหมาย (P-8) | matrix จะผิดเงียบ ๆ ทุกครั้งที่เพดานเปลี่ยน · ใบที่ควรผ่าน 3 ขั้นจะผ่านแค่ 2 โดยไม่มีสัญญาณเตือน |
| **LD-OT-02** ⭐ | **`cap_snapshot_hours_week` + `config_version_ids` ต้องมีค่าตั้งแต่วินาที submit** | หลักฐานว่าใบถูกตัดสินด้วยค่าเวอร์ชันไหน | ตรวจสอบย้อนหลังไม่ได้ · ตอบผู้ตรวจสอบไม่ได้ |
| **LD-OT-03** ⭐ | **เมื่อธง `over_cap` ไม่ตรงกับความจริงกลางทาง → ตีใบกลับไป resubmit ไม่ใช่เติม slot เข้าไปในสายที่ freeze แล้ว** | สายที่ตรึงไว้เป็นหลักฐาน แก้ไม่ได้ · การเติม slot เงียบ ๆ ทำให้เอกสารมีลายเซ็นไม่ครบตามอำนาจ | ความล้มเหลวด้านธรรมาภิบาลที่ตรวจไม่พบ |
| **LD-OT-04** | **เฉพาะใบ `time_confirmed` เท่านั้นที่เผยแพร่ให้ปลายทาง** | อนุมัติ ≠ ทำจริง — คำขอล่วงหน้าอาจไม่ถูกใช้ | จ่ายเงินจากตัวเลขที่ยังเปลี่ยนได้ |
| **LD-OT-05** | **ขอเกินเวลาจริง = บล็อกจนแก้หรือมีการรับทราบพร้อมเหตุผล · ขอน้อยกว่า = ผ่าน + ธง** | สองทิศทางมีความเสี่ยงต่อองค์กรไม่เท่ากัน | ทางหนึ่ง = จ่ายโดยไม่มีหลักฐาน · อีกทาง = กีดกันการสละสิทธิ์โดยไม่จำเป็น |
| **LD-OT-06** | **ไม่มีเกณฑ์ผ่อนผันของส่วนต่างในรอบนี้ (ต่างเกิน 0 = บล็อก)** | ยังไม่มีใครเคาะ (OQ-STD-OT6) · การเดาตัวเลขผ่อนผัน = สร้างนโยบายค่าจ้างลอย ๆ ในโค้ด | ถอยยากเมื่อมีคำตอบจริง |
| **LD-OT-07** | **ใช้ค่าชั่วโมงดิบไม่ปัดเศษ** | `ot_rate` ยังไม่มีฟิลด์การปัดเศษ (OQ-OT-16) · P-8 ห้าม hardcode ค่ากฎหมาย | ตัวเลขที่ส่ง Payroll อาจไม่ตรงกับที่เคยจ่ายมือ — **ยอมรับความเสี่ยงนี้แทนการเดาตัวเลข** |
| **LD-OT-08** | **เพดานรายวัน/รายเดือนแสดงว่า "ยังไม่มีค่าให้อ่าน" ไม่ใช่ซ่อนหรือเดา** | ผู้ใช้ต้องรู้ว่าอะไรที่ระบบยังตรวจให้ไม่ได้ (OQ-STD-OT5) | เข้าใจผิดว่าตรวจครบแล้ว = ความเสี่ยงทางกฎหมายที่มองไม่เห็น |
| **LD-OT-09** | **เขตเวลาเดียวของผู้เช่า · timestamp เก็บแบบมีเขตเวลา** | ระบบใช้ในประเทศเดียว · การรองรับหลายเขตเวลาจะทำให้ `work_date` กำกวม | ต้องนิยาม "วันเข้ากะ" ใหม่ทั้งระบบ |
| **LD-OT-10** | **1 ใบ = 1 คน — ยื่นแทนหลายคนแตกเป็นใบต่อคน · ทั้งชุดเป็นธุรกรรมเดียว** | แต่ละคนต้องมีเลขที่ · สายอนุมัติ · การรับทราบ ของตัวเอง | ร่องรอยรายบุคคลขาด · ตรวจความยินยอมรายคนไม่ได้ |
| **LD-OT-11** | **การถอนต้องผ่านสายอนุมัติอีกครั้ง** `[ASSUMED · OQ-OT-11]` | ยอดที่ส่งปลายทางไปแล้วไม่ควรถูกดึงกลับโดยพลการ | ยอดที่ Payroll อ่านไปแล้วเปลี่ยนโดยไม่มีคนอนุมัติ |
| **LD-OT-12** | **การยกเลิกไม่บังคับเหตุผล แต่การถอนบังคับ** `[AI-DRAFT · OQ-OT-14]` | ยกเลิกเกิดก่อนมีใครเซ็น = ยังไม่มีผลกับใคร · ถอนเกิดหลังมีผลแล้ว | เพิ่มแรงเสียดทานโดยไม่จำเป็น หรือขาดร่องรอยในจุดที่ต้องมี |

| TR-01 | **2 action แยกกันที่ DOA** | 1 action + ขอบตัวเลขใน matrix | ต้องตั้งค่า 2 ชุดที่ทะเบียน · **แลกกับการไม่มีแหล่งความจริงสองที่** |
| TR-02 | **ตีใบกลับเมื่อธงเปลี่ยนกลางทาง** | เติม slot เข้าไปในสายที่ freeze | ผู้ขอต้องส่งใหม่ · **แลกกับเอกสารที่มีลายเซ็นครบตามอำนาจ** |
| TR-03 | **เกณฑ์ส่วนต่างเข้มที่สุด (ต่างเกิน 0 = บล็อก)** | ตั้งเกณฑ์ผ่อนผันเอง | ผู้อนุมัติต้องกดรับทราบบ่อยขึ้นในช่วงแรก · **แลกกับการไม่สร้างนโยบายค่าจ้างลอย ๆ ในโค้ด** |
| TR-04 | **ใช้ค่าชั่วโมงดิบไม่ปัด** | ปัดเป็นบล็อก 15/30 นาทีตามธรรมเนียม | ตัวเลขอาจไม่ตรงกับที่เคยจ่ายมือ · **แลกกับการไม่ hardcode ค่ากฎหมาย (P-8)** |
| TR-05 | **สรุปงวดเป็นตารางที่รวมไว้ล่วงหน้า** | คำนวณสดทุกครั้ง | ต้องมีกลไกรีเฟรช · **แลกกับการตรึงยอดได้จริงเมื่อปิดงวด** |
| TR-06 | **บล็อกเมื่ออ่านต้นทางไม่สำเร็จ** | ใช้ค่าที่เก็บไว้ล่าสุด | ผู้ใช้ทำงานไม่ได้ชั่วคราวเมื่อต้นทางล่ม · **แลกกับการไม่ตัดสินด้วยค่าที่ล้าสมัย (BR-04)** |
