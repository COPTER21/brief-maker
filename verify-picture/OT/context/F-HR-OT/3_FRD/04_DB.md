# 04_DB — F-HR-OT · OT / Shift (โอที)

> Audience: **DBA / BE dev**
> **กติกาเหล็กของไฟล์นี้:** ❶ ทุกคอลัมน์มี `Classification` + `PII` ❷ **ไม่มีคอลัมน์จำนวนเงินที่ใดเลย** (LOCK-MONEY) ❸ **ไม่มี `DELETE` statement ในระบบนี้** (LOCK-AUDIT) ❹ การอ้างข้ามระบบเป็น **soft reference** — ไม่มี FK จริงข้าม feature (LD-4C-02)

## §4.1 Table Overview

## §4.3 Relationships (ER)

```
Employee Master ─(soft)─┐
HR Config ot_rate ─(soft·snapshot)─┐
Attendance day ─(soft·snapshot)─┐  │
Leave request ─(soft)─┐         │  │
DOA entry ─(soft)─┐   │         │  │
                  ▼   ▼         ▼  ▼
              ┌──────────────────────┐
              │   T_ot_request       │──(reversal_of · self)──► T_ot_request
              └───┬────┬────┬────┬───┘
       1:N ┌──────┘    │    │    └──────┐ 1:N
           ▼           ▼    ▼           ▼
  T_ot_request_line  T_ot_attachment  T_ot_approval_trace  T_ot_history
           │
           └──(รวมยอด)──► T_ot_period_summary  ──(อ่านโดย)──► Payroll · ESS · Roster
```

**กติกา:**
- **FK จริงมีเฉพาะภายใน feature** (`ot_request_id`) — ข้าม feature เป็น soft reference ทั้งหมด (LD-4C-02)
- **ไม่มี `ON DELETE CASCADE` ที่ใดเลย** เพราะไม่มี DELETE
- `T_ot_request.reversal_of` ชี้ตัวเอง — รายการกลับจากการถอน (BR-27)

## §4.4 Migration Strategy

| ขั้น | สิ่งที่ทำ | หมายเหตุ |
|---|---|---|
| M-1 | สร้าง 7 ตาราง + index + constraint | ไม่มีข้อมูลเดิมให้ย้าย (New Feature) |
| M-2 | ตั้ง trigger ปฏิเสธ UPDATE/DELETE บน `T_ot_history` · `T_ot_approval_trace` | บังคับ append-only ที่ชั้นฐานข้อมูล (IA-09) |
| M-3 | ตั้ง trigger ปฏิเสธ UPDATE บน `T_ot_period_summary` เมื่อ `snapshot_frozen_at IS NOT NULL` | P-7 |
| M-4 | ตั้ง `EXCLUDE` constraint กันช่วงเวลาทับซ้อนของคนเดียวกัน (ใบที่ยังไม่ปิด) | BR-29 · D-01 |
| M-5 | สร้าง `T_ot_usage_registry` + ลงทะเบียนตัวเองที่ 3 ต้นทาง (`hr-config/usage` · `attendance/usage` · `leave/usage`) | BR-25 · C-6 · AT-7 · LV-7 |
| M-6 | **ไม่มี seed ของค่านโยบายใด ๆ** | ค่าทั้งหมดอ่านจาก HR Configuration (LOCK-CFG) |

> **ไม่มี rollback ที่ลบข้อมูล** — ถ้าต้องถอย ให้ปิดการเข้าถึงแล้วเก็บตารางไว้

| `config_version_ids` | รหัสเวอร์ชันที่ใช้ตัดสิน | jsonb | Internal | ทุกต้นทาง |
| `approval_chain` | สายอนุมัติ (สำเนา) | jsonb | Internal (PII) | DOA |

**ไม่มี field_key ใดที่เป็นจำนวนเงิน** — ตรวจอัตโนมัติ `IA-07`

## §4.6 Data Classification & Sensitive Data ⭐

### §4.6.1 ระดับที่ feature นี้แตะ
**สูงสุด = Confidential** · **ไม่มี Restricted** (ไม่มีข้อมูลค่าจ้าง/เงิน) → **ไม่ต้อง wire Restricted Resources**

### §4.6.2 คอลัมน์ Confidential ทั้งหมด (ต้องมี masking rule ครบ)
`reason` · `work_done` · `partial_reason` · `variance_reason` · `needs_review_note` · `reject_reason` · `cancel_reason` · `withdraw_reason` · `line_note` · `employee_snapshot` · `hours_requested(_total)` · `hours_approved(_total)` · `hours_confirmed(_total)` · `attendance_outside_hours` · `variance_hours` · `leave_conflict_ref` · `attachment.file_name` · `history.before/after` · `approval_trace.decision_reason` · `period_summary.by_rate_type` + ยอดชั่วโมงทั้งหมด

### §4.6.3 กติกา masking
| ผู้ดู | เห็นอะไร |
|---|---|
| เจ้าของใบ | ทุกช่องของใบตัวเอง |
| หัวหน้าโดยตรง | ทุกช่องของลูกทีมในสายบังคับบัญชา |
| ฝ่ายบุคคล | ทุกช่องในบริษัท (ตาม Policy Center) |
| ผู้บริหารต้นสังกัด | **เฉพาะใบที่ตัวเองเป็น slot** + ข้อมูลที่จำเป็นต่อการตัดสิน |
| ระบบปลายทาง (Payroll/ESS/Roster) | **ไม่เห็น `reason` · `work_done` · ชื่อไฟล์แนบ เลย** (§0.13.1) |
| ชั้นรายงาน 7C | **ไม่เห็น `reason` · `work_done`** — payload ส่งเฉพาะ id + ปริมาณ (`CSQ_BRIEF §4`) |

### §4.6.4 PII ที่ต้องระวังเป็นพิเศษ
`employee_snapshot.full_name` · `assignee_snapshot` · `actor_snapshot` — **ส่ง `employee_id` เป็น ref เสมอ · ชื่อใช้เฉพาะใน template ที่แสดงต่อผู้มีสิทธิ์เห็น** (`NTF_BRIEF §4` · `CSQ_BRIEF §4`)

### §4.6.5 การเข้ารหัส
`reason` · `work_done` · เนื้อไฟล์แนบ — เข้ารหัสทั้งตอนส่งกับตอนเก็บ (S06-05)

### §4.6.6 การส่งออก
การส่งออกสรุปงวดผ่าน **ชั้น masking เดียวกับหน้าจอ + บันทึกร่องรอยว่าใครส่งออก** (S02-06 · D-08)

## §4.8 Performance Considerations

| จุด | ความเสี่ยง | ทางแก้ |
|---|---|---|
| **การรวมชั่วโมงสะสมรายสัปดาห์** (เรียกทุกครั้งที่กรอกบรรทัด) | เต็มตาราง scan | **`ix_ot_emp_week`** + คอลัมน์คำนวณ `week_start_date` |
| **การตรวจการทับซ้อนข้ามใบ** | O(n) ต่อบรรทัด | `ix_line_emp_date` + `EXCLUDE` constraint |
| การอ่านค่าจากต้นทาง 3 ระบบต่อบรรทัด | latency สะสม | **อ่านเป็นชุด (batch) เมื่อกรอกหลายบรรทัด** + cache ภายในวันเดียว (BR-04) |
| read model `scope=company` | ผลลัพธ์ใหญ่ | บังคับแบ่งหน้า (`page_size` ≤ 500) |
| การกระจุกตัวปลายงวด | โหลดพุ่ง | สรุปงวดเป็น materialized + ตรึงเมื่อปิดงวด |
