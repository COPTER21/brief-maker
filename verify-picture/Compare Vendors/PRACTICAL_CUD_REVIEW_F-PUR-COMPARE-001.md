# Practical CUD Review — Compare Vendors

เป้าหมาย: ทดลองใช้งานเหมือนเจ้าหน้าที่จัดซื้อจริง โดยตรวจ Create → Update → Delete → Finalize ไม่เน้น layout

> ใช้ข้อมูลทดสอบ/UAT สำหรับการลบและยกเลิก หากต้องทำบน Production ให้ใช้รายการที่ทีมอนุญาตและวางแผน cleanup ก่อน

## ข้อมูลทดสอบ

- PR-A: อนุมัติแล้ว ยังไม่เคยเปิดรอบ มีอย่างน้อย 3 รายการ
- Vendor A: เสนอครบทุกรายการ ราคาต่ำสุด
- Vendor B: เสนอครบทุกรายการ ราคาแพงกว่า A
- Vendor C: ไม่เสนออย่างน้อย 1 รายการ
- จดเลข PR, round, ผู้ขาย, ยอดก่อนและหลังทุกครั้ง

## Flow 1 — Create รอบและใบเสนอราคา

1. เข้าหน้า Compare Vendors แล้วค้นหา PR-A ในคิว
2. กด PR-A และกด `เปิดรอบเทียบราคา`
3. ยืนยันการเปิดรอบ
4. ตรวจว่าสถานะเป็น `เปิดรอบ` และประวัติมีเหตุการณ์เปิดรอบพร้อมผู้ทำ/เวลา
5. กด `เพิ่มใบเสนอราคา`
6. เลือก Vendor A ใส่เลขที่ใบเสนอราคา วันที่ วันหมดอายุ เงื่อนไขชำระ ระยะส่งมอบ และการรับประกัน
7. ใส่ราคาครบทุกรายการ โดยทดลอง VAT อย่างน้อยหนึ่งโหมดและส่วนลดหนึ่งรายการ
8. แนบไฟล์จริง แล้วกดบันทึก
9. ตรวจว่าการ์ด Vendor A แสดงขึ้น สถานะรอบเป็น `กำลังเทียบ` ยอดรวมตรงกับการคำนวณมือ และมีประวัติ `บันทึกใบเสนอราคา`
10. เพิ่ม Vendor B และ Vendor C โดยตั้ง Vendor C เป็น `ไม่เสนอ` หนึ่งรายการ

ผลที่ต้องได้:

- ผู้ขายเดิมเลือกซ้ำในรอบเดียวกันไม่ได้
- จำนวนรายการมาจาก PR และผู้ใช้เปลี่ยนจำนวนไม่ได้
- รายการ `ไม่เสนอ` มียอด 0 ไม่เป็นราคาต่ำสุด และทำให้ Vendor C เลือกแบบทั้งใบไม่ได้
- ตารางเทียบแสดงผู้ขายครบและไฮไลต์ราคาต่ำสุดถูกต้อง

## Flow 2 — Update ใบเสนอราคา

1. เปิด Vendor B แล้วกด `แก้ไข`
2. จดค่าก่อนแก้: ราคา ส่วนลด VAT ยอดรวม และเงื่อนไขการค้า
3. เปลี่ยนราคา 1 รายการให้ต่ำกว่า Vendor A
4. เปลี่ยนส่วนลดและเงื่อนไขชำระ แล้วบันทึก
5. เปิดแท็บ `ตารางเทียบ`
6. ตรวจว่าไฮไลต์ราคาต่ำสุด ยอดสุทธิ ส่วนต่าง และข้อมูลสรุปเปลี่ยนตามทันที
7. เปิดประวัติ ตรวจว่ามีเหตุการณ์แก้ไข ผู้ทำ เวลา และข้อมูลก่อน/หลัง
8. refresh หน้า แล้วเปิดรอบเดิมซ้ำ เพื่อตรวจว่าค่าที่แก้ยังอยู่จริง

ผลที่ต้องได้:

- เปลี่ยนเฉพาะ quote ที่เลือก ไม่กระทบผู้ขายรายอื่น
- ยอดถูกคำนวณใหม่ ไม่ใช้ยอดเก่าหรือยอดที่ browser ส่งมา
- ไม่มี quote ซ้ำจากการกดบันทึกซ้ำ/double-click
- ถ้ามีอีก session แก้ record เดียวกัน คนที่บันทึกทีหลังต้องถูกแจ้งว่าข้อมูลเปลี่ยน ไม่ทับค่าของคนแรก

## Flow 3 — Delete ใบเสนอราคา

1. เลือก Vendor C แล้วกด `ลบ`
2. ตรวจว่ามีกล่องยืนยันและอธิบายว่าการลบย้อนกลับไม่ได้/จะบันทึกประวัติ
3. กดยกเลิกก่อนหนึ่งครั้ง ตรวจว่าข้อมูลยังอยู่
4. กดลบใหม่และยืนยัน
5. ตรวจว่าการ์ด Vendor C หาย ตารางเทียบหายเฉพาะคอลัมน์ Vendor C และยอด/ค่าต่ำสุดคำนวณใหม่
6. ตรวจประวัติว่ามีเหตุการณ์ลบ ผู้ทำ และเวลา
7. ลบ Vendor B แล้วลบ Vendor A ซึ่งเป็นรายสุดท้าย

ผลที่ต้องได้:

- ลบผิดรายไม่ได้ และผู้ขายรายอื่นไม่เปลี่ยน
- เมื่อลบรายสุดท้าย สถานะรอบกลับเป็น `เปิดรอบ`
- ประวัติการเพิ่ม/แก้/ลบยังอยู่ ห้ามหายตาม quote

## Flow 4 — สร้างใหม่และ Finalize

1. เพิ่ม Vendor A และ B กลับเข้ารอบ
2. ไปแท็บ `ผลการเลือก`
3. เลือก Vendor A ซึ่งต่ำสุดทั้งใบ โดยไม่ใส่เหตุผล
4. ตรวจว่าปุ่ม `ยืนยันผลการเลือก` กดได้
5. เปลี่ยนเป็น Vendor B ซึ่งไม่ต่ำสุด
6. ไม่กรอกเหตุผล แล้วลองยืนยัน; จากนั้นกรอก 1–2 ตัวอักษร และสุดท้ายกรอกอย่างน้อย 3 ตัวอักษร
7. ยืนยัน Vendor B เมื่อเหตุผลครบ
8. ตรวจว่าสถานะเป็น `ตัดสินแล้ว` และยอด/ผู้ขายในผลสรุปตรงกับที่เลือก
9. กลับไปแท็บใบเสนอราคาและลองหา `แก้ไข`/`ลบ`
10. refresh แล้วเปิดรอบเดิมอีกครั้ง

ผลที่ต้องได้:

- Vendor B ยืนยันไม่ได้จนกว่าเหตุผลจะครบอย่างน้อย 3 ตัวอักษร
- หลังยืนยัน ไม่มีปุ่มแก้/ลบ และรอบเดิมยังถูกล็อกหลัง refresh
- ห้ามแก้ข้อมูลย้อนหลัง แม้เรียกผ่าน URL/API เดิม
- ประวัติมีผลการตัดสิน ผู้ทำ เวลา เหตุผล และไม่มีรายการซ้ำ

## Flow 5 — Delete ในระดับรอบ

ระบบนี้ไม่มี hard delete รอบ ใช้ `ยกเลิกรอบ` แทน:

1. เปิด PR ทดสอบรายการใหม่และสร้างรอบ
2. กด `ยกเลิกรอบ`
3. ทดสอบเหตุผลว่าง, 1–2 ตัวอักษร และอย่างน้อย 3 ตัวอักษร
4. ยืนยันยกเลิกเมื่อเหตุผลครบ
5. ตรวจว่าสถานะเป็น `ยกเลิก`, PR กลับเข้าคิว และประวัติรอบยังอ่านได้

ผลที่ต้องได้:

- เหตุผลน้อยกว่า 3 ตัวอักษรถูกบล็อก
- ไม่มีการลบรอบหรือประวัติจริง
- รอบที่ยกเลิกต้องไม่ถูกนำไปออก PO

## หลักฐานขั้นต่ำที่ต้องเก็บ

สำหรับแต่ละ flow ให้เก็บภาพก่อนทำ/หลังทำ พร้อม:

- PR number และ round number
- Vendor และค่าที่เพิ่ม/แก้/ลบ
- ยอดที่คำนวณมือเทียบกับยอดระบบ
- สถานะก่อน/หลัง
- แถวประวัติที่เกิดขึ้น
- ชื่อผู้ใช้/บทบาทและเวลาทดสอบ
- กรณี fail: ขั้นตอนทำซ้ำ Expected/Actual และวิดีโอหรือ request/response ถ้ามี

## เกณฑ์แจ้ง Bug ทันที

- แก้หรือลบได้หลัง `ตัดสินแล้ว`
- เลือกผู้ขายที่ไม่ต่ำสุดได้โดยไม่มีเหตุผล
- ลบ quote แล้วข้อมูลผู้ขายอื่นหายหรือยอดผิด
- server รับยอดรวมที่ไม่ตรงกับรายละเอียดรายการ
- ประวัติหาย ถูกแก้ได้ หรือบอกผู้ทำผิด
- ผู้ใช้ read-only เพิ่ม แก้ ลบ หรือยืนยันผลได้
