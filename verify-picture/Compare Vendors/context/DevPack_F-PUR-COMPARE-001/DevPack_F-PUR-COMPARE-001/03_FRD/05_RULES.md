# 05 · RULES — F-PUR-COMPARE-001

## §1 Business Rules (BR-01..10)

| BR | กติกา | ระดับ | ที่บังคับ | สถานะใน HTML |
| --- | --- | --- | --- | --- |
| **BR-01** | เข้าคิวเทียบราคาได้เฉพาะใบขอซื้อที่**อนุมัติแล้ว** | ตายตัว | `GET /queue` + `POST /rounds` | ✅ `queueRows()` L616 |
| **BR-02** | หนึ่งผู้ขายบันทึกใบเสนอราคาได้ครั้งเดียวต่อรอบ | ตายตัว | `UNIQUE (round_id, vendor_id)` | ✅ ตัวเลือกผู้ขายตัดรายที่มีแล้วออก |
| **BR-03** | รายการที่ผู้ขาย "ไม่เสนอ" **ไม่ถูกนำไปคิดราคาต่ำสุด** และเลือกเป็นผู้ชนะรายการนั้นไม่ได้ | ตายตัว | `lineTotal()` · `unitOf()` · `awardCalc()` | ✅ ยืนยันแล้ว — ใบ ฿4,922 (ไม่ครบ) ไม่ถูกใช้เป็นฐานต่ำสุด |
| **BR-04** ★ | **เลือกผู้ชนะที่ไม่ใช่ราคาต่ำสุด หรือมีผู้เสนอรายเดียว → ต้องมีเหตุผล (≥3 ตัวอักษร)** | ตายตัว · **จุดควบคุมหลัก** | `awardCalc().needReason` + server ตรวจซ้ำ | ✅ ทดสอบ 5 สถานะ — `03_LOGIC §4` |
| **BR-05** | ยืนยันผลแล้วรอบล็อกถาวร · เปลี่ยนใจ = เปิดรอบใหม่ที่อ้างรอบเดิม | ตายตัว | `E-CMP-409-LOCKED` · LD-06 | ✅ ปุ่มแก้/ลบหายหลังตัดสิน |
| **BR-06** | ประวัติเพิ่มอย่างเดียว ไม่มีลบถาวร | ตายตัว | `REVOKE UPDATE,DELETE` + trigger | ✅ หัวข้อบนจอระบุไว้ |
| **BR-07** | ฟีเจอร์นี้ **ไม่มีการอนุมัติ ไม่มีเลขที่เอกสาร ไม่มีแบบพิมพ์** | ตายตัว (archetype guard) | LD-01 · LD-02 · LD-03 | ✅ ตรวจแล้วไม่พบทั้งสาม |
| **BR-08** | จำนวนผู้ขายขั้นต่ำตามช่วงยอด | **ยืดหยุ่น** — คำแนะนำบนจอ ยังไม่บังคับ | — | ⚠️ OQ-02 ยังเปิด |
| **BR-09** | เกณฑ์เทียบ 4 แกน (ราคา · เงื่อนไขชำระ · ระยะส่งมอบ · การรับประกัน) | **ยืดหยุ่น** — เพิ่มแกนได้โดยไม่กระทบโครงตาราง | `GET /matrix.summary` | ✅ + แถวที่ 6 "อายุใบเสนอราคา" |
| **BR-10** | ใบเสนอราคาหมดอายุ = **เตือน ไม่บล็อก**การยืนยัน | **ยืดหยุ่น** | `isExpired()` L611 | ✅ OQ-03 ยังเปิด |

> **ไม่มีตัวเลขนโยบายฝังในโค้ด** — จำนวนผู้ขายขั้นต่ำและช่วงยอดเป็นข้อความแนะนำ ไม่ใช่กติกาบังคับ

## §2 Validation Rules (V-01..07)

| V | กติกา | ผลบนจอ | error code |
| --- | --- | --- | --- |
| **V-01** | ต้องเลือกผู้ขาย | ปุ่มบันทึกถูกปิด | — |
| **V-02** | ต้องมีอย่างน้อย 1 รายการที่เสนอราคา > 0 | "ต้องมีอย่างน้อย 1 รายการที่ผู้ขายเสนอราคามากกว่า 0" | `E-CMP-422-NO-PRICE` |
| **V-03** | โหมดแยกรายรายการ: เลือกผู้ชนะไม่ครบ → ยืนยันไม่ได้ | ปุ่มยืนยันถูกปิด (`ok=false`) | `E-CMP-422-INCOMPLETE` |
| **V-04** | เหตุผล ≥ 3 ตัวอักษรเมื่อเข้าเงื่อนไข BR-04 | ปุ่มยืนยันปิด + กล่องเตือนบอกส่วนต่างเป็นตัวเงิน | `E-CMP-422-REASON` |
| **V-05** | เหตุผลการยกเลิกรอบ ≥ 3 ตัวอักษร | ปุ่มยืนยันถูกปิด | `E-CMP-422-REASON` |
| **V-06** | `valid_until` ก่อนวันนี้ → ทำเครื่องหมายหมดอายุทั้งการ์ดและในตารางเทียบ | "วันที่นี้ผ่านมาแล้ว — ใบเสนอราคาจะถูกทำเครื่องหมายว่าหมดอายุ" | — (เตือนอย่างเดียว · BR-10) |
| **V-07** | ส่วนลดรายบรรทัด 0–100% | จำกัดที่ช่องกรอก | — |

## §3 จุดควบคุม (C-01..09)

| C | จุดควบคุม | ใครบังคับ | หลักฐาน |
| --- | --- | --- | --- |
| **C-01** | เข้าคิวได้เฉพาะใบที่อนุมัติแล้ว | server (`GET /queue`) | BR-01 |
| **C-02** | ต้องมี ≥1 รายการที่เสนอราคา > 0 · ผู้ขายซ้ำในรอบไม่ได้ | server | V-02 · BR-02 |
| **C-03** | เกณฑ์เทียบเดียวกันทุกครั้ง ไม่ขึ้นกับผู้ทำ | server คำนวณ `is_best_*` เอง | `03_LOGIC §3` |
| **C-04** | เลือกได้เฉพาะผู้ที่เสนอรายการนั้นจริง | `awardCalc()` → `ok=false` | BR-03 |
| **C-05** ★ | **ไม่ใช่ต่ำสุด / รายเดียว → บังคับเหตุผล** | client ปิดปุ่ม + **server ตรวจซ้ำ** | BR-04 · LD-05 |
| **C-06** | ยืนยันแล้วล็อกแก้ไม่ได้ | `E-CMP-409-LOCKED` | BR-05 · LD-06 |
| **C-07** | ประวัติเพิ่มอย่างเดียว | DB trigger | BR-06 · LD-07 |
| **C-08** | ข้อมูลส่งต่อใบสั่งซื้อมาจากผลที่ล็อกแล้วเท่านั้น | `GET /po-handoff` อ่านจาก `cmp_award_line` | LD-09 |
| **C-09** ★ ใหม่ | **ผู้ขอซื้อ / ผู้ตรวจสอบ = อ่านอย่างเดียว** — ปุ่มบันทึก/ยืนยัน/ยกเลิกไม่แสดง และ server ปฏิเสธ | server (`E-CMP-403-ROLE`) + client ซ่อนปุ่ม | **ยังไม่ได้ทำ** — TD-01 |

## §4 Edge cases (EC-01..09)

| EC | เคส | พฤติกรรมที่ถูก | สถานะ |
| --- | --- | --- | --- |
| **EC-01** | ผู้ขายไม่เสนอบางรายการ | เซลล์ขึ้น "ไม่เสนอ" · ไม่นับเป็นต่ำสุด · เลือกรายการนั้นไม่ได้ · ใบไม่ `complete` | ✅ |
| **EC-02** | มีผู้เสนอรายเดียว | `single=true` → `needReason=true` แม้ราคานั้นจะต่ำสุดก็ตาม | ✅ |
| **EC-03** | ยอดสุทธิเท่ากันสองราย | ไฮไลต์ทั้งคู่เป็นค่าดีที่สุด (epsilon 0.005) · ผู้ใช้ตัดสินและใส่เหตุผล | ✅ (ตรรกะ · ไม่มี seed) |
| **EC-04** | ใบเสนอราคาหมดอายุ | การ์ดขอบส้ม + pill "หมดอายุแล้ว" + แถว "อายุใบเสนอราคา" แดง · **ยืนยันได้** (BR-10) | ✅ |
| **EC-05** | รายการนอกทะเบียนสินค้า | ยึดชื่อรายการจากใบขอซื้อ · เทียบได้ปกติ | ✅ |
| **EC-06** | ลบใบเสนอราคารายสุดท้าย | รอบกลับเป็น `open` · ประวัติ +1 | ✅ |
| **EC-07** | เปิดรอบใหม่หลังตัดสินแล้ว | `round_seq+1` · `prev_round_id` · คัดลอกใบเดิม · รอบเดิมยังอ่านได้ | ✅ |
| **EC-08** | สองคนแก้รอบเดียวกันพร้อมกัน | คนแรกชนะ · คนที่สองได้ "มีคนแก้ข้อมูลนี้ไปแล้ว กรุณาโหลดใหม่" | **ยังไม่ได้ทำ** — TD-03 (L-3) |
| **EC-09** | ใบขอซื้อถูกยกเลิกหลังเปิดรอบ (SC-15) | แถบเตือนหัวคอนโซล · ยืนยันผลไม่ได้ (`E-CMP-409-PR-CANCELLED`) · แนะให้ยกเลิกรอบ | **ยังไม่ได้ทำ** — TD-02 |

## §5 กติกาที่ **ไม่มี** ในฟีเจอร์นี้
| ไม่มี | เหตุผล |
| --- | --- |
| กติกาสายอนุมัติ / วงเงิน | ไม่มีการอนุมัติ (BR-07 · LD-02) — วงเงินควบคุมที่ใบสั่งซื้อ |
| กติกาเลขรัน / snapshot policy | `round_id` ไม่ใช่เลขที่เอกสาร (LD-03) |
| กติกาการแจ้งเตือน | ไม่ประกาศ event แจ้งเตือน |
| กติกาสกุลเงิน | THB อย่างเดียว (OQ-06) |
