## 1. Business Context
### 1.1 ปัญหา / โอกาส
- ปัจจุบันพนักงานขายเขต General Trade ใช้แบบฟอร์ม Excel FM-SAL-09 วางแผนเยี่ยมร้านรายวันต่อรอบการขาย: ส่วนหัว (TO · CC · ผู้รับผิดชอบเขต · ตำแหน่ง · เขต · รอบการขาย) · ตาราง 31 แถว (วันทำงาน · วันที่ · เริ่มต้นตลาด = สิ้นสุดตลาด · จำนวนลูกค้า · รายชื่อร้านค้า 7 ช่อง · ที่พัก (จังหวัด)) · ลงนาม ผู้นำเสนอ + ผู้อนุมัติ 2 ช่อง
- ปัญหา: จำนวนลูกค้ากรอกเองไม่ตรงกับรายชื่อร้าน · ชื่อร้านพิมพ์ไม่ตรง Customer master · ไม่รู้ว่าแผนฉบับไหนคือฉบับที่อนุมัติล่าสุดของเขต/รอบ · ส่งต่อ TO/CC ด้วยมือ
- ขึ้นระบบเพื่อ: เลือกเขตและร้านจาก master · นับจำนวนลูกค้าอัตโนมัติ · ตรวจวันที่ในรอบการขาย · อนุมัติตามสาย DOA · แจ้ง TO/CC อัตโนมัติ · ใบใหม่แทนใบเดิมของเขต/รอบเดียวกัน · พิมพ์แบบฟอร์มหน้าตาเดิมได้

### 1.2 เป้าหมาย
1. ทุกเขต General Trade มีแผนเยี่ยมที่อนุมัติแล้ว 1 ใบต่อรอบการขาย
2. จำนวนลูกค้าในแผนตรงกับรายชื่อร้านจริง (นับจากระบบ)
3. พิมพ์ PDF ตามแบบ FM-SAL-09 ได้ทุกสถานะ

### 1.3 ตัวชี้วัด
- ไม่มีใน input → OQ-03 (ห้ามแต่งตัวเลข)

### 1.4 ที่มา
- ไฟล์ลูกค้า `ใบเป้าหมายการเยี่ยมร้านค้า.xlsx` (sha256 42f961948bb2ba3f · sheet "FM-SAL-09") · ไม่มี PREBRIEF จาก CMS → PREBRIEF v2 สร้างจาก FORM_SPEC

## 2. Scope
### 2.1 In Scope
- หน้ารายการ · สร้าง/แก้ร่าง (wizard 3 ขั้น) · ดู (รายละเอียด › PDF Preview › ลายเซ็น / อนุมัติ › ประวัติ) · ส่งอนุมัติ · อนุมัติ/ไม่อนุมัติ · ยกเลิก · ส่งออก CSV · แนบไฟล์
- แบบพิมพ์ Replica FM-SAL-09 (thai-doc v2.1) · เลขที่ SVT จาก F-DOCCFG / ENG-DOC-NUM
- สายอนุมัติจาก DOA กลาง (dynamic · ค่าเริ่ม 2 ขั้น) · แจ้งเตือน svt_cancelled / svt_plan_published / svt_superseded (ENG-NOTIFY)

### 2.2 Out of Scope
- แก้ Customer / Sales Territory master — อ่านอย่างเดียว (DEC-01)
- สร้าง Visit (Visit Operation) / บันทึกผลการเยี่ยมจริง — รอบนี้ไม่ส่งต่อ (DEC-02) · ประกาศ event ไว้
- ทำซ้ำ · ประกาศ (DEC-11) · เป้ายอดขายรายร้าน (ไม่มีบนกระดาษ)

### 2.3 Assumptions
- Sales Territory มี code · name · ผู้รับผิดชอบ (owner_employee_id) · Customer มี customerId · name · territory
- Employee มีตำแหน่ง + ผู้บังคับบัญชาตรง (ใช้ resolve role-line-manager)

## 4. User Journey
### 4.1 Happy Path
1. ผู้นำเสนอเปิด "ใบเป้าหมายการเยี่ยมร้านค้า" → สร้าง → เลือกเขต (ระบบเติมผู้รับผิดชอบเขต/ตำแหน่ง · TO ค่าเริ่ม) → เลือกรอบการขาย → เพิ่ม CC (ถ้ามี)
2. เพิ่มวันทำงานทีละวัน: วันที่ (จำกัดในรอบ) · เริ่มต้นตลาด = สิ้นสุดตลาด · เลือกร้านจาก Customer ในเขต (จำนวนลูกค้านับสด) · ที่พัก (จังหวัด)
3. แนบไฟล์ → ตรวจสอบ → บันทึกและส่งอนุมัติ (เลือกผู้อนุมัติต่อขั้น ค่าเริ่มจาก DOA) → ระบบออกเลข SVT · สถานะ "รออนุมัติ"
4. ผู้อนุมัติขั้น 1 → อนุมัติ → ขั้น 2 → อนุมัติ → "อนุมัติแล้ว" · ใบเดิมของเขต+รอบเดียวกัน → "ถูกแทนที่" · แจ้ง TO/CC (svt_plan_published)

### 4.2 Alternative
- A1 ไม่อนุมัติ (เหตุผล) ขั้นใดก็ได้ → กลับเป็นร่างเลขเดิม → แก้ → ส่งใหม่
- A2 บันทึกร่างไว้ก่อน (ต้องมีเขต + รอบ) → กลับมาแก้ → ส่ง
- A3 ยกเลิก (เหตุผลบังคับ) โดยเจ้าของหรือผู้จัดการฝ่ายขายที่ร่าง/รออนุมัติ
- A4 ร้านเกิน 7 ร้านในวันเดียว → เตือน ส่งได้ (แบบพิมพ์ต่อชื่อในช่องสุดท้าย)

## 7. Status & Lifecycle
`draft (ร่าง)` → ส่ง → `pending (รออนุมัติ)` → อนุมัติครบทุกขั้น → `approved (อนุมัติแล้ว)`
- ไม่อนุมัติ → `draft` เลขเดิม (DEC-08) · `draft|pending` → ยกเลิก → `cancelled`
- ใบใหม่ของเขต+รอบเดียวกันอนุมัติ → ใบเดิม `approved` → `superseded (ถูกแทนที่)`
- ส่งแล้วแก้ไม่ได้ (ล็อก) · เลขออกตอนบันทึกครั้งแรก (DEC-10)
