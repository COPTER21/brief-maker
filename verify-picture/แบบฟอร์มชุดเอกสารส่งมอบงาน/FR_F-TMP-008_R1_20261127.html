#กฎ / Scenarioผลที่คาดหวังผลจริงผลอ้างอิง

L-02ส่งอนุมัติส่งสำเร็จเมื่อข้อมูลและผู้พิจารณาครบ ใบเข้าสู่รออนุมัติขั้นแรกผู้ตรวจพบ API ตอบ code INTERNAL เมื่อกดส่งอนุมัติ จุดที่ request ล้มยังต้องยืนยันไม่ผ่านBUG-01
L-03ตรวจข้อมูลตอนกดถัดไปตรวจข้อมูลที่ต้องใช้เพื่อไปต่อและแสดงตำแหน่งที่ต้องแก้ผู้ตรวจระบุให้เช็ก validation ทุกขั้น ต้องเก็บตัวอย่างช่องที่หลุดมีข้อสังเกตBUG-02
L-04ตรวจข้อมูลก่อนบันทึกแบบร่างตรวจข้อบังคับของการบันทึกร่างจากข้อมูลทุกขั้นก่อนบันทึกรอยืนยันด้วยข้อมูลที่ผิดทีละเงื่อนไขมีข้อสังเกตBUG-02
L-05ตรวจข้อมูลก่อนบันทึกและส่งอนุมัติตรวจข้อบังคับของการส่งครบทุกขั้น รวมผู้พิจารณา ณ ตอนส่งรอยืนยันด้วยข้อมูลที่ผิดทีละเงื่อนไขมีข้อสังเกตBUG-02
L-06แก้ไขและบันทึกร่างเดิมเจ้าของแก้ร่างได้ เลขเดิม—ไม่ได้ตรวจAPI-04
L-07ยกเลิกเอกสารเจ้าของหรือ admin ยกเลิกร่าง/ใบรอได้เมื่อให้เหตุผล—ไม่ได้ตรวจAC-12
L-08อ่านข้อมูลในแท็บรายละเอียดข้อมูลรับมอบและรายการตรวจรับตรงกับใบที่บันทึก—ไม่ได้ตรวจ01_UI P-03
L-09ดูและดาวน์โหลด PDFPDF แบบ FM-IVM-06 สองหน้า ข้อมูลตรงกับใบ—ไม่ได้ตรวจAC-11/14
L-10ลายเซ็นและสายอนุมัติแสดงขั้นปัจจุบันและการตัดสินตามบทบาท—ไม่ได้ตรวจAC-08/09

4Bug ที่พบ

เรียงจากรุนแรงมากไปน้อย · ทำซ้ำได้ตามขั้นตอน

BUG-01บันทึกร่างหรือส่งอนุมัติแล้ว API ตอบ INTERNALCriticalรอแก้
ขั้นตอนทำซ้ำ
  1. เปิดสร้างแบบฟอร์มชุดเอกสารส่งมอบงาน
  2. ทดลองกดบันทึกร่าง และทดลองทางส่งอนุมัติแยกกัน
  3. ดูผลของแต่ละคำสั่ง
ผลที่ควรเป็นข้อมูลถูกต้องแล้วบันทึกร่างได้ หรือส่งเข้าขั้นพิจารณาได้ตามปุ่มที่ใช้
ผลที่เกิดจริงพบ API response {"code":"INTERNAL","message":"เกิดข้อผิดพลาดภายในระบบ"} และผู้ตรวจสร้างรายการเพื่อทดสอบต่อไม่ได้
BUG-02ตรวจซ้ำการตรวจข้อมูลใน Create/Edit Drawer ทั้งสามปุ่มMediumรอแก้
ขั้นตอนทำซ้ำ
  1. ในรอบตรวจซ้ำ เว้นช่องบังคับหรือทำให้ข้อมูลผิดทีละเงื่อนไข
  2. ลองกดถัดไป บันทึกแบบร่าง และบันทึกและส่งอนุมัติแยกกัน
ผลที่ควรเป็นถัดไปตรวจขั้นที่กำลังทำ ก่อนบันทึกหรือส่งตรวจข้อมูลจากทุกขั้นตามกฎของคำสั่ง และชี้ช่องให้แก้
ผลที่เกิดจริงผู้ตรวจแจ้งประเด็น validation ทุกขั้น ยังไม่มีรายละเอียดช่อง ค่า และปุ่มที่ปล่อยให้ผ่าน
BUG-03Create/Edit Drawer ต่างจากดีไซน์และ layout บางส่วนไม่เรียบร้อยLowรอแก้
ขั้นตอนทำซ้ำ
  1. เปิด Create Drawer
  2. ตรวจ Edit Drawer แยกด้วยใบตัวอย่างที่แก้ได้ในรอบถัดไป
  3. เทียบการจัดกลุ่มช่อง ตาราง สรุป และปุ่มในแต่ละขั้นกับแบบอ้างอิงของ F-TMP-008
ผลที่ควรเป็นการจัดวางและการเดินฟอร์มตรงแบบของ F-TMP-008
ผลที่เกิดจริงผู้ตรวจแจ้งว่าทั้ง Create/Edit Drawer หลุดดีไซน์และ layout บางส่วนไม่เรียบร้อย ยังไม่ได้ระบุจุดด้วยภาพหน้าจอ

5ข้อเสนอแนะ (ไม่ใช่ Bug)

ทำงานถูกตาม spec แล้ว แต่ควรปรับให้ดีขึ้น — ส่งต่อเป็น Enhancement ถ้าทีมเห็นด้วย

#ข้อเสนอเหตุผล

S-02เปิดใบตัวอย่างที่มีอยู่ในระบบเพื่อตรวจ View Drawerถ้ามีใบที่บัญชีผู้ตรวจเปิดได้ ให้ตรวจ 4 แท็บทันทีโดยใช้ภาพประกอบในหมวด UI และ FRD F-TMP-008 ตรวจข้อมูล
