## §1.2 Per-Page Detail

### P-01: รายชื่อโควตา (A)
**ERP:** Sidebar active เกษตรกรรม › Quota · Breadcrumb หน้าแรก / เกษตรกรรม / จัดการโควตา · `.ph` h1 "จัดการโควตา" + count + `.ph-actions`
**Filter bar:** Search (debounce 300ms — เลขโควตา/ชื่อ/นามสกุล/เบอร์/เลขบัตร/อีเมล) + dropdown สถานะ (ทั้งหมด/รออนุมัติ/อนุมัติ/ไม่อนุมัติ) + ล้างตัวกรอง
**Table ≤8 คอลัมน์:** ☑(เฉพาะ unverified) · เลขโควต้า (link) · ชื่อ · นามสกุล · เบอร์โทร · เลขบัตร (masked) · สถานะ (pill) · การดำเนินการ (pencil → trash-2 เฉพาะ unverified)
> ⚠ Legacy มี 9 คอลัมน์ (มี email) → รวมเป็น ≤8 โดยย้าย email ลง detail (Rule #40/#16) · linked member แสดงด้วย icon เล็กหลังเลขโควต้า
**Actions bar:** สร้างโควตา (primary ขวาสุด) · Import CSV (secondary) · ตรวจสอบที่เลือก (N) (secondary, disabled 0, R-02)
**Selection persistence (TC-307):** checkbox ที่เลือกคงอยู่ **ข้ามหน้า pagination** — `ตรวจสอบที่เลือก (N)` นับรวมทุกหน้า · ยืนยัน bulk ส่ง quota_id ที่เลือกครบทุกหน้า
**Status pill:** unverified→รออนุมัติ (`.pill-warning`) · verified→อนุมัติ (`.pill-success`) · rejected→ไม่อนุมัติ (`.pill-danger`)
**States:** Loading (**skeleton loader เมื่อ load > 200ms** — NFR) · Empty ("ยังไม่มีโควตา" + CTA) · Filter-empty · Loaded

### P-02: รายละเอียดโควตา (C — view drawer tabbed 920px)
**Header:** eyebrow "โควตาชาวไร่ · [เลขโควต้า]" + ชื่อ + status pill · header actions: แก้ไข (secondary, R-01) → ตรวจสอบ (primary, R-02+unverified) → ลบ (danger, R-01+unverified) → | → X
**Member card (ถ้า linked):** รหัสสมาชิก (link ไป Farmer) + ชื่อ + เบอร์ + อีเมล + ปุ่มเปิด Farmer detail
**Tab 1 "ข้อมูลทั่วไป":** ข้อมูลส่วนบุคคล (ชื่อ, เลขบัตรเต็ม*, เบอร์, อีเมล, วันเกิด, สถานะสมรส, จำนวนบุตร, ผู้รับผลประโยชน์, Line ID) · ที่อยู่ปัจจุบัน · ที่อยู่ตามบัตร · ธนาคาร (bank/เลขบัญชี/ธ.ก.ส. — mask ตาม permission)
**Tab 2 "ไฟล์ที่อัปโหลด":** สำเนาบัตรประชาชน + สำเนาทะเบียนบ้าน (ชื่อไฟล์ + ขนาด + mime) · คลิก thumbnail → **in-app preview modal (iframe/pdf viewer จาก signed URL)** · preview fail (CSP/format) → ปุ่ม **`btn-open-original`** เปิดไฟล์ใน tab ใหม่ (fallback — TC-313) · empty "ยังไม่มีไฟล์อัปโหลด"
**Tab 3 "ประวัติ":** timeline (created/updated/verify/reject/delete + write-back events) ใหม่→เก่า
**Footer:** `ปิด` (secondary)

### OV-01: สร้างโควตา (B — create drawer v2 920px)
**Sub-flow ด้านบน — ค้นหาสมาชิก (form section 0):**
- search-select (Rule #34): ค้นหาสมาชิก ชื่อ/นามสกุล/เบอร์/เลขบัตร/**อีเมล** — **แสดงเฉพาะสมาชิก Approved** (R08 — CUBE ADD) · **0 match → ข้อความมาตรฐานสีแดง "ไม่พบข้อมูลสมาชิกที่ตรงกับคำค้นหา"** (FN-AT-AGQ-115 / TC-287; email + เลขบัตร ค้นได้) · timeout/DEPENDENCY → ปุ่ม Retry (ไม่ prefill / Save ยัง disabled — TC-322)
- เลือกแล้ว → ตรวจ 1:0..1 (API-13): ถ้ามีโควตาแล้ว → banner แดง "สมาชิกนี้มีโควต้าอยู่แล้ว" (block บันทึก) · ถ้าผ่าน → prefill + member summary card (FM-NNNNNN)
- **ข้ามได้ = No-Member mode** (banner info "สร้างแบบไม่ผูกสมาชิก")

**Form sections (Rule #45):**
1. ข้อมูลส่วนบุคคล: ชื่อ*, นามสกุล*, เลขบัตร* (13, strip), เบอร์* (9-12, strip), อีเมล (optional), เลขโควต้า* (unique — API-06 blur check)
2. ข้อมูลเพิ่มเติม: วันเกิด, สถานะสมรส, จำนวนบุตร, ผู้รับผลประโยชน์, Line ID
3. ที่อยู่ปัจจุบัน: ที่อยู่, จังหวัด*/อำเภอ*/ตำบล* (search-select cascade), ไปรษณีย์ (auto)
4. ที่อยู่ตามบัตร: ชุดเดียวกัน (cascade แยก)
5. ธนาคาร: ธนาคาร (dropdown), เลขบัญชี, เลขบัญชี ธ.ก.ส.
6. เอกสารแนบ: สำเนาบัตร + สำเนาทะเบียนบ้าน (PDF/JPG/PNG ≤5MB)

**Footer:** `ยกเลิก` (ghost) → `ยืนยันสร้าง` (primary) — ไม่มีบันทึกร่าง (ไม่มี draft state)
**Submit:** disabled + "กำลังบันทึก…" → API-02 (From-Member) หรือ API-03 (No-Member) → ปิด → toast "สร้างโควตาสำเร็จ — [เลขโควต้า]"

### OV-02: แก้ไขโควตา (B — edit drawer v2 920px)
- form sections เดียวกับ OV-01 (ไม่มี member search — link คงเดิม, แสดง member card read-only)
- เลขโควต้าแก้ได้ (unique check exclude self — API-06)
- Submit: API-05 + expected version (optimistic lock) → CONFLICT → toast "ข้อมูลถูกแก้ไขโดยผู้อื่น กรุณารีเฟรชและลองใหม่อีกครั้ง"

### OV-03: ตรวจสอบ (D — modal 440px)
- เดี่ยว: สรุป (เลขโควต้า, ชื่อ, รหัสสมาชิก ถ้ามี, สถานะ) · กลุ่ม: list รายชื่อที่เลือก
- ผลการตรวจสอบ*: radio อนุมัติ / ปฏิเสธ
- หมายเหตุ (optional — LOCK-09) — placeholder "ระบุหมายเหตุเพิ่มเติม..."
- **Warning (reject + linked):** กล่องส้ม "การปฏิเสธจะคืนค่าสถานะโควตาของสมาชิก [FM-NNNNNN] เป็น ไม่มีโควตา"
- **A11y (TC-316):** focus-trap (Tab วนใน modal · focus แรกไป radio ผล) · `aria-modal="true"` + `aria-labelledby`(title) · `aria-live` ประกาศ success/fail · danger-variant (reject) อ่านคำเตือนคืนสถานะออกเสียง
- Footer: `ยกเลิก` → `ยืนยัน` · เดี่ยว→API-07 · กลุ่ม→API-08

### OV-04: ยืนยันการลบ (D — modal 440px danger)
- Title `ลบโควตา?` · Body `ต้องการลบ "[เลขโควต้า] — [ชื่อ]" ใช่หรือไม่ การลบไม่สามารถย้อนกลับได้`
- **Warning (linked):** "การลบจะคืนค่าสถานะโควตาของสมาชิก [FM-NNNNNN] เป็น ไม่มีโควตา"
- Footer: `ยกเลิก` → `ลบ` (danger) → API-11
- แถวที่ไม่ใช่ unverified ไม่มีปุ่มลบ

### OV-05: นำเข้า CSV (Rule #32 — No-Member only)
- **ขั้น 1:** banner "นำเข้าเฉพาะโควตาแบบ No-Member" + ดาวน์โหลดแม่แบบ (API-10) + เลือกไฟล์ (.csv, ≤5MB) + คำแนะนำ (ทุกแถว unverified, quota_number ไม่ซ้ำ, citizen 13/phone 9-12)
- **ขั้น 2 (partial success):** summary total/created/failed + ตาราง error + ดาวน์โหลดรายงาน → toast

## §1.3 User Journey (Happy Path)

```
[From-Member] R-01 เข้า P-01 → "สร้างโควตา" (OV-01) → ค้นหาสมาชิก Approved → เลือก (1:0..1 ผ่าน) → prefill → กรอกเพิ่ม → ยืนยันสร้าง
  ↓ API-02 (FN-SEQ-AGQ-166) — gen quota + unverified + member.quota_status→has_quota
R-02 → filter "รออนุมัติ" → เลือก → ตรวจสอบ (OV-03) → อนุมัติ
  ↓ API-07 — verified
```
### Branch: No-Member
```
R-01 OV-01 → ข้ามค้นหาสมาชิก → กรอกเอง → ยืนยันสร้าง → API-03 (FN-SEQ-AGQ-167) — ไม่เขียน quota_status
```
### Branch: Reject → write-back
```
R-02 Reject (linked) → API-07 → rejected + member.quota_status→no_quota (cross-module)
```

## §1.6 Empty States & Errors
| State | UI |
|---|---|
| ไม่มีข้อมูล | "ยังไม่มีโควตา" + CTA สร้าง/Import |
| Filter ไม่เจอ | "ไม่พบรายการที่ค้นหา" + ล้างตัวกรอง |
| 409 CONFLICT | toast danger "ข้อมูลถูกแก้ไขโดยผู้อื่น กรุณารีเฟรชและลองใหม่อีกครั้ง" |
| สมาชิกมีโควตาแล้ว | banner แดง "สมาชิกนี้มีโควต้าอยู่แล้ว" |
| member ไม่ Approved | "ผูกได้เฉพาะสมาชิกที่อนุมัติแล้ว" |
| ค้นหาสมาชิก 0 match | ข้อความมาตรฐานสีแดง "ไม่พบข้อมูลสมาชิกที่ตรงกับคำค้นหา" (ไม่ prefill, Save disabled) — TC-287 |
| ค้นหาสมาชิก timeout/DEPENDENCY | banner/toast + ปุ่ม Retry (ไม่ prefill/Save) — TC-322 |
| member write-back scheduled_retry | non-blocking banner "กำลังอัปเดตสถานะสมาชิก (จะ retry อัตโนมัติ)" — G1/TC-323 |
