# 03_LOGIC — F-TMP-006 หนังสือสัญญายืม (LOA)

## 1. State machine
```
                 ┌──────────────── FN-08 ส่งกลับแก้ไข (เลขเดิม) ───────────────┐
                 v                                                            │
  [draft ร่าง] ──FN-05 ส่งให้ลงนาม──> [pending รอลงนาม] ──FN-07 ลงนามครบ──> [approved ลงนามแล้ว]
      │                                      │                                      │
      └──────────── FN-09 ยกเลิก ────────────┴──────────────────────────────────────┘
                                             v
                                    [cancelled ยกเลิก]
```
- **ไม่มีสถานะ `rejected`** — การไม่ลงนามคือการส่งกลับแก้ไข (DEC-08 · `on_reject: back_to_draft`)
- สายอนุมัติเป็น sequential · ผ่านครบทุกขั้นจึงเป็น `approved`

## 2. ฟังก์ชัน

### FN-01 สร้างร่าง
อ่าน `Customer` ตาม `customer_code` → snapshot `customer_name` · ค่าเริ่ม `customer_address` (ผู้ใช้แก้ได้)
ก่อนบันทึก: เช็คสถานะเปิดใช้ของ doc_type `LOA` ที่ **F-DOCCFG** — ยังไม่เปิดใช้ = 422 ห้ามสร้าง
`approval_chain` ยังว่าง (resolve ตอนส่ง — BR-DOA-02)

### FN-02 แก้ร่าง
แก้ได้เฉพาะเจ้าของและสถานะ `draft` · บันทึกประวัติ "แก้ไขร่าง" · **ไม่ออกเลขใหม่**

### FN-03 เก็บค่านโยบายลงเอกสาร
ตอนออกเลข อ่าน `SalesPolicy.box_free_replace_pct` แล้ว snapshot ลง `free_replace_pct` + คำอ่านไทย
ค่านี้ใช้ประกอบเนื้อสัญญาที่พิมพ์ — **ห้าม hardcode ใน template หรือใน logic** (DEC-04)
ค่าในระบบเปลี่ยนภายหลังไม่ย้อนแก้ฉบับที่ออกเลขไปแล้ว

### FN-04 ออกเลขที่เอกสาร
เรียก **`ENG-DOC-NUM.next('LOA')`** ตอนบันทึกครั้งแรก (DEC-10 · ไม่ใช่เอกสารการเงินที่ต้อง no-gap)
ได้ `doc_no` (รูปแบบ `{PREFIX}-{YYYY}-{run:4}`) และ `print_no` (รูปแบบบนกระดาษ `{run:4}-{ค.ศ.}`)
พร้อมกันนี้ snapshot หัวกระดาษจาก `Organization` (ชื่อนิติบุคคล · โลโก้) ลง `header_snapshot`

### FN-05 ส่งให้ผู้ส่งมอบลงนาม
ตรวจครบตาม 05 §2 → เรียก `GET /doa/resolve?feature_id=F-TMP-006` → ได้ขั้นและ role ปัจจุบัน
ผู้ใช้เลือกผู้พิจารณาต่อขั้น → **freeze ลง `approval_chain`** (BR-DOA-02) → สถานะเป็น `pending` · ขั้นแรกเป็น `pending`
ล้างค่า `returned_*` ของรอบก่อน (ถ้ามี)

### FN-06 resolve สายอนุมัติ (DOA-ENGINE-HOOK)
จำนวนขั้นและ role มาจาก DOA กลาง (F-DLG-001) เสมอ — **ห้าม hardcode จำนวนขั้นหรือ role ใน feature นี้**
ค่าเริ่มที่ประกาศไว้: 1 ขั้น `role-mgr-sales` ป้าย "ผู้ส่งมอบ (บริษัท ครีเดนซ์ จำกัด (มหาชน))" · ไม่มีวงเงิน
คำตัดสินของแต่ละขั้นอ่านจาก `print_config.decision_words.by_role[role_id]` — **ผูก role ไม่ผูกลำดับขั้น**

### FN-07 ลงนาม
ตรวจว่าเป็นผู้ถึงคิว (BR-DOA-04 ผู้จัดทำลงนามใบตัวเองไม่ได้) → ปิดขั้นปัจจุบันเป็น `approved` พร้อมเวลาและความเห็น
มีขั้นถัดไป → ขั้นนั้นเป็น `pending` เอกสารยัง `pending` · ไม่มีขั้นถัดไป → เอกสารเป็น `approved`
เมื่อ `approved` เรียก `ENG-DOC-STORE.store()` ตาม snapshot flag `approved_final`
**ไม่เปลี่ยนค่าใดในระบบ ไม่ตัดสต๊อก ไม่ลงบัญชี ไม่ยิงต่อระบบอื่น** (DEC-01 · DEC-02)

### FN-08 ส่งกลับแก้ไข (ยังไม่ลงนาม)
บังคับเหตุผล → บันทึก `returned_by` · `returned_at` · `returned_reason`
รีเซ็ต `approval_chain` ทุกขั้นเป็น `waiting` · ล้าง `submitted_at` · สถานะกลับเป็น `draft` **ด้วยเลขที่เดิม** (DEC-08)
ประวัติบันทึก "ไม่ลงนาม — ส่งกลับแก้ไข" พร้อมเหตุผล

### FN-09 ยกเลิกเอกสาร
ทำได้โดยเจ้าของหรือ admin role · สถานะ `draft` · `pending` · `approved` · บังคับเหตุผล
ขั้นที่ยัง `pending` เปลี่ยนเป็น `skipped` · สถานะเป็น `cancelled` (ปลายทาง ย้อนกลับไม่ได้)
ถ้าสถานะเดิมเป็น `pending` → ยิง `loa_cancelled` ให้ผู้พิจารณาขั้นปัจจุบัน

### FN-10 สิทธิ์การมองเห็น
`เห็นได้ = เป็นเจ้าของ` หรือ `เป็นผู้อยู่ในสายอนุมัติและเอกสารถูกส่งแล้ว` หรือ `เป็น admin role ของฝ่ายขาย` (DEC-09)
**ร่างของผู้อื่นต้องไม่รั่วถึงผู้พิจารณา** เพราะสายอนุมัติยังไม่ถูก resolve ตอนเป็นร่าง

### FN-11 สร้างแบบพิมพ์
render จาก `print/form.tpl.html` + data ตาม `print/LOA_data-contract.md` (template เดียวกับ prototype)
- **1 เลขที่ = 2 ชุด** (ต้นฉบับ · สำเนา) จาก `print_config.copies` — เนื้อความและเลขข้อ 1. และ 2. เหมือนกันทุกชุด (DEC-12)
- ช่องลงชื่อ = ผู้รับมอบ (คู่สัญญา) + 1 ช่องต่อขั้นใน `approval_chain` · แถวละไม่เกิน 4 ช่อง · ขั้นเกิน 4 ใช้ระยะกระชับ (DEC-07)
- ยังไม่พิจารณา → บรรทัดวันที่เป็นเส้นประ · พิจารณาแล้ว → "พิจารณาในระบบ {วันที่} {เวลา}" · ไม่ใช้ภาพลายมือชื่อ
- รายละเอียดกล่องแสดงอย่างน้อย 1 แถวตามกระดาษ · เกิน 6 แถวใช้ระยะกระชับ (DEC-05)
- เมื่อส่งเอกสารออกนอกองค์กร เรียก `ENG-DOC-STORE.store()` ตาม snapshot flag `sent_external`

### FN-12 ไฟล์แนบ
ผ่าน Document Center · ตรวจชนิดและขนาดที่ server (PDF · Word · Excel · รูป ไม่เกิน 20 MB ต่อไฟล์)
แนบเมื่อเอกสารเป็น `approved` → ยิง `loa_signed_copy_attached` (หลักฐานฉบับที่ลงนามครบสองฝ่าย)

## 3. ลำดับที่ต้องไม่สลับ
1. เช็คแบบเอกสารเปิดใช้ (F-DOCCFG) → 2. ออกเลข (ENG-DOC-NUM) → 3. snapshot ค่านโยบายและหัวกระดาษ → 4. resolve DOA ตอนส่ง → 5. ลงนามเรียงขั้น → 6. เก็บสำเนา (ENG-DOC-STORE)
