## 3. DOA
- entry `DOA-LOA-01` · `doa_type: loa` · `approval_scope: document_sign` · `chainMode: sequential` · โหมด **dynamic** · ไม่มีวงเงิน
- ค่าเริ่มที่ประกาศ: 1 ขั้น `role-mgr-sales` ป้าย "ผู้ส่งมอบ (บริษัท ครีเดนซ์ จำกัด (มหาชน))"
- จำนวนขั้นและ role ปรับที่ DOA กลางได้โดยไม่แก้ feature — feature ต้องรองรับ N ขั้น (ทดสอบแล้วถึง 6 ขั้น)
- ช่องลายเซ็นบนแบบพิมพ์ = ผู้รับมอบ (คู่สัญญา) + 1 ช่องต่อขั้น · แถวละไม่เกิน 4 ช่อง
- คำตัดสินอ่านจาก `print_config.decision_views` ไม่ได้ — ต้องอ่านจาก `print_config.decision_words.by_role[role_id]` (ผูก role ไม่ผูกลำดับขั้น)
- BR-DOA-01 ส่งได้เฉพาะสถานะร่าง · BR-DOA-02 resolve ตอนส่งแล้ว freeze · BR-DOA-04 ผู้จัดทำพิจารณาใบตัวเองไม่ได้ · BR-DOA-05 ไม่ใช้ (ไม่มีวงเงิน)
- **BR-DOA-03 ปรับตาม G7**: ไม่ลงนามแล้วกลับเป็นร่าง (ไม่ใช่จบใบ) — เป็นค่าที่มติอนุญาตให้ปรับได้

## 4. สิทธิ์และการมองเห็น (DEC-09)
| ผู้ใช้ | เห็นใบไหน | ทำอะไรได้ |
|---|---|---|
| ผู้จัดทำ | ของตัวเองทุกสถานะ | สร้าง · แก้ร่างของตัวเอง · ส่ง · ยกเลิกของตัวเอง · พิมพ์ |
| ผู้อยู่ในสายอนุมัติ | เฉพาะใบที่ถูกส่งแล้วและมีชื่อตนในสาย | ลงนาม หรือส่งกลับแก้ไข เมื่อถึงคิว · พิมพ์ |
| admin role ฝ่ายขาย | ทุกใบ | ยกเลิก · พิมพ์ · ส่งออก CSV |
> **ร่างของผู้อื่นต้องไม่ปรากฏต่อผู้พิจารณา** เพราะสายอนุมัติยังไม่ถูก resolve ตอนเป็นร่าง
> ตรวจสิทธิ์ที่ server ทุก endpoint — การซ่อนปุ่มใน UI เป็นชั้นแรกเท่านั้น
