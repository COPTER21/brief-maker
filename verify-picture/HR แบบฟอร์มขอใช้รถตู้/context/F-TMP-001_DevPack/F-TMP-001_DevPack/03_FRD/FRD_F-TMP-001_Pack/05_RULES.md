## 2. Validation Rules
| ช่อง | กฎ | ผล |
|---|---|---|
| `use_date_from` | บังคับ | บล็อก `VALIDATION_FAILED` |
| `use_date_to` | บังคับ · ≥ `use_date_from` | บล็อก |
| `total_days` | คำนวณเท่านั้น — ไม่รับจาก client | ข้ามค่าที่ส่งมา |
| `trip_mode` | บังคับ · ต้องเป็น 1 ใน 3 ค่า | บล็อก |
| `purpose` | บังคับ · ≤ 255 ตัวอักษร | บล็อก |
| `travelers[]` | ต้องมีอย่างน้อย 1 แถวที่มี `name` · แถวที่มี `division` แต่ไม่มี `name` = ผิด | บล็อก |
| `outbound_*` / `return_*` ของเที่ยวที่เลือก | บังคับครบ 4 ช่องต่อเที่ยว (สถานที่รับ · เวลารับ · สถานที่ส่ง · เวลาส่ง) | บล็อก |
| เวลาส่ง vs เวลารับ | เวลาส่งไม่ควรก่อนเวลารับ | เตือน |
| `assignees[]` ตอนส่ง | ครบทุกขั้น · ต้องไม่ใช่ผู้ขอ | บล็อก `VALIDATION_FAILED` / `SELF_APPROVAL_DENIED` |
| `reason` ตอนไม่อนุมัติ / ยกเลิก | บังคับ | บล็อก `REASON_REQUIRED` |

## 3. การอนุมัติ (DOA) — ดู `DOA_BRIEF_F-TMP-001.md`
| BR | เนื้อหา |
|---|---|
| BR-DOA-01 | ส่งอนุมัติได้เฉพาะสถานะ `draft` |
| BR-DOA-02 | สายอนุมัติ resolve ตอนส่งแล้ว **freeze** ลง `approval_chain` — แก้ DOA ทีหลังไม่กระทบใบที่ส่งไปแล้ว |
| BR-DOA-03 | ไม่อนุมัติ → **กลับเป็นร่างเลขเดิม** แก้แล้วส่งใหม่ได้ · ประวัติการตีกลับเก็บแบบ append-only (ใช้ค่า default ของ DOA contract · DEC-08 ไม่ได้ override เป็น `end` จึง**ไม่มีข้อยกเว้น**ต้องประกาศ) |
| BR-DOA-04 | ผู้ขออนุมัติใบตัวเองไม่ได้ (SoD) |
| BR-DOA-05 | ไม่มีวงเงิน → ไม่ต้อง re-resolve เมื่อแก้ยอด (เอกสารนี้ไม่มีช่องจำนวนเงิน) |

**ค่าเริ่มของสาย (ตั้งที่ DOA กลางเท่านั้น):**
| ขั้น | role | คำตัดสิน |
|---|---|---|
| 1 | `role-line-manager` (ผู้บังคับบัญชา — relative role จากผังองค์กร F-ORG-001) | อนุมัติ / ไม่อนุมัติ |
| 2 | `role-mgr-hr` (ผู้จัดการฝ่ายทรัพยากรบุคคล) | เห็นควร / ไม่เห็นควร |

> `role-line-manager` ยังไม่อยู่ใน Roles Master 14 ตัวของ DOA v23 — ต้องยืนยันกับ DOA กลางก่อน wire (BRD §15 OQ-01)
