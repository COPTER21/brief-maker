### P-01: รายชื่อสมาชิกเกษตรกร

**Purpose:** ค้นหา / กรอง / เลือกกลุ่ม / จุดเข้าถึงทุก action ของทะเบียนสมาชิก
**Pattern:** A — list-view

**ERP Context:**
- Sidebar active: เกษตรกรรม › Farmer › จัดการสมาชิกเกษตรกร (Pattern N)
- Breadcrumb: หน้าแรก / เกษตรกรรม / จัดการสมาชิกเกษตรกร
- Page header `.ph`: h1 "จัดการสมาชิกเกษตรกร" + count "[N] รายการ" + `.ph-actions`

**Components:**
- Filter Bar (ใน card): Search box ซ้ายสุด (debounce 300ms — ค้นหา ชื่อ/นามสกุล/เบอร์โทร/เลขบัตร/Member Id) + Dropdown สถานะการยืนยัน (ทั้งหมด/รอตรวจสอบ/อนุมัติแล้ว/ปฏิเสธ) + ล้างตัวกรอง ghost ขวาสุด
- Data Table ≤ 8 คอลัมน์: ☑ (เฉพาะแถว Pending selectable) · Member Id (link → P-02) · ชื่อ · นามสกุล · เบอร์โทร · เลขบัตรประชาชน (masked) · สถานะการยืนยัน (pill) · การดำเนินการ (pencil → trash-2 เฉพาะ Pending)
- Action bar `.ph-actions`: ปุ่ม primary "สร้างสมาชิก" ขวาสุด · secondary "Import CSV" · secondary "ตรวจสอบที่เลือก (N)" (disabled เมื่อ N=0, เฉพาะ R-02)
- Pagination footer: "X – Y จาก Z" ซ้าย / ปุ่มหน้า ขวา

### OV-01: สร้างสมาชิก (B — create drawer v2, 920px)

**Form sections (Rule #45):**

**กลุ่ม 1 — ข้อมูลส่วนตัว**
| Field | Type | Required | Validation (UI) |
|---|---|---|---|
| ชื่อ | text | ✅ | กรุณากรอกชื่อ |
| นามสกุล | text | ✅ | กรุณากรอกนามสกุล |
| เลขบัตรประชาชน | text (numeric, maxLength 13, strip non-digit) | ✅ | 13 หลักเป๊ะ — "เลขบัตรประชาชนต้องเป็นตัวเลข 13 หลัก" |
| เบอร์โทรศัพท์ | text (numeric, maxLength 12, strip non-digit) | ✅ | 9–12 หลัก — "เบอร์โทรศัพท์ต้องเป็นตัวเลข 9-12 หลัก" |
| อีเมล | text | ✅ (authoritative — LOCK-08 superseded 2026-07-22) | required + validate format — blank → "กรุณากรอกอีเมล" · ผิดรูปแบบ → "รูปแบบอีเมลไม่ถูกต้อง" |

**กลุ่ม 2 — ที่อยู่**
| Field | Type | Required | Behavior |
|---|---|---|---|
| ที่อยู่ | textarea (placeholder "บ้านเลขที่ หมู่ ซอย ถนน") | ✅ | — |
| จังหวัด | search-select (Rule #34, M-01 lookup) | ✅ | cascade root |
| อำเภอ | search-select (by province) | ✅ | disabled จนเลือกจังหวัด |
| ตำบล | search-select (by district) | ✅ | disabled จนเลือกอำเภอ |
| รหัสไปรษณีย์ | text read-only (auto จากตำบล) | auto | server validate ต้อง match ตำบล |

**Cascade reset (VR-11):** เปลี่ยนจังหวัด → เคลียร์ อำเภอ/ตำบล/ไปรษณีย์ · เปลี่ยนอำเภอ → เคลียร์ ตำบล/ไปรษณีย์

**Footer (Rule #31):** `ยกเลิก` (ghost ซ้าย) → spacer → `ยืนยันสร้าง` (primary ขวา) — ไม่มีบันทึกร่าง (entity ไม่มี draft state — Rule #31.5)
**Submit:** ปุ่ม disabled + "กำลังบันทึก…" (Rule #44) → API-02 → ปิด drawer → toast "สร้างสมาชิกสำเร็จ — [FM-NNNNNN]"

### OV-03: นำเข้า CSV (Iron Rule #32 — CSV Import modal)

**ขั้น 1 — เลือกไฟล์:**
- Alert แถบบน: "ดาวน์โหลดแม่แบบ CSV เพื่อดูรูปแบบที่ถูกต้อง" + ปุ่ม `ดาวน์โหลดแม่แบบ` (API-09)
- เลือกไฟล์ (.csv เท่านั้น, ≤5MB — block พร้อมข้อความถ้าไม่ผ่าน: "กรุณาเลือกไฟล์ CSV เท่านั้น" / "ขนาดไฟล์ต้องไม่เกิน 5MB")
- คำแนะนำ: ไฟล์ CSV เท่านั้น · ≤5MB · ไม่ระบุรหัสไปรษณีย์ระบบคำนวณจากตำบล · ระบุแล้วต้องตรงตำบล · สมาชิกใหม่สถานะ "รอตรวจสอบ" อัตโนมัติ
- Footer: `ยกเลิก` → `อัปโหลด` (disabled จนเลือกไฟล์; ระหว่างส่ง "กำลังนำเข้า…" + progress bar)

**ขั้น 2 — ผลลัพธ์ (partial success — LOCK-04):**
- Summary 3 กล่อง: แถวทั้งหมด / สร้างสำเร็จ / ล้มเหลว
- ตาราง error (ถ้ามี): แถว · ฟิลด์ · ข้อผิดพลาด · ข้อมูล + ปุ่ม `ดาวน์โหลดรายงาน` (error report .csv)
- ไม่มี error → Alert "อัปโหลดสำเร็จทั้งหมด ไม่มีข้อผิดพลาด"
- Footer: `ปิด` → ปิดแล้ว refresh list + toast "นำเข้าสมาชิก [X] รายการสำเร็จ"

### OV-04: ตรวจสอบสมาชิก (D — modal 440px)

**เดี่ยว:** header "ตรวจสอบสมาชิก" + สรุป (ชื่อ-นามสกุล, Member Id, เลขบัตร masked)
**กลุ่ม:** header "ตรวจสอบสมาชิกทั้งหมด" + list รายชื่อที่เลือก (N รายการ)

- ผลการตรวจสอบ * : radio `ยืนยัน (อนุมัติ)` / `ปฏิเสธ` — ไม่เลือก → "กรุณาเลือกผลการตรวจสอบ"
- หมายเหตุ: textarea — บังคับเมื่อปฏิเสธ ("จำเป็นต้องระบุเหตุผลเมื่อปฏิเสธ"); placeholder "กรุณาระบุเหตุผลในการปฏิเสธ" / "หมายเหตุเพิ่มเติม (ไม่บังคับ)"
- Footer: `ยกเลิก` → `ยืนยัน` (primary; ระหว่างส่ง "กำลังดำเนินการ…")
- เดี่ยว → API-05 · กลุ่ม → API-06 (ประมวลผลรายคน → summary "สำเร็จ X ล้มเหลว Y" + เหตุผลรายการที่ข้าม)
- **Per-item Retry (GAP-11, authoritative TC-264):** ในผลสรุป bulk แต่ละแถวที่ล้มเหลว (STALE/NOT_PENDING) มีปุ่ม `ลองใหม่` ต่อรายการ → เรียก verify เฉพาะรายการนั้นซ้ำ (โหลด expected_updated_at ใหม่) — ไม่ต้อง bulk ทั้งชุดอีกรอบ
- Toast: "ยืนยันสมาชิกเรียบร้อย" / "ปฏิเสธสมาชิกเรียบร้อย" / bulk: "ตรวจสอบกลุ่มเสร็จสิ้น — สำเร็จ X ล้มเหลว Y"

## §1.3 User Journey (Happy Path)

```
R-01 เข้า P-01 → คลิก "สร้างสมาชิก" (OV-01) → กรอก 2 กลุ่ม → ยืนยันสร้าง
  ↓ API-02 (FN-SEQ-AGM-110) — gen FM-NNNNNN + สถานะ รอตรวจสอบ
R-02 เข้า P-01 → filter "รอตรวจสอบ" → เลือกแถว → "ตรวจสอบที่เลือก" (OV-04 bulk)
  ↓ API-06 (FN-AT-AGM-103 batch) — Approve
สมาชิก อนุมัติแล้ว → module Quota อ้างอิงได้ (quota_status เริ่ม no_quota)
```

### Branch: Reject → Re-submit (LOCK-06)
```
R-02 Reject + เหตุผล → สถานะ ปฏิเสธ (verified_note แสดงใน P-02)
R-01 เปิด OV-02 แก้ไข → บันทึก → สถานะกลับ รอตรวจสอบ อัตโนมัติ
  (verified_note เดิมย้ายเข้า history — ดูได้ใน P-02 Tab ประวัติ)
```

### Branch: CSV bulk (LOCK-04)
```
R-01 เปิด OV-03 → ดาวน์โหลดแม่แบบ → upload ไฟล์ → progress → สรุป total/created/failed
  แถวเสีย → ดาวน์โหลด error report → แก้ → import ใหม่ (เฉพาะแถวที่แก้)
```
