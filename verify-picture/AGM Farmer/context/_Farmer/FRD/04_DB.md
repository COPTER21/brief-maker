**Constraints:**
- PRIMARY KEY (id)
- UNIQUE (tenant_id, member_id)
- UNIQUE (tenant_id, citizen_id) — VR-05 (partial index WHERE is_deleted = false — ดู OQ note ท้ายไฟล์)
- CHECK (verify_status IN ('pending_approval','approved','rejected'))
- CHECK (quota_status = 'no_quota') — Phase-1 คงค่า no_quota เสมอ (authoritative, GAP-03); has_quota เปิดใน Phase-2 เมื่อ module Quota ขึ้น
- CHECK (citizen_id ~ '^[0-9]{13}$')

**Indexes:**
- IDX_fm_tenant_status ON (tenant_id, verify_status) WHERE is_deleted = false
- IDX_fm_member_id ON (tenant_id, member_id)
- IDX_fm_citizen ON (tenant_id, citizen_id)
- IDX_fm_search — trigram/tsvector บน first_name, last_name (คำค้น 5 field — phone/citizen/member_id ใช้ prefix match)
- IDX_fm_pending_age ON (tenant_id, created_at) WHERE verify_status='pending_approval' AND is_deleted=false (widget Pending > 7 วัน)

**RLS Policy:**
```sql
CREATE POLICY tenant_isolation ON T_farmer_member
  USING (tenant_id = current_setting('app.current_tenant')::uuid);
```

**verify_status canonical ↔ domain mapping (GAP-08, authoritative FRD 2026-07-22):** wire value ที่ใช้จริงทั้ง DB/API/UI = snake_case `pending_approval` / `approved` / `rejected` (คงเดิม). authoritative ใช้ canonical model + domain alias ตามนี้ (ระบุไว้กัน cross-ref ผิด):

| Domain (ผู้ใช้เรียก) | Authoritative canonical | Wire value (pack นี้) | UI label (ไทย) |
|---|---|---|---|
| unverified | Pending Approval | `pending_approval` | รอตรวจสอบ |
| verified | Approved | `approved` | อนุมัติแล้ว |
| rejected | Rejected | `rejected` | ปฏิเสธ |

## §4.6 Data Classification & Sensitive Data

### §4.6.1 Levels ที่ใช้ใน feature นี้
| Level | Fields | UI | Export |
|---|---|---|---|
| **Restricted** | citizen_id, history diff_before/after | mask บน list (S02-04) · เต็มเฉพาะ detail + ACL ผ่าน · audit ทุกการเข้าถึง | excluded — ต้องผ่าน Restricted Resources approval (S07-01: Phase 1 ไม่มี export ทะเบียนทั้งชุด) |
| **Confidential** | phone, email, address_line | แสดงสำหรับ R-01/R-02 (role ผ่าน ENC) | excluded ถ้า role ไม่ผ่าน |
| **Internal** (default) | ที่เหลือทั้งหมด | แสดงปกติหลัง auth | ตาม role |
| Public | — ไม่มี | — | — |

### §4.6.2 Default Rule
Default = Internal · ไม่มี field ใด Public · ทุก field ≠ Internal ระบุ explicit ใน §4.2 แล้ว

### §4.6.3 Enforcement Mapping
| Classification | DB | API | UI | Audit |
|---|---|---|---|---|
| Internal | RLS | JWT + ENC | — | mutation only |
| Confidential | RLS + column ACL | role check | ซ่อน/แสดงตาม role | view + mutation |
| Restricted (citizen_id) | RLS + column encrypt at rest (D7) | serializer mask (API-01) / ACL (API-03, API-10 diff) | mask `1-XXXX-XXXX-XX-1` | view + mutation + การเข้าถึงค่าเต็ม |

### §4.6.4 PII Overlay
PII = first_name, last_name, citizen_id, phone, email, address_line → PDPA scope (BRD §16.2) · citizen_id = PII + Restricted (ซ้อนกัน)

### §4.6.5 Security Bible Domain Mapping
- D7 (PII): citizen_id encrypt at rest · log ห้ามมี PII (ใช้ member_id อ้าง)
- D9 (Audit): ทุก mutation → T_farmer_member_history + diff (S01-07)

### §4.6.6 Policy Center Linkage
- citizen_id → Restricted Resources registry (OQ-F02 — ทำตอน ENC register)
- PII set → PDPA consent scope
- ENC matrix (BRD §4) → User Access ENC + version (S03-02)
