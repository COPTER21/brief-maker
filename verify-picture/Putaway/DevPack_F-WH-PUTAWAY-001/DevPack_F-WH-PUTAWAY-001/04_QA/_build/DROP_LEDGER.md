## เคสที่ตัดออก (4)

### 1. `TC-02` — คิวมาจากใบรับของที่บันทึกแล้วเท่านั้น
**เหตุผล: ยุบเข้าเคสอื่น (ไม่ได้หาย)**
เนื้อหาทั้ง 3 ขั้นซ้ำกับ `TC-01` ขั้นที่ 3–5 (ตรวจว่าทุกแถวอ้างใบรับของได้ · ไม่มีบรรทัดบริการ · จำนวนแถวตรงกับป้าย)
→ **ยกไปเป็นขั้นที่ 4 ของ `TC-01`** และคำอธิบายในทูลทิปถูกตรวจในขั้นที่ 5 ของ `TC-01`
**ครอบคลุมโดย:** `TC-01` · trace `FN-02` · `R02` ยังครบ

### 2. `TC-13` — งานที่คนอื่นถืออยู่ · หัวหน้าปลดล็อก · หมดเวลาคืนคิวเอง
**เหตุผล: ⛔ ทดสอบบนต้นแบบไม่ได้ (ข้อจำกัดของข้อมูลและของสิ่งที่ยังไม่ได้ทำ)**

| วรรค | ทำไมคนกดทดสอบไม่ได้ |
|---|---|
| งานที่คนอื่นถืออยู่ กดรับไม่ได้ | งานเดียวที่ถูกถือครองในชุดข้อมูลตัวอย่าง **ถือโดยผู้ใช้ที่ล็อกอินอยู่เอง** → หน้าจอแสดง "ในมือคุณ" เสมอ · สาขา "ถือโดยคนอื่น" ไม่มีทางแสดงออกมา |
| หัวหน้าคลังปลดล็อกงาน | ปุ่มอยู่ในสาขาเดียวกันข้างบน จึงไม่มีทางแสดง · และต้นแบบไม่มีตัวสลับบทบาท |
| หมดเวลาถือครองแล้วคืนคิวเอง | **ยังไม่ได้ทำในรอบนี้** — ค่าเวลาถูกประกาศไว้แต่ยังไม่มีโค้ดนำไปใช้ |

**ต้องทดสอบเมื่อไหร่:** ตอนมีระบบจริงที่มีผู้ใช้หลายคน และหลัง dev ทำกลไกคืนคิวอัตโนมัติฝั่งเซิร์ฟเวอร์แล้ว
**อยู่ที่ไหนต่อ:** `03_FRD/06_TESTS.md` **AT-15** · `03_FRD/05_RULES.md` §5.1.1 · `03_FRD/07_LOCKED_DECISIONS.md` **LD-05**
**ข้อเสนอที่ทำให้ทดสอบได้ทันที:** เปลี่ยนผู้ถือครองงาน `กาวทาท่อ PVC 500 กรัม` ในชุดข้อมูลตัวอย่างเป็น **สมชาย ทองใบ** (คนละคนกับผู้ใช้ที่ล็อกอิน) → สองวรรคแรกจะทดสอบได้ทันทีโดยไม่ต้องแก้โค้ดเลย (`OQ-PUT-11`)

### 3. `TC-19` — เลือกเหตุผล "อื่น ๆ" ต้องพิมพ์ข้อความเพิ่ม
**เหตุผล: ยุบเข้าเคสอื่น (ไม่ได้หาย)**
เป็นขั้นตอนต่อเนื่องจาก `TC-18` โดยตรง (ต้องเลือกช่องที่ฝืนเกณฑ์ก่อนถึงจะมีช่องเหตุผล) — แยกเป็นเคสทำให้ผู้ทดสอบต้องทำ setup ซ้ำทั้งชุด
→ **ยกไปเป็นขั้นที่ 6–7 ของ `TC-18`**
**ครอบคลุมโดย:** `TC-18` · trace `VR08` ยังครบ

### 4. `TC-38` — ค่าที่หายจากทะเบียนไม่ทำหน้าจอพัง
**เหตุผล: ⛔ ทดสอบบนต้นแบบไม่ได้ (ไม่มีทางสร้างสถานการณ์ผ่านหน้าจอ)**
ต้องลบหรือปิดใช้งานสินค้า / ช่องเก็บ / พนักงาน ที่ถูกอ้างอยู่ในงานเดิม — ต้นแบบไม่มีหน้าจอทะเบียนให้ทำสิ่งนี้ และหน้าจัดเก็บเข้าที่ก็ไม่มีปุ่มลบอะไรเลยโดยเจตนา
**ต้องทดสอบเมื่อไหร่:** ตอนมีระบบจริง — ลบ/ปิดใช้งานข้อมูลทะเบียนที่ถูกอ้าง แล้วเปิดหน้าจัดเก็บเข้าที่
**คาดหวัง:** หน้าจอยังแสดงข้อความเดิมของค่าที่หายไป · ไม่ขาว ไม่ค้าง ไม่มีข้อความผิดพลาด
**อยู่ที่ไหนต่อ:** `03_FRD/06_TESTS.md` **AT-32** · `03_FRD/05_RULES.md` R23

## สิ่งที่ **ไม่อยู่ในทั้งสองฉบับ** โดยเจตนา

| ไม่มีเคส | เหตุผล |
|---|---|
| ล็อต / ซีเรียล / วันหมดอายุ · พาเลท · cross-docking · ยิงบาร์โค้ด | อยู่นอกขอบเขตรอบนี้ (BRD §3.2 OS-07/OS-08) |
| ปรับยอดคงเหลือด้วยมือ · ย้ายของข้ามคลัง · คืนของผู้ขาย | เป็นของฟีเจอร์อื่น (ใบปรับยอดสต๊อก / ใบย้ายสินค้า / ใบคืนผู้ขาย) |
| การลงบัญชีจริง | ไม่กระทบมูลค่ารวม — เป็นงานของคลื่นถัดไป |
| เอกสาร / เลขรัน / ไฟล์พิมพ์ / ลายเซ็น / สายอนุมัติ | **ไม่มีในฟีเจอร์นี้โดยเจตนา** — มีเคส `TC-35` ตรวจว่า "ต้องไม่มีจริง" แทน |
| เคส `EC-16` … `EC-21` (BRD §10.2) | **ยังไม่ยืนยันเป็นข้อกำหนด** — ไม่ได้เขียนเป็นสเปค จึงไม่สร้างเคส (`05_RULES` §5.3.3) |
| เคสเชื่อมข้ามฟีเจอร์ `XT-01` … `XT-15` | ต้องมีใบรับของ / ใบปรับยอด / ใบย้ายสินค้า / เครื่องประเมินผลกระทบ / ค่าตั้งค่ากลาง ที่ใช้งานได้จริงก่อน |
