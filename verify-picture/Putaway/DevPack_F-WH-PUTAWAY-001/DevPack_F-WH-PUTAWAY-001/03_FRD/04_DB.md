# 04_DB — F-WH-PUTAWAY · จัดเก็บเข้าที่

> ⚠️ **§4.7 คือสัญญากลางของโมดูลคลัง** — `F-WH-STKADJ` (F082) และ `F-WH-STKTRF` (F083) **ต้องใช้ชุดนี้ ห้ามนิยาม location ใหม่** (LOCK-08 · HANDOFF **L5**)
> ชื่อตาราง/คอลัมน์ = `[AI-DEFAULT]` (AD-03) ตาม convention `t_<module>_<entity>`
> **ไม่มีตารางเลขรัน · ไม่มีตารางสายอนุมัติ · ไม่มีตารางไฟล์แนบ/ลายเซ็น** — LOCK-01/02 · L3

### `v_bin_stock` — projection (DR-06)

```sql
CREATE MATERIALIZED VIEW v_bin_stock AS
SELECT to_location_ref AS bin_ref, item_ref,
       SUM(qty) FILTER (WHERE ...) - SUM(qty) FILTER (WHERE ...) AS qty
FROM t_inv_movement GROUP BY 1, 2;   -- เข้า − ออก
```
| กติกา | |
|---|---|
| **ไม่มีหน้าจอ/endpoint ให้แก้ยอดตรง ๆ** | การแก้ยอด = **F-WH-STKADJ เท่านั้น** (OS-04) |
| refresh | **ในทรานแซกชันเดียวกับการเขียน movement** (AD-05) → SLA "ยอดสดทันทีหลังยืนยัน" |
| ห้ามติดลบ | ตรวจตอน reverse ว่าไม่ทำให้ยอดติดลบ (EC-18) |

## §4.6 Data Classification — การบังคับใช้

### §4.6.1 นิยาม 4 ระดับ
D0 = เปิดเผยได้ทั่วองค์กร · D1 = ภายในองค์กร ต้องล็อกอิน · D2 = จำกัดตามหน้าที่ · D3 = จำกัดสูงสุด + เข้ารหัส + log ทุกการเข้าถึง

### §4.6.2 ชั้น DB
D1 ทั้งหมด — เข้ารหัสที่ระดับ storage (at-rest) ตามมาตรฐานองค์กร · **ไม่ต้องเข้ารหัสรายคอลัมน์** (ไม่มี D2/D3)

### §4.6.3 ชั้น API
ทุก endpoint ต้องล็อกอิน + ผ่าน matrix `02_API` §2.9 · **ไม่มี endpoint สาธารณะ** · `warehouse_ref` ถูกจำกัดตามสิทธิ์ของผู้เรียก (จนท.คลัง = คลังตัวเอง)

### §4.6.4 ชั้น UI
**ไม่มีการปิดบัง (masking) ใด ๆ** เพราะไม่มี D2/D3 · ผู้ใช้ที่เห็นหน้าจอนี้เห็นค่าเต็มทุกช่อง
**ห้ามแสดงตัวเลขเงินบนจอ** — ไม่ใช่เรื่อง classification แต่เป็นข้อบังคับของ `CSQ_BRIEF §6` (ทั้ง 2 event เป็น `basis: declared`)

### §4.6.5 ชั้น Audit
`t_inv_movement` และ `t_putaway_audit` เก็บ **ผู้ทำ + เวลา + สิ่งที่เปลี่ยน** ทุกครั้ง · **append-only บังคับที่ชั้น DB** · **ไม่มีใครลบได้ รวมถึงผู้ดูแลระบบ** (BRD §4.2)

### §4.6.6 การเชื่อมกับ Policy Center
Security Preset **P1 (ยกระดับบางส่วน)** — ยกระดับเฉพาะ 2 ด้าน: **append-only** และ **ระบุตัวตนผู้ทำรายการ** ให้เท่าเอกสารธุรกรรม เพราะแตะยอดสินทรัพย์จริง (BRD §16.1)
**ไม่มีการผูก DOA · ไม่มี segregation-of-duties แบบสายอนุมัติ** — การแบ่งแยกหน้าที่ทำผ่าน permission matrix แทน (ผู้จัดเก็บ ≠ ผู้กลับรายการ ≠ ผู้แก้ผัง · BRD §16.2)

## §4.7 ★★ สัญญากลางของ location — สิ่งที่ F082 / F083 ต้องหยิบไปใช้ตรง ๆ

> **HANDOFF L5 · LOCK-08 · PREBRIEF §3.0 · BRD §6.2** — หัวข้อนี้คือเหตุผลที่ Putaway ต้องทำก่อนสองฟีเจอร์นั้น
> **ห้ามนิยามใหม่ ห้ามสร้างชุด mock ใหม่ ห้ามเพิ่ม/เปลี่ยนชื่อค่าใน enum โดยฟีเจอร์เดียว**

### §4.7.1 โครงสร้าง 3 ระดับ

```
Warehouse (คลัง/สาขา)        WH-BKK-01 · WH-CNX-01 · WH-TRN (ระหว่างทาง · เสมือน)
      └── Zone (โซน)          A · B · C · ST · QA · DM · TR
              └── Bin (ช่องเก็บ)   A-01-02-C  = โซน A · แถว 01 · ช่อง 02 · ชั้น C
```
การอ้างอิงแบบเต็มที่ทุกฟีเจอร์ใช้ร่วมกัน: `WH-BKK-01 / A / A-01-02-C` · บนหน้าจอแสดง `bin_code` พอ + tooltip บอกคลัง

### §4.7.2 ★ `location_type` — enum ร่วม 5 ค่า

| ค่า (ไทย) | key | นับเป็นของใช้/ขายได้ | Putaway **เขียนเข้า** | Putaway **ดึงออก** | ★ ใครเขียนได้ |
|---|---|---|---|---|---|
| **พักรับเข้า** | `staging` | ✅ | ❌ (เป็นต้นทาง) | ✅ | GRN (เข้า) · **Putaway (ออก)** |
| **เก็บปกติ** | `storage` | ✅ | ✅ **ปลายทางหลัก** | ❌ | **Putaway** · StockAdj · StockTransfer |
| **กักกัน** | `quarantine` | ❌ | ✅ เฉพาะของที่มาจากกักกัน | ✅ ไปกักกันด้วยกัน | GRN · **Putaway** · RTV |
| **ระหว่างทาง** | `in-transit` | ✅ | ❌ | ❌ | ★ **StockTransfer เท่านั้น** |
| **ของเสีย** | `damage` | ❌ | ❌ | ❌ | ★ **StockAdj เท่านั้น** |

**กติกาข้ามประเภท (บังคับทุกฟีเจอร์ในโมดูล)**

1. ของจาก `quarantine` **ไปไหนไม่ได้เลยนอกจาก `quarantine` ด้วยกัน หรือออกด้วยใบคืนผู้ขาย** (R04 · LOCK-06)
2. **`in-transit` ห้ามมีใครเขียนตรง ๆ นอกจาก StockTransfer** — Putaway และ StockAdj ไม่แตะ (R05 · LOCK-07)
3. **`damage` เขียนได้เฉพาะ StockAdj** — Putaway ไม่แตะ (R05)
4. ยอดที่ `staging` + `storage` + `in-transit` = ทรัพย์สินที่ใช้ได้ · `quarantine` + `damage` = กันออกจากยอดขายได้

> **ยืนยันเชิงกลบนต้นแบบ:** ไล่ทุกงาน × (`suggestBins` + `pickerOptions`) → **ไม่เคยคืน `in-transit` / `damage` เลยแม้แต่ครั้งเดียว** · โซน `TR` แสดงในผังแบบอ่านอย่างเดียว ชื่อ `TR ระหว่างทาง — สงวนให้ใบย้ายสินค้า`

### §4.7.3 ชุด location ตั้งต้น (mock ร่วม — **ห้ามสร้างชุดใหม่**)

| คลัง | โซน | ประเภท | หมวดที่รับ | ช่องเก็บ |
|---|---|---|---|---|
| `WH-BKK-01` คลังกลางบางนา | `ST` โซนพักรับเข้า | พักรับเข้า | ทุกหมวด | `ST-DOCK-01` · `ST-DOCK-02` |
| | `A` สินค้าหมุนเร็ว | เก็บปกติ | เครื่องเขียน · วัสดุสิ้นเปลือง | 4 ช่อง |
| | `B` วัสดุก่อสร้าง | เก็บปกติ | ท่อ/ข้อต่อ · เคมีภัณฑ์ · วัสดุก่อสร้าง | 5 ช่อง (`B-01-01-A` ความจุ 500 · **ห้ามปนสินค้า**) |
| | `C` ของหนัก / นอกอาคาร | เก็บปกติ | ของหนัก · วัสดุก่อสร้าง | 3 ช่อง (มี 1 ช่องล็อก) |
| | `QA` กักกัน (QC ไม่ผ่าน) | กักกัน | ทุกหมวด | 2 ช่อง (`QA-01` ตรงกับที่ใบรับของใช้) |
| | `DM` ของเสีย / รอทำลาย | ของเสีย | ทุกหมวด | 1 ช่อง |
| `WH-CNX-01` คลังเชียงใหม่ | `CNX-ST` · `CNX-A` · `CNX-QA` | ตามข้างบน | — | 4 ช่อง (`CNX-A` **เต็มทั้ง 2 ช่อง** — ใช้พิสูจน์ S-21) |
| **`WH-TRN` ระหว่างทาง (เสมือน)** | `TR` | **ระหว่างทาง** | ทุกหมวด | 2 ช่อง — ★ **จองไว้ให้ StockTransfer ไม่มีใครเขียนในรอบนี้** |

**รวม 10 โซน** · `WH-TRN` **ถูกตัดออกจากตัวกรองคลังบนจอ** (`whOptions()`) เพราะไม่ใช่คลังจริง

### §4.7.6 ⚠️ ผลกระทบกับ F008 (ทะเบียนคลัง) — ต้องขยาย schema ก่อนเริ่ม P2

ฟิลด์ที่ **ยังไม่มีใน F008 วันนี้** และต้องเพิ่ม: `location_type` · `accept_categories` · `near_rank` · `is_open` (โซน) · `capacity_max` · `allow_mixed` · `is_locked` · `lock_reason` · `walk_*` (ช่องเก็บ) — และ **ระดับ `Bin` ทั้งระดับ** (เดิม F008 มีถึงระดับ location = zone เท่านั้น)

| ต้อง regress | เช็คอะไร |
|---|---|
| ข้อมูล location เดิมของ F008 | **ไม่พังเมื่อฟิลด์ใหม่เป็นค่าว่าง** (BRD §11) |
| ยอดคงคลัง F009 | **ยอดรวมระดับคลังยังตรงเท่าเดิม** หลังมีระดับ bin ซ้อนข้างใน |

> เจ้าของ config ผัง (กลาง vs รายคลัง) **ยังไม่เคาะ → `OQ-PUT-05`**
