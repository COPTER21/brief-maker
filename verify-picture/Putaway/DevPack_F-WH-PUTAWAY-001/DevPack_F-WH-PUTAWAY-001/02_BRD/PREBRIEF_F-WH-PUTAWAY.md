## 1. สรุป + ผู้ใช้ + สิทธิ์

**ทำอะไร** [แผน]
Putaway คือ **หน้าทำงานต่อเนื่อง (console) ของเจ้าหน้าที่คลัง** ไม่ใช่เอกสาร — GRN ทำให้ของ "มีอยู่ในคลัง" แต่ของยังกองอยู่ที่ **โซนพักรับเข้า (staging)** ยังไม่อยู่ในที่ของมัน. หน้านี้ทำ 4 อย่างต่อเนื่องในจอเดียว:
1. เห็น **คิวงานค้างจัดเก็บ** (มาจาก GRN บรรทัดที่ผ่าน QC · เรียงตามความเร่งด่วน/อายุงาน)
2. เลือกงาน → ระบบ **แนะนำ bin** ให้ 2–3 ตัวเลือก **พร้อมเหตุผลที่แนะนำ** (มีของตัวเดียวกันอยู่แล้ว / โซนตรงหมวดสินค้า / ว่างและใกล้ staging)
3. คนคลัง **เลือกตามที่แนะนำ หรือ override เป็น bin อื่น** (ฝืนเกณฑ์ต้องบอกเหตุผล) · **แบ่งเก็บหลาย bin ได้**
4. **ยืนยันจัดเก็บ** → เกิด **movement append-only** จาก staging → bin จริง → งานหายจากคิว → เด้งไปงานถัดไปทันที

**Putaway ไม่ออกเอกสาร** — ไม่มีเลขรัน ไม่มี PDF ไม่มีลายเซ็น ไม่มีสายอนุมัติ (OB-1/OB-9). ผลลัพธ์เดียวที่จับต้องได้คือ **ยอดคงเหลือราย bin ที่ตรงกับของจริง** และ **ประวัติ movement ที่ย้อนได้**

**ผู้ใช้ + สิทธิ์** [AI-DRAFT]

| Role | เห็นอะไร | ทำอะไรได้ |
|---|---|---|
| **เจ้าหน้าที่คลัง (ผู้จัดเก็บ)** | คิวงานค้างของคลังตัวเอง · ผัง bin ของคลังตัวเอง | รับงาน · เลือก/override bin · แบ่งเก็บหลาย bin · ยืนยันจัดเก็บ · คืนงานเข้าคิว |
| **หัวหน้าคลัง** | คิวทุกคลัง · ผัง bin ทุกคลัง · ประวัติทั้งหมด | ทุกอย่างของเจ้าหน้าที่ + **กลับรายการจัดเก็บ (reversal)** + ปลดล็อกงานที่ค้างในมือคนอื่น + ล็อก/ปลดล็อก bin |
| **ผู้ดูแลผัง location (master)** | ผัง warehouse/zone/bin ทั้งหมด | แก้ผัง location · ตั้งหมวดสินค้าที่โซนรับได้ · ตั้งความจุ bin (**เป็น config ไม่ใช่ feature code**) |
| **QC** | คิว quarantine (อ่านอย่างเดียว) | ไม่มีสิทธิ์เก็บของ quarantine เข้า bin ปกติ (BR-04) |
| **จัดซื้อ / บัญชี** | ยอดคงเหลือราย bin + ประวัติ (อ่านอย่างเดียว) | — |
| **ผู้ดูแลระบบ** | ทุกอย่าง | ดู audit append-only (อ่านอย่างเดียว) |

> **ไม่มี role "ผู้อนุมัติ Putaway"** โดยเจตนา (OB-9) — การเก็บของคืองาน execution ไม่ใช่การอนุมัติ · สิทธิ์ระดับปุ่มเป็น `[AI-DRAFT]` รอเคาะตอน wireframe review

### ★ 3.0 LOCATION MODEL (สัญญากลางของคลัง — StockAdj + StockTransfer หยิบไปใช้ตรงนี้ · OB-4)

> **นี่คือส่วนที่สำคัญที่สุดของ PREBRIEF ฉบับนี้** — F-WH-STKADJ และ F-WH-STKTRF **ห้ามนิยาม location ใหม่** ให้ใช้ตารางในหัวข้อนี้เท่านั้น
> ระดับที่ GRN ใช้อยู่แล้วคือ **ระดับ location (= zone ในโมเดลนี้)** — Putaway เป็นตัวที่เพิ่มระดับ **bin** เข้ามา (GRN OB-14)

#### 3.0.1 โครงสร้าง 3 ระดับ (ทะเบียนเดียว ห้ามแตกสายอื่น)

```
Warehouse (คลัง/สาขา)          WH-BKK-01 · WH-CNX-01 · WH-TRN (in-transit เสมือน)
      └── Zone (โซน/พื้นที่)     A · B · C · ST (staging) · QA (quarantine) · DM (ของเสีย)
              └── Bin (ช่องเก็บ)  A-01-02-C   = โซน A · แถว 01 · ช่อง 02 · ชั้น C
```

| ระดับ | รหัส | ใครเป็นเจ้าของข้อมูล | ตัวอย่าง |
|---|---|---|---|
| **Warehouse** | `WH-XXX-NN` | Warehouse Master (soft-ref LD-4C-02) | `WH-BKK-01` คลังกลางบางนา · `WH-CNX-01` คลังเชียงใหม่ |
| **Zone** | ตัวอักษร/ตัวย่อ ภายในคลัง | Location Master (config) | `A` สินค้าหมุนเร็ว · `B` วัสดุก่อสร้าง · `C` ของหนัก/นอกอาคาร · `ST` พักรับเข้า · `QA` กักกัน · `DM` ของเสีย |
| **Bin** | `<zone>-<แถว>-<ช่อง>-<ชั้น>` | Location Master (config) | `A-01-02-C` · `B-03-01-A` · `ST-DOCK-01` · `QA-01` |

> **การอ้างอิงแบบเต็ม** ที่ทุก feature ใช้ร่วมกัน: `WH-BKK-01 / A / A-01-02-C`
> **การอ้างอิงย่อในหน้าจอ**: แสดง bin code พอ (`A-01-02-C`) + tooltip บอกคลัง

### 3.4 Computed / แสดงอย่างเดียว

| ค่า | สูตร |
|---|---|
| เก็บแล้วสะสม (ต่องาน) | `Σ จำนวนที่เก็บ ของ movement ประเภทจัดเก็บ − Σ ของ movement กลับรายการ` |
| คงค้างเก็บ (ต่องาน) | `จำนวนที่ต้องเก็บตั้งต้น − เก็บแล้วสะสม` (ไม่ต่ำกว่า 0) |
| คงค้างหลังครั้งนี้ | `คงค้างเก็บ − Σ จำนวนที่เก็บทุกแถวปลายทาง` |
| สถานะงาน (derive) | `คงค้างเก็บ = 0` → **จัดเก็บแล้ว** · มีผู้ถือครอง → **กำลังจัดเก็บ** · GRN ต้นทางถูกกลับรายการ → **ถอนออก** · นอกนั้น **รอจัดเก็บ** |
| อายุงานค้าง | `เวลาปัจจุบัน − เวลาที่เข้าคิว` — ป้ายเตือนตามเกณฑ์ **NC rules** |
| ปริมาณที่ใช้ไปแล้วของ bin | `Σ เข้ามา − Σ ออกไป` ของ movement ทุกชนิดที่ bin นั้น (รวมของ StockAdj/Transfer ในอนาคต) |
| ความจุคงเหลือของ bin | `ความจุสูงสุด − ปริมาณที่ใช้ไปแล้ว` (ว่าง = ไม่จำกัด → แสดง "—") |
| สถานะ bin (derive) | ไม่มีของ → `ว่าง` · มีของ + ยังเหลือที่ → `มีของ` · ความจุคงเหลือ ≤ 0 → `เต็ม` · ตั้งล็อกมือ → `ล็อก` (ทับทุกกรณี) |
| **ยอดคงเหลือราย bin** | `Σ movement เข้า − Σ movement ออก` ต่อ (bin, สินค้า) — **ฐานที่ StockAdj + StockTransfer อ่าน** |
| KPI: อัตรา override | `จำนวนแถวปลายทางที่ที่มา = override ÷ แถวปลายทางทั้งหมด` (ช่วงเวลาตาม filter) |
| KPI: งานค้างเกินเกณฑ์ | นับงานที่ `อายุงานค้าง > เกณฑ์ NC rules` |

## 7. Data behaviour

- **ไม่มีเลขรันเอกสาร** — Putaway ไม่ใช่เอกสาร (OB-9) · รหัสงาน `PT-<seq>` เป็นรหัสภายในเพื่อ trace เท่านั้น **ห้ามแสดงเป็นเลขที่ใบ ห้ามประกาศผ่าน doccfg**
- **Soft-reference (LD-4C-02)**: สินค้า · หน่วย · คลัง · โซน · bin · พนักงาน = combobox picker · **ไม่ FK validate · nullable** — ค่าที่หายจาก master ยังแสดงข้อความเดิม ไม่พัง (BR-23)
- **Inventory movement append-only** (OB-8 · BR-16/BR-17): ยืนยัน → movement `ต้นทาง → bin` ทันที · **ห้ามลบ ห้ามแก้** · กลับรายการ = สร้าง movement ตรงข้ามผูกกับแถวเดิม (ของเดิมยังอยู่ในประวัติ)
- **ยอดคงเหลือราย bin** = ผลลัพธ์ derive จาก movement ทั้งหมด — **ไม่มีตารางยอดที่แก้มือได้** (การแก้ยอด = **StockAdj**)
- **quarantine** (`OQ-GRN-01 [ASSUMED]`): ของ QC ไม่ผ่านอยู่ในโซน `quarantine` · **ไม่นับเป็นของขายได้** · Putaway จัดเก็บได้เฉพาะภายใน bin quarantine ด้วยกัน · ออกจริงทางเดียวคือ **RTV** — `TODO: RTV handoff`
- **in-transit** (`OQ-TRF-01 [ASSUMED]`): จองประเภท location ไว้ใน model แล้ว (§3.0.2) แต่ **รอบนี้ไม่มีใครเขียน** — เจ้าของคือ **F-WH-STKTRF** (`TODO: stock-transfer handoff`)
- **Audit append-only**: รับงาน · คืนงาน · ปลดล็อก · ยืนยัน (พร้อมปลายทาง/จำนวน/ที่มาการเลือก/เหตุผล override) · กลับรายการ · ล็อก/ปลดล็อก bin — ต่อท้ายอย่างเดียว **ไม่มี hard delete** (BR-21)
- **ไม่มี soft archive ของงาน** — งานที่ `ถอนออก` ยังค้นเจอผ่าน filter "รวมที่ถอนออก"
- **แจ้งเตือน**: **ไม่ประกาศรอบนี้** — chip ไม่มี `ntf` (OB-9) · ถ้าอนาคตต้องเตือน "งานค้างเกินเกณฑ์" ให้ไปประกาศที่ ENG-NOTIFY ห้าม hardcode
- **บัญชี**: putaway = ย้ายภายในคลังเดียวกัน **โดยหลักไม่กระทบมูลค่ารวม** → ป้าย "ไม่กระทบบัญชี" + `TODO: JE posting` (W5) เผื่อกรณีข้าม valuation area `[AI-DRAFT]`
- **Threshold ทุกตัว** (aging · soft lock · ย้อนกลับรายการกี่วัน) → **NC rules / config** ไม่อยู่ feature code (BR-20)
- **วันที่-เวลา**: **ค.ศ. ล้วน** ทุกจุด (BR-22)
