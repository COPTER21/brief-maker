# 04_DB — F-PUR-PR · PR ใบขอซื้อ

> Audience: DBA / BE dev
> **LOCK-SR:** ผู้ขาย · สินค้า · ศูนย์ต้นทุน · หน่วยนับ = **soft-reference** — เก็บเป็นค่า ไม่สร้าง FK constraint ไม่ตรวจความมีอยู่

## §4.1 Tables Overview

| Table | คำอธิบาย | ชนิด |

## §4.3 Relationships

```
t_pr_header 1 ──< t_pr_line            (FK จริง · cascade delete เฉพาะ draft)
            1 ──< t_pr_approval_slot   (FK จริง · append-only)
            1 ──< t_pr_attachment      (FK จริง)
            1 ──< t_pr_history         (FK จริง · append-only)
            1 ──< t_pr_vendor_suggest  (FK จริง)

t_pr_header ··> cost_center · item · uom · vendor   ← soft-ref: เก็บค่า ไม่มี FK constraint ไม่ validate การมีอยู่
t_pr_header ··> ทะเบียน DOA · ENG-DOC-NUM · ENG-NOTIFY · ENG-CSQ   ← เรียกผ่าน service เท่านั้น
```

## §4.6 Data Classification — นิยามและการบังคับใช้

### 4.6.1 นิยาม 4 ระดับ
| ระดับ | นิยาม | ในฟีเจอร์นี้ |
|---|---|---|
| **Public** | เปิดเผยได้ทั่วไป | `currency` |
| **Internal** | พนักงานในองค์กรเข้าถึงได้ | ค่าเริ่มต้นของฟีเจอร์นี้ |
| **Confidential** | จำกัดเฉพาะผู้เกี่ยวข้องกับเอกสาร | ราคา · ยอดเงิน · งบ · ผู้ขายที่แนะนำ |
| **Restricted** | ต้องขออนุมัติเป็นรายกรณี + ลงทะเบียน Restricted Resources | **ไม่มีในฟีเจอร์นี้** |

### 4.6.2 การบังคับใช้
| ชั้น | Confidential | Internal |
|---|---|---|
| **DB** | column-level grant ตาม role · ห้าม `SELECT *` จาก report user | grant ปกติ |
| **API** | ตัดฟิลด์ราคาออกจาก response ของผู้ที่ไม่มีสิทธิ์ดูเอกสาร (ดู `02_API §2.8`) | — |
| **UI** | ผู้ตรวจสอบ/จนท.จัดซื้อเห็นได้ (อยู่ในสายงาน) · ผู้ไม่เกี่ยวข้องเปิดใบไม่ได้เลย | — |
| **Audit** | ทุกการอ่านเอกสารที่ไม่ใช่เจ้าของบันทึกลง access log | — |

### 4.6.3 Default
**ไม่มี column ใดตั้ง Public โดยปริยาย** — default ของฟีเจอร์นี้คือ **Internal** · `currency` เป็น Public เพราะเป็นค่าคงที่ระดับระบบ

### 4.6.4 PII overlay
`requester_id/name` · `approver_id/name/position` · `actor_id` · `submitted_by` · `approved_by` · `uploaded_by` · `created_by`/`updated_by`
= **ชื่อและตำแหน่งพนักงานภายในเท่านั้น** — ไม่มีเลขบัตรประชาชน ที่อยู่ เบอร์โทร หรือข้อมูลอ่อนไหวตาม PDPA

### 4.6.5 Retention
`t_pr_history` และ `t_pr_approval_slot` = **เก็บถาวร** (หลักฐานการอนุมัติทางบัญชี) · ห้ามลบแม้ใบถูกยกเลิก

### 4.6.6 Policy Center linkage
**ไม่มีฟิลด์ Restricted** → ไม่ต้องลงทะเบียน Restricted Resources
Classification override (ถ้าองค์กรต้องการยกระดับราคาเป็น Restricted) ทำที่ **Data Classification module (Policy Center)** ไม่แก้โค้ดฟีเจอร์
