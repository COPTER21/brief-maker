# 05_RULES — F-PUR-PR · PR ใบขอซื้อ

> Audience: BE dev + QA
> **ทุกกติกาต้องบังคับที่ชั้นบริการด้วย ไม่ใช่แค่หน้าจอ** (BRD §14.3)

## §5.1 Business Rules

| BR | กติกา | ระดับ | บังคับที่ | test |
|---|---|---|---|---|
| **BR-01** | ส่งอนุมัติได้เฉพาะสถานะร่าง | ตายตัว | FN-08 · `PR_NOT_DRAFT` | AT-20 |
| **BR-02** | สายอนุมัติเลือกจากทะเบียน DOA **ตามยอดสุทธิ ณ เวลากดส่ง** แล้วบันทึกติดกับใบ — แก้ทะเบียนภายหลังไม่กระทบใบที่ส่งแล้ว | ตายตัว | FN-08 · ENG-DOA-RESOLVE · snapshot ลง `t_pr_approval_slot` | AT-05 · AT-21 |
| **BR-03** | **ผู้ขอเซ็นอนุมัติใบของตัวเองไม่ได้** (แบ่งแยกหน้าที่) | ตายตัว | FN-08 (`PR_SELF_APPROVAL_FORBIDDEN`) · FN-11 (`PR_NOT_CURRENT_APPROVER`) | AT-06 · AT-22 |
| **BR-04** | แก้ยอดหลังส่งอนุมัติไม่ได้ — ต้องเรียกคืนแล้วส่งใหม่ (เลือกสายใหม่ตามยอดใหม่) | ตายตัว | FN-06 · `PR_NOT_EDITABLE` | AT-09 · AT-10 |
| **BR-05** | เลขที่เอกสารออก**ตอนส่งอนุมัติเท่านั้น** และเปลี่ยนไม่ได้ | ตายตัว | FN-08 · `ENG-DOC-NUM` · `ux_pr_no` unique | AT-04 · AT-23 |
| **BR-06** | ราคาในใบขอซื้อเป็น **ราคาประมาณ** ไม่ผูกพันผู้ขาย | ตายตัว | label บนจอ + `unit_price_est` | AT-24 |
| **BR-07** | **งบไม่พอ = เตือน ไม่บล็อก** | ยืดหยุ่น | FN-07 (mock) | AT-11 |
| **BR-08** | ระดับวงเงินและผู้ถือสิทธิ์อนุมัติ **ไม่อยู่ในฟีเจอร์นี้** | ยืดหยุ่น | ทะเบียน DOA กลาง | AT-21 |
| **BR-09** | รูปแบบเลขเอกสารและนโยบายเก็บสำเนา **ไม่อยู่ในฟีเจอร์นี้** | ยืดหยุ่น | `ENG-DOC-NUM` / `ENG-DOC-STORE` | AT-23 |
| **BR-10** | ช่องทางแจ้งเตือน **ไม่อยู่ในฟีเจอร์นี้** | ยืดหยุ่น | `ENG-NOTIFY` | AT-25 |
| **BR-11** | ประวัติเป็นแบบ **เพิ่มอย่างเดียว** ไม่มีการลบถาวร | ตายตัว | `t_pr_history` grant INSERT/SELECT เท่านั้น | AT-26 |
| **BR-12** | ผู้ขายที่แนะนำ **ไม่ผูกพันผลการจัดซื้อ** — ผู้ขายจริงตัดสินที่ขั้นเทียบราคา | ตายตัว | soft-ref · ไม่มี FK | AT-27 |

> **§9.5 ข้อสังเกต:** กติกายืดหยุ่นทั้ง 4 ข้อ (BR-07..BR-10) **ไม่มีตัวเลข/รายชื่อใดอยู่ในฟีเจอร์นี้เลย** — เปลี่ยนได้โดยไม่แตะโค้ด

## §5.2 Validation Rules

| V | กติกา | ข้อความ (verbatim จากจอ) | บังคับที่ | test |
|---|---|---|---|---|
| **V-01** | หน่วยงาน · วันที่เอกสาร · วันที่ต้องการใช้ · ประเภท · เหตุผล = บังคับ | `กรุณากรอกข้อมูลให้ครบถ้วน` | FN-04 | AT-01 |
| **V-02** | วันที่ต้องการใช้ ≥ วันที่เอกสาร | ทำเครื่องหมายช่อง + คำอธิบายใต้ช่อง | FN-04 | AT-02 |
| **V-03** | ต้องมี ≥1 รายการที่มีชื่อ · จำนวน>0 · ราคา>0 | `ต้องมีอย่างน้อย 1 รายการที่ระบุสินค้า จำนวน และราคาครบ` | FN-05 | AT-03 |
| **V-04** | ห้ามมีแถวว่าง | `มีแถวว่าง {N} แถว — กรุณาระบุรายการหรือลบแถวออก` | FN-05 | AT-15 |
| **V-05** | ห้ามสินค้า+หน่วยซ้ำกัน | `มีสินค้าและหน่วยซ้ำกัน: {ชื่อ} — รวมเป็นแถวเดียว` | FN-05 | AT-16 |
| **V-06** | ไฟล์แนบ: PDF·JPG·PNG·XLSX ≤10MB | `ไฟล์ "{ชื่อ}" ({ขนาด}) แนบไม่ได้ — รองรับเฉพาะ PDF · JPG · PNG · XLSX ขนาดไม่เกิน 10 MB ต่อไฟล์ (ไฟล์อื่นที่แนบไว้ยังอยู่ครบ)` | FN-15 | AT-17 |
| **V-07** | เหตุผลไม่อนุมัติ/ยกเลิก ≥ 3 ตัวอักษร | ปุ่มยืนยันถูกปิดจนกว่าจะครบ | FN-13 · FN-14 | AT-07 · AT-18 |
| **V-08** | ต้องเลือกผู้อนุมัติครบทุกขั้นก่อนส่ง | ปุ่ม `ส่งอนุมัติ` ถูกปิด | FN-08 | AT-05 |
| **V-09** | ส่วนลดรายบรรทัด 0–100% · ส่วนลดท้ายบิลไม่เกินยอดหลังภาษี | คำนวณตัดยอดอัตโนมัติ | ENG-PR-CALC | AT-28 |

| **EC-02** | ไม่ระบุศูนย์ต้นทุน | **ข้ามการตรวจงบ ไม่ถือเป็นข้อผิดพลาด** · FN-07 คืน `{ok:true, remaining:null}` | AT-12 |

| **EC-05** | ไฟล์แนบผิดชนิด/ใหญ่เกิน | error inline · **ไฟล์อื่นที่แนบไว้ยังอยู่ครบ ไม่ล้มทั้งฟอร์ม** | AT-17 |
| **EC-06** | ผู้ไม่มีสิทธิ์เปิดดู | `PR_NOT_VISIBLE` (403) · ผู้ที่ดูได้แต่ไม่ใช่ผู้อนุมัติขั้นปัจจุบัน → เห็นใบแต่**ไม่มีปุ่มอนุมัติ** | AT-06 |
| **EC-07** | งบไม่พอ | แถบเตือน + pill `งบไม่พอ (จำลอง)` · **ยังส่งอนุมัติได้** · ผู้อนุมัติเห็นคำเตือนเดียวกัน | AT-11 |

## §5.4 State Transition Rules

| จาก | เหตุการณ์ | ไป | เงื่อนไข | ผลข้างเคียง |
|---|---|---|---|---|
| `draft` | ส่งอนุมัติ | `pending_approval` | ข้อมูลครบ + ≥1 รายการ + slot ครบ + ไม่ใช่ตัวเอง | ออกเลขที่ · แช่แข็งสาย · `pr_submitted` |
| `pending_approval` | อนุมัติ (ยังไม่ครบ) | `pending_approval` | อยู่ในขั้นปัจจุบัน | บันทึกลายเซ็น · แจ้งขั้นถัดไป |
| `pending_approval` | อนุมัติ (ขั้นสุดท้าย) | `approved` | เหมือนบน | `pr_approved` · `doc.approved` (EC/estimated) · เก็บสำเนา `approved_final` |
| `pending_approval` | ไม่อนุมัติ | `rejected` | มีเหตุผล ≥3 | ขั้นที่เหลือถูกข้าม · `pr_rejected` (**ปิดไม่ได้**) |
| `pending_approval` | เรียกคืน | `draft` | **ผู้ขอเท่านั้น** | slot → `void` · `pr_recalled` |
| `draft` | ยกเลิก | `cancelled` | มีเหตุผล | — (**ไม่ยิง** `doc.cancelled`) |
| `approved` | ยกเลิก | `cancelled` | มีเหตุผล + ยังไม่มี PO อ้าง | `pr_cancelled` · `doc.cancelled` (EC/avoided) |

> **ทุก transition เขียนลง `t_pr_history` แบบเพิ่มอย่างเดียว** · ไม่มีการลบถาวรในฟีเจอร์นี้
> `rejected` และ `cancelled` เป็นสถานะปลายทาง — ทางเดินต่อเดียวคือ **ทำสำเนาเป็นใบใหม่**

## §5.7 D-CLASS · Data Classification Enforcement

| ระดับ | ฟิลด์ | การบังคับใช้ในฟีเจอร์นี้ |
|---|---|---|
| **Confidential** | ราคา/ยอดเงินทุกตัว · `budget_check_result` · ผู้ขายที่แนะนำ | (1) **API-02 ตัดฟิลด์ออกจาก response** ของผู้ที่ไม่มีสิทธิ์ดูเอกสาร (2) DB column-level grant (3) บันทึก access log ทุกการอ่านเอกสารที่ไม่ใช่เจ้าของ |
| **Internal** | ฟิลด์ที่เหลือ | ขอบเขตการมองเห็นตาม role ใน FN-01 (BRD §4.2) |
| **PII** | ชื่อ/ตำแหน่งผู้ขอและผู้อนุมัติ | ข้อมูลพนักงานภายใน · ไม่ใช่ sensitive PDPA · แสดงได้ในบริบทเอกสาร |
| **Restricted** | **ไม่มี** | ไม่ต้อง wire Restricted Resources registry |

> **หลักการ:** ฟีเจอร์นี้ไม่ตั้ง Public โดยปริยาย — default = **Internal** (ยกเว้น `currency` ที่เป็นค่าคงที่ระดับระบบ)
