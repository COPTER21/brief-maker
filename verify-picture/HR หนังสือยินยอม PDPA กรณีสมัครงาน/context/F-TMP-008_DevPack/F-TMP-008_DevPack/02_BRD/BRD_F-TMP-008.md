## 1. Business Context
### 1.1 ปัญหา / โอกาส
วันนี้หนังสือยินยอม PDPA ของผู้สมัครงานและบุคลากรเป็นกระดาษ เซ็นแล้วเก็บเข้าแฟ้ม ทำให้ (1) ค้นหาไม่ได้ว่าใครยินยอมข้อไหนบ้าง (2) ไม่รู้ว่าหนังสือที่เซ็นเป็นฉบับไหน เมื่อเปลี่ยนถ้อยคำแล้วของเก่ายังอ้างได้หรือไม่ (3) เมื่อเจ้าของข้อมูลใช้สิทธิถอนความยินยอม ไม่มีที่บันทึกให้ต้นทางหยุดใช้ข้อมูล และ (4) ตอบผู้ตรวจไม่ได้ว่าข้อมูลอ่อนไหวที่บริษัทถืออยู่มีฐานความยินยอมครบหรือไม่

### 1.2 เป้าหมาย
ขึ้นหนังสือยินยอมฉบับนี้เป็นเอกสารในระบบ CUBE โดยหน้าตาแบบพิมพ์เหมือนกระดาษเดิม 1:1 เก็บ **หลักฐานความยินยอมรายข้อ** พร้อม **วันที่ให้ความยินยอม** และ **ฉบับ (revision) ของหนังสือ** และรองรับ **การถอนความยินยอม** ที่ผูกกับใบเดิม

### 1.3 ตัวชี้วัด
| ตัวชี้วัด | ค่าเป้าหมาย |
|---|---|
| ผู้สมัครงาน/บุคลากรที่มีหนังสือยินยอมในระบบ | 100% ของผู้ที่เริ่มกระบวนการหลังขึ้นระบบ |
| เวลาค้นหาหลักฐานความยินยอมของ 1 คน | < 1 นาที (จากเดิมค้นแฟ้มกระดาษ) |
| คำขอถอนความยินยอมที่บันทึกพร้อมวันที่และผู้บันทึก | 100% |

### 1.4 ที่มา

## 2. Scope
### 2.1 In Scope
1. หน้ารายการหนังสือยินยอม (ค้นหา · ตัวกรองสถานะ/ผลความยินยอม/ฝ่าย · ส่งออก CSV)
2. สร้าง/แก้ไขร่าง 3 ขั้น (ข้อมูลหลักหนังสือยินยอม › เอกสารแนบ › ตรวจสอบและยืนยัน) — เลือก **ยินยอม/ไม่ยินยอม รายข้อ** ตามรายการของฉบับนั้น
3. ยืนยันความยินยอม → ออกเลขที่ · บันทึกวันที่ให้ความยินยอม · snapshot ฉบับของหนังสือ · เก็บสำเนา PDF เป็นหลักฐาน
4. ถอนความยินยอม (ทั้งฉบับหรือรายข้อ) พร้อมวันที่ ผู้บันทึก และเหตุผล — ใบเดิมคงอยู่เป็นหลักฐาน
5. แบบพิมพ์ Replica A4 เหมือนกระดาษเดิม (ทุกสถานะ) + PDF Preview ในหน้าจอ
6. เอกสารแนบ (Document Center) · สิทธิ์การมองเห็นตามมติ G8

### 2.2 Out of Scope
1. **การบังคับใช้ผลความยินยอมกับ module อื่น** (เช่น บล็อกการบันทึกเวลาด้วยข้อมูลชีวภาพเมื่อไม่ยินยอมข้อ 4) — DEC-02 ไม่ส่งต่อระบบอื่นรอบนี้ ประกาศ event ไว้ใน FRD แต่ยังไม่ยิง
2. การแก้ถ้อยคำ/ออกฉบับใหม่ของหนังสือยินยอม (เป็นงานของ ConsentPurpose master + F-DOCCFG revision)
3. การเก็บความยินยอมของลูกค้า/คู่ค้า (ฉบับนี้ใช้กับผู้สมัครงานและบุคลากรเท่านั้น)
4. ลายมือชื่ออิเล็กทรอนิกส์แบบภาพ/ใบรับรอง (DEC-07 ใช้ข้อความ "ยืนยันในระบบ")

### 2.3 Assumptions
- ผู้สมัครงานเข้าระบบได้ (ผ่านลิงก์/บัญชีชั่วคราว) หรือเจ้าหน้าที่บุคคลบันทึกแทนโดยมีหลักฐานการยินยอม — **OQ-01**
- Organization มีค่า `legal_name`, `logo`, `privacy_policy_url` ให้ snapshot ตอนออกเลข
- รายการความยินยอมทั้งหมดในฉบับนี้มาจาก ConsentPurpose master ที่ผูกกับ revision ของหนังสือ

## 4. User Journey
### 4.1 Happy Path
1. เจ้าของข้อมูลเปิดเมนู "หนังสือยินยอม PDPA" → กด "สร้างหนังสือยินยอม"
2. ขั้น 1 ระบบแสดงชื่อ/หน่วยงานจากทะเบียน (ไม่ต้องกรอก) และรายการความยินยอมของฉบับปัจจุบัน → เลือกยินยอม/ไม่ยินยอมให้ครบทุกข้อ
3. ขั้น 2 แนบเอกสารประกอบ (ถ้ามี) · ขั้น 3 ตรวจสอบแล้วกด "บันทึกและยืนยันความยินยอม"
4. ระบบออกเลขที่ · บันทึกวันที่ให้ความยินยอม · snapshot ฉบับของหนังสือ · เก็บสำเนา PDF เป็นหลักฐาน · แจ้งผู้ดูแลงานบุคคล
5. เอกสารเข้าสถานะ "ยินยอมแล้ว" และแก้ไขไม่ได้อีก

### 4.2 Alternative
- **บันทึกร่าง** — ยังเลือกไม่ครบ กดบันทึกแบบร่างไว้ก่อนได้ (ร่างยังไม่มีผลเป็นความยินยอม)
- **ไม่ยินยอมบางข้อ** — ระบบรับได้ แต่เตือนเมื่อเป็นข้อมูลอ่อนไหว และแจ้งผู้ดูแลงานบุคคลให้ตรวจผลต่อกระบวนการปลายทาง
- **ถอนความยินยอม** — เจ้าของข้อมูล (หรือผู้ดูแลงานบุคคลตามคำขอ) เลือกข้อที่ถอน + ระบุเหตุผล → ใบเปลี่ยนเป็น "ถอนความยินยอม" ข้อที่ถอนไม่นับว่ามีผลอีกต่อไป แต่ใบเดิมและสำเนายังอยู่เป็นหลักฐาน
- **ยกเลิกเอกสาร** — เฉพาะร่าง/ยังไม่มีผล (เช่น บันทึกผิดคน) ต้องมีเหตุผล

## 7. Status & Lifecycle
| สถานะ | ความหมาย | ไปต่อได้ |
|---|---|---|
| ร่าง (draft) | ยังไม่มีผลเป็นความยินยอม | ยืนยัน → ยินยอมแล้ว · ยกเลิก |
| รอพิจารณา (pending) | เฉพาะเมื่อลูกค้าเพิ่มขั้น DOA ภายหลัง | รับหนังสือ → ยินยอมแล้ว · ไม่รับหนังสือ |
| ยินยอมแล้ว (confirmed) | มีผลเป็นหลักฐานความยินยอม · แก้ไขไม่ได้ | ถอนความยินยอม |
| ถอนความยินยอม (withdrawn) | ข้อที่ถอนไม่มีผลต่อไป ใบเดิมคงอยู่ | — (ออกฉบับใหม่ถ้าต้องการให้ความยินยอมอีกครั้ง) |
| ยกเลิก (cancelled) | ใบที่ยังไม่มีผลและไม่ใช้ต่อ | — |

## 14. Security & Compliance
- ข้อมูลอ่อนไหวตาม PDPA ม.26 (สุขภาพ · ศาสนา · ชีวภาพ · ประวัติอาชญากรรม) → Data Classification **Restricted**
- การเข้าดู/ส่งออกต้องบันทึก audit · ส่งออก CSV ไม่รวมถ้อยคำข้อมูลอ่อนไหวรายข้อ (เฉพาะผลยินยอม/ไม่ยินยอม)
- ห้ามเก็บ credential ในเอกสาร · ห้ามใช้ข้อมูลบุคคลจริงจากไฟล์ลูกค้าเป็นข้อมูลตัวอย่างใน prototype/แบบพิมพ์
- สำเนา PDF ที่เก็บเป็นหลักฐานต้องแก้ไขไม่ได้และผูกกับ revision ของหนังสือ

## 15. Health Check / Monitoring
- จำนวนใบสถานะ "ร่าง" ค้างเกิน 7 วัน (เจ้าของข้อมูลยังไม่ยืนยัน)
- จำนวนการถอนความยินยอมต่อเดือน + เวลาเฉลี่ยจากแจ้งถึงบันทึก
- จำนวนใบที่ไม่ยินยอมข้อมูลอ่อนไหว แยกตามข้อ
