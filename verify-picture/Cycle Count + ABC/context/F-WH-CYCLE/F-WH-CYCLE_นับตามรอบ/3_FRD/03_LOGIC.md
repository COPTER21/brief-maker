# Logic registry and algorithms
FN-01 `validatePolicy/savePolicy`: basis value(default)|value_times_frequency(optional), thresholds nonnegative sum100, effective ISO date, positive window/cadence; append new version, do not rewrite plans; `policyFor(asOf)` chooses greatest effectiveDate≤asOf and version tie, so future policy does not immediately alter current ABC. FN-02 `classify`: score=value default, weighted=value×qualifying count optional; values/counts nonnegative, sort descending score then itemCode, cumulative-before thresholds A/B/C, total0 all C, report actual shares. FN-03 `createPlan`: Item/Warehouse/UoM/expected snapshot and policy effective on plan asOf captured, due add class months to last accepted review with month-end clamp `[ASSUMED]`, assign counter. FN-04 `counterProjection`: server omit expected/value/variance before/after submit and on export; reviewer projection only after submitted. FN-05 `submit`: count blank invalid, zero valid, finite≥0, countedBase=count×captured conversion, lock attempt/assignment/version. FN-06 `review`: submitted latest attempt only; accept requires reason, recount opens new blank attempt and retains old. FN-07 `dispatch`: reviewed nonzero only, send W3 mock with latest accepted delta, same key same ref, no stock mutation; zero closes without dispatch. FN-08 append-only policy/plan/attempt/review/mock events, optimistic version/idempotency. FN-09 search/filter/count from current sessions/classes, role-scoped export. Local JS proves arithmetic/state only, not API security or DB atomicity.
