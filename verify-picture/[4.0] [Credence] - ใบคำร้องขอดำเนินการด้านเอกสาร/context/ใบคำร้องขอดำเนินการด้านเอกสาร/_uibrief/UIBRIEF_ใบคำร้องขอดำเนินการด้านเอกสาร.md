## §7 Interaction Spec
- Esc chain: ปฏิทิน → modal → drawer (handler ใน BASE-KIT + be-datepicker capture)
- Wizard ถัดไป: `wizNext()` → `validateMain()` ไม่ผ่าน = อยู่ขั้น 1 + `.is-invalid` + toast "กรุณากรอกข้อมูลให้ครบถ้วน" · วันที่บังคับใช้ก่อนวันที่เขียนใบ DAR = ข้อความเตือนใต้ช่อง (ไม่บล็อก)
- พิมพ์ในช่อง = soft update `setF2()` / `setRel()` (ไม่ rebuild) · การ์ดสรุปอัปเดต `#sumPurpose` `#sumDist` (`sumSync()`)
- ส่งอนุมัติ: `openSubmit()` → `.slot-row` ต่อขั้น `resolveDoa()` (ค่าเริ่ม 4 ขั้น ผู้ตรวจสอบ · ผู้อนุมัติ · ผู้ควบคุมเอกสาร · ผู้จัดการฝ่ายสำนักเลขานุการบริษัท) → `confirmSubmit()` · อนุมัติ `confirmApprove()` (sequential · ครบ = อนุมัติแล้ว) · ไม่อนุมัติ/ยกเลิก `confirmReason()` (ไม่อนุมัติ = กลับร่าง) · ลงนามรับ `openReceive()` → `confirmReceive()` (บังคับเลือกผู้รับ)
- ทุก commit ผ่าน `commitRejected()` (prototype จำลอง 409/403/500)
