# 01_UI — F-WH-LOT

## Layout Decision Log
| Page | HTML route | Observed pattern | Evidence | FRD authority |
|---|---|---|---|---|
| P-01 Lot list | `#/records` | Pattern A console list | `.page-head` → `.tabs` → `.stats` → `.toolbar > .search-box` → `.tbl` | actions in `.ph-actions` |

## P-01 List states and controls
`renderTableOnly()` filters/sorts rows and updates `#tableFoot`; `#empty` displays “ไม่พบรายการที่ตรงกับตัวกรอง”. Stats counts derive from lotRows/state.rows/movements, not fixed targets. Buttons “ส่งออก”, “สร้างรายการ” are top-right actions. No banner/hint. Canonical toolbar block retains inline widths mandated by #106.

## P-02 Trace
`#traceLot` switches selected lot; `lotTrace()` filters by `lot`; row click calls `lotShowMovement(id)` to show source, destination, predecessor and successor. Missing history renders “ยังไม่มีการเคลื่อนไหวของล็อตนี้”. GRN/Transfer labels are reference snapshots, not active transaction controls.

## P-03 Policy and recommendation
Searchable master option anatomy is item code/name/warehouse/availability, bound to item configuration. “บันทึกการตั้งค่า” calls `lotSaveSetting()`. “แนะนำล็อต” calls `eligibleLots()`, showing ordered lot, expiry and available count. “เปิดกฎแจ้งเตือน” calls NC soft hook only. Config error: “เปิดวันหมดอายุต้องติดตามล็อตหรือซีเรียล”.

## P-04 Drawer
Create shows item picker, lot code, serial only for serial-mode item, expiry only for expiry-enabled item. Validation text “เลือกสินค้าจากรายการ”, “กรอกรหัสล็อต”, “กรอกซีเรียล”, “กรอกวันหมดอายุ”, “ซีเรียลนี้ถูกใช้แล้ว”. Save disables button and shows “กำลังบันทึก…” then “บันทึกแล้ว”. Esc/backdrop/close dismiss; cancel does not persist. View is read-only and shows selected lot availability/movements.

## Demo-only elements
The topbar `DEMO` badge identifies fixture identity. There is no persona switcher. Production identity comes from authenticated session; demo badge is removed in production.

## Accessibility/responsive limitations
Buttons and inputs have visible labels; tab order follows DOM. Body adapts at 1024/767 breakpoints; Scan-specific mobile exception does not apply. Actual browser layout/Thai font rhythm is NOT-CHECKED (S3c browser launch failed), so visual QA is an explicit handoff task.
