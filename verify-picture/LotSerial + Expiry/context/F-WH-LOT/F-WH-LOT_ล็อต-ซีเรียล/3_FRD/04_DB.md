# 04_DB — F-WH-LOT

## §4.1 Tables and relationships
`T_item_tracking_policy` versioned 1-to-many per tenant+item; `T_lot_identity` many per tenant+item; `T_lot_audit` append-only by subject. W3-LITE movement and QHold availability are read models, not owned tables. No FK from soft Item/Warehouse refs to master storage.

## §4.3 Keys and indices
Unique `(tenant_id,item_code,serial_code)` partial where serial_code not null. Unique `(tenant_id,item_code,version)` policy. Audit idempotency unique `(tenant_id,idempotency_key)`. Index `(tenant_id,item_code,expiry_date)` for list/recommendation; movement index belongs to W3-LITE. No hard delete; history retention policy central.

## §4.4 State/enum
`tracking_mode = none|lot|serial`; display status `พร้อมใช้|กักอยู่|หมดอายุ` is derived from upstream availability/date, not freely editable; movement kind is W3-LITE contract and never mutated here.

## §4.6 Data classification governance
### §4.6.1 Inventory
All owned columns listed with classification and PII flags in §4.2.
### §4.6.2 Collection
Only operational item/lot refs and actor IDs are collected; no customer/person names.
### §4.6.3 Access
Tenant-scoped read; policy mutation config role; audit read auditor role.
### §4.6.4 Storage/retention
Append-only audit; no hard delete; retention follows central policy [ASSUMED] Security owner.
### §4.6.5 Sharing
CSQ/NC event envelopes include minimal ref/expiry fields, no raw actor IDs unless engine contract explicitly requires them.
### §4.6.6 Restricted resources
No field marked Restricted by current classification. Security owner must confirm actor ID treatment and register if central policy raises it to Restricted.
