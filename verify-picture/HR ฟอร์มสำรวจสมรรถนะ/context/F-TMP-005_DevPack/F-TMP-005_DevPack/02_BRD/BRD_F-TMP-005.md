## 1. ที่มาและปัญหา
ลูกค้าใช้ **แบบฟอร์มสำรวจสมรรถนะ (FM-HRM-40)** เป็นกระดาษ ให้พนักงานบันทึกสมรรถนะหลักและสมรรถนะเฉพาะสายงาน
พร้อมระดับ 1–4 แล้วให้หัวหน้าลงนามรับรอง ปัญหาที่พบของการทำบนกระดาษ:
1. ผลประเมินกระจายอยู่ตามแฟ้ม ไม่สามารถเรียกดูย้อนหลังรายคน/รายฝ่ายได้
2. คำอธิบายระดับ 1–4 ถูกพิมพ์ติดกับแบบฟอร์ม เมื่อองค์กรปรับนิยามต้องพิมพ์ฟอร์มใหม่ทั้งชุด
3. ไม่มีร่องรอยว่าใครเห็นชอบเมื่อไร และแก้ไขอะไรไปบ้าง
4. ฝ่ายบุคคลรวบรวมแผนพัฒนา (อบรม / Coaching / OJT) ต่อไม่ได้โดยไม่คีย์ซ้ำ

## 2. วัตถุประสงค์ทางธุรกิจ
| # | เป้าหมาย | วัดผลอย่างไร |
|---|---|---|
| O-1 | ขึ้นแบบฟอร์มเข้าระบบโดยหน้าตาเอกสารพิมพ์ออกมาเหมือนกระดาษเดิม | ลูกค้าเปิด PDF แล้วจำแบบฟอร์มของตัวเองได้ทันที |
| O-2 | เก็บผลสำรวจสมรรถนะเป็นข้อมูล เรียกดู/กรอง/ส่งออกได้ | ค้นตามผู้รับประเมิน ตำแหน่ง ฝ่าย แนวทางการพัฒนา · ส่งออก CSV |
| O-3 | มีร่องรอยการเห็นชอบตามสายอนุมัติจริง | ทุกใบมี approval_chain + ประวัติ append-only |
| O-4 | นิยามระดับสมรรถนะแก้ได้โดยไม่ต้องแก้โปรแกรม | ฝ่ายบุคคลแก้ที่หน้า config แล้วแบบพิมพ์เปลี่ยนตามทันที |

## 3. ขอบเขต
### 3.1 อยู่ในขอบเขต
- สร้าง / แก้ร่าง / ส่งอนุมัติ / เห็นชอบ / ส่งกลับแก้ไข / ยกเลิก ตามแบบ FM-HRM-40
- ช่องทั้งหมดตรงกระดาษ **1:1** — ข้อมูลทั่วไป 4 ช่อง · สมรรถนะหลัก (ซ้ำ) · สมรรถนะเฉพาะสายงาน (ซ้ำ) · สรุปผลและแผนพัฒนา 4 ช่อง
- ตารางระดับการประเมิน 1–4 เป็น **ค่าตั้งค่า** ไม่ใช่ข้อความตายตัว
- แบบพิมพ์ PDF โหมด Replica · แนบไฟล์ · ส่งออก CSV
### 3.2 นอกขอบเขตรอบนี้
- ❌ คะแนนรวม / คะแนนเฉลี่ย / กราฟเปรียบเทียบ (กระดาษไม่มี — DEC-07)
- ❌ ชุดสมรรถนะมาตรฐานต่อตำแหน่ง (master) — ผู้ใช้พิมพ์ชื่อสมรรถนะเอง
- ❌ รอบ/ปีการประเมิน · การเชื่อมผลไปขึ้นเงินเดือนหรือแผนอบรม (DEC-01 · DEC-02)
- ❌ คำสั่งทำซ้ำเอกสาร · ประกาศเมื่ออนุมัติ (DEC-12)

## 5. Business flow
1. พนักงานเปิดเมนู "สำรวจสมรรถนะ" → สร้างแบบฟอร์ม → ระบบออกเลขที่ตอนบันทึกครั้งแรก
2. กรอกวันที่ประเมิน → ใส่รายการสมรรถนะหลักและสมรรถนะเฉพาะสายงาน พร้อมเลือกระดับ 1–4 ต่อรายการ
3. สรุปจุดแข็ง · สิ่งที่ควรพัฒนา · เลือกแนวทางการพัฒนา (อบรมเพิ่มเติม / Coaching / On-the-job Training) · รายละเอียดเพิ่มเติม
4. แนบไฟล์ประกอบ (ถ้ามี) → ตรวจสอบ → ส่งอนุมัติ โดยเลือกผู้พิจารณาตามขั้นที่สายอนุมัติกำหนด
5. ผู้ประเมินเปิดใบ → **เห็นชอบ** (จบ) หรือ **ส่งกลับแก้ไข** (เอกสารกลับเป็นร่างเลขเดิม ให้แก้แล้วส่งใหม่)
6. เมื่อเห็นชอบครบทุกขั้น ระบบเก็บสำเนา PDF ไว้ที่ Document Store — **ไม่มีการเปลี่ยนค่าใด ๆ ในระบบอื่น**

## 8. Edge case ที่ต้องรองรับ
| # | กรณี | ทางออก |
|---|---|---|
| EC-1 | ใส่ชื่อสมรรถนะแต่ลืมเลือกระดับ | บล็อกพร้อมชี้แถวที่ขาด (VR-04) |
| EC-2 | ใส่คำอธิบายแต่ไม่มีชื่อรายการ | บล็อก ให้แก้หรือลบแถว (VR-05) |
| EC-3 | ระบุสิ่งที่ควรพัฒนาแต่ไม่เลือกแนวทางการพัฒนา | เตือนไม่บล็อก (VR-08) |
| EC-4 | ผู้ประเมินส่งกลับแก้ไข | กลับเป็นร่างเลขเดิม resolve สายอนุมัติใหม่ตอนส่งรอบถัดไป |
| EC-5 | รายการสมรรถนะเกินจำนวนบนกระดาษ | แบบพิมพ์ใช้ระยะกระชับ ไม่ตัดข้อมูล |
| EC-6 | องค์กรเพิ่มขั้นอนุมัติภายหลัง | ช่องลงชื่อในแบบพิมพ์เพิ่มตามเอง (1 ช่อง/ขั้น แถวละ ≤4) |
| EC-7 | พนักงานย้ายหน่วยงานหลังออกเลข | เอกสารเก็บ snapshot ตำแหน่ง/แผนก ณ วันที่ประเมิน ไม่เปลี่ยนย้อนหลัง |
| EC-8 | doc_type ยังไม่เปิดใช้ | สร้างใบใหม่ไม่ได้ + แจ้งบนหน้ารายการ |
