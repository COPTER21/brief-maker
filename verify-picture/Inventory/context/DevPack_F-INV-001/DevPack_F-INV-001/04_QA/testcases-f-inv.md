## วิธีที่ agent รัน (Run protocol)

1. **Open the file directly** — `StockByLocation.html` is a single-file SPA; no server or build step is required. Open it in a Chromium-based browser (the prototype was authored and gated against desktop widths ≥1180px — do not run below that width).
2. **Role switching** — this is a single-user mock with no real login. Use the **user chip** in the top-right shell bar to switch the `CURRENT_ROLE` for any case whose `Setup:` line specifies a `role=` other than the default (`finance`). Always switch role **before** the case's `Start:` step, and switch back to `finance` (the default) at the end of a role-specific case unless the next case in sequence also needs that role.
3. **State is in-memory only** — there is no persistence across a full page reload beyond what the hash route encodes. Data mutated by one case (e.g. a completed Break/Pack order, a new ADJ document) **persists for the rest of the same browser session** but resets on a hard reload of the file. Cases that depend on a prior case's mutation (e.g. TC-LOG-01 depending on a fresh adjustment) call this out explicitly in their `Setup:` line — run cases within a group in the documented order where such a dependency exists.
4. **Every case is otherwise independent** (R7) — each case's `Start:` line gives a full route to navigate to directly; you do not need to replay prior navigation to reach it, except where a `Setup:` line says a prior mutation must exist first.
5. **`(ต้อง simulate)`-tagged cases** (TC-RBAC-07) require server/API access this static prototype does not have — mark these **BLOCKED**, not fail, and note the reason.
6. **⚠-flagged cases** (TC-ADJ-15, TC-STK-05, TC-LIST-12, TC-LOG-06, TC-ADJ-01 step 9, TC-ADJ-20 step 4) describe a known ambiguity or seed-data limitation discovered during pack analysis — read the flag text carefully before marking pass/fail; these are instructions for how to interpret an unusual result, not defects in the test case itself.
7. **Record evidence on any fail/blocked** — exact text seen, route at time of failure, and which step. Fill the JSON schema below.
