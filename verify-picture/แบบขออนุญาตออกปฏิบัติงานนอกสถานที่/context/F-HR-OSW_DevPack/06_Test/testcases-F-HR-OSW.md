2. `Setup: role=` → **สลับผู้ใช้ผ่านเมนูชื่อมุมขวาบน › สลับผู้ใช้ (ตัวอย่างสายอนุมัติ)** (prototype เท่านั้น — ระบบจริงคือ login): E01 สิริกานต์ (พนักงาน) · E02 กริสดา (ผู้พิจารณา) · E08 ศศิธร (HR)
3. เคส `(ต้อง simulate)` → runner พิมพ์คำสั่ง inject ใน Setup ที่ DevTools console ก่อน step แรก · ทำไม่ได้ = **BLOCKED**
4. ทำ Start (OPEN route) แล้วทำ Action ทีละ step ตาม verb · หา target จากข้อความบนจอ · ช่องวันที่พิมพ์รูปแบบ YYYY-MM-DD ตาม Input
5. Expected ตรง = ผ่าน step · เคส PASS เมื่อทุก step ผ่าน + ตรง "ผ่านเมื่อ" · ไม่ตรง = FAIL (บันทึก step + สิ่งที่เห็น)
6. เคสติด `[AI-DEFAULT]` ใน Ledger = เกณฑ์ที่ AI ตัดสินแทน BA → FAIL อาจแปลว่า default ผิด ไม่ใช่โค้ดผิด
