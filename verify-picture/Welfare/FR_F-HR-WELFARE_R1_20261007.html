0ขอบเขตการตรวจ

ส่วนที่ไม่ได้ตรวจ อยู่นอกความรับผิดชอบของรายงานฉบับนี้

ตรวจแล้ว

  • ทะเบียนสวัสดิการ — list + drawer สร้าง/แก้/ดู ประเภท
  • คำขอใช้สิทธิ์ — list + drawer คำขอ 4 แท็บ (รายละเอียด/หลักฐาน/คงเหลือ/ประวัติ)
  • คงเหลือรายคน + ผู้ติดตาม
  • รายงานการใช้สิทธิ์
  • สิทธิ์การแสดงข้อมูล/ปุ่มตาม role (admin/manager/employee)
  • สายอนุมัติ DOA + timeline/ประวัติ
  • การแนบ/ดาวน์โหลดไฟล์หลักฐาน + ข้อความบนจอ + layout drawer/modal

ไม่ได้ตรวจ

  • ความถูกต้องของการคำนวณยอดคงเหลือ/ตัดโควตา + บันทึกมูลค่าเข้า 7C·EC — รอบนี้เน้น UX/UI — การคำนวณต้องมีชุดข้อมูลทดสอบแยก
  • การกลับรายการ (reversal) + clawback ปลายทาง Payroll — ต้องมีคำขอ approved + สถานะจ่ายจริง
  • concurrent approve (2 คำขอสิทธิ์เดียวกันพร้อมกัน) + multi-tenant/RLS — ต้องจัด scenario หลาย session พร้อมกัน

1Logic — ทำงานถูกตามกฎธุรกิจ

เทียบผลจริงกับ FRD / Test Case — ข้อที่ไม่ผ่านต้องผูกกับ Bug ในข้อ 4

#กฎ / Scenarioผลที่คาดหวังผลจริงผลอ้างอิง
L-01สิทธิ์การแสดงข้อมูล/ปุ่ม ตาม role (admin/manager/employee)mask มูลค่า/ผู้ติดตาม (•••) + ซ่อน/แสดงปุ่มตามสิทธิ์จริงของ user ตาม Permission Matrix §5.3 (enforce หลังบ้าน BR-DOA-6)ข้อมูลและปุ่มแสดงเหมือนกันทุก account ที่ลอง — เหมือนยังไม่ได้ตรวจสิทธิ์ของ user จริงไม่ผ่านBUG-01
L-02สายอนุมัติผ่าน DOA (resolve / freeze / เดิน 2 ขั้น)ดึงสายจาก DOA (GET /doa/resolve) + freeze snapshot + one-step advanceพฤติกรรมไม่สอดคล้องกับ DOA จริง — เหมือนยังไม่ได้เชื่อมต่อ DOAไม่ผ่านBUG-02
L-03ดาวน์โหลดไฟล์หลักฐานที่แนบในคำขอเปิด/ดาวน์โหลดไฟล์แนบได้จริงกดแล้วขึ้นว่าเป็น mock — ดาวน์โหลดไม่ได้ไม่ผ่านBUG-03
L-04บันทึกประเภทสวัสดิการแบบสัดส่วน % (percent)บันทึกค่าสัดส่วน % ได้จริงและแสดงผลหลังบันทึกกดบันทึกแล้วขึ้นว่าเป็น mock — ไม่บันทึกจริงไม่ผ่านBUG-04

4Bug ที่พบ

เรียงจากรุนแรงมากไปน้อย · ทำซ้ำได้ตามขั้นตอน

BUG-01สิทธิ์ (permission) ไม่ถูก enforce ตาม role — ข้อมูล/ปุ่มแสดงเท่ากันทุก accountCriticalรอแก้
ขั้นตอนทำซ้ำ
  1. ล็อกอินด้วย account คนละ role (employee / manager / admin)
  2. เปิดหน้าคำขอใช้สิทธิ์ + หน้าคงเหลือรายคน
  3. สังเกตการ mask มูลค่า/ผู้ติดตาม และปุ่มอนุมัติ/กลับรายการ
ผลที่ควรเป็นemployee เห็นมูลค่าเป็น ••• และไม่เห็นปุ่มอนุมัติ/กลับรายการ · manager เห็นมูลค่าได้แต่ผู้ติดตามถูก mask (ตาม §5.3)
ผลที่เกิดจริงข้อมูลและปุ่มแสดงเหมือนกันทุก account ที่ลอง — เหมือนยังไม่ได้ตรวจสิทธิ์ของ user จริง
BUG-02สายอนุมัติยังไม่ได้ทำงานร่วมกับ DOA จริงCriticalรอแก้
ขั้นตอนทำซ้ำ
  1. เปิดคำขอ 1 ใบ กดส่งอนุมัติ
  2. ดู slot picker / ผู้อนุมัติที่ resolve มา
  3. ไล่กดอนุมัติทีละขั้น
ผลที่ควรเป็นดึงสายอนุมัติจาก DOA (GET /doa/resolve) + freeze snapshot + เดินทีละขั้น (one-step advance)
ผลที่เกิดจริงพฤติกรรมไม่สอดคล้องกับ DOA จริง — เหมือนยังไม่ได้เชื่อมต่อ DOA
BUG-03ดาวน์โหลดไฟล์หลักฐานไม่ได้ (ยังเป็น mock)Mediumรอแก้
ขั้นตอนทำซ้ำ
  1. เปิดคำขอที่มีไฟล์แนบ
  2. ไปแท็บหลักฐาน
  3. กดดาวน์โหลด / เปิดไฟล์
ผลที่ควรเป็นดาวน์โหลด / เปิดไฟล์แนบได้จริง
ผลที่เกิดจริงขึ้นข้อความว่าเป็น mock — ดาวน์โหลดไม่ได้
BUG-04บันทึกค่าสัดส่วน % ยังเป็น mockMediumรอแก้
ขั้นตอนทำซ้ำ
  1. สร้าง/แก้ประเภทสวัสดิการที่หน่วยเป็นสัดส่วน %
  2. กรอกค่า % แล้วกดบันทึก
ผลที่ควรเป็นบันทึกค่า % ได้จริงและแสดงผลหลังบันทึก
ผลที่เกิดจริงขึ้นว่าเป็น mock — ไม่บันทึกจริง
BUG-05แท็บใน drawer คำขอ layout หลุด designLowรอแก้
ขั้นตอนทำซ้ำ
  1. เปิดคำขอใช้สิทธิ์ 1 ใบ
  2. สลับแท็บ รายละเอียด/หลักฐาน/คงเหลือ/ประวัติ
ผลที่ควรเป็นแท็บจัดวางตาม design (เรียงเสมอกัน ไม่หลุดกรอบ)
ผลที่เกิดจริงlayout แท็บหลุด design
BUG-06timeline DOA และแท็บประวัติ layout เพี้ยนLowรอแก้
ขั้นตอนทำซ้ำ
  1. เปิดคำขอ ไปแท็บประวัติ / ดู timeline สายอนุมัติ
ผลที่ควรเป็นtimeline + ประวัติเรียงตามลำดับเวลา จัดแนวเรียบร้อย
ผลที่เกิดจริงlayout เพี้ยน
BUG-07มีคำที่เป็นภาษาระบบ/ศัพท์เทคนิคโผล่บนจอLowรอแก้
ขั้นตอนทำซ้ำ
  1. เปิดหน้า/overlay ต่างๆ ของฟีเจอร์
  2. อ่านข้อความ label / สถานะ
ผลที่ควรเป็นใช้ภาษาผู้ใช้ทั้งหมด ไม่มี code / ศัพท์ระบบ
ผลที่เกิดจริงพบคำภาษาระบบโผล่บนจอ

5ข้อเสนอแนะ (ไม่ใช่ Bug)

ทำงานถูกตาม spec แล้ว แต่ควรปรับให้ดีขึ้น — ส่งต่อเป็น Enhancement ถ้าทีมเห็นด้วย

#ข้อเสนอเหตุผล
S-01เพิ่ม smoke test ก่อน deploy: ตรวจ permission matrix 3 role + DOA resolve + ไม่มี mock stub ค้างใน build4 จุด (สิทธิ์/DOA/ดาวน์โหลด/บันทึก %) เป็น mock หรือไม่ทำงานบน production — บ่งชี้ว่า build ที่ deploy อาจพก prototype stub มาด้วย

6การรับรองผลตรวจ

ข้าพเจ้าได้ตรวจฟีเจอร์นี้ตามขอบเขตในข้อ 0 บน environment และ build ที่ระบุ ผลทั้งหมดมาจากการทดสอบจริง ข้อที่ระบุว่า "ผ่าน" คือได้ตรวจแล้วไม่พบปัญหา ส่วนที่ "ไม่ได้ตรวจ" อยู่นอกความรับผิดชอบของรายงานฉบับนี้

เกณฑ์ตัดสินผล (คำนวณอัตโนมัติ)
  • ไม่ผ่าน — มี Bug Critical ค้าง หรือ Logic ไม่ผ่านตั้งแต่ 3 ข้อ
  • ผ่านแบบมีเงื่อนไข — มี Bug High ค้าง หรือ Logic ไม่ผ่าน 1–2 ข้อ → แก้แล้วตรวจซ้ำเฉพาะจุด
  • ผ่าน — Logic ผ่านทุกข้อ ไม่มี Bug High ขึ้นไป (Medium / Low ตามแก้รอบถัดไป)
