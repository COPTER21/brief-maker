### 3.5 ข้อมูลตัวอย่างที่ขัดกัน → กฎตรวจที่ควรมี
- ข้อความคัดลอกประโยคของ 'มีความเสี่ยง' มาซ้ำทั้งประโยค แล้วต่อด้วยความหมายจริง (มีความล่าช้าหรือปัญหาที่ส่งผลกระทบชัดเจน … ต้องการการตัดสินใจเร่งด่วน) → **แบบพิมพ์คงถ้อยคำตามต้นฉบับ 1:1 · หน้าจอแสดงคำอธิบายส่วนที่เฉพาะของตัวเลือก (ติด OQ ให้ลูกค้ายืนยันถ้อยคำ)**
- % สำเร็จ เป็นช่องกรอกอิสระ อาจเกิน 100 หรือติดลบ → **% สำเร็จ 0–100 (บล็อก)**
- เลือก 'ล่าช้า หรือมีปัญหา' (ต้องการการตัดสินใจเร่งด่วน) แต่ไม่กรอกประเด็นที่ต้องการการตัดสินใจ / ปัญหา → **สถานะ = ล่าช้า หรือมีปัญหา → ต้องมีปัญหา ≥1 แถว และประเด็นตัดสินใจ ≥1 แถว (บล็อก) · มีความเสี่ยง → ต้องมีปัญหา/ความเสี่ยง ≥1 แถว (เตือน)**
- รอบการรายงานเป็นช่องเดียว ไม่บอกรูปแบบ · วันที่รายงานอาจอยู่ก่อนสิ้นรอบ → **รอบ ถึง ≥ ตั้งแต่ (บล็อก) · วันที่รายงานก่อนวันสิ้นรอบ = เตือน · รอบซ้อนกับรายงานเดิมของโครงการเดียวกัน = เตือน**
- กระดาษรวม 2 ค่าในคอลัมน์เดียว → **เก็บแยก owner + due_date · แสดงรวม 'ชื่อ / dd/mm/yyyy' ในช่องเดียว (G5)**

## 8. กติกา / declaration
- DOA: ถาม (มีช่องลงชื่อผู้อนุมัติ 2 จุด) — gate G2
- DOCCFG: ประกาศ doc_type + print_config (form_code/revision/min_rows/sign_boxes) — ร่างก่อน HTML
- MDOC: ลงทะเบียนแบบเอกสาร (F-DOCCFG / F003) · source=request
- NTF: event ของ feature เอง (เช่น ยกเลิกระหว่างรอ) — DOA ส่งแจ้งรออนุมัติ/ผลเอง
