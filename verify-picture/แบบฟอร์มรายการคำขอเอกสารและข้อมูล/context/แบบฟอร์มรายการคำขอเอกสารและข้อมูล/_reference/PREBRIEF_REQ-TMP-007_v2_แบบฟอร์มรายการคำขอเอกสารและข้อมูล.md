### 3.1 รายการซ้ำ
- **รายการคำขอเอกสารและข้อมูล** — บนกระดาษ 20 แถว (min_rows) · ช่องในแถว: รหัสคำขอ, เอกสาร / ข้อมูลที่ขอ, ผู้ถูกขอข้อมูล, ผู้รับผิดชอบ, วันที่ขอ, กำหนดส่ง, สถานะ, วันที่ได้รับ, หมายเหตุ, ลิงก์เอกสาร

### 3.2 ตัวเลือก
- **สถานะ (ต่อแถวคำขอ)** (เลือกได้ข้อเดียว): ยังไม่ขอ · ขอแล้ว · ได้รับบางส่วน · ได้รับครบ · ไม่เกี่ยวข้อง · ยกเลิก

### 3.3 สูตร + ค่าคงที่บนกระดาษ
- ค่าคงที่ "DR-001 … DR-020" = รูปแบบรหัสคำขอ (prefix DR- + เลข 3 หลัก) → ควรอ่านจาก `DocRequestPolicy.code_prefix` (ห้าม hardcode)
- ค่าคงที่ "ให้ผู้รับผิดชอบปรับปรุงข้อมูลอย่างสม่ำเสมอ และจัดเก็บไฟล์ไว้ในตำแหน่งที่กำหนดในห้องข้อมูลหรือไดรฟ์ส่วนกลาง เพื่อให้สามารถตรวจสอบย้อนหลังได้" = หมายเหตุการใช้งาน (ข้อความคงที่บนแบบ) → ควรอ่านจาก `DocRequestPolicy.usage_note` (ห้าม hardcode)

### 3.5 ข้อมูลตัวอย่างที่ขัดกัน → กฎตรวจที่ควรมี
- ชื่อชีตเป็น INV-FM-05 แต่ Doc. No. ท้ายกระดาษเป็น FM-IVM-05 → **ยึด FM-IVM-05 ตาม footer เป็นรหัสแบบฟอร์ม**
- ไม่มีช่องระบุว่ารายการคำขอนี้เป็นของโครงการ/ธุรกรรมใด (แถว 4 ว่าง) → **ชื่อโครงการ / ธุรกรรม บังคับกรอก (ช่องเพิ่ม F01 · AI-DEFAULT รอลูกค้ายืนยัน)**
- วันที่ขอ / วันที่ได้รับ ไม่ผูกกับสถานะ (dropdown G13:G32 อย่างเดียว) → **ขอแล้ว/ได้รับบางส่วน/ได้รับครบ → ต้องมีวันที่ขอ (บล็อก) · ได้รับครบ → ต้องมีวันที่ได้รับ (บล็อก) · ยังไม่ขอ แต่มีวันที่ได้รับ → บล็อก**
- ไม่มีกติกาลำดับ วันที่ขอ / กำหนดส่ง / วันที่ได้รับ → **กำหนดส่งก่อนวันที่ขอ → บล็อก · วันที่ได้รับก่อนวันที่ขอ → บล็อก · เลยกำหนดส่งแล้วยังไม่ได้รับครบ → เตือน (ป้ายเกินกำหนด)**
- ปิดแถวด้วยสถานะ ไม่เกี่ยวข้อง / ยกเลิก ได้โดยไม่ต้องให้เหตุผล → **ต้องกรอกหมายเหตุ (เหตุผล) เมื่อเลือก ไม่เกี่ยวข้อง / ยกเลิก (บล็อก)**
- ช่องลิงก์เป็นข้อความอิสระ อาจถูกใส่รหัสผ่านไดรฟ์ปนมา → **รับเฉพาะ path / URL · ห้ามเก็บรหัสผ่าน (กติกาข้อ 3) · ข้อความมีคำว่า password/รหัสผ่าน → เตือน**
- ตารางประวัติการแก้ไขมี 1 แถว (วันที่ ____ / ____ / ______) และเส้นตารางว่างต่อท้ายอีก ~20 แถวไม่มีหัว → **เป็นข้อมูลควบคุมแบบฟอร์ม (form revision) ไม่ใช่ช่องกรอก · เส้นตารางว่างด้านล่างไม่เป็นช่อง**
