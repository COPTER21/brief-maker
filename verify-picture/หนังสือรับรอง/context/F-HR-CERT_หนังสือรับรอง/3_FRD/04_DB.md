โครงเต็มอยู่ที่ **`00_OVERVIEW §0.13.2`** · สร้างจาก `T_certificate` (สถานะ ∈ `issued`/`delivered`/`revoked`/`superseded`) join `T_certificate_snapshot` เฉพาะ field ที่ปลอด

## §4.6 Data Classification — สรุปรายระดับ

### §4.6.1 รายการคอลัมน์ RESTRICTED (3 คอลัมน์ + 1 ไฟล์)
`snap_base_amount` · `snap_currency` · `snap_amount_text` · `pdf_file_ref` (เมื่อ `has_salary_figure = true`)

### §4.6.2 การควบคุม RESTRICTED
- ⭐ **มาจากต้นทางพร้อม `masked`** — feature ไม่ปิดบังเอง ไม่ถอดการปิดบังเอง (`SS-5`)
- ⭐ **`masked = true` → ไม่มีแถว snapshot เกิดขึ้นเลย** (เพราะไม่ออกหนังสือ) — ไม่ใช่ "มีแถวแต่คอลัมน์เป็น null"
- ⭐ **ACL ของไฟล์แยกจากสิทธิ์เห็นทะเบียน** — ตรวจที่ตัวไฟล์ทุกครั้งที่เปิด (`F-28`) ไม่ใช่ตอนสร้างลิงก์

### §4.6.3 การควบคุม Confidential
`recipient_name` · `consent_note` · `revoke_reason` · `reject_reason` · `cancel_reason` · comment ของ trace — ⭐ **อยู่บนใบเท่านั้น ไม่อยู่ใน read model ไม่อยู่ใน payload ของท่อสัญญาณ (ยกเว้น `recipient_name` ที่ CSQ ขอไว้โดยเจตนา · `OQ-CSQ-CT-B`)**

### §4.6.4 การควบคุม PII
⭐ **ทุก payload ของท่อสัญญาณส่ง `id` ไม่ส่งชื่อ** — Engine join เองด้วยสิทธิ์ของตัวเอง (`CSQ_BRIEF §4`)

### §4.6.5 Retention
⭐ **ยังไม่กำหนด — และห้ามตั้งค่าลบอัตโนมัติใด ๆ ก่อนมีคำตอบ** · เป็นคีย์ที่ขอไว้ใน `cert_policy` (`OQ-DOCCFG-CT-04` · `OQ-STD-CT3`)

### §4.6.6 ไม่มีคอลัมน์ Public
⭐ **ทุกคอลัมน์ในฟีเจอร์นี้เป็น Internal ขึ้นไป** — ไม่มี default เป็น Public

## §4.7 ⭐ Append-only Enforcement (บังคับที่ระดับฐานข้อมูล ไม่ใช่แค่ที่โค้ด)

| # | กติกา | บังคับด้วย |
|---|---|---|
| **D1** ⭐⭐ | `T_certificate_snapshot` — **ห้าม UPDATE ห้าม DELETE ทุกกรณี** | `CREATE TRIGGER ... BEFORE UPDATE OR DELETE ... RAISE EXCEPTION` |
| **D2** ⭐ | `T_certificate_history` · `T_certificate_access_log` — **ห้าม UPDATE ห้าม DELETE** | trigger เดียวกัน |
| **D3** ⭐⭐ | `T_certificate` — **ห้าม UPDATE คอลัมน์เหล่านี้เมื่อ `status` ≥ `issued`:** `cert_doc_no` · `employee_id` · `cert_type` · `has_salary_figure` · `language` · `copies` · `issue_date` · `template_version_id` · `rendition` · `verification_code` · `issue_place` · `pdf_file_ref` · `recipient_name` · `purpose_code` · `purpose_note` | trigger ตรวจ `OLD.status` |
| **D4** | `T_certificate` — **ห้าม UPDATE `cert_doc_no` เมื่อ `OLD.cert_doc_no IS NOT NULL`** | trigger |
| **D5** | `T_certificate` — **ห้าม DELETE เมื่อ `cert_doc_no IS NOT NULL`** (ลบได้เฉพาะร่างที่ยังไม่มีเลข) | trigger |
| **D6** | `T_certificate` — **CHECK: ห้ามมีทั้ง `revoked_at` และ `superseded_by` พร้อมกัน** | CHECK constraint (CA-04) |
| **D7** | `T_certificate` — **CHECK: `rendition` ∈ 4 ค่าเท่านั้น** · **CHECK: `rendition` สอดคล้องกับ `language` × `has_salary_figure`** | CHECK constraint (⭐ ไม่มีค่าที่ห้า) |
| **D8** | `T_certificate` — **CHECK: `has_salary_figure = (cert_type = 'salary')`** | ⭐ CHECK constraint — ผู้ใช้ตั้งเองไม่ได้แม้จะเขียน SQL ตรง |
| **D9** ⭐⭐ | **ไม่มีคอลัมน์ใดใน `T_certificate_snapshot` ที่รับข้อความอิสระจากผู้ใช้** | ⭐ **ตรวจด้วย `F-44` ตอน build** — เจอ placeholder ที่ map ไปคอลัมน์ที่ผู้ใช้พิมพ์ได้ = build fail (**BR-28**) |
| **D10** | **ไม่มีตัวนับเลขเอกสารในสคีมาของฟีเจอร์นี้** | ⭐ ตรวจด้วย grep `sequence` / `counter` / `nextval` ในไฟล์ migration ที่เกี่ยวกับเลขเอกสาร = ต้องไม่พบ (BR-02) |

## §4.8 Migration Plan

1. สร้าง 6 ตาราง + 1 view + index + CHECK constraint ทั้งหมดใน migration เดียว
2. สร้าง trigger append-only (D1–D5) **ก่อน** เปิดใช้งาน — ⭐ **ห้าม deploy ตารางโดยไม่มี trigger แม้ชั่วคราว**
3. ไม่มีข้อมูลเดิมให้ย้าย (New Feature) — ⭐ **หนังสือที่ออกด้วยไฟล์ Word เดิมไม่ถูกนำเข้าระบบ** (ไม่มี snapshot จึงพิสูจน์ย้อนหลังไม่ได้ · บันทึกไว้เป็น `OQ-FRD-CT-03`)
4. register `doc_type = CERT` ที่ Document Configuration · register DOA entry · register NTF event · register CSQ profile
5. รัน `F-40 registerWhereUsed()` กับต้นทางทั้ง 4
