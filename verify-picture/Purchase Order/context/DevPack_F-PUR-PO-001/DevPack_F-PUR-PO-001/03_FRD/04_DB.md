## §4.3 Relationships

```
t_po_header 1 ──< N t_po_line         ON DELETE RESTRICT
t_po_header 1 ──< N t_po_approval     ON DELETE RESTRICT
t_po_header 1 ──< N t_po_audit        ON DELETE RESTRICT (append-only)
t_po_header 1 ──< N t_po_attachment   ON DELETE RESTRICT

t_po_header  }o..o| PR_Header        soft-ref (ไม่มี FK จริง)
t_po_header  }o..o| Compare_Result   soft-ref
t_po_header  }o..|| Vendor           soft-ref
t_po_line    }o..|| Item             soft-ref
t_po_line    1 ──< N GRN_Line        ถูกอ้างโดยใบรับของ (F079)
```

> **LOCK-01:** ทะเบียนหลักทั้งหมดเป็น soft-ref — **ห้ามสร้าง FK constraint** ไปยังทะเบียนภายนอก
> เหตุผล: ค่าที่ถูกลบ/ปิดใช้งานในทะเบียนต้องยังแสดงค่าที่บันทึกไว้ในใบเดิมได้ (E14)

## §4.6 Data Classification — นิยามและการบังคับใช้

### §4.6.1 นิยาม 4 ระดับ

| ระดับ | นิยาม | ตัวอย่างใน feature นี้ |
|---|---|---|
| `Public` | เปิดเผยสู่ภายนอกได้ | **ไม่มีในรอบนี้** |
| `Internal` | พนักงานที่มีสิทธิ์เข้าระบบเห็นได้ | เลขเอกสาร · สถานะ · จำนวน |
| `Confidential` | เห็นเฉพาะผู้มีหน้าที่เกี่ยวข้อง | ราคา · ยอดรวม · เงื่อนไขชำระ · ผู้อนุมัติ |
| `Restricted` | ต้องขึ้นทะเบียนทรัพยากรจำกัดสิทธิ์ | — |

### §4.6.2 การบังคับใช้ชั้น DB
คอลัมน์ `Confidential` อยู่ในกลุ่มที่ต้องเข้ารหัสขณะพัก (at-rest) ตาม policy ขององค์กร · `t_po_audit` ให้สิทธิ์ `INSERT`/`SELECT` เท่านั้น

### §4.6.3 การบังคับใช้ชั้น API
response ที่ส่งให้ role อ่านอย่างเดียว (คลัง) **ตัดฟิลด์ราคา/ยอดรวมออก** — คลังเห็นเฉพาะรายการ+จำนวน+กำหนดรับ (ดู `02_API §2.8`)

### §4.6.4 การบังคับใช้ชั้น UI
`01_UI §1.5` — คลังเห็นใบตั้งแต่สถานะ "ส่งผู้ขายแล้ว" ขึ้นไป และไม่เห็นคอลัมน์ยอดสุทธิ

### §4.6.5 การบังคับใช้ชั้น Audit
ทุกการอ่านข้อมูล `Confidential` แบบ export (ดาวน์โหลด PDF/CSV) ต้องลงประวัติ

### §4.6.6 การเชื่อมกับ Policy Center
ระดับชั้นข้อมูลของ feature นี้ประกาศไว้ที่ Policy Center (F-056) — **feature ไม่กำหนดนโยบายเอง** (LOCK-05)
