## 1. Business Context
### 1.1 ปัญหา / โอกาส
- ปัจจุบันหน่วยงานใช้แบบฟอร์มกระดาษ FM-HRM-32 (2 หน้า) กำหนดหน้าที่ของแต่ละตำแหน่ง: ข้อมูลทั่วไป · วัตถุประสงค์ · ความรับผิดชอบหลัก · คุณสมบัติ · KPI · คุณสมบัติอื่น · ผังหัวหน้า/ลูกน้อง · ลงนาม 3 ฝ่าย (ผู้จัดทำ · ผู้อนุมัติ · ผู้ดำรงตำแหน่ง)
- ปัญหา: ชื่อตำแหน่ง/แผนก/ฝ่ายเขียนไม่ตรงผังองค์กร · ไม่รู้ว่าฉบับไหนเป็นฉบับล่าสุดของตำแหน่ง · ตามลายเซ็นรับทราบของผู้ดำรงตำแหน่งยาก
- ขึ้นระบบเพื่อ: เลือกตำแหน่งจาก master · อนุมัติตามสาย DOA · ฉบับอนุมัติใหม่แทนฉบับเดิมอัตโนมัติ · ผู้ดำรงตำแหน่งกดรับทราบในระบบ · พิมพ์แบบฟอร์มหน้าตาเดิมได้

### 1.2 เป้าหมาย
1. ทุกตำแหน่งมี JD ฉบับใช้งานได้ 1 ฉบับที่อนุมัติแล้ว
2. ผู้ดำรงตำแหน่งรับทราบ JD ของตนในระบบ
3. พิมพ์ PDF ตามแบบ FM-HRM-32 ได้ทุกสถานะ

### 1.3 ตัวชี้วัด
- ไม่มีใน input → OQ-03 (ห้ามแต่งตัวเลข)

### 1.4 ที่มา
- ไฟล์ลูกค้า `ใบกำหนดหน้าที่งานประจำตำแหน่ง (JD).docx` (sha256 d9c979e256777691) · ไม่มี PREBRIEF จาก CMS → PREBRIEF v2 สร้างจาก FORM_SPEC

## 2. Scope
### 2.1 In Scope
- หน้ารายการ · สร้าง/แก้ร่าง (wizard 3 ขั้น) · ดู (รายละเอียด › PDF Preview › ลายเซ็น / อนุมัติ › ประวัติ) · ส่งอนุมัติ · อนุมัติ/ไม่อนุมัติ · ยกเลิก · ระบุผู้ดำรงตำแหน่ง · รับทราบ · ส่งออก CSV · แนบไฟล์
- แบบพิมพ์ Replica FM-HRM-32 (thai-doc v2.1) · เลขที่ JD จาก F-DOCCFG / ENG-DOC-NUM
- สายอนุมัติจาก DOA กลาง (dynamic · ค่าเริ่ม 1 ขั้น) · แจ้งเตือน jd_cancelled / jd_ack_requested / jd_acknowledged / jd_superseded (ENG-NOTIFY)

### 2.2 Out of Scope
- แก้ Position master (ชื่อ/ผังองค์กร) — JD อ่านอย่างเดียว (DEC-01)
- ส่งต่อ Performance / Recruit / Competency — รอบนี้ไม่ส่ง (DEC-02) · ประกาศ event ไว้
- ทำซ้ำ · ประกาศ (DEC-12)

### 2.3 Assumptions
- Position master (Organization · Position & Tier) มี name_th · org_unit · reports_to · ไม่มี name_en (กรอกในเอกสาร)
- Employee มี position_id + ผู้บังคับบัญชาตรง (ใช้ resolve role-line-manager)

## 4. User Journey
### 4.1 Happy Path
1. ผู้จัดทำเปิด "ใบกำหนดหน้าที่งานประจำตำแหน่ง" → สร้าง → เลือกตำแหน่ง → ระบบเติมแผนก/ฝ่าย/รายงานต่อ + แถวหัวหน้าแรก
2. กรอกชื่อตำแหน่งอังกฤษ · หัวข้อ 2–6 · ตารางหัวหน้า/ลูกน้อง → ระบบสรุป "ผู้ใต้บังคับบัญชา"
3. เลือกผู้ดำรงตำแหน่ง (ถ้ามี) → แนบไฟล์ → ตรวจสอบ → บันทึกและส่งอนุมัติ (เลือกผู้อนุมัติต่อขั้น ค่าเริ่มจาก DOA) → ระบบออกเลข JD · สถานะ "รออนุมัติ"
4. ผู้อนุมัติ → อนุมัติ → สถานะ "อนุมัติแล้ว" · ฉบับเดิมของตำแหน่งเดียวกัน → "ถูกแทนที่" · แจ้งผู้ดำรงตำแหน่ง (jd_ack_requested)
5. ผู้ดำรงตำแหน่งกดรับทราบ → "รับทราบแล้ว" · PDF ช่องผู้ดำรงตำแหน่ง "รับทราบในระบบ วันที่ เวลา"

### 4.2 Alternative
- A1 ไม่อนุมัติ (เหตุผล) → กลับเป็นร่างเลขเดิม → แก้ → ส่งใหม่
- A2 ยังไม่ระบุผู้ดำรงตำแหน่ง (ตำแหน่งว่าง) → HR ระบุภายหลังในแท็บลายเซ็น
- A3 บันทึกร่างไว้ก่อน → กลับมาแก้ → ส่ง
- A4 ยกเลิก (เหตุผลบังคับ) โดยเจ้าของหรือ HR ที่ร่าง/รออนุมัติ

## 7. Status & Lifecycle
`draft (ร่าง)` → ส่ง → `pending (รออนุมัติ)` → อนุมัติครบทุกขั้น → `approved (อนุมัติแล้ว)` → ผู้ดำรงตำแหน่งรับทราบ → `acknowledged (รับทราบแล้ว)`
- ไม่อนุมัติ → `draft` เลขเดิม (DEC-09) · `draft|pending` → ยกเลิก → `cancelled`
- ฉบับใหม่ของตำแหน่งเดียวกันอนุมัติ → ฉบับเดิม `approved|acknowledged` → `superseded (ถูกแทนที่)`
- ส่งแล้วแก้ไม่ได้ (ล็อก) · เลขออกตอนบันทึกครั้งแรก (DEC-11)
