0ขอบเขตการตรวจ

ส่วนที่ไม่ได้ตรวจ อยู่นอกความรับผิดชอบของรายงานฉบับนี้

ตรวจแล้ว

  • สถานะเมื่อแบบเอกสาร JD ยังไม่เปิดใช้งาน
  • ข้อความแจ้งเตือนและสถานะ disabled ของปุ่มสร้างใบกำหนดหน้าที่งาน

ไม่ได้ตรวจ

  • สร้างและแก้ไขร่าง รวม validation และการคำนวณผู้ใต้บังคับบัญชา — ปุ่มสร้างถูก disabled เพราะแบบเอกสาร JD ยังไม่เปิดใช้งาน
  • ส่งอนุมัติ อนุมัติ ไม่อนุมัติ และสายอนุมัติ DOA — ไม่มีรายการทดสอบที่สร้างใหม่ได้
  • ระบุผู้ดำรงตำแหน่งและการรับทราบ — ไม่สามารถเดิน flow ตั้งแต่สร้างเอกสารได้
  • ยกเลิก ฉบับใหม่แทนฉบับเดิม สิทธิ์การมองเห็น PDF CSV ไฟล์แนบ ประวัติ และ notification — ไม่สามารถสร้างข้อมูลทดสอบสำหรับตรวจ flow ต่อเนื่องได้
  • UI และ UX ส่วนอื่นของฟีเจอร์ — ผู้ตรวจรายงานเฉพาะข้อความแจ้งเตือนและปุ่มสร้างในสถานะ disabled

1Logic — ทำงานถูกตามกฎธุรกิจ

เทียบผลจริงกับ FRD / Test Case — ข้อที่ไม่ผ่านต้องผูกกับ Bug ในข้อ 4

#กฎ / Scenarioผลที่คาดหวังผลจริงผลอ้างอิง
L-01ความพร้อมใช้งานของการสร้าง JD บน Productionแบบเอกสาร JD เปิดใช้งานและผู้มีสิทธิ์สามารถกดสร้างใบกำหนดหน้าที่งานใหม่เพื่อเริ่ม flow หลักได้แบบเอกสาร JD ยังไม่เปิดใช้งาน ปุ่มสร้างถูก disabled และไม่สามารถสร้างรายการได้ไม่ผ่านBUG-01
L-02F-DOCCFG ปิดแบบเอกสาร JDแสดงว่าแบบเอกสารนี้ยังไม่เปิดใช้งาน และปุ่มสร้างถูก disabledแสดงข้อความ “แบบเอกสารนี้ยังไม่เปิดใช้งาน — สร้างใบกำหนดหน้าที่งานใหม่ไม่ได้” และปุ่มสร้างถูก disabledผ่านEC-09
L-03เลือกตำแหน่งและดึงข้อมูลจาก Position masterแผนก/ฝ่ายเป็น read-only และรายงานต่อกับหัวหน้าแถวแรกเติมจาก master—ไม่ได้ตรวจAC-01
L-04Validation ฟิลด์บังคับและ KPIข้อมูลไม่ครบต้องถูกบล็อกพร้อมข้อความระบุจุดที่ต้องแก้—ไม่ได้ตรวจAC-02 · BR-02–BR-04
L-05จำนวนและสรุปผู้ใต้บังคับบัญชาระบบคำนวณจำนวนตำแหน่งและจำนวนคนจากรายการ และรองรับ 12 แถวใน PDF—ไม่ได้ตรวจAC-03 · AC-04
L-06ส่งอนุมัติผ่าน DOAresolve สายอนุมัติจาก DOA กลางและผู้จัดทำไม่สามารถเลือกตนเองเป็นผู้อนุมัติ—ไม่ได้ตรวจAC-05 · AC-15
L-07อนุมัติและไม่อนุมัติอนุมัติได้เฉพาะขั้นปัจจุบัน; ไม่อนุมัติต้องมีเหตุผลและกลับร่างด้วยเลขเดิม—ไม่ได้ตรวจAC-06 · AC-07
L-08ระบุผู้ดำรงตำแหน่งและรับทราบเฉพาะ HR ระบุผู้ดำรงตำแหน่งในใบ approved และผู้ที่ถูกระบุจึงรับทราบได้—ไม่ได้ตรวจAC-08 · AC-09
L-09สิทธิ์การเห็นรายการและ CSVข้อมูลรายการและ CSV ถูกจำกัดตามสิทธิ์ของผู้ใช้—ไม่ได้ตรวจAC-10 · TC-D01–TC-D09
L-10PDF ทุกสถานะมีเลขเอกสาร ไม่มี placeholder ค้าง และแสดงสถานะกับช่องลงนามถูกต้อง—ไม่ได้ตรวจAC-11
L-11ยกเลิกเอกสารยกเลิก draft/pending ได้เฉพาะผู้มีสิทธิ์และต้องระบุเหตุผล—ไม่ได้ตรวจAC-12
L-12ฉบับใหม่แทนฉบับเดิมเมื่อฉบับใหม่อนุมัติ ฉบับใช้งานเดิมของตำแหน่งเดียวกันเปลี่ยนเป็น superseded—ไม่ได้ตรวจAC-13
L-13หัวหน้าแถวแรกไม่ตรงรายงานต่อระบบเตือนแต่ไม่บล็อกการส่ง—ไม่ได้ตรวจAC-14

4Bug ที่พบ

เรียงจากรุนแรงมากไปน้อย · ทำซ้ำได้ตามขั้นตอน

BUG-01Production ยังไม่เปิดใช้งาน Document Type JD ทำให้สร้างใบกำหนดหน้าที่งานไม่ได้Criticalรอแก้
ขั้นตอนทำซ้ำ
  1. เข้าสู่ฟีเจอร์ HR ใบกำหนดหน้าที่งานประจำตำแหน่ง (JD) บน Production
  2. ดูบริเวณปุ่มสร้างใบกำหนดหน้าที่งาน
  3. ลองกดปุ่มสร้างรายการ
ผลที่ควรเป็นDocument Type JD เปิดใช้งานและปุ่มสร้างพร้อมให้ผู้มีสิทธิ์เริ่มสร้างรายการ
ผลที่เกิดจริงแสดงข้อความ “แบบเอกสารนี้ยังไม่เปิดใช้งาน — สร้างใบกำหนดหน้าที่งานใหม่ไม่ได้” และปุ่มสร้างถูก disabled

5ข้อเสนอแนะ (ไม่ใช่ Bug)

ทำงานถูกตาม spec แล้ว แต่ควรปรับให้ดีขึ้น — ส่งต่อเป็น Enhancement ถ้าทีมเห็นด้วย

#ข้อเสนอเหตุผล
S-01ทบทวนข้อความแจ้งเตือนที่อยู่ข้างปุ่มสร้างรายการผู้ตรวจเห็นว่าข้อความดังกล่าวซ้ำซ้อนกับกลไกแจ้งเตือนที่ระบบมีอยู่แล้ว; ควรรวมให้เหลือจุดสื่อสารเดียว หากยังทำให้ผู้ใช้เข้าใจได้ชัดเจนว่าแบบเอกสารยังไม่เปิดใช้งาน
S-02เปิดใช้งาน Document Type JD ใน environment ที่ใช้ตรวจ แล้วทดสอบใหม่ปัจจุบันไม่สามารถสร้างรายการเพื่อครอบคลุม logic และ flow หลักตาม FRD ได้

6การรับรองผลตรวจ

ข้าพเจ้าได้ตรวจฟีเจอร์นี้ตามขอบเขตในข้อ 0 บน environment และ build ที่ระบุ ผลทั้งหมดมาจากการทดสอบจริง ข้อที่ระบุว่า "ผ่าน" คือได้ตรวจแล้วไม่พบปัญหา ส่วนที่ "ไม่ได้ตรวจ" อยู่นอกความรับผิดชอบของรายงานฉบับนี้
