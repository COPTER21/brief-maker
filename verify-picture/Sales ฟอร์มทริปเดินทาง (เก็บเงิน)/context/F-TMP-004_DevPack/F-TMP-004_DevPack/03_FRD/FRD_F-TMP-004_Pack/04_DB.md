## 3. `approval_chain` (jsonb ใน `trip_sheet`) — โครงต่อขั้น
```json
[ { "step": 1, "role_id": "role-line-manager", "label": "ผู้อนุมัติ (ลำดับ 1)",
    "assignee_id": "<uuid>", "status": "pending", "at": null, "note": "" } ]
```
`status`: `waiting` · `pending` · `approved` · `rejected` · `skipped`
จำนวนขั้นมาจาก DOA กลาง — **ห้าม fix จำนวนขั้นหรือ role ในสคีมา/โค้ด** (`doa_ref` ชี้ entry ที่ใช้)

## 6. การ map ช่องบนกระดาษ → คอลัมน์
| บนกระดาษ | คอลัมน์ |
|---|---|
| TO : / CC : | `to` / `cc` |
| ผู้รับผิดชอบเขต : / ตำแหน่ง : | `owner_name` / `owner_position` (จากระบบ) |
| เขต : / รอบการขาย : | `territory` / `sales_period` |
| ตารางวันทำงาน 31 บรรทัด × 19 คอลัมน์ | `trip_sheet_line` (ไม่จำกัดจำนวนแถว) |
| แถว "รวมยอด" 13 ช่อง | `trip_sheet.total_*` (computed) |
| ลงชื่อ ผู้นำเสนอ / ผู้อนุมัติ × 2 | `approval_chain` + ผู้สร้างเอกสาร (ไม่เก็บภาพลายมือชื่อ — DEC-07) |
| (ไม่มี Doc No./Rev. บนกระดาษ) | `print_config.form_code` / `revision` ว่างจนกว่า F-DOCCFG กำหนด |
