### T_payroll

**Purpose:** Main payroll record per employee per period

| Column | Type | Null | Default | Classification | PII | Description |
|---|---|---|---|---|---|---|
| `id` | uuid | NO | gen_random_uuid() | Internal | — | PK |
| `tenant_id` | uuid | NO | — | Internal | — | FK → T_tenant; RLS |
| `period_id` | uuid | NO | — | Internal | — | FK → T_payroll_period |
| `employee_id` | uuid | NO | — | Confidential | Yes | FK → T_employee |
| `status` | varchar(20) | NO | 'draft' | Internal | — | enum: draft/submitted/approved/paid/cancelled |
| `base_salary` | numeric(15,2) | NO | — | **Restricted** | — | Monthly base — salary data |
| `gross_pay` | numeric(15,2) | NO | — | **Restricted** | — | Computed by ENG-005 |
| `net_pay` | numeric(15,2) | NO | — | **Restricted** | — | Computed by ENG-005 |
| `tax_amount` | numeric(15,2) | NO | 0 | Confidential | — | Computed by ENG-005 |
| `submitted_at` | timestamp | YES | — | Internal | — | Set on submit action |
| `approved_at` | timestamp | YES | — | Internal | — | Set on approve action |
| `approved_by` | uuid | YES | — | Internal | — | FK → T_user (approver) |
| `created_at` | timestamp | NO | NOW() | Internal | — | Audit |
| `updated_at` | timestamp | NO | NOW() | Internal | — | Audit + optimistic lock |
| `created_by` | uuid | NO | — | Internal | — | FK → T_user |
| `version` | integer | NO | 1 | Internal | — | Optimistic locking (PR-2) |

**Constraints:**
- PRIMARY KEY (id)
- UNIQUE (tenant_id, period_id, employee_id) — 1 payroll per employee per period
- CHECK (gross_pay >= 0)
- CHECK (net_pay >= 0)
- CHECK (status IN ('draft','submitted','approved','paid','cancelled'))

**Indexes:**
- IDX_payroll_tenant_status ON (tenant_id, status)
- IDX_payroll_period ON (tenant_id, period_id)
- IDX_payroll_employee ON (tenant_id, employee_id)
- IDX_payroll_created_at ON (created_at DESC)

**RLS Policy:**
```sql
CREATE POLICY tenant_isolation ON T_payroll
  USING (tenant_id = current_setting('app.current_tenant')::uuid);
```

## §4.6 Data Classification & Sensitive Data ⭐ (v5.1)

### §4.6.1 Classification Levels (CUBE 4.0 Standard)

ทุก field ใน §4.2 ต้องระบุระดับ classification 1 ใน 4 ระดับนี้:

| Level | นิยาม | ตัวอย่าง | UI Behavior | Export Behavior |
|---|---|---|---|---|
| **Public** | เผยแพร่ได้ภายนอกองค์กร | company name, product catalog, public article | แสดงปกติ | export ได้ทุก role |
| **Internal** | เห็นได้เฉพาะคนในบริษัท (default) | org chart, internal SOP, status, audit timestamps | แสดงปกติสำหรับ authenticated user | export ได้ทุก internal role |
| **Confidential** | จำกัด role | customer contract, vendor payment terms, employee ID, performance score | mask `***` ถ้า role ไม่ผ่าน | excluded column ถ้า role ไม่ผ่าน |
| **Restricted** | จำกัดถึงระดับ person (ACL) | salary, board minutes, M&A docs, restricted project files | hidden + audit log ทุกการเข้าถึง | excluded + require Restricted Resources approval |

### §4.6.2 Default Rule

- **Default classification = Internal** (ถ้าไม่ระบุใน §4.2)
- ห้าม default เป็น Public — ต้อง explicit
- Field ที่ classification ≠ Internal → ต้องระบุชัดเจนใน §4.2

### §4.6.3 Enforcement Mapping

| Classification | DB Layer | API Layer | UI Layer | Audit |
|---|---|---|---|---|
| Public | — | — | — | — |
| Internal | RLS (tenant) | JWT auth | — | mutation only |
| Confidential | RLS + column ACL | role check | mask if no permission | view + mutation |
| Restricted | RLS + row ACL (Restricted Resources) | role + ACL check | hide if no permission | view + mutation + export |

### §4.6.4 PII Overlay (Independent Flag)

PII flag เป็น **overlay** แยกจาก classification — field สามารถมีทั้ง 2 attributes:
- `classification` = ระดับการเข้าถึง (4 levels)
- `pii_flag` = เป็น personal data ภายใต้ PDPA หรือไม่ (boolean)

ตัวอย่าง:
- `employee_name` → Confidential + PII (จำกัด role + อยู่ใน PDPA scope)
- `base_salary` → Restricted + ไม่ PII (จำกัด person + ไม่ใช่ personal data ของผู้สมัคร)

### §4.6.5 Security Bible Domain Mapping

| Domain | เกี่ยวข้องกับ |
|---|---|
| **D5 (Financial):** all amount fields → audit log mandatory + default = Confidential หรือ Restricted |
| **D7 (PII):** field ที่ pii_flag=true → encrypt at rest (column-level) + PDPA scope |
| **D9 (Audit):** all changes → T_audit_log with diff (ทุก mutation ระดับ Internal ขึ้นไป) |

### §4.6.6 Linkage with Policy Center

- Field classification → linked กับ **Data Classification module** (Policy Center)
- Restricted fields → linked กับ **Restricted Resources registry** (Policy Center)
- PII fields → linked กับ **PDPA consent scope** (Policy Center)

> **Note:** Default classification ถูกกำหนดที่ FRD/Schema build-time —
> Data Classification module ใน Policy Center ใช้ override ได้ runtime (พร้อม audit log)
